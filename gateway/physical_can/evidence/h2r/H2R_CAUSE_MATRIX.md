# H2R 只读归因矩阵

冻结起点：`a9951fd2f8c66437e2db195a85daa23fef7054b3`。本表初版只使用既有代码、脱敏H2记录和现场口述；没有用猜测补齐硬件测量。

| 假设 | 支持证据 | 尚不能排除/反证 | 单变量验证 |
|---|---|---|---|
| 主循环诊断占用期间，3深度FIFO来不及释放 | 旧驱动每poll最多3帧；同线程整段snprintf/Router；H2末窗FOVR29→43，TEC/REC/LEC=0 | 尚无微秒级服务空隙实测；不能仅凭错误计数排除电气原因 | 固定A频率/接线/时效，Host MMIO重现4帧与一秒PDO突发；仅替换C bench接收，IRQ入静态队列，分别测服务空隙/报告耗时 |
| 单纯加大poll budget即可根治 | 无 | 主循环完全未运行期间，任何budget都无法读取FIFO | 保留旧模型作为对照；诊断占用期间连续到达，与IRQ路径比较 |
| UART输出/Host日志丢失被误当CAN丢样 | 旧Host曾因状态文件PermissionError中断；原UART只有字节/队列粗计数 | 硬件FOVR也真实增长，Host问题不能解释FOVR | 公开报告序号及行数，分别记录设备UART丢弃和Host可观测缺行；不可互相替代 |
| A Flash应用损坏/向量错误 | 尚无支持；H2向量与候选一致、下载回读通过 | 仅能说明当时字节一致，不代表普通启动时序正确 | 保留原备份、只读核对向量/选项；先不重刷A |
| A的BOOT/NRST/独立供电/调试器复位采样有差异 | 普通J-Link reset后VTOR/PC仍在ROM；调试入口可运行 | 用户回报BOOT0/BOOT1接地，与ROM结果不一致；不能直接断定BOOT0高 | C先被动接收，断开A调试器，独立供电正常冷启动；每次记录实际Boot-up和后续心跳，另列J-Link reset结果 |
| A初始化代码破坏启动/双屏 | H2强制入口后可运行原应用；屏黑曾随供电方案改变恢复 | 正常冷启动仍未独立验证；未核实的供电时序不得当软件缺陷修 | 先固定原A源码，正常冷启动3次；只有定位到初始化缺陷才改A最小启动代码 |
| 无探头/无合格夹具导致读数缺失 | H2初期无探头，后期曾报告人体连接；Q可为0 | 帧接收成功不证明生理值准确，旧人体数据不作为本轮非人体夹具 | R1/R2通过后再验非人体来源；无合格夹具只验INVALID/断开，真实采集PENDING |

## 保护清单

P4固定`67f5f57bd82c6e326e9e78ec9540481c80105e5f`、main、CANopenNode/coreMQTT上游、原Router/MQTT QoS1/PUBACK/AT/TLS、Node-A采集算法与双屏均不改。原物理完整候选保持原构建，H2R接收实现仅用于独立bench。旧H2失败/连续观测不覆盖。

## 现场冻结与待核实

用户已确认无人连接、A/C/屏及传感器全部断电，CAN三线不动。随后回报A为J5外部DC并接J-Link、BOOT0/BOOT1接GND；铭牌输出、复位瞬间引脚电平、NRST波形没有实际测量证据，保留未知。用户要求减少重复静态问询，后续复用已确认状态，只集中提出必需现场动作。

板图确认的可核对网络：VOUT1 3.3V/GND、VOUT2 5V/GND、U3 VCC(3)/GND(2)、BOOT0、PB2/BOOT1、RESET/NRST。无法可靠定位时不在细小相邻脚上盲探，不把J-Link VTref等同整板供电。没有瞬态仪表时，万用表静态值不能证明复位采样瞬间状态。

## 1. 概述与调研背景

本项目 Web 监护端最初主要用于第一阶段与第二阶段的云网关连通性验证及 MQTT/CANopen 链路联调，其视觉呈现更接近“浅色后台运维/营销 Dashboard”。

随着系统迈入第三阶段，数据链路已经完成了：
- 节点硬件驱动（ECG/RESP ADS1292R、SpO2 HKS-12C、NIBP HKB-08B、TEMP GY-641-V3）；
- CANopen 字典汇聚与网关调度；
- MQTT TLS 安全上云与 Backend 统一时钟快照封装。

为了让样机展示与远程中央监护呈现符合真实临床级医疗设备规范，本专项对主流临床多参数监护仪进行了深度调研，包括：
1. **Mindray（迈瑞）ePM 10M / 12M 与 BeneVision 系列**
2. **Philips（飞利浦）IntelliVue MX400 / MX800 系列**
3. **EDAN（理邦仪器）iM 系列（iM80/70/60/50）与 iX 系列**

本文档系统性梳理三家主流产品的共性设计法则，明确可复用要素、不可照搬边界，以及 Web 浏览器环境下专业监护大屏的技术实现策略。

## 2. 主流临床监护仪共性规律 (Clinical Common Patterns)

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ 顶部状态区: 床号/患者类型/科室 | 设备与网络状态 | 当前系统时间 | 全局报警条 │
├───────────────────────────────────────────────────────┬─────────────────────┤
│ ECG Lead II 连续平滑波形 (Sweep Trace)               │ HR 心率 (bpm)       │
├───────────────────────────────────────────────────────┼─────────────────────┤
│ PLETH / PPG 脉搏容积波形 (Sweep Trace)                │ SpO2 (%) & PR (bpm) │
├───────────────────────────────────────────────────────┼─────────────────────┤
│ RESP 阻抗呼吸波形 (Sweep Trace)                       │ RR 呼吸率 (/min)    │
├───────────────────────────────────────────────────────┼─────────────────────┤
│ 辅助区域: 节点状态 / 事件流 / 补传标记              │ NIBP (SYS/DIA mmHg) │
│                                                       │ TEMP 体温 (°C)      │
└───────────────────────────────────────────────────────┴─────────────────────┘
```

调研三家厂商的操作手册与人机工程指南后，归纳出以下 6 条普适性临床人机界面法则：

### 2.1 极简暗黑基底（Dark Low-Glare Surface）
- **规范**：所有专业床旁监护仪与中央监护站无一例外采用深黑或近黑色纯色背景（如 `#000000`、`#090d14`、`#10141a`），绝无亮色背景、渐变背景、投影拟物或高光磨砂玻璃。
- **临床原因**：ICU/CCU/病房常年处于低照度或夜间监护环境。亮色屏幕会严重刺激患者眼睛并造成反光倒影；暗色背景能让发光波形与大数字形成 20:1 以上的高动态对比度，使医护人员在数米开外或斜视角度下也能一眼捕捉数值突变。

### 2.2 “左波右数、水平对齐”黄金分割
- **规范**：
  - 屏幕横向切分为左右两大视区：**波形区（Waveform Area）占据 65%～72%**，**大数字读数区（Numeric Area）占据 28%～35%**；
  - 垂直方向严格分为水平通道行（Horizontal Tracks），每个波形通道与右侧对应的关键生命体征大数值在视线高度上严格水平对齐；
  - 每一行参数模块自成逻辑闭环，如第一行是 ECG 波形与 HR，第二行是 PLETH 波形与 SpO2/PR，第三行是 RESP 波形与 RR。
- **临床原因**：极大减轻医护人员的认知负荷（Cognitive Load），杜绝在全屏杂乱卡片中反复寻找波形与读数对应关系的疲劳感。

### 2.3 行业沉淀的通道识别色彩（Parameter Color Coding）
虽然国际上并未强制统一定义波形颜色，但在飞利浦、迈瑞、理邦等厂商数十年临床实践中，已形成了全球广泛认同的“默认习惯色彩”（Defacto Standard）：
- **ECG / 心电**：经典绿色系（`#00e676`、`#22c55e`、`#5be0ad`）
- **SpO2 / 血氧脉搏容积**：青蓝/青色系（`#00e5ff`、`#06b6d4`、`#5dc6ef`）
- **RESP / 呼吸**：黄色/琥珀色系（`#ffd600`、`#f59e0b`、`#e6c179`）
- **NIBP / 血压**：白色/浅紫灰系（`#ffffff`、`#b0a3ff`、`#e2e8f0`）
- **TEMP / 体温**：暖白/浅橙色系（`#ff9100`、`#fb923c`）

### 2.4 极端清晰的异常与缺失状态语义
- **缺失或无效（INVALID）**：显示大号双横线 `--` 或 `No Signal`，**严禁显示 `0`**。
- **陈旧数据（STALE）**：读数置灰或清除，明确标注 STALE，杜绝误读上一次健康快照。
- **通道离线（OFFLINE）**：对应通道显著降暗（暗灰调），明确标记离线状态，波形走平并提示断线。

### 2.5 波形扫描与时间轴标定
- **波形扫描**：主流监护仪采用平滑扫描（Sweep）或滚动（Scroll）模式，时间轴一般提供 25 mm/s 或 50 mm/s 走纸等效速度，在屏幕上呈现 8 秒到 16 秒的波形视窗。
- **微网格背景**：波形区衬底带有暗灰色等距微网格，用于提供视觉基线参考。

### 2.6 顶部高权重全局条（Global Header）
- 固定居顶，承载：设备/床位唯一标识、监护时钟、生理报警/技术报警专区（Alarm Banner）。

## 3. 哪些设计可以复用与借鉴？

结合本项目当前的系统架构与数据流，本重构方案直接复用并强化以下优秀设计：

1. **左波形（70%）+ 右读数（30%）紧密横向成行布局**：
   - Row 1: ECG II 导联模拟波形 ↔ HR 读数 + 单位 bpm + 来源标签
   - Row 2: PLETH 容积波形 ↔ SpO2 读数 (%) + PR 读数 (bpm)
   - Row 3: RESP 阻抗呼吸波形 ↔ RR 读数 (/min) + 算法 120 秒 RR 趋势折线图
   - Row 4: 节点/系统状态 ↔ NIBP (SYS / DIA mmHg) + TEMP (°C)
2. **专业医疗监护仪暗黑配色系统（Design Tokens）**：
   - 彻底摒弃第一阶段的亮色外框与普通网页卡片样式，引入原生暗黑底色、低饱和度背景网格与高对比荧光通道色。
3. **标准状态展示语言**：
   - 统一遵循 `VALID` -> 读数正常；`INVALID` -> 显示 `--`；`STALE` -> 读数清除；`OFFLINE` -> 模块变暗并显著标明。
4. **双视窗比例切换（8 秒 / 16 秒）与浏览器全屏沉浸模式**：
   - 提供 8s 与 16s 走纸视窗无缝平滑伸缩；全屏模式下一键隐去所有非监护元素，获得与硬件监护仪完全一致的满屏视觉冲击力。

## 4. 哪些设计绝对不能照搬？（技术与法规边界）

真实临床硬件监护仪具备封闭系统专有硬件、经过 NMPA/CE/FDA 三类医疗器械严苛认证的固件算法以及专用物理热键。作为 Web 远程大屏样机，**必须划定清晰的红线，坚决不照搬以下设计**：

| 实体监护仪特性 | 为什么本项目 Web 端不能照搬 | 本项目的处理策略 |
| :--- | :--- | :--- |
| **三级生理报警颜色变换**（如 HR>120 变红闪烁） | 当前 Backend 仅提供通道采集与连通性状态，**尚未集成正式临床报警引擎**。前端若擅自设置阈值变红，属于“伪造医疗报警”，严重违反医疗软件合规边界。 | 通道颜色只作为“参数识别”，不因数值大小变红；仅在 Backend 明确下发 FAULT 或离线事件时显示技术状态。 |
| **虚假患者信息**（张三/李四、ICU-08 床） | 本项目无 HIS/LIS 医院信息系统对接，不可臆造假患者数据。 | 标明真实网关 ID（如 `GW-DEV-001` / `GW-C-001`）与节点 ID，诚实反映工程样机数据。 |
| **反推或衍生未采集指标**（如 MAP 平均动脉压、PI 灌注指数、PVR） | Backend 当前仅上报 `[SYS, DIA]` 数组，未上报 MAP；血氧模块未启用 PI 字节输出。 | 严禁前端通过 `(SYS + 2*DIA)/3` 伪造 MAP，未上传的数据一律不展示或标为 Not Available。 |
| **前端从呼吸波形反推 RR** | 呼吸率 RR 属于独立算法输出。在算法未完成定标前，不可前端自己找峰值算 RR。 | 严格以 Backend streams 中 RR 的 `validity` 为准。无效时必须显示 `--`，波形与读数解耦。 |
| **远程控制按键**（如云端点击“启动测血压”、“静音报警”） | 样机系统为单向监护流，且云端远程启动气泵加压存在患者被缠绕夹伤的巨大安全风险（ISO 60601-1-8 / 60601-2-30 安全隐患）。 | Web 端定位为纯只读大屏（Read-Only Central Monitor），不提供任何下行危险控制按钮。 |

## 5. 本项目布局与色彩决策汇总

### 5.1 布局形式：1920 × 1080 零滚动网格

为确保在标准医疗工作站（1080p 屏幕）上无需任何鼠标滚轮滚动即可纵览全局，界面采用 CSS Flex/Grid 弹性绝对约束：
- **顶部系统状态栏（高度 52px）**：网关选择与状态、时钟、通道在线指示灯、只读凭据设置、全屏切换；
- **核心监护栅格（高度 calc(100vh - 52px - 36px)）**：4 行平铺，左侧 70% 宽度的 Canvas 波形，右侧 30% 宽度的深色数值读数卡片；
- **底部工程与时间栏（高度 36px）**：显示最近采样时间、数据来源（LIVE / MOCK 醒目标签）、工程样机调试声明。

## 6. Web 端与床旁硬件监护仪的技术差异处理策略

| 挑战场景 | 硬件监护仪做法 | 本项目 Web 端优化策略 |
| :--- | :--- | :--- |
| **网络抖动与延迟** | 本地传感器直连采集卡，无网络抖动，硬件定时器精准中断。 | **时间戳平移锚点机制**：利用单调时钟与采集时间戳建立锚点偏移量，消除网络包抖动对波形平滑走纸的影响。 |
| **网络断流与丢包** | 导联脱落时硬件检测并置零/走平。 | **断线重起笔算法**：若 `timestamp gap > 100ms` 或 `session_id` 改变，Canvas 立即 `moveTo` 起新线段，**严禁跨断点连线伪造连续心电**。 |
| **屏幕多分辨率适配** | 硬件监护仪为固定硬件屏（如 12.1寸 1280×800 或 15.6寸 1920×1080）。 | **弹性断点与纯矢量/Canvas 缩放**：保证 1920×1080 零滚动铺满，1366×768 自动等比例缩放字体间距，手机端（<768px）自适应纵向折叠只读模式。 |
| **长时间运行内存泄漏** | 嵌入式 RTOS 静态内存分配。 | **有界环形缓冲队列（Bounded Ring Buffer）**：波形点严格限制最大 16 秒容量（超出自动丢弃），RR 趋势限制 120 秒，杜绝长周期运行 DOM 或内存膨胀。 |

## 7. 结论

本设计方案在不触碰后端数据逻辑的前提下，严格吸收了飞利浦、迈瑞、理邦等临床监护仪的人机工程精髓，确立了“波形主导、高对比暗黑基准、行级水平对应、真实语义呈现”的 Web 监护大屏视觉规范，为后续代码模块化拆分与本地验收提供了严密的理论与工程依据。

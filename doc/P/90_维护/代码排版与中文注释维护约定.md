本轮以第三轮复核的 `cfb30d0` 为行为基线，只整理自有代码，不改变冻结的 WebSocket Snapshot v1、MQTT Topic、OD/PDO 或运行参数。第三阶段 UI 重构另开分支，本轮维护提交保留在 PR #2。

## 排版约定

- C/H 使用 4 空格缩进，函数和控制块大括号独占一行，展开一行多语句，相邻函数留空行；配置位于 `gateway/.clang-format`。
- Python 使用 Black、100 列目标宽度，函数与类按标准留白；保留原字符串引号，配置位于根目录 `pyproject.toml`。
- TypeScript/CSS 使用 2 空格缩进和 100 列目标宽度；函数之间、CSS 顶层规则之间留空行，配置位于 `cloud/web/.prettierrc.json`。
- 源文件由格式工具输出 LF。长度限制是排版目标，不强拆协议字符串、正则或测试表达式；前端内嵌 HTML/SVG 字符串原样保留，以免此次整理改变页面内容。
- 不格式化 `gateway/third_party/**`，不重写原验收证据或构建产物。CANopenNode/Paho 的版本、许可证和已固定的源码应保持可追溯。

本次实际工具版本为 clang-format 23.1.1、Black 25.1.0、Prettier 3.5.3。它们只用于本机开发，不加入服务器运行依赖；格式工具升级应单独检查差异。

在仓库根目录可检查 Python；C 示例检查单个文件，批量检查时只选择自有 C/H：

```text
python -m black --check cloud gateway
clang-format --dry-run --Werror gateway/mqtt/src/gateway_transport.c
```

在 `cloud/web` 中检查前端：

```text
npx --yes prettier@3.5.3 --check src/main.ts src/style.css vite.config.ts
```

## 中文注释约定

注释优先说明为什么这样设计、输入输出约束、单位、失败处理和资源归属，而不是翻译每一条赋值。维护时重点关注：

- 采集时间与单调调度时间分离，重连不重写历史时间或会话。
- CAN 回调、UART 中断、Paho 网络线程和 asyncio 的职责边界。
- 有界队列、在途帧副本、实时优先配额，以及容量溢出会丢数据的事实。
- QoS0、PUBACK、Backend 接收和最终持久化之间的区别。
- 质量位、合成来源、RR 无效状态、REPLAY 与当前读数隔离。
- OD 固定容量、映射位宽、堆上限、超时回绕与退出清理。
- 原始 AT 回复、载荷及凭据不进入诊断日志。

注释不能把测试节点验证写成真实传感器验收，也不能把通信实例重启写成整机掉电测试。改变实现时同步核对注释；注释不是绕过合同授权的操作指令。

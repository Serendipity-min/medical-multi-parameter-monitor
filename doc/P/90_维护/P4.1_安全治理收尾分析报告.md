## 4. Paho 修复详细说明

### 4.1 Remaining Length

修改前：P4 已让 `MQTTPacket_decode()` 返回读取失败，但 `MQTTPacket_read()` 未检查返回值；客户端也先向目标缓存回填长度，再验证容量。

修改后：decode 失败立即退出。成功时先在固定四字节临时区编码，再按前缀非负、前缀不超过容量、正文非负、正文不超过剩余容量的顺序检查；只有通过才回填前缀并读取正文。这样避免在失败后继续处理部分长度，也避免 `size_t - int` 下溢或边界检查之前的写入。

当前客户端白名单内的 CONNACK、ACK、SUBACK、PUBLISH 解析器使用 `MQTTPacket_decodeBufSafe()`；UNSUBACK 委托有界 ACK，并保留底层失败。实际客户端调用传 `read_packet_len`。PUBLISH parser 仅用固定 host-only 输入验证，Gateway 调度直接拒绝下行 PUBLISH。

未覆盖：上游 server-side 兼容模块、非阻塞兼容 API 的完整审计、所有 MQTT 规范组合。旧 `MQTTPacket_decodeBuf()` 为兼容保留，当前 Gateway 源文件名单内没有调用；不把该结论推广为全库已安全化。

### 4.2 read_packet_len

- [x] `MQTTClientInit()` 显式初始化为 0。
- [x] `readPacket()` 每次进入先清零。
- [x] 只有完整报文成功接收后才设置实际字节数。
- [x] 首字节超时、长度解码失败、容量不足和正文截断不会复用旧长度。

## 5. Inbound PUBLISH

当前架构为 Gateway publish-only。P4 已有行为保持如下：

```text
unexpected PUBLISH → cycle() FAILURE → MQTTCloseSession → 无消息回调
```

固定测试使用真实 MQTTClient 实现和内存 Network stub，同时注册匹配回调和默认回调，确认返回 FAILURE、isconnected 清零、会话回调槽清除、handler 调用次数和发送次数均为 0。

关闭的是 MQTT 会话状态；传输连接的关闭 / 重连仍由既有 Gateway 外层管理。本轮未改变正常 MQTT 状态机或 AT/TLS 顺序，仅修边界、清零并锁定既有拒绝行为，因此按合同不重新烧录或联网验证。

## 6. Sensitive Memory

## 12. Python Finding 人工定性

### SEC-PY-01

结论：**False Positive**。`install.py` 的 `os.chmod(backup.parent, 0o700)` 只开放属主权限；目录还需要执行权限才能访问，不能改成文件常见的 `0o644`。配置文件原有 `0o600` 保持不变。本轮没有为了减少提示而修改权限。

结论：**Accepted Risk**，适用范围为受信本机运维。install / upgrade / browser_acceptance 的调用使用参数列表，未设置 shell=True；参数源于操作员 CLI、受控配置和脚本固定值，不存在已确认的远程请求到 shell 拼接链。工具仍通过 PATH / 本机可执行文件解析，操作者须控制配置和执行环境。本轮未把该环境信任假设宣称为已消除的风险。

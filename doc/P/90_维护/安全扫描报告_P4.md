## 3. 已知 Finding 的准确解释

| Finding | 根因与当前解释 | P4 / P4.1 处置 |
|---|---|---|
| SEC-C-01 | Paho 部分解码器没有把实际输入长度作为边界；已有本机 ASan 证据证明库级越界读。不能由此直接推断当前部署具有严重远程利用影响。 | P4 引入 Safe 解码、Topic / Packet ID 边界；P4.1 对既定反序列化器补固定回归。 |
| SEC-C-02 | 缓冲区容量不能代表本包真实长度；Gateway 既有架构不需要下行 PUBLISH。 | P4 记录实际包长并拒绝下行 PUBLISH；P4.1 补长度生命周期、错误传播及拒绝路径固定回归。 |
| SEC-C-03 | 格式化截断返回值曾被用作实际偏移；日志格式化包含密码输出。库级越界写成立，当前 Gateway 不调用该格式化功能。 | P4 采用有界追加、密码脱敏、显式源文件名单排除 MQTTFormat；P4.1 加构建完整性门禁。 |
| SEC-C-04 | 普通 memset 可能被优化；P4 的 secure_memzero 仍未覆盖部分提前返回。Will 为合成状态 JSON，不等同于密码。 | P4.1 在 CWJAP 使用后立即擦除，补 Will 失败及 Probe 已知临时缓冲的退出清理。 |
| SEC-PY-01 | `cloud/deploy/install.py` 设置备份目录权限为 `0o700`，只给属主访问权限，不是权限过宽。 | **False Positive**；保留现有权限，不机械改成 `0o644`。 |
| SEC-PY-02 | 部署 / 验收包装器采用参数数组、默认 `shell=False`，输入来自操作员命令行及本机配置，没有发现来自远程未受信请求的命令拼接链。工具解析仍依赖本机 PATH / 配置信任边界。 | **Accepted Risk**（受信运维环境）；不将规则提示直接认定为已确认远程命令注入，也未声称已更换全部解析器或工作目录。 |

`SEC-PY-02` 涉及 `cloud/deploy/install.py` 的 `command()`、`cloud/deploy/upgrade_mqtt.py` 的 `run()`、`cloud/tools/browser_acceptance.py` 的 `cli()`。部署入口只由受信操作员执行，发布名称 / 包散列 / 解包目标具有既有检查；浏览器工具通过本机 `shutil.which` 查找。若未来把这些脚本接入对外服务，必须重新评估输入与执行环境，不能沿用本次定性。

## 4. 验证结论的边界

本次覆盖的 Gateway MQTT 接收路径、固定反序列化器和当前固件构建路径，在现有 ASan/UBSan 回归中未检测到内存违规。具体 P4.1 运行命令、结果、CI 和尚未覆盖范围，以 [P4.1 最终分析报告](P4.1_安全治理收尾分析报告.md) 为准。

该结论仅限已执行的固定案例。存在 Error、Skipped、parser limitation 或 0 files scanned 的条目保留为 Coverage Gap；不以零命中替代完整覆盖证明。不存在“全库无漏洞”或“所有栈内存已清零”的结论。

## 5. 后续维护

- Paho 保留原上游版本、许可证、PATCHES 和项目补丁后的独立 SHA-256；修改须通过完整性与固定回归门禁。
- Gateway-C 保持 MQTT publish-only。将来若需要 OTA、Remote Command 或 MQTT Subscription，必须重新签订协议与安全合同，不能直接恢复旧 PUBLISH 分发逻辑。
- 原始扫描结果默认不入普通 Git；报告使用项目相对路径和脱敏统计，不包含凭据、真实连接信息或原始源码片段。
- 本轮未做公网测试、Fuzzing、真实三板 CAN、24h 稳定性或真实患者数据验证。

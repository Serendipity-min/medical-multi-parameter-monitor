## 4. 深度漏洞剖析与修复策略

### 4.1 SEC-C-01: Paho MQTT 反序列化缓冲区越界读 (OOB Read)
- **根因分析**：
  在原始 Paho Embedded C 中，`MQTTDeserialize_publish` 虽接收了 `int buflen` 参数，但在解析 Remaining Length 时调用 `MQTTPacket_decodeBuf(curdata, &mylen)`，该函数内部指针递增并未传入缓冲区长度上限。当收到截断报文（如首字节带持续位 0x80 但后续已无数据），指针将持续向前越界寻址。随后 `enddata = curdata + mylen` 盲目信任报文声明的长度，如果 `mylen > buflen - lenlen - 1`，后续 `readMQTTLenString` 与 `memcpy` 将从不可信的越界内存中读取数据。此外，底层 `MQTTPacket_decode` 在读取失败时误返回正数 `len`，导致调用者无法正确识别解析错误。
- **治理措施**：
  1. 在 `MQTTPacket.c` 中新增有界安全解析函数 `MQTTPacket_decodeBufSafe(const unsigned char *buf, int buflen, int *value)`，在每个字节读取前严格验证 `offset < buflen`。
  2. 修复 `MQTTPacket_decode`：任何网络读取失败或超长异常时统一返回 `MQTTPACKET_READ_ERROR` (`-1`)。
  3. 在 `MQTTDeserialize_publish` 与 `MQTTDeserialize_ack` 中加入完整长度门禁：
     - 校验 `buflen >= 2`
     - 校验 `1 + lenlen <= buflen`
     - 校验 `mylen <= buflen - 1 - lenlen`
     - 校验 `enddata <= buf + buflen`
     - 校验 Topic 长度与 QoS 报文标识符长度不超出报文实际有效字节。

### 4.2 SEC-C-02: 网关 MQTT 攻击面主动收敛与实际报文长度校验
- **架构事实**：本项目 Gateway-C 属于单向临床遥测上行发布者，只向云端 Mosquitto 发送 QoS1 遥测与心跳，不订阅任何业务主题。
- **治理措施**：
  1. **主动丢弃非预期 PUBLISH**：在 `MQTTClient.c` 的 `cycle()` 消息调度中，收到 `PUBLISH` 报文直接判定为协议违规（Protocol Error），立即返回错误并重置连接，彻底切断外部下行报文的攻击面。
  2. **传递真实有效报文长度**：在 `readPacket()` 中记录本次网络接收并校验通过的实际长度 `c->read_packet_len`，在调用 `MQTTDeserialize_ack()` 等解包逻辑时传递 `c->read_packet_len`，杜绝继续向反序列化器传递缓冲区总容量 `c->readbuf_size`。

### 4.3 SEC-C-03: MQTTFormat 越界写与固件编译面剔除
- **根因分析**：
  `MQTTFormat.c` 中的 `MQTTStringFormat_connect` 使用 `strindex += snprintf(...)`。C 语言标准规定 `snprintf` 在截断时返回拟写入的完整字符数，当剩余空间不足时 `strindex` 将大幅超过 `strbuflen`，随后 `strbuflen - strindex` 转换为无符号 `size_t` 发生回绕溢出变成超大正数，进而引发越界写入。此外，该函数在明文中输出 password 字符串。
- **治理措施**：
  1. **构建层面彻底排除**：修改 `gateway/mqtt/build.py`，明确枚举网关固件所需的 5 个核心源文件（`MQTTClient.c`, `MQTTConnectClient.c`, `MQTTSerializePublish.c`, `MQTTDeserializePublish.c`, `MQTTPacket.c`），不再使用通配符包含 `MQTTFormat.c`，实现攻击面彻底隔离。
  2. **源码层面补丁加固**：在 `MQTTFormat.c` 中引入安全追加函数，防止索引越界，并将密码输出脱敏为固定遮蔽字符。

### 4.4 SEC-C-04: 敏感缓冲区死存储消除 (memset-removal)
- **根因分析**：
  在 `gateway_transport.c` 和 `network_probe.c` 中，局部字符数组（存储 Wi-Fi 密码、MQTT 遗嘱及 AT 命令）在退出函数前调用 `memset(buf, 0, sizeof(buf))`。GCC/Clang 的死存储消除（Dead Store Elimination）优化器判定该内存在离开作用域后不再被读取，会直接删除该 `memset` 调用，使敏感数据残留在栈内存中。
- **治理措施**：
  实现高可靠的内存清零安全宏 `secure_memzero(void *ptr, size_t len)`，通过 `volatile unsigned char *` 访问并结合编译器内存屏障 `__asm__ __volatile__("" ::: "memory")`，确保编译器优化器绝不抹除安全清零操作。

### 4.5 SEC-PY-01 / 02: 部署与测试脚本权限及参数硬化
- **治理措施**：
  1. `cloud/deploy/install.py`：对 Mosquitto 证书及密码文件设置严格的文件掩码（私钥采用 `0o600`，目录采用 `0o700`），避免过于宽松的文件权限。
  2. 显式校验并在 `subprocess.run` 中指定明确的解析器与工作目录，规避潜在的环境变量污染。

## 4. 隔离构建与可审计性（D2）

### 4.1 两份源码都必须由冻结提交导出

生成两份独立的临时源码树：一份由 `P4@8dee339...`，一份由 `P5@e598fc6...`；可用经核对的 `git archive` / `git show` 安全导出或临时 detached worktree，**不得改变实际 P4/P5 生产 worktree 文件**。任何临时 worktree 必须有自己独立路径，不可复用或删除用户创建的 worktree。源文件落盘后按原 Git blob 或 SHA256 精确核验。

每份 overlay 只能在对应冻结源身份通过后应用，记录 `before_sha`、patch 文件 hash、`after_sha`、修改文件清单；不允许用模糊字符串替换跳过前置上下文。若 P4/P5 源结构不同，应使用两个独立小 patch，不得对差异过大的代码强行共享替换。第三方 Paho/coreMQTT 原始源、许可证、补丁历史与验证清单绝对不改。

### 4.2 测量探针要求

- **M01**：入口到所有返回的前台 `gateway_mqtt_open/publish/yield` 外层 span；成功/失败分别计数。P5 必须覆盖“发送成功后等待 PUBACK”的完整耗时，P4 必须覆盖原 Paho 对应语义；所有早返回保留原始结果和错误路径。
- **M02**：SysTick 计划点与主线程 service 完成点配对，记录有界事件索引/不可配对/丢样数量；仅称“静默环回合成源协作时延”，不得称物理三板 CAN 中断延迟。ISR 只做定长无阻塞写，不做 JSON、printf 或网络。
- **M03**：记录完整业务帧前台包容 cycles，若分段记录库函数/AT/ProcessLoop，明确父子时间和 IRQ 包含，不混算重叠 span、不把忙等待空转视作 CPU 占用率。
- **M04**：仅在**已证明安全的诊断启动最早期**允许方案性栈哨兵；必须检查 MSP、早期启动栈使用、FPU/异常栈、诊断版当前 `_heap_end` 与栈区域，且不能在运行中的活动栈或 J-Link 暂停点填充。如无法通过反汇编和内存映射证明安全，**不实现自动填哨兵**，将 M04 保持 `BLOCKED_UNSAFE_SENTINEL`，提交替代观察建议，不得为了凑齐 M01–M07 强行施工。
- **M05**：可在诊断副本 `_sbrk` 加**只记录**的峰值/ENOMEM 计数；原边界、errno、返回值不变。无可靠计数则保留 `NOT_MEASURED`。
- **M06**：同一固件时钟域区分 D 指令、原30s故障延时结束、2s连接清理、`gateway_network_open`入口、TLS、CONNACK、首条 `VALID/MOCK` **业务**帧。不得把旧 D→首帧36.234s减30s当作重连实测；不得跨 MCU/主机时钟直接相减。
- **M07**：有界记录 `cache/lost/replay/drop` 前后值和 `LIVE/REPLAY` 先后；32帧上限与历史 `lost=203` 不变，未观察排空就写 `NOT_DRAINED/NOT_OBSERVED`。

探针使用固定结构和单一诊断 profile，主线程/中断共享需按 ARM 内存与并发模型实现，不得靠未经验证的多字段原子假设；不得调用 malloc、阻塞 AT、动态输出或重入 MQTT/Router；原 CAN 调度预算8、MQTT3.1.1、QoS、TLS、`platform_poll`、Flash 配置区域、协议 Topic/Payload、客户端超时和 30s/2s 时序保持。日志和数据**只输出数字事件和脱敏 ID**，不可打印 SSID、MQTT 凭据、host、患者或原始载荷。

**额外 RAM 上限为每个诊断版本不超过 1536 B**，以相同工具链编译后的 RAM 段/符号证明；不得缩减原 24KiB heap、8KiB stack 或挤占末尾 sector7 来满足预算。若上限不足就停止并提出更简化的采样方案，不能自动批准超额。

### 4.3 严守诊断/生产身份

上游只编译 core_mqtt.c、core_mqtt_serializer.c、core_mqtt_state.c，文件对应官方
v2.3.1 / `2beef04725328923e05e576b884212d53ec97af7`。Paho 与 CANopenNode 历史源码、
清单及安全报告均未改。`verify_coremqtt_integrity.py` 检查原清单、固定路径、文件集合、
原字节 SHA256 / Git blob SHA1，以及 active MQTT 显式列表，拒绝 glob/追加扩大白名单。

MQTT wire version 仍为 3.1.1（CONNECT level=4）；Clean Session=true，keepalive=15s，
Client ID/用户名/密码仍从同一 312 字节 sector7 配置读取。Will/status retained、Will QoS1、
实时波形 QoS0、标量/状态/REPLAY QoS1，以及 mp_json/mp_topic 输出不变。
CWJAP 格式增加字段长度上限，合法已校验配置生成的 AT 字节相同；其他 CA/CCN/SNI/SSL:8883 语句原样。

QoS1 发布流程为获取 packet ID → MQTT_Publish → 有界 ProcessLoop → 正常解析回调与当前
packet ID 相等 → 返回成功。错误、超时、未完整报文、意外 PUBLISH 均失败，交回原 Router 回存/重连。
每次重连清 context、outgoing、RX 和 ESP 接收缓存；开机内包序号继续递增（16 位正常回绕），
结合新 TCP 会话避免旧会话 ACK 续活新帧。此处补足 P4 未比较 PUBACK packet ID 的实际缺口。

5000ms 为连接/发布逻辑总预算，空闲半包也有 5000ms 装配期限；有符号短预算与无符号 elapsed
兼容 SysTick 回绕。ESP 既有 AT 查询最长 1000ms、串口等待仍协作轮询 CAN；host 合成时钟预算
测试不能证明实际最大阻塞或 CAN 协作延迟。相关实测保留待硬件窗口完成。

`semgrep-code-serendipity-min` 的自动检查。统一 Security Gate、本地扫描、烧录、生产 Broker
故障操作与自动合并仍未授权。

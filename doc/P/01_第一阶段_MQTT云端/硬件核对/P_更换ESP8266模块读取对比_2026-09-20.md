# 更换 ESP8266 模块读取对比

日期：2026-09-20。工作分支：`dev/p-gateway-cloud-v07`。

用户更换模块后要求先读取并与上一模块比较。本轮复用已授权的临时 STM32 查询程序，
只发送七条固定 AT 查询；未烧录 ESP、设置 Wi-Fi、写入证书或修改服务器和合同。

## 实测结果

新模块的固件版本和指令响应与旧模块不同：

| 项目 | 旧模块 | 新模块 |
|---|---|---|
| AT version | 1.1.0.0（2016-05-11） | 2.3.0.0-dev（s-bcd64d2，2021-06-23） |
| SDK version | 1.5.4（baaeaebb） | v3.4-22-g967752e2 |
| compile time | May 20 2016 15:08:19 | Jun 30 2021 11:28:20（b498b58） |
| Bin version | 未返回该字段 | 2.2.0(ESP8266_1MB) |
| AT / AT+GMR | OK / OK | OK / OK |
| AT+UART_CUR? | ERROR | OK |
| AT+CIPSSLCCONF? | ERROR | OK |
| AT+CIPSSLCCN? | ERROR | OK |
| AT+CIPSSLCSNI? | ERROR | OK |
| AT+CIPRECVMODE? | ERROR | OK |

七项查询均完整结束，串口接收错误和缓冲溢出均为零。
`ESP8266_1MB` 是固件返回的构建标识，不能替代实际 Flash ID/容量测量。
未读取 ESP Flash，因此不能认定模块内固件与任何本地 BIN 文件逐字节一致。

SSL 查询返回五个连接的 auth_mode 均为 0。按匹配版本的
[乐鑫 TCP/IP AT 文档](https://docs.espressif.com/projects/esp-at/en/release-v2.2.0.0_esp8266/AT_Command_Set/TCP-IP_AT_Commands.html)，
0 表示不认证，2 表示加载 CA 验证服务端证书。查询成功证明该查询接口可用，
并不证明已启用证书验证，也不证明实际 TLS 握手、CA 导入或 MQTT 发布成功。

## 恢复与证据

- STM32 身份与上次一致；整片 1 MiB Flash 双读一致，并与上次原程序备份一致。
- 临时查询程序下载前、下载后均执行回读核验。
- 查询后恢复 STM32 原始首扇区，并核验完整 1 MiB Flash 与备份一致。
- 后续被动监听四秒，确认原 `DMA_ADC` 输出恢复。
- 原 Flash SHA-256：`852d7618f8fc46c80cbe035ebd41f4e21e4d5a76a26cf10a39e0600f7a89ffb8`。
- [本轮结构化证据](../../../../gateway/esp_at_probe/evidence/replacement-module-query-2026-09-20.json)
  与[旧模块证据](../../../../gateway/esp_at_probe/evidence/hardware-query.json)分别保留。
- 原始日志和备份保存在仓库外的本机私有目录，不提交设备标识或原始网络配置。

## 对合同执行的影响

现行 v0.2 执行合同已经规定 MQTT 3.1.1 over TLS，MQTT 客户端运行在 STM32，
ESP8266 提供 TLS Socket。本次结果消除了“新式 TLS 查询全部不支持”的现象，
目前不需要据此修改合同或升级 ESP 固件；下一步应验证证书配置和实际 TLS 连接。

如后续改为 ESP8266 内置 MQTT AT 客户端，需要明确修改主控与模块的职责；
此变化本身不能代替 TLS 验证。当前未作此架构变更，也未将硬件上云标为通过。

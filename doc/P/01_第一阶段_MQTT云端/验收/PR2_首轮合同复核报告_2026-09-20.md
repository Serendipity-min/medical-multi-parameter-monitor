# 5. 高优先级维护风险

## P1-1：部署脚本用 `assert` 做安全前置条件

`cloud/deploy/upgrade_mqtt.py` 的 root、release 名、SHA-256、目录存在性、ZIP 路径安全等使用 `assert`。

Python 在 `-O` / `PYTHONOPTIMIZE` 下会移除 assert。安全/完整性检查应改为显式：

```python
if bad_condition:
    raise RuntimeError("...")
```

## P1-2：Mosquitto 完全关闭日志

当前：

```text
connection_messages false
log_type none
log_dest none
```

不记录 Payload 是对的，但完全无 error/warning 会显著降低故障定位能力。

建议：

- 保留 `connection_messages false`；
- 不记录 Payload；
- 开启 error/warning/notice 到 journald/syslog；
- 维护手册规定脱敏与保留周期。

## P1-3：Backend MQTT 使用 `clean_session=True`

这意味着 Backend 离线期间 Broker 不为该订阅持续保存 QoS1 消息。第一阶段内存态/模拟数据可接受，但真实数据阶段必须明确：

- Backend 持久 Session；
- 或 Gateway 离线缓存 + REPLAY；
- 或二者结合。

不能把“QoS1”直接等同“Backend 停机期间一定不丢数据”。

## P1-4：浏览器当前使用单共享 View Token

MOCK 阶段可接受。出现真实人体可关联数据以前，应至少满足：

- 受控内网/VPN；
- 或独立用户认证/会话；
- 或可撤销的人员/终端凭据。

真实人体数据不建议长期使用单共享 Token 公网访问。

# 6. 中优先级风险

- ESP8266 `client_ca` 是独立信任存储；服务器证书链切换根 CA 时必须同步测试设备 CA；
- Gateway 当前是 HSI16MHz + UART 中断 Ring Buffer + 同步 AT 的阶段验证工程，不是最终可靠实现；
- 无独立 CI，仓库测试当前依赖人工执行；
- 尚未完成 24h；
- Gateway 当前没有正式 Flash 离线缓存；
- Backend 单 worker、内存状态，重启后依靠 retained + 新数据恢复。

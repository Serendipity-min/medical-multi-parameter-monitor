## 四、上位机总体设计

### 4.1 技术栈与进程模型

建议后端采用 Python `asyncio` + FastAPI + Uvicorn，前端采用 TypeScript + React + Canvas；SQLite 存元数据、参数结果与索引，连续原始波形保存在按会话分段的二进制文件中。FastAPI 官方支持 WebSocket，但设备 TCP 接入需要单独用 `asyncio.start_server` 等机制实现，不是 WebSocket 路由自动提供的功能。[S5]

首版采用**一个 Uvicorn worker**。在应用生命周期中启动/关闭 TCP 监听和后台服务；不能直接启用多个 worker，让每个进程重复绑定采集端口、各自维护不同设备状态。未来多进程扩展必须拆出独立接入进程与共享消息/状态设施。

```text
host/
  backend/app/
    main.py                  # 生命周期、配置、HTTP/WS
    transport/tcp_server.py  # TCP 会话与读写超时
    protocol/codec.py        # 帧级解析
    protocol/schemas.py      # JSON / 波形语义校验
    services/auth.py         # 注册设备、挑战应答
    services/device.py       # 节点、流、会话与状态
    services/timesync.py     # 单调时钟映射
    services/recording.py    # 原始分段、索引、磁盘状态
    services/alerts.py       # 工程提示与技术故障
    services/broadcast.py    # 独立 WS 客户端队列
    api/                    # REST / WebSocket 路由
  frontend/src/
    pages/ components/ waveform/ api/ state/
  simulator/                # 1–4 节点、掉线/坏帧/状态模拟
  tests/                    # 协议、API、集成、性能
  scripts/                  # 安装检查、启动、备份、诊断
  config.example.yaml
  pyproject.toml            # Python 依赖及版本约束
  uv.lock                   # 或已签认的等效锁定文件
  frontend/package-lock.json
```

此目录是拟实施结构，不表示仓库已有这些文件。W3 冻结 Python、Node、依赖及包管理器版本，提交 lockfile；禁止未经检查地写“任意最新版均可”。

### 4.2 数据处理流水线

```text
TCP 字节流
  → 有界缓冲 / 帧头同步 / 长度上限 / CRC
  → 设备握手认证 / 协议版本 / 消息 schema
  → 身份与会话绑定 / 序号和样本连续性
  → 原始记录队列 ───────────→ 分段文件与 SQLite 索引
  → 各参数时间与质量状态
  → 独立的显示变换（有元数据）
  → 各浏览器有界队列
  → WebSocket
  → 前端时间环形缓冲 / Canvas 绘制
```

持久化不能阻塞接入事件循环；SQLite 和文件写入由受控工作线程或专门写入服务处理，队列必须有容量及失败策略。每个浏览器独立排队，慢浏览器不能拖垮设备接收与其他浏览器。

## 五、状态、单位与时钟设计

### 5.1 设备状态与参数状态分离

设备状态：`CONNECTING → AUTHENTICATING → ONLINE → OFFLINE`，协议错误或认证失败可进入 `REJECTED`。节点在线不能覆盖其传感器故障。

每个参数的质量至少支持 `VALID / INVALID / WARMUP / SENSOR_OFF / LEAD_OFF / ERROR / UNKNOWN`；服务端另计算 `STALE`。供应商不提供某状态时不猜测，映射为 `UNKNOWN` 或有证据的通用无效状态。

连续参数默认超过 3 s 未有新的有效采集结果时标陈旧，具体周期随能力表冻结；离线默认是 5 s 没有通过校验和会话检查的通信。收到心跳或重复旧数值不能刷新参数的采集时间。无效值在数据层为 `null`，网页显示 `--` 和原因，不用 0 表示探头脱落。

血压是事件型结果：展示“最近一次结果 + 完成时间 + 当前状态”。测量中收到压力值，不得替换为最终 SYS/DIA；最近结果可以保留但必须标“历史结果”，不能包装成当前连续测量。

### 5.2 时间定义

每帧 `mono_us` 为设备本次启动后的单调微秒计数。波形帧表示**第一采样点的采集时间**，不能填写发送时刻；参数帧中每项 `sample_mono_us` 表示该结果自身的采集/生成时间。MCU 应采用可靠的 64 位扩展时间基准并测试溢出，不能直接把 32 位微秒计数当作永不回绕。

服务器分别记录接收单调时间和 UTC 时间；UTC 用于日志展示，不参与重连超时和采样间隔判断。设备重启用 `boot_id` 切分时间轴；不得让波形时间倒退后继续拼接成同一段。

### 5.3 近似时间映射与限制

握手后每 10 s 发起一次 `SYNC_REQ`，服务器记录发送时刻 `s0`；设备回复接收时刻 `d1`、回复入发送队列时刻 `d2`；服务器记录收回时刻 `s3`。使用微秒为单位估计：

```text
offset = ((s0 + s3) - (d1 + d2)) / 2
server_mono_est(device_time) = device_time + offset
network_delay_est = (s3 - s0) - (d2 - d1)
```

选择近期有效样本中往返开销较小者，并记录至少为残余往返时延一半加测时裕量的映射不确定度；负时延、重启、过旧同步等情况视为无效。串口排队、Wi-Fi 不对称延迟和时钟漂移会影响精度，所以**不承诺跨节点采样级同步，不据此做 ECG–PPG 脉搏传导时间等研究**。

浏览器到服务器另做同类 ping/pong 映射，不直接相减 `performance.now()` 和 Python 的时钟。端到端延迟仅在设备及浏览器映射总不确定度不超过 50 ms 时报告，否则展示“时钟未校准”并单独测接收/绘制处理开销。

## 六、网页大屏设计要求

### 6.1 页面与角色

| 页面 | 内容 | 权限 |
|---|---|---|
| `/dashboard` | 参数、波形、单位、会话、质量、在线状态、模式标签、全屏 | 只读展示 |
| `/devices` | 节点身份、固件、能力、速率、队列/缺口、重连记录 | 管理员 |
| `/records` | 会话列表、回放、导出、记录完整性 | 授权用户 |
| `/settings` | 设备绑定、实验网络、记录目录、工程提示配置 | 管理员 |
| `/diagnostics` | 服务健康、磁盘、协议统计、最近错误 | 管理员 |

模拟、回放、实物三种来源不可混淆。页面顶栏强制显示“工程样机 / 非临床用途”，并以醒目文字显示当前数据模式；不能通过普通设置隐藏该标识。

### 6.2 波形显示

接收频率和绘制频率分离，使用 10 s 有界时间缓冲与 `requestAnimationFrame`；优先 Canvas 连续绘制，不让 React 在每个样本到达时重建整页。采样率影响数据时间轴，刷新率只影响画面更新。

默认显示秒与已知物理单位。未核验量程时显示 ADC counts 或相对幅值；显示器未做物理尺寸标定时，不宣称严格的 25 mm/s 医疗走纸速度。数据量超过像素宽度时采用保峰值的最小/最大抽取等可解释显示方法，原始文件保持不变。

丢包/断线处留空并标记，不用重复点、0 填充或平滑直线伪造连续波形。拖慢页面时允许丢弃过期的显示消息以追上实时，但须产生客户端 `display_gap`；这一行为不能影响原始记录，也不能被统计成采集端真实丢样。

### 6.3 数值和告警

HR_ECG 与 PR_SPO2 分别显示来源，不能相互覆盖。温度标“物表/环境/模块补偿值”，NIBP 显示最后完成时间。技术故障优先保持可见；工程阈值提示需要迟滞、持续时间及确认日志。音频可能受浏览器播放授权限制，不能假定页面打开就一定会鸣响，也不能依赖网页提示承担安全保护。

## 七、API 与 WebSocket 契约

### 7.1 HTTP API

| 方法与路径 | 功能 | 约束 |
|---|---|---|
| `GET /api/v1/health` | 服务、记录、磁盘、接入状态 | 不泄露密钥和敏感路径 |
| `GET /api/v1/devices` | 节点及能力列表 | 管理权限 |
| `POST /api/v1/sessions` | 创建实验监测会话 | 使用实验编号，不收集患者身份 |
| `PUT /api/v1/sessions/{id}/bindings` | 显式绑定节点/流 | 拒绝同流被冲突绑定 |
| `GET /api/v1/sessions/{id}/snapshot` | 当前状态与可用值 | 必含质量与采集时间 |
| `POST /api/v1/devices/{id}/commands` | 受控命令入口 | 白名单、权限、幂等；不能接收任意 AT/串口字节 |
| `GET /api/v1/records` | 记录索引 | 只访问记录根目录 |
| `GET /api/v1/records/{id}/export` | CSV/原始文件导出 | 单位、质量、时间、版本完整 |
| `WS /ws/v1/sessions/{id}` | 订阅实时数据 | 同源校验、授权、背压、重连 |

浏览器不得自行提交“血压模块原始启动帧”。服务器接受业务命令，再由设备固件映射为已经核验的供应商指令。

### 7.2 WebSocket 消息

使用 JSON 消息封装 `schema`、`kind`、`monitor_session_id`、`device_id`、`boot_id`、`stream_id`、`source_mode`、`server_received_utc`、`data`。`uint64` 时间与样本编号在 JSON 中使用十进制字符串，以避免跨语言整数精度问题。波形先用批量数组，测试证明需要优化后再引入二进制 WS，而非首版并行维护两套实现。

```json
{
  "schema": "mmp-web/1",
  "kind": "wave",
  "monitor_session_id": "lab-session-001",
  "device_id": 101,
  "boot_id": 7,
  "stream_id": 1,
  "source_mode": "SIMULATED",
  "server_received_utc": "2026-09-18T00:00:00Z",
  "data": {
    "config_id": 1,
    "sample_rate_hz": 250,
    "first_sample_index": "0",
    "sample_mono_us": "1000000",
    "channel_codes": ["RESP_ADC", "ECG_ADC"],
    "unit": "adc_count",
    "samples": [[12, -25], [15, -10]],
    "quality": "VALID"
  }
}
```

示例为格式演示，样本数量缩短，不代表真实测量；`channel_codes` 必须来自经核验的当前配置，不得硬编码所有 ADS 模块必定为上述通道顺序。

客户端重新连接先取快照和当前配置，再开始接收新帧。不能将上次浏览器缓存的正常值在新会话中直接展示。服务器对单客户端的待发送时间窗上限建议 1 s；超限丢弃过期显示波形并发出缺口事件，必要时断开慢客户端。

## 八、记录、日志与恢复

### 8.1 存储组织

```text
records/
  <monitor_session_id>/
    manifest.json
    <device_id>/<boot_id>/
      chunk_000001.mmp
      chunk_000002.mmp
    index.sqlite
```

每个分段保存完整原始 MMP 帧，保留设备身份、采样配置、版本和 CRC。SQLite 保存会话、设备绑定、低频参数、事件、分段索引与完整性状态；不要把每个 ECG 采样点作为独立数据库事务。

建议 60 s 分段，使用临时文件完成后重命名；中途崩溃时识别末尾不完整帧并报告截断位置。刷盘策略、崩溃时最大可能未落盘区间须写入实现说明，不能声称普通异步写盘完全没有掉电丢失窗口。

根据默认数据预算，原始记录可能达到每天数百 MB；具体值取决于通道、JSON 参数量与日志量。暂按 **0.4–1 GB/24h 的设计预算**准备空间并实测修订，不把估算写成精确容量。自动删除默认关闭；只有经批准的保留策略才可删除本应用记录根目录内的过期文件，不触碰用户其他目录。

### 8.2 必须记录的诊断信息

协议/固件/软件版本、连接起止、认证失败类别、字节速率、有效/坏帧计数、全局序号跳变、每流样本缺口、队列高水位、重连、供应商错误状态、时间映射质量、磁盘警告、记录失败、控制命令状态、浏览器显示缺口。

日志不得输出 PSK、管理员密码或完整认证材料。必须区分“MCU 采样丢失”“节点缓存丢弃”“TCP 连接中断”“服务器记录失败”“浏览器追帧丢弃”，不能统称为网络丢包。

### 8.3 断网策略

设备本地采样与安全状态机继续运行。首版实时发送队列保留有限最近数据，满时丢弃最旧的完整波形批次并累计缺口；恢复后发送缺口事件和当前数据，不把几十秒前的波形当实时流灌入页面。

本期不承诺板端全量断网存储。即使仓库提到板载 Flash，也要重新计算容量、寿命、文件格式与补传协议；是否支持历史补传按二期或 G0 条件项处理。TCP 的可靠字节流不代表设备断网、掉电、采样溢出时不会丢数据。

## 九、安全、网络与权限基线

首版限实验室受控局域网，AP 支持 2.4 GHz，电脑建议有线接路由器；确认 AP 没有阻断终端互访。服务器地址用 DHCP 保留或经管理员确认的固定地址，设备主动建立 TCP 连接。

默认不开放公网端口、不配置路由器端口转发、不接入用户腾讯云服务器、不提供穿透服务。Windows 防火墙只放行程序/目标端口到指定私有实验子网。网页在本机回环访问，其他客户端访问必须单独授权。

设备采用附录 A 的 PSK 挑战应答和身份白名单；管理员口令哈希保存，控制接口另做权限与 CSRF/Origin 防护。前端登录令牌不得放进可泄露的 WebSocket URL 查询参数，优先采用同源安全会话机制。

**重要限制：PSK 握手、CRC、Wi-Fi 密码、白名单都不等于 TCP 应用数据已加密，也不等于抵御主动中间人或每帧篡改。**本期正常 TCP/HTTP/WS 路径仅适用于上述实验测试数据。在引入真实人体可识别健康数据、跨不可信网络或外网访问前，必须增加经过验证的端到端 TLS/证书校验、数据治理和安全评审；不能把“ESP 支持某种 SSL 命令”直接视为方案已安全落地。[S6–S7]

# 附录 A：MMP/1 通信协议 v0.1

**性质：本项目原创工程协议草案，不是医疗行业标准，也不是任何传感器供应商的串口协议。**G2 冻结后，C 固件、Python 服务与模拟器必须使用相同版本。本附录采用“二进制外帧 + 二进制波形 / UTF-8 JSON 控制与低频值”。

## A1. 分层与统一规则

传感器 SPI/UART/I2C 帧在 STM32 的驱动层解析；MMP/1 帧由 STM32 生成，通过 ESP-AT 的定长发送进入 TCP 字节流。ESP 不负责解释体征含义。服务器解析 MMP/1 后再转为网页 JSON，不把 ASCII `+IPD` 或 `SEND OK` 当成体征数据。

所有多字节二进制整数均为**小端**；文本为 UTF-8；外帧无换行、无结尾 `0D0A`、无字节转义。帧最大载荷 4096 B，总长最大 4140 B。CRC 只用于完整性检测，不是认证或加密。认证连接的 `session_id` 与业务监测的 `monitor_session_id` 是两个不同标识，不得混用。

## A2. 固定 40 字节帧头

| 偏移 | 长度 | 字段 | 类型/规则 |
|---:|---:|---|---|
| 0 | 4 | magic | 固定 ASCII `MMP1`，十六进制 `4D 4D 50 31` |
| 4 | 1 | version | `uint8`，当前为 1 |
| 5 | 1 | msg_type | `uint8`，见 A3 |
| 6 | 2 | flags | `uint16`；bit0=源数据为模拟；bit1=回放；其余必须为 0 |
| 8 | 2 | header_len | `uint16`，固定 40 |
| 10 | 2 | reserved0 | 固定 0 |
| 12 | 4 | payload_len | `uint32`，0–4096，具体消息另有最小长度 |
| 16 | 4 | seq | `uint32`，每方向、每 device/boot 独立递增，模 2^32 回绕 |
| 20 | 4 | device_id | `uint32`，项目配置的非零节点 ID，不是 IP |
| 24 | 4 | boot_id | `uint32`，本次启动标识；重连保持，重启更换 |
| 28 | 8 | mono_us | `uint64`，节点单调时间；服务器发出的帧头此字段填 0，时间字段放入相应载荷 |
| 36 | 2 | stream_id | `uint16`，0 表示节点控制/聚合；非 0 表示已登记流 |
| 38 | 2 | reserved1 | 固定 0 |

帧布局为：`40 B header + payload_len B payload + 4 B CRC`。CRC 覆盖头和载荷，不覆盖自身；尾部 CRC 也用小端。不得用编译器默认对齐的 C struct 直接 memcpy 上网，应显式读写字段；C `sizeof` 与 Python 头长度测试都必须等于 40。

`boot_id` 配套 HELLO 的 128 位 `boot_nonce`，由冻结的随机/唯一性方案产生；同启动重连不得改变。项目设备 ID 冲突必须拒绝注册，不依赖“随机碰撞几乎不会发生”掩盖配置错误。

## A3. 消息类型

| 值 | 名称 | 方向 | 载荷 |
|---|---|---|---|
| 0x01 | HELLO | 节点→服务器 | JSON，身份、boot_nonce、固件、模块与流能力 |
| 0x02 | CHALLENGE | 服务器→节点 | JSON，session_id、server_nonce、challenge_id |
| 0x03 | AUTH | 节点→服务器 | JSON，challenge_id、hmac_sha256 |
| 0x04 | WELCOME | 服务器→节点 | JSON，结果、session_id、配置与心跳要求 |
| 0x10 | WAVE | 节点→服务器 | A5 的二进制批量波形 |
| 0x11 | VITALS | 节点→服务器 | A6 的低频参数 JSON |
| 0x12 | EVENT | 节点→服务器 | 状态、错误、样本缺口、重启等 JSON |
| 0x20 | COMMAND | 服务器→节点 | 受控业务命令 JSON |
| 0x21 | COMMAND_RESULT | 节点→服务器 | 命令接收/完成/失败 JSON |
| 0x30 | HEARTBEAT | 双向 | JSON，状态与统计；不是生理参数刷新 |
| 0x31 | SYNC_REQ | 服务器→节点 | JSON，sync_id、s0_us 字符串 |
| 0x32 | SYNC_RESP | 节点→服务器 | JSON，sync_id、s0_us、d1_us、d2_us 字符串 |

不认识的消息类型记录为协议错误，不以另一类型尝试解释。连接阶段不合法的消息（例如认证前的 WAVE）直接拒绝。每个 TCP 连接只能对应一个已认证 device/boot；最多 4 个采集连接。

## A4. 握手、能力与认证

HELLO 示例（格式演示，不代表已验证的硬件能力）：

```json
{
  "protocol": "MMP/1",
  "device_uid": "provisioned-node-A-001",
  "boot_nonce": "00112233445566778899aabbccddeeff",
  "firmware": "prototype-0.1.0",
  "board": "STM32F407-revision-TBD",
  "modules": [{"module_id": "ecg", "model": "ADS1292R", "verified": false}],
  "streams": [{
    "stream_id": 1,
    "config_id": 1,
    "sample_rate_hz": 250,
    "format": "i24_le",
    "channel_codes": ["CH1_RAW", "CH2_RAW"],
    "unit": "adc_count",
    "gain": null,
    "vref_uv": null,
    "sensor_profile_hash": "TBD"
  }]
}
```

正式固件不能以 `TBD` 或 `verified:false` 冒充已通过硬件能力验收。`gain`/`vref_uv` 未核验时允许传原始 counts，但服务器不得显示为校准 mV。HELLO 中的配置在该连接期间不可悄然变化；改配置需先停流、重新登记新 `config_id` 并形成事件。

PSK 为每节点独立的 32 字节密钥，离线配置并排除出 Git。服务器生成 32 字节 `server_nonce` 和 16 字节 `session_id`，分别以 64/32 个十六进制字符传输；`challenge_id` 为唯一挑战编号，5 s 到期，一次使用。

认证字节串严格为：

```text
ASCII("MMP-AUTH-v1\0")
  || LE32(device_id)
  || LE32(boot_id)
  || HEX_DECODE(boot_nonce)     # 16 B
  || HEX_DECODE(server_nonce)   # 32 B
  || HEX_DECODE(session_id)     # 16 B
```

其中 `\0` 表示实际的一个 `0x00` 字节，不是反斜杠加数字。节点返回 `HMAC-SHA256(PSK, 上述字节串)` 的小写十六进制字符串。服务器以恒定时间比较，拒绝旧挑战、错误 device_uid/ID 绑定与重复活跃连接。认证通过后才能发送体征帧；重连必须重新挑战，不能复用旧 session_id。

这只是实验网络的设备准入，不保护认证后每帧免遭主动攻击，也不加密数据；不允许据此声称可处理公网或患者数据。进一步安全要求见第九章。

## A5. 二进制波形载荷

| 载荷偏移 | 长度 | 字段 | 规则 |
|---:|---:|---|---|
| 0 | 4 | sample_rate_hz | `uint32`；首版 ADS 默认 250，压力档 500 |
| 4 | 2 | sample_count | `uint16`；必须 >0，且满足长度上限 |
| 6 | 1 | channel_count | `uint8`；必须 >0，并与 HELLO 一致 |
| 7 | 1 | sample_format | 1=`signed int24 little-endian` |
| 8 | 4 | config_id | `uint32`；必须对应已登记配置 |
| 12 | 4 | reserved | 固定 0 |
| 16 | 8 | first_sample_index | `uint64`；该 boot/stream 内连续样本编号 |
| 24 | 可变 | samples | 按“采样点优先、该点各通道依次排列” |

长度必须精确满足：`payload_len = 24 + sample_count × channel_count × 3`。ADS 从 SPI 收到的字节顺序由驱动解释后再转成上述小端格式；不能把 SPI 帧整段未经处理当成本协议数据。

例如两通道、10 个采样点时，样本布局为 `t0ch0,t0ch1,t1ch0,t1ch1,...,t9ch0,t9ch1`。`mono_us` 是 `t0` 时间；第 i 点在不发生丢样时的时刻为 `t0 + i×1e6/sample_rate_hz`。

24 位有符号解码：先取 `u=b0|(b1<<8)|(b2<<16)`；若 `u&0x800000` 非零，则值为 `u-0x1000000`。范围 `[-8388608, 8388607]`。原始整数与换算单位分开，是否转换 mV 依赖已核验的量程与增益。

每流独立核对 `first_sample_index`。样本缺口、设备缓存丢弃、配置切换需 EVENT；一包中间存在缺口时拆为两包，不能在缺口处填 0 后仍报告连续。

## A6. 低频参数与事件

VITALS 示例为**模拟数据格式**：

```json
{
  "metrics": [
    {"code": "HR_ECG", "value": 72, "unit": "bpm", "quality": "VALID", "sample_mono_us": "1000000", "algorithm": "hr-demo-v1"},
    {"code": "SPO2", "value": null, "unit": "%", "quality": "WARMUP", "sample_mono_us": "1000000", "algorithm": "vendor"},
    {"code": "TEMP_OBJECT", "value": 32.5, "unit": "degC", "quality": "VALID", "sample_mono_us": "1000000", "algorithm": "vendor"}
  ]
}
```

合法代码首版为 `HR_ECG / PR_SPO2 / SPO2 / NIBP_SYS / NIBP_DIA / TEMP_OBJECT / TEMP_AMBIENT / TEMP_COMPENSATED`；条件项为 `RR / NIBP_MAP`。单位分别限定为 `bpm / % / mmHg / degC / rpm`，其中 `rpm` 在本项目仅定义为每分钟呼吸次数，网页写中文避免歧义。

不允许 `NaN`、`Infinity`、把整数百分比当 0–1 比例、把 kPa 当 mmHg。合法值域来自冻结的传感器能力表与数值类型，不在本协议中假定临床正常区间。`quality != VALID` 时 `value` 必须为 null；历史有效值由服务端另存，不与当前无效结果混成一项。

NIBP 的最终结果必须作为同一测量的原子集合，包含 `measurement_id`、`completed_mono_us`、SYS/DIA 及可用的 MAP/PR；不得将两次测量的 SYS 与 DIA 配成一组。模块“心律不齐”标志仅作为来源明确的 `vendor_flags` 保存，不在网页改写成确诊结论。

EVENT 基本字段：`event_id`、`event_code`、`module_id`、`stream_id`、`severity`、`details`。样本缺口还含 `first_missing_sample_index`、`missing_count`、`reason`。设备本地错误的原始码可保留，但网页显示经过文档化映射的人类可读原因。

## A7. 控制、幂等和血压安全

首版默认允许 `get_status`、`get_capabilities` 及经硬件核验的安全取消操作；`nibp.start` 默认关闭。不存在“任意执行串口字节”命令。

```json
{
  "command_id": "0123456789abcdef0123456789abcdef",
  "session_id": "00112233445566778899aabbccddeeff",
  "module_id": "nibp",
  "op": "get_status",
  "args": {},
  "deadline_server_mono_us": "5000000"
}
```

命令必须匹配当前认证会话和目标模块。可能启动执行器的命令需要有效时钟映射，建议有效期不超过 3 s；未同步或截止时间已过时拒绝开始。只读命令可以采用服务器超时处理；安全取消按经审查的本地策略处理，不因网页超时而屏蔽必要取消。

结果分为 `ACCEPTED / COMPLETED / REJECTED / FAILED / CANCELLED`。`ACCEPTED` 仅表明接收并获准，不表示测量完成；`SEND OK`、TCP 写入成功更不等于业务执行成功。

节点缓存最近至少 16 个 command_id 及执行状态，至少保留 120 s。同一 ID 重发只能返回已有状态，不再次启动测量；缓存满且无法保证幂等时拒绝新的执行器开始命令。设备重启后不得接受旧会话命令，服务器也不能自动重发开始命令。

UI 超时显示“结果未知/待查询”，不能自动生成新 command_id 再次启动。物理取消、超时、模块异常处理由 B 的本地状态机独立完成。

## A8. 心跳、重连与序号

HEARTBEAT 建议 1 s 一次；内容为节点运行状态、uptime、模块状态、队列高水位、丢弃样本计数等，不重复伪造体征采集时间。

设备重连退避建议 `1、2、4、8、16、30 s`，加 ±20% 抖动，认证成功后恢复初值；验收时从 AP 和服务器均已可用开始计时，目标 45 s 内恢复，实际网络必须冻结。设备主动连接，服务器不依赖设备固定 IP。

`seq` 对每个发送方向、每 device/boot 连续递增，即使重连也继续；到 0xFFFFFFFF 后按模 2^32 回绕。服务器分方向记录，不把下行与上行序号混为一列。序号跳变用于诊断；具体丢失样本由各流的样本编号决定，不能从混合消息 seq 差值推断 ECG 丢了多少点。

## A9. CRC 与流式解析

CRC 使用 **CRC-32/ISO-HDLC**：多项式 `0x04C11DB7`，反射实现多项式 `0xEDB88320`，初值 `0xFFFFFFFF`、输入/输出反射、最终异或 `0xFFFFFFFF`。不能直接假设 STM32 硬件 CRC 外设的默认输出符合本规范：输入顺序、反射、尾部不足 4 字节和最终异或均需先通过金样。与 Python `zlib.crc32(data) & 0xFFFFFFFF` 一致；字符串 `123456789` 的检查值为 `0xCBF43926`。[S8]

解析顺序：寻找 magic → 足够 40 B 后读头 → 验版本/保留位/类型/长度 → 等完整帧 → CRC → 身份/状态/schema → 业务处理。不能“一次 recv 就是一包”，也不能只靠 `MMP1` 分割二进制载荷。

无效头或 CRC 失败可丢弃一个字节后继续寻找 magic；保留末尾 3 字节以处理跨读取边界的帧头。应用层建议连续 8 次协议错误断开连接；单个不完整帧超过 5 s 也应中止，防止攻击者或故障设备占用缓冲。所有错误计数应可见。

## A10. ESP8266 AT 通信约束

ESP8266 使用正常发送模式而非默认透传，便于同时管理命令、接收、错误和重连。初始化序列为逻辑顺序，实际命令兼容性以 `AT+GMR` 和固件文档核验：[S6]

```text
AT
ATE0
AT+GMR
AT+CWMODE=1
AT+CWJAP="<实验SSID>","<实验密码>"
AT+CIPMUX=0
AT+CIPMODE=0
AT+CIPSTART="TCP","<电脑实验网卡IP>",9000

发送每个字节块：
AT+CIPSEND=<N>
等待 > 提示符
发送严格 N 字节（二进制，不能 strlen）
等待 SEND OK / ERROR / 超时
```

使用 `AT+CIPSEND`，不混用可能解释转义序列的扩展发送方式。正常发送参考文档规定的长度上限为 2048 B，本项目将单次发送块限制为 **≤1024 B**，便于队列管理；大于此值的 MMP 帧拆成多次 CIPSEND，由 TCP 接收端重新组成，不能截断应用帧。[S6]

`+IPD,<len>:<data>` 按声明长度解析，数据内可能含 `\r\n`、`OK`、`+IPD` 等任意字节；不能用文本子串查找方式解析二进制数据。固件若启用额外 IPD 字段/被动接收模式，必须固定并更新解析器测试，不能混用格式。

AT 状态机只有一个发送拥有者，UART 接收使用 DMA 环形区并及时消费。AT 回应、异步 `CLOSED/WIFI DISCONNECT` 与入站数据分层解析。发送超时不可让采样任务一直等待；网络堵塞使用有界队列和缺口事件。

## A11. 测试向量和实现要求

最小心跳帧：version=1、type=0x30、flags=1（模拟）、seq=3、device_id=1、boot_id=2、mono_us=1000000、stream_id=0、payload=`{}`。十六进制金样由附录 B 的实际运行生成，见其末尾结果。

至少增加以下 C/Python 共同测试：int24 的最小/最大/负一/零；250 SPS 双通道批量；JSON 中文 UTF-8；含 magic 字节的载荷；长度 4096；长度 4097 拒绝；CRC 错误；逐字节喂入；两包粘连；序号回绕；半帧断开；鉴权前发数据拒绝；旧 session 控制拒绝。

供应商串口帧金样与 MMP 金样分开管理：前者由模块负责人提供原始出处，后者由本协议生成。两者都应纳入仓库测试，但不能相互替代。

# 附录 B：可执行的帧级 Python 参考与编制时检查

下面代码只覆盖外帧打包、CRC、int24、流式解帧和金样；**不是完整服务器、认证模块、JSON schema 校验器或医疗软件**。保存为 `mmp_frame_reference.py`，用锁定的 Python 3 环境执行。正式实现还要补齐附录 A 的身份、长度语义、超时、消息状态、HMAC 和资源限制测试。


```python
"""MMP/1 frame reference. Standard-library only; not a complete server."""
from __future__ import annotations

from dataclasses import dataclass
import hashlib
import hmac
import random
import struct
import zlib

HEADER = struct.Struct("<4sBBHHHIIIIQHH")
U32 = struct.Struct("<I")
MAGIC = b"MMP1"
MAX_PAYLOAD = 4096
TYPES = {1, 2, 3, 4, 0x10, 0x11, 0x12, 0x20, 0x21, 0x30, 0x31, 0x32}
assert HEADER.size == 40


def uint(value: int, bits: int) -> int:
    if isinstance(value, bool) or not isinstance(value, int):
        raise TypeError("integer required")
    if not 0 <= value < (1 << bits):
        raise ValueError(f"out of uint{bits} range")
    return value


@dataclass(frozen=True)
class Frame:
    msg_type: int
    flags: int
    seq: int
    device_id: int
    boot_id: int
    mono_us: int
    stream_id: int
    payload: bytes


def encode(frame: Frame) -> bytes:
    if frame.msg_type not in TYPES or frame.flags & ~3:
        raise ValueError("unsupported type/flags")
    if not isinstance(frame.payload, bytes):
        raise TypeError("payload must be bytes")
    if len(frame.payload) > MAX_PAYLOAD or frame.device_id == 0:
        raise ValueError("payload too large or device_id is zero")
    head = HEADER.pack(
        MAGIC, 1, uint(frame.msg_type, 8), uint(frame.flags, 16), 40, 0,
        len(frame.payload), uint(frame.seq, 32), uint(frame.device_id, 32),
        uint(frame.boot_id, 32), uint(frame.mono_us, 64),
        uint(frame.stream_id, 16), 0,
    )
    body = head + frame.payload
    return body + U32.pack(zlib.crc32(body) & 0xFFFFFFFF)


class Parser:
    """Frame extraction only; caller enforces auth/schema/timeouts/error budget."""
    def __init__(self) -> None:
        self.buffer = bytearray()
        self.errors = 0

    def feed(self, data: bytes) -> list[Frame]:
        if not isinstance(data, bytes):
            raise TypeError("data must be bytes")
        if len(data) > 65536:
            raise ValueError("feed chunk exceeds 64 KiB; use bounded socket reads")
        self.buffer.extend(data)
        out: list[Frame] = []
        while True:
            pos = self.buffer.find(MAGIC)
            if pos < 0:
                if len(self.buffer) > 3:
                    del self.buffer[:-3]
                break
            if pos:
                del self.buffer[:pos]
            if len(self.buffer) < HEADER.size:
                break
            fields = HEADER.unpack_from(self.buffer)
            (magic, version, typ, flags, hlen, r0, plen, seq,
             device, boot, mono, stream, r1) = fields
            if (version != 1 or typ not in TYPES or flags & ~3 or hlen != 40
                    or r0 != 0 or r1 != 0 or plen > MAX_PAYLOAD or device == 0):
                self.errors += 1
                del self.buffer[0]
                continue
            total = HEADER.size + plen + U32.size
            if len(self.buffer) < total:
                break
            wanted = U32.unpack_from(self.buffer, total - U32.size)[0]
            actual = zlib.crc32(self.buffer[:total - U32.size]) & 0xFFFFFFFF
            if wanted != actual:
                self.errors += 1
                del self.buffer[0]
                continue
            payload = bytes(self.buffer[HEADER.size:total - U32.size])
            out.append(Frame(typ, flags, seq, device, boot, mono, stream, payload))
            del self.buffer[:total]
        return out


def encode_i24(value: int) -> bytes:
    if isinstance(value, bool) or not isinstance(value, int):
        raise TypeError("integer required")
    if not -(1 << 23) <= value < (1 << 23):
        raise ValueError("out of int24 range")
    return (value & 0xFFFFFF).to_bytes(3, "little")


def decode_i24(data: bytes) -> int:
    if len(data) != 3:
        raise ValueError("exactly three bytes required")
    value = int.from_bytes(data, "little")
    return value - (1 << 24) if value & (1 << 23) else value


def auth_digest(psk: bytes, device_id: int, boot_id: int,
                boot_nonce: bytes, server_nonce: bytes, session_id: bytes) -> str:
    if tuple(map(len, (psk, boot_nonce, server_nonce, session_id))) != (32, 16, 32, 16):
        raise ValueError("invalid key/nonce/session length")
    if device_id == 0:
        raise ValueError("device_id must not be zero")
    body = (b"MMP-AUTH-v1\x00"
            + struct.pack("<II", uint(device_id, 32), uint(boot_id, 32))
            + boot_nonce + server_nonce + session_id)
    return hmac.new(psk, body, hashlib.sha256).hexdigest()


def self_test() -> None:
    assert zlib.crc32(b"123456789") == 0xCBF43926
    for value in (-(1 << 23), -1, 0, 1, (1 << 23) - 1):
        assert decode_i24(encode_i24(value)) == value
    sample = Frame(0x30, 1, 3, 1, 2, 1_000_000, 0, b"{}")
    raw = encode(sample)
    p = Parser()
    result: list[Frame] = []
    for byte in raw:
        result.extend(p.feed(bytes([byte])))
    assert result == [sample]
    assert Parser().feed(raw + raw) == [sample, sample]
    assert Parser().feed(b"noise" + raw) == [sample]
    bad = bytearray(raw)
    bad[-1] ^= 1
    p = Parser()
    assert p.feed(bytes(bad) + raw) == [sample] and p.errors == 1
    large = Frame(0x12, 1, 4, 1, 2, 0, 0, b"X" * MAX_PAYLOAD)
    assert Parser().feed(encode(large)) == [large]
    try:
        encode(Frame(0x12, 1, 4, 1, 2, 0, 0, b"X" * (MAX_PAYLOAD + 1)))
    except ValueError:
        pass
    else:
        raise AssertionError("oversized payload accepted")
    forged = bytearray(raw)
    U32.pack_into(forged, 12, MAX_PAYLOAD + 1)
    p = Parser()
    assert p.feed(bytes(forged) + raw) == [sample] and p.errors >= 1
    embedded = Frame(0x12, 1, 5, 1, 2, 0, 0, b"MMP1\r\n+IPD\x00")
    assert Parser().feed(encode(embedded)) == [embedded]
    batch = [Frame(0x30, 1, i, 1, 2, i * 40000, 0, b"{}") for i in range(1000)]
    stream = b"".join(map(encode, batch))
    rng, p, out, at = random.Random(20260918), Parser(), [], 0
    while at < len(stream):
        n = rng.randint(1, 2048)
        out.extend(p.feed(stream[at:at + n]))
        at += n
    assert out == batch and p.errors == 0
    digest = auth_digest(bytes(range(32)), 1, 2,
                         bytes(range(16)), bytes(range(32, 64)), bytes(range(16, 32)))
    print("PASS: CRC, int24, byte-feed, coalescing, noise, bad CRC,")
    print("      max length, oversized encode/header, embedded magic, 1000 random-split frames")
    print("HEADER_BYTES=", HEADER.size)
    print("HEARTBEAT_FRAME_BYTES=", len(raw))
    print("HEARTBEAT_GOLDEN_HEX=", raw.hex(" "))
    print("HMAC_VECTOR_HEX=", digest)
    print("NOTE: no C firmware, real devices, full schema or server tests executed here.")


if __name__ == "__main__":
    self_test()
```

## 二、项目目标、范围与非目标

### 2.1 最终交付定义

交付一套可在受控局域网演示的工程样机：四个功能模块完成采集或模块结果读取，经 STM32 适配为统一协议，通过 ESP8266 发送给电脑 TCP 服务，服务器记录数据并通过 WebSocket 推送给网页；电脑以 HDMI/DP 连接显示器或电视形成大屏。大屏不是直接接 STM32 的显示外设。

首版必须形成“实物采集 → 数据封装 → 无线传输 → 服务端解析 → 可追溯记录 → 大屏展示 → 故障状态反馈”的闭环，而不是仅制作一张固定数值的界面。

### 2.2 范围分级

| 优先级 | 内容 | 验收口径 |
|---|---|---|
| P0 必交 | ECG 原始波形、ECG 来源 HR；SpO2/PR；NIBP SYS/DIA；红外测温；设备/传感器状态；局域网接入；大屏；记录回放 | 真实模块输出能与原始抓包、统一协议、界面记录逐项对应 |
| P0 必交 | ECG 导联异常、血氧无效/探头状态、血压失败/取消、测温无效等状态处理 | 以模块实际支持的状态为准；不支持项标“未知”，不能编造正常 |
| P0 必交 | 断线重连、心跳、过期标识、异常长度/校验处理、运行日志、版本标识 | 按第十章测试 |
| P1 条件交付 | 阻抗呼吸原始波形、呼吸率 RR、PPG 波形、MAP、本地串口屏、受控远程血压启动 | 必须在 G0 确认硬件能力、资料、仪器和工作量；未确认不能视为默认承诺 |
| P2 后续扩展 | RS485/CAN、MQTT、云端、手机 App、多床位、多机构、持续断网补传 | 另立变更单或二期合同 |

**四模块**指 ECG/呼吸、血氧/脉率、血压、温度四个功能域，不等于“四个测量值”，也不等于已经确认要购买四块 STM32。呼吸是 ECG 负责人名下的条件子任务，不另设第五位负责人。

### 2.3 明确不在本期承诺范围内

不承诺临床诊断精度、除颤防护、心律失常诊断、ST/QT 分析、自动治疗建议、婴幼儿/新生儿使用、人体试验、医疗注册、试产量产、公开互联网部署及连续断网时所有原始波形的无损补传。本期只设置工程演示告警，不宣称符合医疗告警标准。[R12]

## 五、功能设计

### 5.1 采集与参数语义

ECG 负责人保存未经显示滤波的 ADC 数据、通道配置、增益、参考电压来源、采样率和导联状态。HR 算法首先针对模拟器进行验证；算法未产生有效结果时输出无效状态，而不是固定数值。

呼吸必须区分 ADS1292R 阻抗呼吸通道与 ECG 衍生呼吸算法。不能仅凭“芯片支持呼吸”承诺模块已经具备完整测量电路；也不能把经 5–40 Hz 显示带通处理后的 ECG 直接当成保留了呼吸低频成分的信号。优先验证独立阻抗通道，ECG 衍生 RR 作为另行评审的算法任务。[R6]

血氧如果实物是 UART 成品模块，读取其结果和质量状态；如果是直接连接的 AFE4490，则需要 SPI 驱动、LED 时序、红/红外原始采集及供应商算法移植。AFE4490 芯片本身不等于已经提供了 HKS 系列 UART 帧或临床标定的 SpO2 算法，后者是影响工期的实质变更。[R4、R7]

NIBP 使用模块成熟的测量流程，不在首版自行重写示波法核心算法。MAP 仅在模块明确输出且协议被验证时显示；不能默认用 `(SYS + 2×DIA)/3` 替代实际测得的 MAP。

温度默认按经核验的实际模式读取，推荐低频 1 Hz 展示。裸 MLX90614 的 SMBus 数据和 GY 桥接板的“人体补偿温度”不是同一种协议，也不是同一种医学含义。[R8]

### 5.2 大屏与状态功能

首页设一个监测会话：左侧 ECG/可用 PPG/可用 RESP 波形，右侧 HR、SpO2、PR、SYS/DIA、TEMP 等数值；底部显示节点、探头、连接质量、最近更新时间和事件。每个数值必须能显示单位、来源和无效/过期原因。血压显示最近完成时间，不以 1 Hz 重复上报伪装成每秒测量。

设备页展示固件版本、协议版本、节点能力、重连次数、接收速率、样本缺口；记录页负责会话回放与导出。设置页仅管理员可进入；展示人员不应有启动气泵或改校准参数权限。

### 5.3 告警边界

工程告警分为技术故障与参数阈值提示。阈值、迟滞、持续时间、确认/静音行为要有配置与事件日志；不在本合同中设定临床治疗阈值。所有预设演示阈值标注“模拟演示”。无效数据不参与生理阈值判断，技术故障不能被“静音”变成正常。[R12]

## 六、系统方案设计与通信选型

### 6.1 建议冻结的首版拓扑

```text
节点 A：A 负责
  ADS1292R ── SPI + DRDY/控制 GPIO ──┐
  血氧模组 ── 已核验 UART 或 SPI ────┤ STM32F407-A
                                       └─ UART3 + ESP-AT ─ ESP8266-A ─┐
                                                                    │
节点 B：B 负责                                                        │
  HKB 血压模块 ── 已核验 UART ────────┐                              ├─ 2.4 GHz AP
  GY 测温模块 ── 已核验 I2C/UART ─────┤ STM32F407-B                  │       │
                                       └─ UART3 + ESP-AT ─ ESP8266-B ─┘       │ TCP
                                                                              ▼
                                                        P：电脑接入服务 + 记录/状态服务
                                                                              │ WebSocket
                                                                              ▼
                                                             浏览器网页 ── HDMI/DP ── 大屏
```

这是**推荐的两节点工程方案，不是已确认拥有两套板卡的事实**。G0 核实数量后冻结：两节点便于两位成员并行负责完整链路，也可将气泵电源干扰与 ECG 节点分开管理；但物理分开不等于实现医疗电气隔离。

若只有一块板，使用同一协议的多 `stream_id` 模式并重新审核引脚/资源；若四模块各有独立 F407+ESP，则配置四个 `device_id`，网页仍按同一个 `monitor_session_id` 聚合。二者均须更新 BOM、引脚表和实物验收范围，不能口头切换。

### 6.2 接口和协议的明确结论

| 链路 | 首版选型 | 理由及限制 |
|---|---|---|
| ADS1292R → F407 | SPI 主机 + DRDY EXTI + 控制 GPIO | 芯片原生数字接口；不是 UART、RS485 或 CAN |
| 血氧 → F407 | 成品桥接模块才选 UART；直接 AFE4490 选 SPI | G0 以实物和源码确定；不能用模块名相似代替核验 |
| 血压 → F407 | 硬件 UART，8N1；波特率随实物协议冻结 | README 的 115200 仅作线索，不自动覆盖其他版本 |
| GY 测温 → F407 | 优先核验仓库拟用 I2C 100 kHz；UART 为经证实后的替代方案 | 100 kHz 是本项目候选设置；地址、帧、上拉和电平先核验 |
| F407 → ESP8266 | 3.3 V 逻辑 UART，初始 115200、8N1，DMA + AT 状态机 | 默认正常发送模式 `CIPMODE=0`；不把调试串口混进协议串口 |
| ESP8266 → 电脑 | TCP 长连接，设备主动连接服务器；MMP/1 应用帧 | TCP 是字节流，服务器必须处理半包、粘包和断连 |
| 服务端 → 网页 | 同源 HTTP + WebSocket | 网页通过 WebSocket 接实时流；不直接连接原始 TCP 端口 |
| 本地串口屏（条件项） | 按实物选 TTL 或 RS232 + 对应收发器 | UART 是控制器方式，TTL/RS232 是电气层；两者不可裸连混用 |
| RS485 | **本期不采用** | 只有需要长距离有线多点接入时再增收发器、终端/偏置和主从协议 |
| CAN | **本期不采用** | 如未来采用，需 CAN 收发器、终端、ID、总线负载及分片设计；不能把 UART 线接上就当 CAN |
| Modbus RTU / CANopen / MQTT / HL7 / FHIR | **本期不采用** | 当前目标无需同时引入多套应用协议；存在扩展需求时另行论证 |

不能以“更专业”为理由同时增加 RS485、CAN、MQTT。当前最小闭环已经需要传感器协议、ESP-AT、TCP 应用帧和 WebSocket 四层边界，优先把这四层做正确。[R6–R9]

### 6.3 节点身份和会话绑定

`device_id` 标识采集节点，`stream_id` 标识该节点上的数据流，`boot_id` 区分设备重启，`monitor_session_id` 标识一次演示/记录会话。IP 地址、MAC 地址或连入顺序不能代替会话绑定。不同节点的数据只有在管理员明确绑定后才在同一屏聚合；设备更换、重启、同 ID 重复连接均应触发可见事件。

### 6.4 吞吐预算

以下是设计计算，不是实测结果。UART 115200、8N1 每字节占 10 bit，理论单方向上限为 `115200/10=11520 B/s`。

按附录 A 的 40 B 头、24 B 波形元数据、4 B CRC：ADS 两通道、250 SPS、每包 10 个采样时，单包 `40+24+10×2×3+4=128 B`，每秒 25 包，即 **3200 B/s**。如核验存在 50 SPS 的单通道 PPG，每包 5 点，其开销为 **830 B/s**。再为低频值、心跳和 AT 交互留预算，首版目标持续串口负载不超过约 70%，并以逻辑分析仪/实际计数验证。

500 SPS、每包 20 点时 ADS 流为 **4700 B/s**；它是服务器压力测试档与条件扩展，不自动等于硬件首版承诺。若提高采样率或增加通道导致负载超限，先调整批量与固件队列，再申请验证 230400/460800 等波特率。不能根据 Wi-Fi 的名义速率忽略 UART 瓶颈。

### 7.2 电源、气路和电气安全

全部人体接触功能先用生理信号模拟器、测试负载或供应商规定的台架方法验证。未获得适格人员的电气与风险审查，不进行人体连接；也不因“电池供电”“无线传输”“两个 LDO”就宣称具备患者隔离。普通 LDO 分供电不等于电气隔离。

B 负责提供供电预算、泵启动瞬态、ESP 发射期间压降、稳压温升、复位记录、气路连接及模块故障处理说明。禁止把开发板 3.3 V 引脚默认当成气泵或 ESP 电源容量已足够的证据；禁止将不明 5 V/RS232 信号直接接入 MCU。

血压本地控制必须能在网络失联时独立处理取消、超时、模块错误。停泵/泄压策略、最大工作时间和相关保护值须由已核验模块说明及安全审核确定，不能从 README 复制不完整命令后直接驱动人体袖带。本合同不提供未经审核的人体测试步骤。[R12]

### 7.3 固件基础架构

建议统一使用 STM32Cube HAL/CMSIS、C 语言和 FreeRTOS；具体工具链版本、调试器及 RTOS 配置在 G2 冻结。已有 F103/F429 或 Arduino 示例仅作移植参考，不能认为直接替换芯片名即可用于 F407。某一外设不得同时由 HAL、标准库和直接寄存器的不同代码路径竞争控制。

```text
BSP/板级资源
  ├─ sensor_ecg / sensor_spo2 / sensor_nibp / sensor_temp
  ├─ 时间基准、DMA、环形队列、看门狗
  ├─ protocol_mmp（B 实现，P 提供规范与金样，A 复核）
  ├─ esp_at_transport（B 实现，两节点共用）
  └─ 应用状态机、状态/质量映射、可选本地屏
```

建议优先级：采集与本地安全事件高于网络封包，网络高于本地屏与日志。SPI/USART 中断只做必要读写、DMA 管理和事件通知，禁止在采样中断里等待 `SEND OK`、写磁盘或执行长时间滤波。NIBP 停机/错误状态机不得受 UI 或联网任务阻塞。

STM32F407 的内存规划要区分系统 SRAM 与 CCM；DMA 缓冲区不得默认放进 CCM。必须交付 linker map、缓冲区分配表和栈高水位报告。建议共享网络发送队列上限 16 KiB，ESP UART DMA RX 环形区 4 KiB，协议解析区 8 KiB；这是待实际 map 文件验证的预算，不是要求不加分析地全部分配。[R5]

### 7.4 DSP、单位和校准

原始流和显示滤波流分开。任何带通、陷波、缩放、采样率改变都记录配置版本；上位机不得在不知道增益/参考电压时将 ADC counts 标成 mV。生理参数算法输出包括有效性、窗口、算法版本和来源。模块补偿温度、脉搏波相对幅值不能自动标成具有已校准物理意义的测量量。

### 7.5 上位机架构

上位机采用 Python 异步接入与 FastAPI/WebSocket、SQLite 元数据及二进制原始记录；前端建议 TypeScript + React + Canvas。版本在 G2 锁定，使用 lockfile，不依赖在线 CDN，不将本次文档中的框架名称解读为某一具体最新版本已完成兼容性验证。具体目录、接口、协议与验收见专项合同。[R13]

## 十、验收标准与证据

### 10.1 分层验收原则

验收分为：软件正确性、模块台架一致性、系统稳定性与显示效果。**临床测量准确性不在这些测试通过后自动成立**。没有校准仪器、参考方法和审批条件，不签发“医疗精度达标”结论。

| 测试 ID | 用例 | 通过条件 |
|---|---|---|
| T01 | 全新环境构建 | 根据锁定工具链和说明，非作者可编译固件、启动服务及网页；无写死个人路径 |
| T02 | 协议金样 | Python 与 C 对同一向量的帧长度、字节序、字段、CRC 完全相同 |
| T03 | TCP 分包/粘包 | 不少于 1000 帧混合类型，随机切分、连续拼接，恢复结果逐帧一致 |
| T04 | 异常输入 | 错 CRC、超长、坏版本、非法状态、半帧断连被识别；不导致失控分配或进程退出 |
| T05 | 模块一致性 | 各模块有效输出及异常状态能与供应商抓包/台架输入对应；无占位假数值 |
| T06 | ECG 连续性 | 冻结的 250 SPS 配置下，DRDY、样本计数与时间基准可核验；实际两个 ADC 通道均按配置解释 |
| T07 | 多节点聚合 | 建议 2 个真实节点完成全链路；另外用 4 个模拟节点验证服务端连接能力；会话不混绑 |
| T08 | 故障时效 | 连续参数超过有效期标陈旧；节点在最后有效通信后 5 s 标离线，UI 最迟再 1 s 更新；无效不得显示为 0 |
| T09 | 重连 | AP/服务器恢复可用后，在冻结测试网络下 45 s 内自动恢复；重复 10 次；不重复执行旧控制命令 |
| T10 | 大屏 | 1920×1080、2 个浏览器客户端连续演示；数值/状态清晰，波形有时间轴和缺口，不因窗口缩放失真 |
| T11 | 延迟 | 正常网络下服务端接收至前端入绘制队列 P95≤200 ms；采集至网页估计 P95≤500 ms 仅在时间映射不确定度≤50 ms 时评价 |
| T12 | 稳定性 | 2 个实物节点按默认配置运行 24h：无未解释重启、死锁和样本缺口；刻意注入的断线/丢弃必须形成事件，不冒充无损 |
| T13 | 记录回放 | 抽取不少于 3 段各 60 s 数据，回放样本计数、原始数值、单位与事件和记录一致 |
| T14 | 血压控制 | 台架验证本地取消、重复命令、网络中断、超时、模块失败；一次 command_id 不得触发第二次测量 |
| T15 | 安全基线 | 未注册设备不能绑定，非管理员不能控制，无公网映射；密钥不进仓库；模式标签不能关闭 |
| T16 | 存储故障 | 磁盘低空间/写入失败不被静默忽略；界面和日志明确“记录失败”，实时显示可按约定继续 |

延迟是测量值而非浏览器“感觉流畅”。浏览器自身时钟与服务器时钟不可直接相减；需按专项合同做时间映射或使用外部同步测量。P95 的样本数、采样窗口、计算脚本、主机配置与网络环境必须写入报告。

24h 试验优先使用生理模拟器或不连接人体的已批准台架方案。不能为了满足连续时间要求让人体持续连接未经审查的样机。NIBP 不在 24h 内无间隔自动充气；按经审核的台架用例执行有限次数，并记录其间歇状态。

### 10.2 缺陷与验收决定

阻塞缺陷包括：电气/气路风险未关闭、参数来源混淆、无效值显示正常、错误单位、会话混绑、重复启动血压、数据静默丢失、固件或上位机不可复现构建。阻塞缺陷为零方可最终验收。

一般缺陷可在已知问题表中注明影响、临时措施、责任人与修复日期，由验收方书面接受。评审结论只有“通过”“有条件通过”“退回整改”；不设“超时未回复视为通过”。

| 血压版本/停机协议不一致 | 高 | 未核验前禁用远程开始，禁止人体试验；保持台架验证 |

| 气泵/无线瞬态干扰、供电不足 | 高 | 示波器测量、独立电源支路、复位/噪声对照；必要时改布局 |
| 协议未冻结，三方各写一套 | 高 | G2 规范、金样、C/Python 测试同时冻结 |
| 假数值/旧数值被当作实时 | 高 | null + quality + 时间戳，真实/模拟/回放强制标识 |
| ESP8266 生命周期 | 中 | 已有模块可用于本次样机；记录官方 NRND 状态，量产/新设计再评估替代，不临时强制换板 |
| 任务超出三人投入能力 | 中 | 每周燃尽与关键路径审查，优先 P0，P1 未签署不默认加班吞并 |

Espressif 的公开资料已标注 ESP8266EX 为 NRND（不推荐用于新设计）。这不等于现有模块立即不可用，但属于后续产品化选型风险。[R9]

### 12.2 变更控制

变更单至少包含：编号、原因、受影响需求、硬件/固件/上位机影响、旧新字段对照、测试影响、预算工期变化、回退方式、三方意见。修改采样率、单位、帧头、模块型号、UART 波特率、引脚、节点数量或远程控制权限均属受控变更。

安全纠正可先停止相关测试，再补齐变更手续；不能以“合同已写死”为理由继续执行已知风险方案。P 不得只改网页掩盖硬件数据异常。

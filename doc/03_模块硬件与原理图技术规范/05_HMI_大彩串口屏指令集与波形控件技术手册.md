## 1. 方案定位与合同阻塞项 E06 澄清

在总合同中，明确了“局域网 Web 网页大屏作为首版必交交付物”，而对于本地串口屏，本手册将其明确定义为：
* **定位**：**本地床旁脱机监护交互终端**，与局域网 Web 大屏并行运作，两者数据源完全统一（均由 STM32 统一计算后推送）；
* **架构优势**：大彩串口屏内置高性能图像渲染 GPU 与大容量 SPI 显存，单片机主控无需维护高开销的 LCD 点阵显存，仅需通过串口发送十几个字节的组态指令，即可在屏幕上实现医疗级平滑波形走纸和数值毫秒级刷新。

## 2. 电气接口与接线规范

大彩 M 系列屏支持 TTL 与 RS232 两种电气电平（出厂硬件配置决定）：

### 2.1 硬件连接表（与 STM32F407ZGT6 开发板）

| 串口屏引脚 | 信号说明 | 开发板引脚 | STM32 内部复用 | 硬件说明与跳线配置 |
| :---: | :--- | :---: | :--- | :--- |
| **VCC** | 屏幕供电 | `+5V` | 系统 5V 稳压电源 | 5 寸屏幕背光功耗较大（约 300～450 mA），接低纹波 5V 供电。 |
| **GND** | 电源地 | `GND` | 电源地 | 严格共地。 |
| **DIN (RX)** | 串口数据输入 | `PA2` | USART2_TX | 接收单片机发送的波形与数值指令。 |
| **DOUT (TX)**| 串口数据输出 | `PA3` | USART2_RX | 向单片机上报用户触摸按钮、参数设置事件。 |

> [!IMPORTANT]
> **开发板 P3 跳线配置要求**：
> * 若串口屏为 **RS232 电平**（DB9 接口或 SP3232 驱动）：开发板 **P3 跳线短接 1-3、2-4**，使 PA2/PA3 接入板载 SP3232 电平转换芯片；
> * 若串口屏为 **TTL 3.3V/5V 电平**：从 P9 扩展排针直接引出 `PA2`（Pin 36）和 `PA3`（Pin 34）直连屏幕。

## 3. 通信协议与通用帧格式规范

* **波特率**：默认 115200 bps（支持通过上位机 VisualTFT 配置修改为 9600～921600 bps）；
* **数据位**：8 位；**停止位**：1 位；**校验位**：无校验（8N1）；
* **通用帧结构**：
  * **固定帧头**：`0xEE`（1 字节）；
  * **指令与参数**：变长（大端对齐：高字节在前，低字节在后）；
  * **固定帧尾**：`0xFF 0xFC 0xFF 0xFF`（4 字节）。

## 4. 监护仪核心功能指令集详析

### 4.1 切换界面指令（画面跳转）
用于在“开机欢迎页”、“主监护大屏”、“系统设置页”、“历史记录页”之间切换：

* **指令格式**：`EE B1 00 Screen_ID(2B) FF FC FF FF`
* **工程示例**：跳转至监护主界面（Screen ID = 1）：
  `EE B1 00 00 01 FF FC FF FF`

---

### 4.2 数值/文本控件刷新指令（体征看板更新）
单片机提取心率、血氧、血压、体温后，直接发送 ASCII 字符串更新指定文本框：

* **指令格式**：
  `EE B1 10 Screen_ID(2B) Control_ID(2B) [ASCII 字符串] FF FC FF FF`
* **工程示例**：
  * 更新心率文本框（Screen 1, Control 5）显示 **`75`**：
    `EE B1 10 00 01 00 05 37 35 FF FC FF FF`
  * 更新血氧文本框（Screen 1, Control 6）显示 **`98`**：
    `EE B1 10 00 01 00 06 39 38 FF FC FF FF`
  * 更新血压文本框（Screen 1, Control 7）显示 **`120/80`**：
    `EE B1 10 00 01 00 07 31 32 30 2F 38 30 FF FC FF FF`
  * 更新体温文本框（Screen 1, Control 8）显示 **`36.8`**：
    `EE B1 10 00 01 00 08 33 36 2E 38 FF FC FF FF`

---

### 4.3 动态平移走纸曲线指令 `0xB1 0x35`（核心中的核心）
在常规动态波形绘制中，若采用全屏重新画线，单片机会产生极高的计算开销。大彩串口屏内置了硬件级**波形末尾追加并自动向左平移（走纸模式）**的专用指令：

* **指令格式**：
  `EE B1 35 Screen_ID(2B) Control_ID(2B) Channel(1B) Data_Len(2B) [Data...] FF FC FF FF`
  * `Screen_ID`（2 字节）：当前曲线控件所在画面编号；
  * `Control_ID`（2 字节）：曲线控件的控件 ID；
  * `Channel`（1 字节）：数据通道编号（支持 0 ～ 7 共 8 个独立通道，如通道 0 为心电波，通道 1 为脉搏波）；
  * `Data_Len`（2 字节）：本次压入的采样点数据长度（点数 × 每点字节数）；
  * `Data`：Y 轴采样点序列。
* **平滑走纸运作机理**：
  * 新压入的采样点自动在曲线控件最右侧插入；
  * 原有历史曲线平滑向左侧平移；
  * 当曲线数据达到控件右边缘缓冲区上限时，最左侧的旧波形自动移出屏幕，实现医疗监护仪完全一致的走纸扫描效果！
* **工程批处理推荐**：
  * 单片机无需每采集一个点（4ms）就发送一次串口；
  * 建议在单片机内开辟 40ms（10 个采样点）的批处理缓冲区，每 40ms 打包发送一次（每次追加 10 个 Y 轴点），既保证屏幕视觉 25 fps 以上的极佳流畅度，又将串口总线占用率压至 20% 以下。

---

### 4.4 清空指定通道曲线指令
在重新测量或切换患者导联时清空已有波形：

* **指令格式**：`EE B1 33 Screen_ID(2B) Control_ID(2B) Channel(1B) FF FC FF FF`
* **工程示例**：清空主界面（Screen 1）曲线控件（Control 2）的通道 0（心电通道）：
  `EE B1 33 00 01 00 02 00 FF FC FF FF`

---

### 4.5 触摸按键事件上报（屏幕主动发送至 STM32）
当受试者或护士点击屏幕上的“开始测血压”、“静音报警”、“保存数据”按钮时，串口屏主动向 STM32 回传事件帧：

* **屏幕上报格式**：
  `EE B1 11 Screen_ID(2B) Control_ID(2B) Type(1B) Status(1B) FF FC FF FF`
  * `Type`：控件类型（`0x10` 为按钮控件）；
  * `Status`：状态变化（`0x01` 为按下，`0x00` 为弹起）。
* **单片机处理逻辑**：
  ```c
  // STM32 串口中断解析大彩屏触摸事件
  if (rx_buf[0] == 0xEE && rx_buf[1] == 0xB1 && rx_buf[2] == 0x11) {
      uint16_t screen_id  = (rx_buf[3] << 8) | rx_buf[4];
      uint16_t control_id = (rx_buf[5] << 8) | rx_buf[6];
      uint8_t  status     = rx_buf[8];

      if (screen_id == 1 && control_id == 10 && status == 1) {
          // 用户按下了主界面的“开始测血压”按钮
          NIBP_Start_Measurement();
      } else if (screen_id == 1 && control_id == 11 && status == 1) {
          // 用户按下了“消警/静音”按钮
          Alarm_Mute();
      }
  }
  ```

## 5. 5寸专业监护仪 UI 布局与工程设计指南

* **颜色规范**：
  * **心电波形与 HR**：统一采用**鲜绿色（Green）**；
  * **血氧波形与 SpO2**：统一采用**天蓝色（Cyan / Light Blue）**；
  * **呼吸波形与 RESP**：统一采用**亮黄色（Yellow）**；
  * **无创血压与体温**：统一采用**纯白色（White）**；
  * **越限告警**：红色加粗高亮闪烁，并在顶栏弹出醒目警示弹窗。

## 专题一：HKS-12C 血氧模块校验和冲突深度辨析与工程冻结

### 1.1 矛盾事实与溯源排查

在历史方案草案与部分调试笔记中，HKS-12C 的启动测量指令被记录为：
```text
0xFF 0xC7 0x03 0xCD 0xA0
```
其中第 4 字节的校验和（CKSUM）标注为 `0xCD`。

然而，根据原厂《医用传感器组合模块技术规格书 R1.17》第七章（第 19 页）定义的统一通信协议规范：
* **帧结构定义**：
  * `Byte 1`：帧头 `0xFF`
  * `Byte 2`：设备类别码（血氧为 `0xC7`）
  * `Byte 3`：长度字段（包含长度、校验和、命令及后续参数的总字节数，此处为 `0x03`）
  * `Byte 4`：校验和 `CKSUM`
  * `Byte 5`：控制命令（启动测量为 `0xA0`）
* **原厂统一校验和计算公式**：
  > “校验和（CKSUM）为长度、命令、参数求和后取低字节。”

按此规范计算启动指令：
```c
Length  = 0x03;
Command = 0xA0;
CKSUM   = (Length + Command) & 0xFF 
        = (0x03 + 0xA0) & 0xFF 
        = 0xA3;
```
公式严谨计算结果应为 **`0xA3`**，与示例中的 **`0xCD`** 严重矛盾。

**根因溯源**：  
查阅规格书第 19 页设备类别列表发现，代码 **`0xCD` 恰好是“血压：HKB-08B”的设备识别码**（`0xCD 血压：HKB-08B`）。历史文档编写人员在整理示例时，误将另一行设备码混淆复制至校验和字段，随后被草率解释为所谓的“厂商出厂默认兼容码”。

### 1.2 本版处理决策与驱动落地规范

1. **坚决摒弃臆测**：
   在嵌入式驱动中**严禁硬编码未经协议逻辑证明的 `0xCD`**，坚决不采纳“兼容校验码”等未经验证的推测。
2. **驱动层标准动态校验和实现**：
   主控 STM32 发送任何命令均由标准校验函数动态生成：
   ```c
   uint8_t HKS_CalcChecksum(uint8_t length, uint8_t cmd, const uint8_t *params, uint8_t param_len) {
       uint8_t sum = length + cmd;
       for (uint8_t i = 0; i < param_len; i++) {
           sum += params[i];
       }
       return sum;
   }
   ```
3. **G1 阶段硬件实物抓包验证流程（冻结红线）**：
   在传感器物理接入 STM32 前，必须通过 PC 串口助手（SSCOM）执行两组抓包对比：
   * **对照测试 1**：发送标准算法帧 `FF C7 03 A3 A0`，观察模块是否正常应答周期数据帧；
   * **对照测试 2**：发送历史错误帧 `FF C7 03 CD A0`，记录模块是返回错误帧、无响应还是被容错；
   * **实收帧反向检验**：捕获模块周期上报的遥测帧（`FF C7 06 [CKSUM] A0 [MB] [XY] [XL]`），检验其回传的 `CKSUM` 是否严格满足 `(0x06 + 0xA0 + MB + XY + XL) & 0xFF`。
   * **验收依据**：以实物抓包确认的逻辑为唯一准出标准并固化至 Git 驱动分支。

## 专题二：GY-641V3 测温端序矛盾澄清与双端格式转换

### 2.1 矛盾排查：大端序（Big-Endian）的确证

前期文档表格中将 16 位整型数据类型标注为了小端 `int16_le`，而换算公式却明确注明：
```text
To (℃) = ((Byte 1 * 256) + Byte 2) / 100.0
```
在 I2C 连续读取的字节流中，`Byte 1` 先被接收，`Byte 2` 后被接收。高权值字节（MSB）在先，低权值字节（LSB）在后，在计算机体系中这是标准的**大端序（Big-Endian，MSB First）**。标注 `int16_le` 纯属笔误，已在此版本彻底纠正为 **`int16_be`**。

查阅原厂工程源码（`c51_iic/user/main.c` 第 78 行），原厂代码如下：
```c
datas[0] = my_ir.to = (raw_data[1] << 8) | raw_data[2];
datas[1] = my_ir.ta = (raw_data[3] << 8) | raw_data[4];
datas[2] = my_ir.bo = (raw_data[5] << 8) | raw_data[6];
datas[3] = my_ir.e  = raw_data[0];
```
证实传感器传输格式确凿为**大端序**。

### 2.2 负温度符号规则与补码安全解码

红外测温探头的物表测量范围为 -40 ℃ ～ +125 ℃，环境温度范围为 -20 ℃ ～ +85 ℃。  
当温度处于零下时（例如在寒冷室外测试 -5.20 ℃），内部协处理器输出的是**16 位带符号二进制补码（Two's Complement）**：
- 例如 -5.20 ℃ 对应计数值为 `-520`，其 16 位补码十六进制为 `0xFDFC`（`raw[1]=0xFD`, `raw[2]=0xFC`）。

**严重错误写法**：
若在无符号类型下直接左移并相加：
```c
uint16_t temp_u16 = (raw[1] << 8) | raw[2]; // 得到 65016
float temp_c = temp_u16 / 100.0f;           // 错误计算为 650.16 ℃！
```

**标准化防溢出解码实现**：
必须强制转换为标准有符号整数 `int16_t`，利用 C 语言算术右移与符号位扩展正确恢复负数：
```c
int16_t to_raw = (int16_t)(((uint16_t)raw[1] << 8) | (uint16_t)raw[2]);
int16_t ta_raw = (int16_t)(((uint16_t)raw[3] << 8) | (uint16_t)raw[4]);
int16_t bo_raw = (int16_t)(((uint16_t)raw[5] << 8) | (uint16_t)raw[6]);

float To_Celsius = to_raw / 100.0f; // 正确解析为 -5.20 ℃
float Ta_Celsius = ta_raw / 100.0f;
float Bo_Celsius = bo_raw / 100.0f;
```

### 2.3 传感器物理端序与 MMP/1 网络通信端序的分层隔离

系统采用分层架构，杜绝端序混乱：
1. **板端驱动层（HAL/Sensor）**：
   负责与硬件交互，按照 **Big-Endian** 从 I2C 总线接收并解析为 STM32 本地物理量（Cortex-M4 内部原生整型/浮点）；
2. **协议封包层（MMP/1 Protocol）**：
   根据《专项合同》附录 A 规定，MMP/1 二进制遥测协议统一采用 **小端序（Little-Endian）**。
   将本地数值填入网络帧时，统一执行小端编码：
   ```c
   // 将本地 int16_t 写入 MMP/1 发送缓冲区 (Little-Endian)
   p_buf[0] = (uint8_t)(to_raw & 0xFF);        // LSB
   p_buf[1] = (uint8_t)((to_raw >> 8) & 0xFF); // MSB
   ```
3. **Web / 上位机解析层**：
   按小端序（`DataView.getInt16(offset, true)`）解包，保证两端转换对称清晰。

## 专题三：引脚复用深度排查 —— PD0/PD1 与 FSMC 总线复用隔离

### 3.1 隐患本质分析：FSMC 数据总线争用

在前期审查中，通过将 ADS1292R 的 `PWDN` 引脚重定向至 `PE8`，成功消除了与 `UART5_RX`（`PD2`）的引脚冲突。  
然而，心电控制引脚中仍然使用了：
* **`PD0`**：作为 ADS1292R 的片选使能端 `CS`
* **`PD1`**：作为 ADS1292R 的硬件转换启动端 `START`

查阅 STMicroelectronics 官方数据手册《STM32F407ZG Datasheet》第 4 章引脚定义表（第 48 页）与参考手册 RM0090：
* **`PD0` 的复用功能 12（AF12）为 `FSMC_D2`**（可变静态存储控制器数据线第 2 位）；
* **`PD1` 的复用功能 12（AF12）为 `FSMC_D3`**（可变静态存储控制器数据线第 3 位）。

```
+-----------------------------------------------------------------------------------+
| 潜在硬件灾难场景分析                                                               |
|                                                                                   |
|  STM32F407 主控                                                                   |
|   +-------------------+                                                           |
|   | FSMC 控制器 (AF12)| ---> 试图读写板载 1MB 外部 SRAM (IS62WV51216)             |
|   +-------------------+      或驱动 8080 并口 TFT LCD                             |
|             |                                                                     |
|             v (数据线 D2 / D3 高频跳变)                                           |
|       PD0 / PD1 引脚                                                              |
|             |                                                                     |
|             v                                                                     |
|   +-------------------+                                                           |
|   | ADS1292R 心电芯片 | ---> CS (片选) 和 START (转换) 被外部 SRAM 随机电平频繁触发!|
|   +-------------------+      导致 SPI 通信彻底瘫痪、心电连续漏帧、状态机锁死!     |
+-----------------------------------------------------------------------------------+
```

### 3.2 资源现状与本版处置决议

1. **资源评估**：
   * 本项目显示终端采用大彩智能串口屏（USART2）以及局域网/公网 Web 1080p 大屏，**完全不需要并口 FSMC LCD 屏**；
   * STM32F407ZGT6 片内自带高达 **192 KB 的零等待 SRAM**（112 KB SRAM1 + 16 KB SRAM2 + 64 KB CCM RAM）。对于处理 5 参数生理监护任务（采样吞吐量约 1.2 KB/s），内部 SRAM 充裕度超过 90%，**完全无需扩展外部 SRAM 芯片**。
2. **强制工程禁令（Firmware Invariant）**：
   * **在 Keil / STM32CubeMX 工程中，必须彻底关闭并禁用 FSMC（Flexible Static Memory Controller）时钟**；
   * 严禁调用 `FSMC_NORSRAM_Init()` 等任何外部总线初始化函数；
   * 确认 `RCC->AHB3ENR` 寄存器中的 `FSMCEN` 位保持为 `0`；
   * 将 `PD0` 和 `PD1` 配置为纯通用推挽输出模式（`GPIO_Mode_OUT / GPIO_OType_PP`），上拉电阻使能。
3. **扩展备选方案（若二期确需外扩内存）**：
   若后续迭代必须使用外部 SRAM，则必须在硬件飞线阶段将 ADS1292R 的 `CS` 和 `START` 迁移至非总线冲突引脚（推荐采用与原厂 F4 评估板完全一致的 `PE7` 作 START、`PE10` 作 CS）。

## 专题四：滤波算法群延迟与实时传输指标冲突攻关

### 4.1 数学定理与指标冲突揭示

在原系统方案中，提出了两项技术要求：
1. **滤波方案**：采用 129 抽头（129-tap）、采样率 `fs = 250 Hz` 的线性相位对称 FIR 带通滤波器（5～40 Hz）；
2. **网络延迟指标（P-T07）**：要求“服务接收至前端入绘制队列 P95 ≤ 200 ms；全链路端到端 P95 ≤ 500 ms”。

**严格的数字信号处理数学定理**：  
对于一个抽头数为 `N` 的对称线性相位 FIR 滤波器，其群延迟（Group Delay）为恒定常数：
```text
群延迟样本数 = (N - 1) / 2
```
当 `N = 129`，`fs = 250 Hz` 时：
```text
群延迟样本数 = (129 - 1) / 2 = 64 个样本
群延迟绝对时间 = 64 / 250 Hz = 0.256 秒 = 256 ms
```

**冲突结论**：  
对称线性相位 FIR 滤波器在数学物理层面要求必须蓄积并向前跨越 64 个样本才能解算出中心点滤波值。这意味着**仅滤波器算法自身的理论纯时间滞后就已经达到 256 ms**！  
若将滤波后的数据作为“端到端实时网络流”考核，要求包含网络传输与渲染必须在 200 ms 内完成，在物理学和数学上是**绝对不可能实现的伪命题**。

### 4.2 本版双链路架构解耦与指标重构

为了解决该矛盾，本版将系统数据流正式解耦为**“低延迟原始遥测链路”**与**“滤波特征显示链路”**，分别设立科学严谨的验收标准：

```
                              +-------------------------------------------------------+
                              |         ADS1292R 原始采集 (250 SPS, 每 20ms 一包)      |
                              +-------------------------------------------------------+
                                           |                                |
                     [支路 A：原始数据遥测流]                               [支路 B：滤波算法流]
                                           v                                v
                        +------------------------------+     +-------------------------------+
                        | 实时打包透传 (5 样本/包)     |     | CMSIS-DSP FIR 滤波 (129 抽头) |
                        | 网络传输 + Web 接收队列      |     | 群延迟 tau = 256 ms           |
                        +------------------------------+     +-------------------------------+
                                           |                                |
                                           v                                v
                        +------------------------------+     +-------------------------------+
                        | 实时传输性能指标 (P-T07)     |     | 滤波波形呈现指标 (P-T07 扩展)  |
                        | 测量点: 发送至前端入队       |     | 包含算法延迟的综合视觉滞后    |
                        | 严格约束: P95 <= 200 ms      |     | 约束: P95 <= 500 ms (约350ms) |
                        +------------------------------+     +-------------------------------+
```

#### 1. 支路 A：原始数据遥测链路指标（对应 P-T07 严格考核）
* **数据内容**：原始心电（250 SPS）、呼吸阻抗（50 SPS）、血氧容积波（50 SPS）、实时压力（10 Hz）；
* **传输调度**：每 20 ms 发送一包（含 5 个心电点、1 个呼吸点、1 个血氧点）；
* **延迟预算分解**：
  * MCU 本地打包缓冲：20 ms
  * ESP8266 串口 DMA 转发：5 ms
  * 局域网 / 腾讯云 WSS 传输：30 ～ 60 ms
  * 后端广播与前端 WebSocket 入队：15 ms
* **实测保证**：**支路 A 传输链路 P95 延迟控制在 70 ～ 100 ms，完全满足 ≤ 200 ms 的合同要求**。

#### 2. 支路 B：滤波波形呈现链路指标（对应全链路 ≤ 500 ms 指标）
* **数据内容**：经 5～40 Hz FIR 滤波后的平滑心电走纸波形；
* **延迟预算分解**：
  * FIR 群延迟物理恒定量：256 ms
  * 硬件浮点运算开销（Cortex-M4F 运行 CMSIS-DSP 库）：≤ 0.05 ms（忽略不计）
  * 传输与前端入队：70 ～ 100 ms
* **综合端到端视觉延迟**：`256 ms + 85 ms ≈ 341 ms`。  
  **完美契合合同中关于“条件满足时估计端到端 P95 ≤ 500 ms”的指标红线**。

### 4.3 滤波算法工程优化备选方案

若临床使用场景对波形滞后有极致要求（例如床旁心电走纸要求视觉延迟 < 200 ms），本系统提供以下两种成熟替代滤波模式供切换：

| 滤波方案 | 滤波器类型与阶数 | 算法群延迟 | 优势 | 适用场景 |
|---|---|---|---|---|
| **基准方案 (默认)** | 129-tap 线性相位 FIR | **256 ms** | 严格线性相位，波形零相移失真，ST 段高度保真 | 医疗辅助诊断、离线数据记录与分析 |
| **优化方案 1** | 65-tap 紧凑型 FIR | **128 ms** | 群延迟降低 50%，全链路综合延迟 ≤ 215 ms | 实时 Web 大屏与移动端常规动态监护 |
| **优化方案 2** | 4 阶双二阶 IIR Butterworth | **15 ～ 30 ms** | 极低延迟（< 30 ms），全链路延迟 ≤ 110 ms | 手术室/急救床旁高灵敏度实时走纸 |

## 五、 纠偏结论与执行清单

1. **血氧校验和**：废止静态 `0xCD` 解释，采用动态累加函数，硬件到货以 G1 串口抓包为最终基准。
2. **测温端序与符号**：确认 GY-641V3 为大端序（`int16_be`），负温解码必须经 `int16_t` 补码还原，网络传输按统一规范转小端。
3. **总线隔离**：确认系统不使用外部 FSMC LCD 与外部 SRAM，在固件中彻底关闭 FSMC 外设时钟，保障 `PD0/PD1` 安全充当 GPIO。
4. **延迟指标**：将 200 ms 延迟指标界定为“原始数据遥测传输延迟”，129-tap FIR 滤波波形按“256 ms 算法延迟 + 传输延迟 ≈ 341 ms”纳入全局 500 ms 预算，物理逻辑严密自洽。

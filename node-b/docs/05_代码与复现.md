# 代码归档、普通验证与采集工具

## 1. 可构建入口

最新完整BIO_V2源位于 `node-b/firmware/biov2/实验固件/`，原C、头文件、启动文件和Keil工程保持字节一致。CMSIS/标准外设库原许可头保留。预编译 `arm_cortexM4lf_math.lib` 没有加入本次提交，名称、大小和SHA在 `evidence/external-build-dependencies.json`；构建时必须从用户本地合法副本显式提供，脚本先校验SHA。

在仓库根目录执行普通Host验证：

```powershell
python node-b/tools/run_host.py
```

使用Python3.11及已有MinGW `C:/mingw64/bin/gcc.exe`。本次没有安装/升级工具。脚本运行算法、通道隔离、真实队列、合成采集协议、源板控制台/ROM模型及BIAS观测工具测试，不打开设备。结果写入唯一的 `node-b/build/host-<UTC>/`，该目录不提交。

普通ARM重建：

```powershell
python node-b/tools/build_arm.py --keil-root D:/keil --dsp-lib <本地同SHA的arm_cortexM4lf_math.lib路径>
```

ARM构建复制到独立目录，临时ASCII盘符只用于旧Keil兼容，退出清理本轮映射；不改变主项目路径。原编译选项、链接布局、业务源码和协议不改。脚本没有下载命令。实际固件二进制只留本地，公开回执列出SHA和资源。

## 3. 采集协议和profile不是一回事

`node-b/acquisition/`保存统一session/condition/channels模板、CSV/JSON约束、稳定版本选择、尾段规则、冲突/flags记录和多样本表征工具。

- 通用的是文件结构、字段含义、身份与完整性规则。
- 旧 `ads1292r_swd_ring24_v1_9f58a890.json` 固定旧镜像/地址，不可用于当前BIO_V2。实际运行前必须提供与实际BIN/ELF/全片身份匹配的profile。
- 本次清除公开工具中的真实UID默认值；硬件模式仍强制校验外部明确提供的UID，空值不能启动采集。普通测试只用合成身份。
- BIO_V2固定120B诊断区与旧算法/UI符号不同。现场专用 `capture_v2.py`、`make_profile.py` 等作为 `reference/biov2-local-tools/*.txt`审查材料保存：它们依赖历史目录与已安装镜像，不能改扩展名就宣称适配今天设备。
- 本轮没有设计新的BIO_V2实时导出协议，也没有把旧profile重新命名后当作BIO_V2兼容证据。

当下轮采集前核验实际镜像/符号表，并决定使用已有专用工具还是做最小适配；任何适配都需冻结新工具SHA和普通负向测试。

## 4. 原件与公开副本

`evidence/source-provenance.json`同时列出原件路径标识、原SHA、公开SHA及是否逐字节相同。固件快照按字节保存；公开Host测试仅改变输出位置、旧源相对路径、真实UID默认值和不公开原码的测试处理，不改变算法C。

`history/`中的实测数值/结论来自原轮次，设备号已脱敏、原本地附件链接改为“本地保留”说明。历史源码注释和报告可能有过时表述，解释以本包当前复盘与精确源码身份为准。

本次未运行Security Gate或主动安全扫描；普通构建/功能回归不构成安全准出。

## 2. P1-B入口和可信授权：DESIGN_PROPOSED

最小下一步为独立P1-B薄入口，复用已有BLink/CLink的SDK方法、原生日志和读取白名单，**不调用G3联合worker，不打开COM，不启动云或采集**。当前没有实现或启用该入口。

建议在另行许可的离线变更中做到：

1. 默认只输出disabled计划；一块板一个scope，B40928/C49132分别绑定私有身份、全片/options和对应工具/DLL清单，不能给它R6业务卡或B41012安装卡。
2. 真实PI信任根放在仓库外，由PI选择既有签署方案及公钥/可信引用；验固定Git树、全部制品/工具SHA、板卡、scope、起止时间。严禁应用自签或把pi_signature非空视作签名。签署格式和信任根未冻结前继续无条件拒止。
3. nonce由PI签发，父进程独占消费；子进程核对marker内容中的授权SHA/nonce/scope/板卡和父事务身份，而非只检查`.used`存在。失败不返还次数，禁止重试。不得把本方案字段自行生成成真实授权。
4. 90s总监督、全片45s、其他5s为待审建议；Flash/options各一次，原生负返回/正短读分别记录。读取地址、次数和Close政策必须写进同一冻结清单。

## 3. SDK隐式CPU控制及Close异常：OPEN_WITH_PLAN

原因：只读API白名单不约束SDK连接/Device配置的内部实现；Close可由SetRestartOnClose触发续跑；旧温度worker的取消策略失败可能跳过Close。当前证据不能证明“无隐式Halt/Reset/Go”。

解决方案：先在上述薄入口的离线候选中明确最外层API/地址过滤，禁止所有Halt/Go/Reset/Write/DAP控制及UART读写；按PI批准的原生语义保存每次策略返回，不以未核实的返回码解释重复原生调用；将唯一Close放在独立finally路径，取消策略失败也保留Close执行/未执行的真实状态。故障后不得补读或自动恢复。若仍无法从既有SDK文档/历史日志确定连接/Close语义，则须由PI单独审查并接受该残余影响或选择获准的替代只读方式，不能用P1-A Mock证明原生无副作用。

不在本轮改变继承层的现场恢复/关闭逻辑，以免未审变更获得旧授权。B/C禁用申请明确列了此前置项，不能立即激活。

## 4. WCET及连续采样：WCET_MODEL_ONLY

原因：FrameFeed完整路径包含BioV2、CAN、FIFO多帧耗尽及同步HMI发送；TXE/TC等待没有本地上限，模型却把出队当零成本。普通负载测一次也不能证明所有路径有硬上界。

解决方案：先保持原模型和判据，按调用链列出待测参数；HMI最坏字节/等待、每帧BIO/CAN耗时、积压上界、多周期重合、UART4相位均须有独立时间证据。若要修复无界等待或调度，还需单独固件变更合同，绝不能在本轮修改驱动/采样时戳、clamp或丢样。真实测时属于后续独立授权，不并入只确认身份/Flash的P1-B。

## 5. SKX菜单、HR语义和实物：部分文档已核，现场UNKNOWN

找到的真实说明书在原项目目录 `doc/B/SKX2000D+说明书.pdf`，12页，SHA256 `27fe9e4a37a761ab7df939bf49693942dbf3e5692f09e2e10311106053503cc8`。P5表格分别列呼吸率5–120rbpm、幅度0.3R–3.0R、窒息0–120秒、波形周期20–120bpm；P11列默认呼吸15、幅度1.5R、基线阻抗1K，同时出现“心率范围60bpm”。这支持菜单应分开记账，但不能证明“周期30”为载波，也不能证明RR改线后的CH2必无真实QRS。

解决方案：未来获准前仅由负责人目视/既有照片登记当前菜单和端子，三方对齐说明书、R5操作卡及实物；若源本身确有QRS，提交独立工况解释和评审，不屏蔽HR、不用lead-off/假接地过关，也不事后放宽冻结判据。本轮不调整菜单、不新增导联、不触碰J3。

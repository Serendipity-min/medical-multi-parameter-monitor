# FIVE-APPLIANCE-P3 网络出口定位

**CAPACITY_NOT_PASS。** P1 两个现场窗口的实时队列持续接近满载，C 完成约 8.08 批/秒，低于可证明的输入下界约 10.45 批/秒。P3 用同一份合成输入比较真实 C 出口代码，在虚拟串口上重现了波形缺口与音频挤压。容量缺口留给网络架构设计。P2 已单独提交于 `87f872d03666ac6b6ca7ad476cb10314c47c1995`。[P2 报告](P2-REPORT.md) [P3 机器回执](P3-EVIDENCE.json)

## N0 同负载 Host 对照

夹具编入当前 Router、单所有者 coreMQTT、MQTT adapter、AT UART 状态机与音频推进器。只有 STM32 寄存器和 ESP/Broker/麦克风/TTS 对端使用替身。五个约 110 秒的虚拟窗口重用相同输入，采样率为 ECG 250 Hz、RESP 与 PPG 各 50 Hz。实时容量 24、历史容量 56、3 个遥测 QoS1 票据和 1 个音频事务均按源码。每个输出 MQTT 载荷与入队时对应的规范序列化 CRC 核对，记录波形缺失、替换、溢出和历史帧，绝不把有损情况下的高发送率作为 PASS。

42 ms 档的遥测差值较小，因为音频机会更少，完成音频块从 65 降至 13。22 ms 档 64 块首末发送接近原 90 秒组装预算且已经有波形缺口。两个 125 块组均在窗口结束时未完成，不能据此虚构后续完成时间。所有已发送载荷的 CRC 不一致与实时倒序/重复均为 0。真实 C 的音频防挤压条件会在积压时抑制音频，不能靠降低音频服务量把容量标为通过。

## N1 优化候选及边界

模型使用 P1 两组原件中各流按幸存包顺序采样的尺寸与源率下界，以及 P2 每流实测包长上界和实送率。缺失的现场报文内容与时间没有复原。模型按每流合成到达时间，保留独立的 MQTT 包边界和同流发送顺序，使用 24 个有限实时槽及原时限。基准每笔服务成本由 P1 速率和真实负载尺寸折算，约为 85 ms 固定残差加线时。这是校准假设，包含多种未拆分的成本。固定 120 ms 的发送后 ACK 亦为敏感性假设。模型按固定队列处理，真实 Router 的优先级和历史策略另由 N0 Host 代码覆盖。

| 模型候选 | P2 负载加 125 块时实时遥测完成率 | 波形缺失 | 125 块中确认数 | 验证重点 |
|---|---:|---:|---:|---|
| 基准 | 7.62 批/s | 16 | 0 | 复现有限队列持续过载 |
| 每笔少 5 ms 空查占用 | 7.98 批/s | 18 | 3 | 证明减少的是空查询且 ACK 尾延迟未恶化 |
| 机会式两包合发，每组合省 30 ms | 7.70 批/s | 14 | 2 | 核对队龄保护下真实可合发比例 |
| 非阻塞推进，线事务耗时相同 | 7.62 批/s | 16 | 0 | 量测 CPU 回收与接收时序，仍需降低实际所有者占用 |
| 乐观重叠 20 ms | 8.45 批/s | 17 | 80 | 需要逐事务证据证明可重叠 |
| 空查与合发同时优化 | 8.05 批/s | 15 | 7 | 证实可叠加节省量 |
| 乐观上沿，空查 12 ms、每组合省 45 ms、重叠 20 ms | 10.32 批/s | 3 | 125 | 仍溢出，不能据模型签发实板验收 |

- **先验证接收提示与有限兜底查询。** 对照空查、收到提示、有效读、ACK、下行回复、PINGRESP 和断开事件。若目标 ESP 版本可靠提供被动模式提示，用提示减少无效长度查询，同时保留有界兜底。SSL 提示长度不能直接当作应用可读长度。[ESP8266 ESP-AT TCP/IP 说明](https://docs.espressif.com/projects/esp-at/en/release-v2.2.0.0_esp8266/AT_Command_Set/TCP-IP_AT_Commands.html)
- **评估机会式合发。** 只在两条完整 MQTT 包已待发、串行载荷总长不超过现有 2,048 B、票据和原时效均满足时验证一次 AT 发送。保持独立 Packet ID、QoS、序号、来源与失败处置。需先证明 coreMQTT 不会在真正写出前将缓冲内容报为已发送，并覆盖中途失败、重连与重复。当前适配器已经在单个 MQTT 包内部合并发送向量，收益假设来自跨包省去一组 AT 往返。[MQTT 3.1.1 传输与 QoS 说明](https://docs.oasis-open.org/mqtt/mqtt/v3.1.1/mqtt-v3.1.1.html)
- **评估有界非阻塞推进。** 把命令、提示符、二进制、终态和接收切成可恢复状态，并记录每段独占时间。先验证超时与失败保序，再测可重叠的序列化或诊断时间。在真实 UART 上仍只能有一个 AT 命令所有者。FreeRTOS 留在后续技术评估。

## 已确认：缺在成批前，C会额外清掉未满批采样

约293.234秒首末诊断区间内，A-PPG记录：时间间断计数增加231、有效性/合成身份切换清批增加14、部分批采样丢弃增加2,935；B-ECG/B-RESP对应三项增量均0。C的Router丢弃为0与此不矛盾：这些点在进入Router前已经被波形组包器清掉。

当前实际安装C的源码SHA与离线分析代码一致。`gateway/dual_can/b4_gateway.c`的`waveform()`按以下规则处理PPG：

1. 50Hz的相邻tick应约20ms；单步超出19–21ms，或批内累计相位偏差超过±1ms，计为间断。
2. 一旦触发间断，先将当前未满批点数加入`flow_discarded`，随后直接令`f->count=0`。
3. 有效性或合成身份变化时，同样先计丢弃再清零。
4. 只有凑满50点才发一批，批序号在实际发批时才增加。

因此，“已发批序号连续”“Router未丢弃”“网页未漏批”都不能证明这些未成批采样得到保留。间断计数也不等于丢了231个点：计数同时覆盖漏点、重复/倒序tick和相位异常。

## 尚待定因：A输入/调度为何触发间断

SpO₂数值非0与PPG逐点连续是两个条件。当前A源码中：SpO₂和PR是独立标量有效位；PPG还要求最近波形点不超过100ms。标量仍有效时，波形仍可能间断或被判无效，R5的295条有效标量与1批无效PPG可以同时存在。

当前源码存在以下可核验路径，但本轮没有逐点A原码及对应运行计数，不能签为现场唯一根因：

- `HARDWARE/UNO/uno.c`将IR值与USART6接收时刻`uwTick`配对；这不是模块内部硬件采样时钟。接收突发/调度延迟可能影响时刻分布，屏幕数值正常不证明其均匀。
- `HARDWARE/CANopen/node_policy.h`只用两点真实接收时间夹住的20ms网格输出，禁止外推；输入跨度超过100ms或重复接收tick会重置网格。
- `canopen_app.c`遇输入/输出年龄超过250ms会丢弃并计入`node_a_can_wave_expired`；CAN专用环另有`g_uno_wave_can_drop`。这两个A运行计数未在R5采集。
- A主循环在屏幕/应用任务后才处理CAN；`app_bp.c`血压屏USART3发送和`USART/usart.c`血氧屏USART2发送都等待TXE。阻塞发送、屏幕重绘和批量处理是调度停顿的候选路径；未测得A本窗最长主循环间隔，不能把全部231次间断直接归于屏幕。

R5没有新EMCY，不取消R3的历史EMCY-8110；本轮也没有证据证明所有上游缺点都来自模拟器。需要区分原始波形输入、A环/过期、A发出点和C收到点，而不是继续只观察SpO₂是否为0。

## 下一步最小修复方向

先修复已确认的C缺失放大：在真实时间间断/质量边界前，保留并发送原部分段，使用真实末点时间、原速率和原有效性；不同段不拼成等间隔连续波形，不补点、不外推、不放宽质量和5秒门。现有Backend允许短波形数组，但固定50点的旧检查及新增短包负载必须相应验证，不能只改一行清零逻辑就刷板。

短段增加报文数，可能影响当前医疗排队和音频速度，因此须先在上述真实反例及并发压力中验证点数、值、时戳、质量、队列容量和原期限；音频119.147秒医疗门等待需要继续拆分旧帧/容量/ACK额度，不能放宽门槛换速度。A侧再以原始IR接收时刻、重采样输入/输出/重置、环丢弃、过期及主循环最大间隔完成定位。

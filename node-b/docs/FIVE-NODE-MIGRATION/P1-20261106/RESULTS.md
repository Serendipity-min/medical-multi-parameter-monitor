# FIVE-NODE-P1｜离线整改与容量裁定

**两项确认缺陷已定向修复并验证；当前实测服务能力没有足够余量，不能签发新的五板实板候选。按合同停止本轮裸机队列微调，交给下一阶段FreeRTOS/网络传输架构设计。**

代码起点为`codex/five-node-single-module-v1@e8804f8a8092a38a8a5ff9be2f7162dfbcd091e3`。本轮只改两个生产文件：`gateway/storage/router.c`、`gateway/b5/egress.h`，未操作设备、串口、调试器或真实网络。硬件保持负责人最后确认的全部断电状态。

## 1. 最小整改与修改前后复现

- PPG加入现有B5候选的按次FIFO集合；实时队列有空位时不再提前替换同源PPG。有效/无效批均保留原状态，不改采样点、时间戳、seq或会话身份。ECG/RESP原保护行为不变。
- 将历史配额提取为同一内部取帧函数，在出口选择实时帧之前检查，消除提前返回。原规则保持：新连接先成功发实时；忙时至少8条实时成功后才能补1条，且历史间隔至少2秒；空闲间隔至少500毫秒。
- 历史补传只使用余量：实时队列至少留3个空位、所有排队帧源龄小于2,500毫秒、QoS1未受限。任一实时在途帧源龄达到2,500毫秒时，出口先推进确认，只继续不占QoS1槽的实时波形，暂不启动新的QoS1事务。保留原单一coreMQTT/AT所有者、三个遥测票据和先推进/回收票据再取帧的顺序。
- 这是一项基于半窗余量的调度保护，**不是对最长5秒阻塞下绝不过期的保证**。没有扩大缓存、补样、降采样或更改5秒新鲜度、90秒血压期限、2秒录音和设备420秒上限。

| 同一真实实现的Host用例 | 修改前原生退出 | 修改后原生退出 |
|---|---:|---:|
| 三路波形FIFO及点值/seq/时间/质量保持 | 3：断言失败 | 0 |
| 持续实时负载下执行历史配额 | 3：断言失败 | 0 |
| 2,500ms边界、近满队列、QoS1背压保护 | 3：断言失败 | 0 |
| 发送机会与老在途事务保护 | 3：断言失败 | 0 |

边界用例还使用本次ECG记录的MQTT发送最大耗时159ms，核对允许一次历史发送后原实时帧仍可原样取出且无新增过期/溢出；这是受控离线用例，不是完整五板压力通过。

直接使用两组原件中的12个PPG幸存批组成短突发，原实现均只留下1批、提前替换11批；修复后12批全部按序保留，逐字段一致。突发时序是明确的合成压力，载荷来自原件，不冒充现场到达时序。

## 2. 实录回放与完整性范围

按原始Broker收包顺序，将两个300秒源时间窗内已收到的全部波形批逐帧通过实际Router，原件SHA与此前提交的证据索引一致。每帧立即取走的控制回放，修改前后均没有字段不一致：

| 原件载荷（包含源无效批） | ECG60窗 | RR18窗 |
|---|---:|---:|
| 波形批数 | 1,046 | 1,048 |
| ECG点数 | 69,700 | 70,700 |
| RESP点数 | 14,450 | 14,350 |
| PPG点数 | 2,914 | 2,676 |
| 点值/seq/时间戳/质量/身份不一致 | 0 | 0 |

这里ECG60的PPG为60批、2,914点，含1个无效点；此前实板报告的59个**有效**批、2,913点仍成立。RR窗ECG的无效状态照原件保留，不能将70,700点宣称为有效ECG。

**证据缺口：没有完整有序的C全量入站，尤其缺少A全窗UART/PPG；AT/MQTT只保存周期快照和累计延迟桶，没有每笔事务的完整耗时表。** 因而本轮能精确回放幸存批、原始Broker顺序与实际报文尺寸，并核算真实计数/延迟；不能逐事务精确重放被丢弃的未知批，也没有补造它们的点值、质量、seq、时间或到达顺序。失效标量在MQTT中被遮蔽为null，其隐藏原值不能从原件恢复。

这项幸存者控制回放不是带全量源输入和实测逐笔延迟的饱和压力通过。下面的容量裁定来自现场产生量/服务量及持续队列压力，不能用控制回放的零不一致替代。

## 3. 实际容量预算：两组均不足

| 同窗原件推导 | ECG60窗 | RR18窗 |
|---|---:|---:|
| C服务计数首末间隔 | 294.899s | 295.089s |
| QoS0完成＋QoS1确认增量 | 1,043＋1,337 | 1,044＋1,340 |
| 实测服务速率 | **8.0706帧/s** | **8.0789帧/s** |
| 周期诊断看到的实时队列占用（容量24） | 20–23 | 19–22 |
| 源产生量下界估计 | **10.4420帧/s** | **10.4556帧/s** |
| 按此服务水平折合300s的积累缺口 | 约711帧 | 约713帧 |
| 现场历史淘汰/实时溢出增量 | 716/48 | 709/50 |

B的ECG/RESP/HR/RR和D温度采用C的`B5 FLOW put`首末增量及各自实际采样间隔；A的PPG/SpO₂/PR使用同一会话内幸存seq跨度，得到300秒内已出批数量的下界；状态与血压采用实际消息数量。各字段采样时点不完全相同，速率是跨约295–300秒的保守估计，不宣称逐毫秒精确；累计差额也不冒充现场丢弃计数的逐条重现。

实测服务量是周期快照间QoS0完成与QoS1确认增量，边界尚在途的最多三个事务不影响约2.37帧/s的数量级缺口。队列占用是60次周期观察，不能证明两次观察之间从未短暂下降。它证明现有运行路径在本负载下没有交付所需服务水平，不是网络或MCU的理论物理上限。

已收真实MQTT包字节（含Topic、MQTT头和QoS1标识，不含TLS/AT）约3,662/3,685 B/s。按各流实际幸存包尺寸分布估算，输入约4,637/4,649 B/s，占115200 8N1单向载荷能力约40%；缺失批尺寸本身未知，这不是对所有缺失字节的直接测量。AT命令/应答、ACK、主动接收查询及调度开销另计，因此不能把瓶颈简单归为UART带宽不足。

现场MQTT发送累计桶：两组p50上界50ms、p95上界250ms，最大159/158ms；QoS1确认p95上界500ms，最大370/348ms。累计桶包含启动及早期窗口，不能还原逐笔时间表或将桶上界当作精确分位数。周期AT耗时样本、各流实际包尺寸和原始计数在[OFFLINE-RESULTS.json](OFFLINE-RESULTS.json)。

**现有约8.08帧/s服务水平低于约10.45帧/s源产生量；历史配额还需要额外发送机会。** 修复替换/配额不会凭空产生服务能力，忙时历史可能因实时保护继续推迟。只扩大FIFO、修改公平次序或延长时效不能消除持续积累，本轮不再用这些手段反复尝试。

# PI 审查 R5：R4 批次裁定与 C 板“供电 + 烧录 + 串口”定版规格

**日期** 2026-11-09　**审查人** Claude（PI）　**执行人** Windows 上的 Codex
**被审对象** `codex/field01-preflight@de28580`
**承接** [R4](R4-20261109.md)。边界、AT 白名单、停止条件沿用 R3/R4；本文新增“固定接法”，目的是**不再在供电上浪费时间**。

## 0. 先说结论

1. R4 批次里 S2、S3 没跑成，**原因不在固件，在现场接线与上电时序**：串口没抓到启动横幅、供电路径来回换、一次 DAP 初始化失败（板上开关没开）。固件的 S1′ 基线是好的。
2. 本文给出**一种固定接法**（USB_UART 单电源 + J-Link 只接 SWD 信号 + 板上开关做上电闸门，J5 不接），并配一次 10 分钟的接线基线确认和一套把“烧录、复位、串口”串成一次上电的流程。Codex 不再自行选择供电方案。
3. 额度（上电 8/8、回退 2/2）已用尽，继续 S2/S3 需要负责人确认新额度，见 §6。

### 一个镜像 2 的小发现（非阻塞）
setter 被 ACK 之后 ESP 已经切到候选速率；若此时本端切速因 `RX_NOT_QUIET` 等原因被拒绝，固件的恢复路径回到 115200 去确认，**必然失败**，只能落到 `NEED_POWER_CYCLE`。这是安全的失败（断电即恢复），但会白耗一次上电。镜像 2 不改；若 S2/S3 真的出现这个现象，`PRE RETIME reason=` 会直接告诉我们原因，届时再决定要不要出镜像 3。

## 2. 硬件事实（来自负责人，Codex 不要再质疑，只做一次基线核对）

| 编号 | 事实 |
|---|---|
| H1 | USB_UART（板载 CH340C，micro-USB）接上后可烧录/读取；**打开板上电源开关后，板子由 USB 自动供电**。 |
| H2 | J-Link 拔掉 3.3V 线，只接 SWD 信号线和 GND 时，能完成烧录与读取，**不会给板子供电**。（负责人口述为“RX、TX、GND”，请 Codex 在基线里确认实际是 SWDIO/SWCLK/GND。） |
| H3 | J5 模块通过分压/稳压芯片分出 3.3V 与 5V，可以单独给开发板供电。 |
| H4 | 在这个批次之前，C 板上 J-Link 与 USB 一起使用没有任何供电问题。 |

R3 批次里“USB_UART 拔下后 LED 仍亮”的原因，对应 H2：**J-Link 的 3.3V 线在给板子反向供电**。把那根线拆掉，问题就不存在。

## 3. 定版接法：CFG-U（以后所有会话都用这一种）

| 连接 | 状态 |
|---|---|
| USB_UART → 电脑（COM15） | **全程保持插着**；它既是电源，也是串口日志口 |
| 板上电源开关 | **唯一的上电闸门**：OFF=断电，ON=上电 |
| J-Link | **只接 SWD 信号 + GND**；**不接 3.3V/VTref、不接 5V**；全程保持插着 |
| J5 模块 | **不接**（整个批次都不用） |
| A/B/D/E 板 | 不上电 |
| 热点 | PRE 会话开启；烧录、回退、原应用启动检查时关闭 |

**为什么这样定**
- 只有一个电源（USB），不存在 USB 与 J5 并联或 J-Link 反灌的问题。
- 开关就是闸门，不需要再“拔插线”来上下电。
- J-Link 全程插着而且软件不连接时是被动的；需要烧录读回时才由工具连接。

**禁止的组合**
1. USB_UART 与 J5 **同时**给板子供电（两路 5V 可能并联，板上有没有“或”电路没有证据）。
2. J-Link 的 3.3V/VTref 线接在目标上。
3. 在板子带电时插拔 J-Link 或 USB 线。要换接法先把开关拨到 OFF。
4. 用会拉 DTR/RTS 的串口终端打开 COM15（如默认设置的 PuTTY/串口助手）。**CH340C 在这块板上很可能用 DTR/RTS 做 FlyMcu 的一键 ISP（复位/BOOT0）**，随手开一个终端就可能让 C 复位甚至进 ROM 引导。只用 Codex 的脚本打开 COM15（它们已设 `dtr=rts=False`）。

## 4. 接线基线 BP（一次性，约 10 分钟，只读，不烧录、不发 PRE）

负责人按 Codex 的口令做，Codex 只记录。每一步记录“电源灯、COM15 是否存在、有无输出”：

| 步 | 动作 | 记录 |
|---|---|---|
| BP-1 | 只按 CFG-U 接好，开关 **OFF**，USB 与 J-Link 已插 | 电源灯是否灭；电脑里 COM15 是否存在 |
| BP-2 | 开关 **ON**（COM15 已由脚本只读打开，DTR/RTS 为低） | 电源灯；是否收到 `FIELD01 DISARMED …` 横幅；横幅相对开关动作的时间 |
| BP-3 | 保持上电，用 J-Link 只读连接（读身份，不 Halt、不复位、不下载）后关闭 | 是否连接成功；COM15 有无受影响 |
| BP-4 | 开关 **OFF** | 电源灯是否灭（J-Link 全程插着）；10 s 后电源灯仍灭 |

**判定表（决定后面怎么抓横幅）**

| BP-1 的 COM15 | 含义 | 后续做法 |
|---|---|---|
| 开关 OFF 时**已存在** | CH340 由 USB 直接供电，不受开关控制 | 主机脚本先打开 COM15，再拨开关，横幅可以完整抓到 |
| 开关 OFF 时**不存在**，ON 后才出现 | CH340 也受开关控制，串口要等 1–3 s 才枚举，**横幅会在串口打开前就发完** | 用 §5 的“无横幅”主机模式（WP-M） |

这一点很可能就是 R4 里“COM15 在线但采集 0 字节”“主机到期后才看到 COM15”的真实原因。

## 5. 定版流程（一次上电串起来）

### 5.1 PRE 的触发方式（主机侧，不改固件）
固件**不需要**横幅：它在上电后 45 s 内接受一条 `FIELD01 PRE[…]`，并在 `PRE BEGIN` 里回报自己的 `boot_ms`。所以主机可以这样绑定“新启动”：
- COM15 打开后，**不等横幅**，读空缓冲，再**只发一次**目标 PRE 命令；
- 以回执里 `PRE BEGIN boot_ms < 45000` 作为“确实是新启动”的证据；没有 `PRE BEGIN` 就判失败，不重发；
- 横幅如果恰好收到，仍然记录。

这就是 WP-M（见 §7），**只改 `field01_preflight.py` 与它的测试**，不改固件、不占镜像额度。

### 5.2 一次上电的标准顺序（S2/S3 用）

**会话 A（热点开，USB 供电，J-Link 插着）**
1. 开关 ON，脚本只读打开 COM15。
2. J-Link 工具：整片与 Options 读回（作为回退基准）→ 安装镜像 2（只写 sector0/4）→ 写后整片读回。工具末尾的 Reset/Go 会让镜像 2 启动，**这就是一次新启动**。
3. 脚本在 45 s 内发 `FIELD01 PRE 230`（S2）→ 收 `PRE END`。
4. 若 `RESTORE=OK` 且 `uart_err=0`、`STRESS n=50 fail=0`：**用 J-Link 做一次纯复位+运行（不烧录）**得到新启动，发 `FIELD01 PRE 500`（S3）。
   若 S2 出现 `NEED_POWER_CYCLE` 或 ESP 速率未恢复：开关 OFF→ON 重新上电，先发 `FIELD01 PRE`（115200）确认基线，再按规则继续。
5. 结束：开关 OFF，电源灯灭，回执记“断电待负责人确认”。

**会话 B（热点关，回退）**
1. 开关 ON；J-Link 工具回退到原五板镜像（`unified_install.py --phase install`，用会话 A 的读回做 `--backup`），整片对照。
2. **可选，零额外成本的“原应用冷启动检查”**：回退工具末尾的 Reset/Go 会让原应用启动，COM15 此时已经打开，被动记录器（`field01_original_boot_watch.py`）在 60 s 内看是否出现 `UNI DISARMED V1 C_BC_ABC NO_FLASH_WRITE`。不发 START/KEY，不联网（热点已关）。
3. 开关 OFF。

两次会话合计：**上电 2 次**（含意外重试最多 4 次）、回退 1 次、J-Link 纯复位最多 3 次。

### 5.3 J-Link 纯复位的约束
- 只在上一次 PRE 以 `RESTORE=OK` 结束（ESP 已回到 115200）后使用；任何 `NEED_POWER_CYCLE`、`RESYNC_FAIL`、`STOP` 之后一律用开关断电重启。
- 只做“复位并运行”，不 Halt、不改 PC/MSP/VTOR、不写 Flash；执行前后各记录一条台账。
- 目的只是得到新启动，不是诊断手段。

## 8. PI 预先约定的解读（沿用 R3 §8，补充）

| 现象 | 结论范围 |
|---|---|
| S2（230400）`NEGOTIATE=OK`、`n=50 fail=0 uart_err=0`、`RESTORE=OK` | 230400 在 ESP→STM32 方向、AT 级负载下可用；与 115200 基线（18.4 ms/次 GMR）比较每事务耗时，**不等于**容量达标 |
| S3（500000）同上 | 仅为测量候选，生产档位优先 230400（见 R3 §8 的 CPU/CAN 余量） |
| `RETIME reason=RX_NOT_QUIET/TC` | 切速保护间隔内 ESP 有输出或发送未完成；记录后由 PI 决定是否调保护间隔（需要镜像 3，需另批） |
| 横幅在 BP-2 里总是抓不到 | 支持“CH340 受开关控制”，后续一律用无横幅模式 |

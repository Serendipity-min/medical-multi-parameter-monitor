# R16 WP-AL 稳定重入与启动转义

生产候选沿用三次重入上限和 2、4、8 秒普通重连退避。只有同一 MQTT 会话连续在线至少 300 秒，且网络推进仍成功时，才清零重入计数和软件复位额度。期间任何断连都重新开始计时。

## 恢复流程

1. 有效配置下，STM32 冷启动和受控软件复位后都先锁住普通 AT 与 MQTT 入口。在首次常规 AT 序列前做发送静默 1,001 ms、无 CRLF 的 `+++`、再静默 1,001 ms。清理可能残留的命令前缀并排掉响应，然后独立发 AT、等待完整 OK。失败最多再试一次。后续建链先关闭上一代套接字，必要时查状态确认无连接，再设置传输模式。
2. 运行中退出和既有 ESP 复位接口均无法确认时，才考虑 STM32 软件复位。仅对未 STOP、无固定运行期限且仍有重入额度的生产候选放行。先关 CAN 新发送和自动重传、取消发送邮箱，重新处理本地控制口，再关中断核对 STOP。符合条件才保存包含本次消耗的计数并执行 `NVIC_SystemReset()`。
3. 续接记录含标签、计数与按位反码，仅占 8 B 常规 SRAM 的 `.pass_resume` NOLOAD 段，位于 `_ebss` 后、堆前。链接与向量核验通过。启动只在 RCC 软件复位标志与有效记录同时成立时续接，读后消费记录。复位前的次数随记录恢复，且同一恢复周期的软件复位额度已用。无有效记录的软件复位、启动期 AT 未确认、重复降级及额度耗尽均停止。候选的 J-Link 软件复位如果没有有效记录，也会进入这条锁存路径。
4. STOP 或定时截止后不触发自复位。启动转义阶段继续读本地 STOP，未确认 AT 前不初始化 CAN 硬件，也不发 NMT。允许的自动恢复会让 C 的本地队列、采集缓存和 UTC 状态随复位重建，可能形成数据缺口。A/B/D/E 不由 C 的 MCU 自复位直接复位。恢复成功后 C 会走既有生产自动启动流程，重新进入 CAN/NMT 并重新授时建链。

保留步骤码包括 `GW PASS_BOOT_ESCAPE`、`PASS_PREFIX_FAIL`、`PASS_BOOT_AT_OK`、`PASS_BOOT_AT_UNCONFIRMED`、`PASS_BOOT_SOCKET_UNCONFIRMED`、`PASS_SOFT_RESET_PENDING`、`PASS_SOFT_RESET_RESUMED`、`PASS_SOFT_RESET_BLOCKED`、`PASS_BOOT_RESET_LOCKED` 和 `PASS_REENTRY_STABLE_RESET`。本轮按任务指定交付软件恢复，PF6 板级复位尚未绑定到固件。 [板图核对和裁图](R16-HARDWARE-20261110.md)

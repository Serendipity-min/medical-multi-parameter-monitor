## 2. 必须修改（阻断窗口 2）：配置缺失时把 LOCAL_ONLY 改成了全停
`network_main.c` 主循环在 `--link-resilience` 下把
```c
if(!gateway_config_valid()){platform_poll();continue;}
```
改成了 `console("GW PASS_LOCAL_CONFIG");stop();break;`。

- 现有设计在配置缺失时明确进入**本地运行**：启动打印 `FIVE AUTO CONFIG_MISSING LOCAL_ONLY`（`network_main.c:827`），继续 `platform_poll()`，C 仍做 CAN 网关并向节点发 TIME。
- `stop()` 会调用 `b4_hw_stop()`，**停掉 C 的 CAN 侧**。新改动会让"没配网"的设备连本地网关功能也停掉。这是功能回归。
- 这是我 R34 §2.1 写得不够准确造成的："身份/配置错误可锁止"指的是**网络侧不再尝试**，不是停掉本地功能。我的措辞问题，不是 Codex 的偏离。

**要求：**
1. 删去主循环里这一处改动，恢复 `platform_poll();continue;`（LOCAL_ONLY 行为不变）。
2. `pass_reconnect()` 里新增的 `!gateway_config_valid()` 判断一并删去：能走到重连说明已经建链过，配置不可能变无效，留着只会制造另一条停掉 CAN 的路径。UART 错误增量那一半保留（与 R19 既有语义一致）。
3. Host 用例：`--link-resilience` 打开时，配置缺失 → 不停止、CAN/TIME 继续、无网络尝试；与 `test_entry.c` 的"先无效后有效"用例同口径。
4. 新 SHA；关闭选项时仍须与 S2-c 逐位一致。我复核后再签窗口 2。

## 3. 其余审读结论：接受
- 网络断链不再停止，退避 2/4/8/16 s 后保持 30 s（低于 60 s 上限）；连续计数在稳定 300 s 后清零，累计保留。UART 错误增量、启动基线、STOP 请求仍停止。符合 R34。
- 退避期间 `delay_ms` 阻塞主循环最长 30 s，与既有获取退避相同，S1b-2/S3 已证明期间 CAN 入队与时间锚正常，不另提要求。
- **节流阈值 1,500 ms：接受，但预期它不会改变断链率。** 已记录的断链前 5 s，相邻 PUBACK 间隔最大只有 825 ms（S3）和 422 ms（S2-c），都低于 1,500 ms；长间隔出现在破坏发生**之后**。所以在已观察到的模式下，节流在破坏发生前不会启动。它的作用只是在长停顿时限制 QoS0 继续写入。我不把它记为缓解措施，只记为"稳态无副作用的保护"。预登记：稳态触发 0 次。
- 用"已确认事务延迟上界"校准 T 的方法可以接受；600/800/1,000 ms 的精确触发率 UNKNOWN，已如实列出。

## 4. 两窗口方案裁定
### 4.1 窗口 1（PF6 单板）：**建议本阶段不做，记为已知限制**
- 它需要一条新的"只写 sector0 整块"的安装入口，现有分段安装器不能直接用。这意味着新工具、新的离线验收和一个额外现场窗口，与"尽快结项"冲突。
- PF6 硬复位只在恢复梯度升级到最后一级时才动作；当前 C 侧网络事件已改为长退避重试，升级到 PF6 的场景很少。代码在 GPIO0 为低时保持 RST，有安全门控。
- 结论：**冻结时把"PF6 硬复位路径未经硬件验证"写入已知限制**；若负责人要完整性，再按 Codex 草案单独排期。

### 4.2 窗口 2（WP-AW + 五板 300 s + 短断网）：**接受草案，补充如下，待 §2 新 SHA 复核后签发**
- 跳过窗口 1 后，C 当前为 S2-c，直接用已验证的 `unified_install.py` sector0/4 路径安装新 SHA。额度：安装 1、上电 ≤2、隔离 Broker 1（开连接日志）、热点切换 ≤4；无 START/KEY/泵/J-Link 复位；总运行上限 25 min。
- **300 s 窗口若被非人工断链打断**：标记该次窗口状态并保留原件；**在 25 min 上限内允许重新开始一次 300 s 窗口**（不额外上电）。第二次仍被打断则如实记录，不再重试。
- **PPG 名义覆盖预登记：92–95%，预计低于 99%**（S1b/S1b-2 按点测得 93.2%/93.7%，原因已定位为 A 的质量门控）。按草案单列 SOURCE_LIMIT，传输层按 C 已接纳的数据核对。不把这项预计的未达写成传输失败。
- 其余预登记采用草案：ECG ≥74,250 点；五路标量各 ≥297/300、零重复、保序；队列 ≤16/24、丢弃顶替 0、UART/CAN 增量 0；`console_max` ≤40 ms；稳态 `LINKRES triggers=0`；短断网约 40 s 内无 LINK 停止，`consecutive_drops` +1，热点恢复后首条实时遥测 ≤90 s（SNTP 失败另记分相）；断网期标量完整度 ≥99%；在线满 300 s 后 `consecutive_drops` 清零而 `total_drops` 不回退。

# R22 离线分析：A 板 PPG 与断网计数

重读 S1b、S1b-2 的受限 Broker/UART 原件，四份 SHA-256 均与已推送回执一致。另重新解码历史 CAN60 原始记录。两次 S1b 均没有逐帧 CAN 原件，只有 C 的按节点接收计数和 Broker 载荷。三个窗口的证据分开使用。本轮未修改固件、启动 Broker、上电或刷写。 [R22](https://github.com/Serendipity-min/medical-multi-parameter-monitor/blob/f732278/node-b/docs/PI-REVIEW/R22-20261110.md) · [S1b 回执](R20-S1B-FIELD-20261110.md) · [S1b-2 回执](R21-S1B2-FIELD-20261110.md)

## PPG 缺口位于质量无效段

| 证据 | S1b 稳态 480 s | S1b-2 稳态 600 s |
| --- | ---: | ---: |
| PPG 实收批 / 名义 50 点批 | 467 / 480 | 587 / 600 |
| 实收总点 / 名义 50 Hz 点数 | 22,361 / 24,000（93.17%） | 28,110 / 30,000（93.70%） |
| 满 50 点批 / 短批 / INVALID 批 | 442 / 25 / 12 | 557 / 30 / 15 |
| 采集时间缺口 / C 的 A TPDO1 `gap0` 增量 | 12 / 12 | 15 / 15 |
| C 的 A TPDO1 `p0` 增量及诊断采样跨度 | 22,305 / 477.500 s | 27,966 / 596.953 s |
| 缺口附近 ±2 s 内出现 INVALID（SpO₂、PR 分别计） | 11/12、12/12 个缺口 | 12/15、15/15 个缺口 |

两窗各自的 PPG 都是单一会话，批序号相邻差均为 1。按每批末点时间戳和实际点数还原段首，S1b 的 12 个采集空档共 31.435 s，10 个约 2.08 s、1 个约 4.18 s、1 个约 6.25 s。S1b-2 的 15 个空档共 37.648 s，12 个约 2.08 s、3 个约 4.17 s。以每窗首个恢复边沿为零点拟合，恢复边沿落在约 2.079 s 网格，最大偏差分别为 69 ms、49 ms。空档没有每周期都出现，也没有固定在 UTC 整秒。27 个空档后第一批全部是 **1 点 INVALID**。短批仍算一批，因此按批数衡量的 2.2–2.7% 会低估按点衡量的约 6.3–6.8% 名义差额。节点状态一直在线，两个窗口 C 的 A `boot`、`gen`、`emcy` 无增量。

历史 CAN60 原始文件 SHA-256 `a8fa868149c32186fc17555b8e12ee40c63b52f9147ebe1034847d4450019d7b`，重新解码 17,676 条，CRC 错误和截断均 0。四段 `0x181` 源 tick 间隔为 2,121、4,202、2,114、2,126 ms。上一个波形点后 11–20 ms 内，A 的 `0x681` 从 `0x397` 降为 `0x200`，PPG、SpO₂ 和探头位均为 0。距第一个恢复波形点约 24–35 ms 时，SpO₂ 和探头位已恢复，PPG 位随后恢复。该历史窗另有 EMCY 和小步进异常，只用于说明这四段长缺口的质量时序。 [历史 CAN60 回执](../FIVE-NODE-MIGRATION/FIELD01-20261106/CAN60-41OHM-result.json)

A 的 UNO 解帧路径把 SpO₂ 字节为 0 同时解释为结果无效和探头状态无效。CAN 生产路径在 `!fresh` 时清 CAN 波形环及重采样器，无新的 `0x181` 样本；C 在波形间断或质量切换时提交已有短批。证据支持把规律性长间断定位到 **A 的源质量门控及其恢复边沿**。未捕获两次 S1b 同窗的 UNO 帧或逐帧质量 PDO，外部 UNO 固件也未随 A 工程导入。因此约 2.079 s 是观测到的源事件时间网格，具体 UNO 算法窗口、工装耦合和上游失效条件仍为 `UNKNOWN`。 [A CAN 生产路径](../../../node-a/STM32F407_HOSPITAL/HARDWARE/CANopen/canopen_app.c) · [UNO 解帧](../../../node-a/STM32F407_HOSPITAL/HARDWARE/UNO/uno.c) · [C 波形组批](../../../gateway/dual_can/b4_gateway.c)

## 断网账差来自 Router 前和 Router 内的不同环节

对齐断网前最后一轮周期诊断与重连后第一轮。各行串口快照存在数百毫秒偏差，表内保留各计数原单位。S1b-2 的 210.685 s 是关/开回执间隔，负责人现场报 180 s，物理边沿未独立测量；241.640 s 是 Broker 实时遥测空档。三个时间口径不能互换。

| 可观测项 | S1b | S1b-2 |
| --- | ---: | ---: |
| `B5 WAVE` 跨断网快照间隔 | 70.359 s | 237.657 s |
| Router 前 `unstamped` 增量 | **356** | **1,513** |
| A PPG / A 标量 PDO 增量 | 3,195 / 71 | 11,359 / 237 |
| B ECG / RESP / 标量 PDO 增量 | 12,061 / 2,413 / 71 | 11,164 / 2,233 / 237 |
| B 波形对应的有输出时长，ECG 250 Hz / RESP 50 Hz | 48.244 / 48.260 s | 44.656 / 44.660 s |
| Router 缓存溢出丢弃 / 实时顶替 / Broker replay | 220 / 10 / 58 | 185 / 8 / 56 |

1. **B 的一部分波形未到 CAN。** B 标量仍按约 1 Hz 到 C，ECG 与 RESP 却只收到约 48 s、45 s 的名义波形量。按同一节点标量 PDO 数量估算跨度，对应少约 80、673 个名义波形批。B 在 CANopen TIME 失效时从本地发送队列移除样本，30 s 后失去 UTC 锚，因而这个缺口不会进入 C 的 `unstamped` 或 Router 计数。B 的实板本地丢弃计数没有同窗读数，无法把全部缺口逐点归给该分支。 [B 波形发送门控](../../../node-b/canopen/b_canopen_app.c) · [B TIME 时效](../../../node-b/canopen/node_policy.h)
2. **C 仍接收部分 CAN 数据，但停止接受无时标批。** C 网络打开时刷新 UTC 锚，断开后锚过 30 s 失效。`emit()` 对零时间戳先加 `unstamped`，直接返回，不调用 `mp_router_put()`。两窗的 356、1,513 是这条路径的实测增量。S1b-2 的 56 条 replay 的采集时间均落在断网前最后一条实时遥测采集时间之后 23.000–29.333 s。该分布与到期前缓存的解释一致，单条时间戳归属仍受锚和边界误差影响。 [C UTC 与入队](../../../gateway/dual_can/b4_gateway.c) · [网络授时](../../../gateway/b5/network_main.c)
3. **Router 的几个累计量不能直接相加。** 56 槽历史环在满时覆盖并加 `dropped`，状态批离线不进历史；`live_replaced` 表示把旧实时批移入历史、换成新批，旧批随后可能补传或再次被覆盖。replay 条数也包含断网边界及恢复后的部分历史批。两窗的 56–58 条与容量相容，不能用 `补传 + 丢弃 + 顶替` 当作互斥归宿。网关状态只在 MQTT 在线时产生，按名义 0.2 条/s 乘整个断网跨度还会多估。 [Router 缓存、顶替与补传](../../../gateway/storage/router.c) · [缓存容量](../../../gateway/storage/router.h)

**近似核算。** 在 70.359/237.657 s 跨断网快照上，按 10.5 条/s 估算 739/2,495 条。只合并互相分层的项，`unstamped`、B 名义波形差额、A 名义波形差额（约 7/10 批）、Router 覆盖及实际 replay，对应约 721/2,437 条，剩约 18/58 条。网关状态未产生、其他状态未缓存、部分批和快照边界都会影响这个余数。此估算说明主要差额的量级，未闭合逐批账，也不据此选缓存保留策略。

## WP-AR 上板前核验

- 本机制品 54,088 B，code SHA-256 `dff9cfb974710fd668df7af971fef0b76fb05e97611d4928083ca49155bb0fc1`。以已验证 S1b 安装读回为当前镜像参考，离线安装器已校验 HEX、向量、回退原件及 sector0/4 写入计划。
- R22 稳态开销基线采用 S1b 的 `B5 SCHED console_ms` 最大 23 ms（96 个快照），S1b-2 对照最大 24 ms。固件该字段记录单次 `console()` 调用峰值，需同时记录同 tick 的 `B5 PROD` 至 `B5 PROD_SLOTS` 日志组耗时，才能评估整组发送暂停。组内首行已经开始发出，主机的首末行时间差只能近似。
- `B5 PROD*` 在 MQTT 在线的空闲诊断时隙输出，断网期间没有同周期快照。可用断网前和恢复后紧邻的同 tick 组计算跨断网分流增量，同时标注两端在线时间、队列余量和 replay。WP-AR 的 `enqueued` 从 Router 入口开始，无法单独覆盖 `unstamped` 或 B 未上 CAN 的点，继续使用原有 `B5 WAVE` 与 `FIVE RX` 分层取证。若中间状态或归宿不可见，仍记 `UNKNOWN`。 [WP-AR 离线回执](R21-AR-OFFLINE-20261110.md)
- R22 上板窗需负责人按完整 SHA 放行，并给出断网保留要求。刷写只涉及 C 的 sector0/4，计划为安装 1 次、上电不超过 2 次、热点切换不超过 4 次、隔离 Broker 1 次。五板、工装与热点最后一次已确认关闭。

## 3. 走查结论

**符合规格的部分**
- PRE 只接受精确的三条命令，只在启动 45 s 内受理，一次性；`pre_state` 防重复；`PRE_DIRTY` 拒绝同次 START；PRE 期间 `b5_business_remaining()` 返回 PRE 截止，不会被 45 s 就绪计时误锁存；`b5_hard_tick` 仍保留 210 s 硬上限。
- DC-1：`runtime_ready=false` 使 DISARMED 阶段的 `service()` 提前返回，到不了 `field01_poll()`/CAN 诊断；`pre_active()` 时只放行 `local_control()` 以响应 STOP。
- 回执脱敏：IPv4 只判断非全零，UART 五元组与 CIPSTA 只取行首完整行、校验字段范围；`wifi_join()` 用后 `secure_memzero`；`reply_begin()` 现在会把 `reply[0]` 清零，避免读到上一事务内容。
- 恢复条件比我的设计更严：必须在 115200 下重新得到 `AT` 的 OK **并且**五元组为 8N1/无流控才报 `RESTORE=OK`。
- 主机脚本没有任何 START/KEY 写入路径，只有三条 PRE；发送标记先于写串口；短写、重复横幅、超长行、畸形回执都会终止并保留标记。
- 手册核对：我从仓库内的 `ESP-AT-ESP8266-v2.3.0.0.pdf` 确认 `AT+CWMODE=<mode>[,<auto_connect>]` 有定义（PDF 第 55 页，印刷页 51），`AT+CIPSTA` 的 `+CIPSTA:ip:<"ip">` 格式与解析器一致，`AT+SYSSTORE` 在手册中。

**非阻塞的发现（记录，不要求先修）**
- **F-1 切速保护间隔内收到任何字节就判失败。** `platform_preflight_retime()` 在 20 ms 保护间隔内若 `head` 变化即返回 0。若 ESP 在重配 UART 时吐出杂字节，会被判成 `NO_SWITCH`/`RESYNC_FAIL`，而 ESP 实际可能已切换，需要断电重来。这是保守方向的失败，可接受；但失败原因在回执里分不开（是 TC 未完成、RX 不安静、还是 BRR 失败）。
- **F-2 `NEGOTIATE=NO_SWITCH/RESYNC_FAIL` 含义有歧义**，见 F-1。
- **F-3 PRE 之后同次 START 在实现上仍可能被受理**（若 PRE 在 45 s 内结束）。本批主机脚本不会发 START，所以不构成风险；W-04 的“已联网再发 `CWJAP`”问题因此在本批内回避，不是被验证过。
- **F-4 `AT+CWMODE=1,0` 若被 dev 构建拒绝，会让 Wi-Fi 步骤整体跳过。** 此时回执为 `PRE WIFI ok=0 code=NONE ms=0`。`ms=0` 表示根本没有尝试入网，**不是** Wi-Fi 证据。
- **F-5 构建环境记录：** VPS 系统 GCC 13.2.1 + Ubuntu Newlib 现在无法链接该候选（超 sector4 1,720 B）。Codex 的 Windows map 分账显示 Windows 的 `libc_nano.a` 只占 4,324 B，而 VPS 旧工具链链入约 10 KB，**U-01 的 5.6 KB 差值主要是 libc 链入量不同**，这与我早先的线索一致。此后 VPS 交叉验证改用 Arm GNU 14.2.Rel1，路径见回执。
- **F-6** 我在项目 `.venv` 里装了 `pyserial` 与 `numpy` 用于跑测试，未提交任何文件。

## 5. 批次卡

### 5.1 对象与上限（负责人已授权，PI 在此固化）

| 对象 | 上限 |
|---|---|
| 安装对象 | 仅 C 的 sector0/4；候选镜像最多 **2** 个版本（本次为第 1 个）；回退最多 **2** 次 |
| 上电会话 | 每个镜像最多 **8** 次；每次最多 **210 s** |
| 控制台命令 | 仅 `FIELD01 PRE`、`FIELD01 PRE 230`、`FIELD01 PRE 500`；每次启动 1 条 |
| 有效期 | 2026-11-09 至 2026-11-16 |
| 不包含 | `FIELD01 START`/`KEY`、TLS/MQTT 联云、sector3/Options/ESP 固件写入、`AT+UART_DEF`、`AT+RESTORE`、A/B/D/E 板、云与防火墙配置 |

### 5.2 现场 AT 白名单（PI 确认版）

只允许下面这些命令（均为 ESP **易失**操作，由固件发出，主机不直接发 AT）：

| 命令 | 说明 |
|---|---|
| `AT`、`ATE0` | 同步与关回显 |
| `AT+GMR` | 取数字版本；STRESS 阶段最多 50 次 |
| `AT+UART_CUR?` | 只读 |
| `AT+UART_CUR=<115200\|230400\|500000>,8,1,0,0` | 仅白名单速率，**不保存到 Flash** |
| `AT+SYSSTORE=0` | 必须先看到完整 `OK`，才能发 `AT+CWMODE` 与 `AT+CWJAP` |
| `AT+CWMODE=1,0` | 手册有定义；不自动连 ESP 里残留的热点 |
| `AT+CWJAP="…","…"` | 使用 C 的 sector3 里的现有配置；命令串用后清零；失败只取数字子码 |
| `AT+CWJAP?`、`AT+CIPSTA?` | 只判断入网信号与 IPv4 是否非全零，不输出内容 |

任何不在表内的 AT 命令不得发送。

### 5.3 阶段与门控

| 阶段 | 命令 | 进入条件 | 要得到的证据 |
|---|---|---|---|
| S0 | — | §4 全部具备 | 只读核对 C 身份、sector3 CRC、整片与 Options；安装候选到 sector0/4 并读回核对 |
| S1 | `FIELD01 PRE` | S0 通过；热点按 §6 准备好 | 115200 下的 `UART_CUR` 五元组、`WIFI` 子码或成功、`IPV4`、50 次 GMR 基线 |
| S2 | `FIELD01 PRE 230` | S1 的 `UART_CUR` 为 115200/8/1/0/0 且 `PRE RESTORE=OK` | 230400 协商结果、`uart_err`、每事务耗时、`RESTORE` |
| S3 | `FIELD01 PRE 500` | S2 的 `NEGOTIATE=OK`、`n=50`、`fail=0`、`uart_err=0`、`RESTORE=OK` | 同上，500000 |

S1 即使 `PRE END result=BLOCKED reason=WIFI`，只要回执完整且无 STOP 锁存，就算**取得了诊断证据**，可继续 S2。每个阶段都是一次独立上电（PRE 每次启动只执行一次）。

### 5.4 批内自治与停止条件

- 批内 Codex **不逐步请示**，按 S0→S3 自行推进，结束后一次性汇报。
- **立即停止并保留原件**：非预期复位、HALT/ROM；J-Link 身份或 Flash 与记录不符；`PRE END` 之外的 STOP 锁存（`B5 STOPPED` 出现在 PRE 窗口内且原因不是 45 s 就绪到期或 210 s 硬上限）；任何电气异常；STRESS 中**连续两次**试验 `fail>0`，或单次 `uart_err` 增量 ≥5。
- **`PRE RESTORE=FAIL` 的处理（对 Codex 回执里“首次即停整批”的澄清）：** 一次 `RESTORE=FAIL` **不**停整批。处置是：该速率标记为不通过 → 由现场人员断电 → 新启动重做一次 S1（115200）确认 ESP 已回到默认速率。若这次 S1 回执完整，批次继续（跳过该速率及其后续门控的阶段）；若 S1 也异常或 `UART_CUR` 不是 115200，才停批。
- 失败重试：未触发立即停止的可恢复故障，在新启动与新事务里**最多重试一次**。

### 5.5 预授权的“第 2 个候选镜像”（只在需要时使用）

下列三种情况允许 Codex 自行出第 2 个镜像并走一次 S0 安装，不需另批：
1. **S1 出现 `WIFI ok=0 ms=0`**（`AT+CWMODE=1,0` 被拒）：改为失败时回退到 `AT+CWMODE=1` 再试一次。
2. **S2 或 S3 出现 `NO_SWITCH`/`RESYNC_FAIL`**：增加一行 `PRE RETIME reason=<TC|RX_NOT_QUIET|BRR|STOP|DEADLINE>`，并允许调整 `ESP_UART_SWITCH_GUARD_MS`（从 20 ms 起，每次只改一个变量，说明依据）。
3. 其它**只为取得本批诊断数据**的小改动，需写入台账并说明原因。

第 2 个镜像之后若还需要再出，就停批，交 PI。

### 5.6 结束动作

批次结束（或停止）后：由现场人员断电；按既有回退入口把 C 恢复到原五板镜像（`gateway/microphone/unified_install.py --phase install` 的原五板制品；`--backup` 用 S0 备份；`--current-install` 指向最后成功的候选回执），回退后整片与原五板 `prior` 对照。**不得声称已断电**，断电状态在回执里保持 `PENDING`，直到有人确认。

## 6. 现场准备清单（给负责人）

1. **只让 C 上电**：A/B/D/E 不上电；C 通过 USB_UART 供电，COM15 为串口；安装用 J-Link 在 C 后接入。其余接线沿用 FIELD01 的做法。
2. **热点（S1 的关键）**：S1 测试的是 **C 的 sector3 里保存的那个热点**（SSID 15 字节、密码 8 字节），不是历史成功窗用的 RAM 注入那个（SSID 11 字节、密码 10 字节）。请让 sector3 对应的热点在线：
   - 开启 **2.4 GHz**（ESP8266 只支持 2.4 GHz），SSID 不隐藏；
   - 关闭热点的省电/无连接自动关闭；
   - 靠近 C；
   - 如果你不确定 sector3 里存的是哪个热点，请在 S1 前告诉 Codex。这种情况下 S1 只能证明“存的那个热点当前是否可用”，不能证明别的。
3. **每个阶段**：Codex 会提示你接线/上电与断电；`FIELD01 PRE` 只在上电后 45 s 内发出，其后最多 60 s 诊断，之后固件会停在待机，由你断电。

2. 每个会话的 `PRE-RESULT-public.json`、镜像 SHA、串口原件 SHA、工具版本、原生退出码、断电状态。
3. 汇总表：S1–S3 各速率的 `UART_CUR`、`WIFI`（`ok`/`code`/`ms`）、`IPV4`、`NEGOTIATE`、`STRESS`（`n`/`fail`/`uart_err`/`rx_high`/`ms`）、`RESTORE`、`END`。
4. 回退后的身份核对结果。
5. **Host/Windows 构建 PASS 与实板结果分栏**，不得混写。

## 8. PI 预先约定的解读（不得事后改标准）

沿用 [PREFLIGHT 设计 §6](PREFLIGHT-DESIGN-20261109.md)，补充：

| 现象 | 结论范围 |
|---|---|
| `WIFI ok=0 ms=0` | 入网**未被尝试**（`CWMODE` 或前置失败），不是 Wi-Fi 证据；按 §5.5 第 1 条处理 |
| `WIFI code=2/3` | 支持 sector3 凭据或热点名问题（H1）；改 sector3 是独立授权对象，由负责人另批 |
| `WIFI code=1` | 支持关联超时（H2）；需热点侧核对 |
| `WIFI ok=1` 且 `IPV4 ready=1` | sector3 当前配置可用；FIELD01 当时失败原因**未复现**，不得宣称已修复 |
| 某速率 `fail=0`、`uart_err=0` | 只说明 ESP→STM32 方向在 AT 级负载下可用；**不等于** TX 重载、CAN 同时活动或容量通过 |
| 500000 | Codex 的 WP-I 估算：正常路径约占 82% CPU，带硬件错误约 96%，CAN 3 帧 FIFO 在 500000 下有溢出风险。即使 S3 通过，500000 也只是**测量候选**，不会直接成为生产档位；生产候选优先看 230400 |
| 任何批/s | 不得由 PRE 得出；容量结论仍走 P3 同负载对照与后续窗口 |

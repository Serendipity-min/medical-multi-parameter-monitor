## 2. 不能多说的
1. **余量很薄。** 发送 CPU 占比 54%，对比 230400 的 27%；输入再高一点是否仍跟得上**未测**。
2. PUBACK 656 ms 超预测；R8 扫点显示 500 ms 起 QoS1 窗口吃紧，本窗未丢，但**没有 p50/p95**。
3. 数据有效性：PPG/SpO₂/PR 有效 134/139、131/141、129/141（W2 为全有效），输入端有少量无效段；RESP、RR 仍 0 有效。均为来源问题，不是传输，根因未判。
4. `svc_max` 20.59 ms，位置仍在 T0+140.2~150.1 s 之间，UNKNOWN。
5. **透传退出未确认**（STOP 后 `PASS_MODE_UNKNOWN`），现场冷停。这对生产是实质问题，见 §3-①。
6. 容量上限、300 s 完整性、血压：NOT_RUN。

## 3. 下一阶段（离线为主）
1. **WP-AI 透传生命周期（生产必需）。** 生产不会"STOP 后冷停"。需要设计并测：链路掉线/重连、`+++` 退出与 ≥1 s 保护时间、退出未确认时的降级（硬复位 ESP 或重走启动）、重入。先 Host，再决定实板。
2. **WP-AJ 余量测试（离线台架）。** 用 C 单板 transport bench 的透传 115200 模式，把入队速率扫到 12/14/16 批/s，找出队列开始上升的点；给出 115200 与 230400 的各自上限。这是回答"54% 够不够"的直接手段。
3. **WP-AK 生产镜像接入。** 非 FIELD01 的 five-appliance 镜像加透传 115200（230400 不带）；SHA 冻结后交我位级复核。
4. **WP-AD 续。** 分段 DWT 设计（已有）实施成测量镜像，定位 20 ms 峰值与每帧/每 tick 成本；它也是降低 54% 占比的唯一抓手。
5. PUBACK 分布：在 AJ 或下一个实板窗口输出 p50/p95/p99 与最大值时间点。

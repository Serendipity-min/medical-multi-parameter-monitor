## 2. 发送路径审读：接受，不加戏
Codex 未发现 STM32 发送路径的明确缺陷：短写→负值→关闭连接、重入受 `polling` 保护、缓冲所有权单一、IRQ 不写 TX、QoS0 声明长度与写入长度同源。我读了 `txcheck.inc` 与调用点，与结论一致。

**含义：** 审读没发现 C 侧缺陷，抬高"ESP 接收侧丢字节"的先验，但**不是证明**。寄存器写成功只证明本地提交，线上字节和 ESP 的接收仍看不到。

## 3. WP-AU 的使用限制（必须在读数时遵守）
1. **报文环只有 16 个报文，覆盖约 1.5 s。** C 在遗嘱后 5–6 s 才退出透传，故障报文大概率已经**不在 `B5 TXPKT` 环里**。判别要靠**累计计数**（`short`、`txe_to`、`reentry`、`gap_ms`）在 5 s 周期 `B5 TXCHK` 行之间的**增量**，精度 5 s，不要依赖环。
2. **累计 `gap_ms` 是会话最大值**，不能定位时间；出现异常增量时再看前后两个 `TXCHK` 行。
3. **TXACK 环 256 项、保留最近 16 s**，足以裁出遗嘱前 5 s 的逐条 PUBACK 间隔，按 Broker 遗嘱时刻对齐后使用。
4. 周期行线时约 15.2 ms；退出回执整组线时上限约 1.1 s，会增加故障后到 `+++` 的间隔，属已知观测代价。
5. 常规 SRAM 余量降到 16,120 B（S2 为 20,680 B），sector4 余 8,288 B；仍可用，但后续再加诊断前要先看这两个数。

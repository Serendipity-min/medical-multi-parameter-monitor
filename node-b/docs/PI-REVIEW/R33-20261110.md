## 4. 收尾路线（建议）
### 4.1 排空速度（WP-AV，离线，低优先）
当前标量回放单在途，每条约 0.55 s。允许 **2 个在途、按序确认**，理论翻倍（约 340 s 级）；不改云端载荷。若你认为"数据全部到达、实时不受影响"就足够，也可**接受 676 s 作为已知行为并记录**。需要负责人选择。

### 4.2 链路韧性（WP-AW，离线，建议做）
不依赖根因，直接降低断链的**影响**：
1. **重入策略：** 已建立会话的断链不再因"第三次"而停止；改为长退避继续重试（例如退避上限 30–60 s），LINK 停止仅保留给真正不可恢复的情形（例如 10 min 内超过 N 次且本地诊断异常）。理由：监护设备不应因为网络反复出错而永久停止上传。这是对我 R17 设计的修正。
2. **停滞感知的波形节流（缓解试验）：** PUBACK 超过阈值时暂停新的 QoS0 波形报文，避免 ESP 缓冲在 TCP 停顿时被灌满。Host 模型验证对 10.45 条/s 吞吐的影响。
3. 两项都默认由编译选项控制，并带 `B5 TXCHK`。

### 4.3 浸泡窗口（需放行）
WP-AW 通过复核后做一次**长窗口**：同一 Wi-Fi 条件、无人触碰，≥2 h（或负责人可接受的时长），统计断链次数、LINK 停止、数据完整度。同时作为"容量余量 + 稳态"的长窗口证据。断链率波动很大（6 次/1,415 s 对 0 次/1,209 s），**短窗口无法判断缓解是否有效**，这是必须做长窗口的原因。

### 4.4 其余必须项
- WP-AP（PF6 诊断镜像）复核 + 一次短窗口，验证硬复位路径。
- 五板 300 s 完整性：需要负责人确定验收输入（真人还是模拟器）、RESP/RR 有效性的接受标准，A 源头间断（PPG 质量门控）作为已知限制或另立节点 A 任务。
- 生产镜像冻结（最终 flag 组合、SHA、回退到原五板应用的决定），文档汇总，`CLAUDE.md` 提交。

## 5. 估算（含不确定度）
以今天的节奏（每轮 离线交付 + 复核 + 一个窗口 约半天到一天）：
- **WP-AV + WP-AW 离线与复核：** 约 1–2 天。
- **浸泡窗口：** 1 天（含 2 h 窗口与复核）。
- **WP-AP + 五板 300 s 完整性窗口 + 冻结与文档：** 约 2–3 天。
- **合计约 4–6 个工作日可达到"可结项"**：出口容量问题关闭、断网 3 分钟标量无损、链路自愈、冻结镜像和文档齐备；断链根因以"自愈 + 降低影响 + 已知限制"收尾。
- **断链字节级根因：** 无外部抓取器则**不承诺**；若浸泡窗口显示缓解后无 LINK 停止且数据完整，我建议不再追字节根因，把它记为已知限制与后续硬件排查项。

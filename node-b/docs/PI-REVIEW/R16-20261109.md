## 3. PI 发现的问题（需要处理）
1. **重入上限是"每次启动 3 次、成功后不清零"。** 生产监护仪连续运行，Wi‑Fi 抖动 3 次后设备就永久进入 LINK 停止，直到整机重启。这对生产是缺陷。应改为**稳定连接一段时间后清零**（例如连续 ≥300 s 在线），仍保留短时间内连续失败的上限。
2. **硬复位不可用时没有出口。** 退出失败即网络锁存。有一条纯软件的恢复路径可用：**STM32 自复位 + 启动期转义**——重启后若 ESP 仍在透传，启动序列的第一条 `AT` 会被当数据发给 Broker。因此启动时应先做"静默→`+++`→静默→`AT`"（命令态下多发 `+++` 不改变状态，只多约 2 s 启动时间；是否真无副作用需实板确认，现为 UNKNOWN）。有了它，硬复位不可用时的降级可以是"有界重试→STM32 软复位→启动期转义"，而不是永久锁存。STM32 复位需要保证不破坏五板/CAN 的停止语义，Codex 需写明。
3. **"ESP 在对端断开后是否自动退出透传"是 UNKNOWN。** 新逻辑对两种情况都有处理，但实板行为未知，直接影响退出/重连路径是否被触发。
4. **AJ 结论依赖输入口径。** 10.5 批/s 是输入**下界**（R6）。需要上界清单（含 NIBP、状态/事件帧、KEY/音频若启用）才能说 14 批/s 是否真有 33% 余量。
5. 硬件事实需要负责人：**C 板上 ESP 的 RST/EN 引脚是否可被 STM32 或外部电路控制？**（原理图/实物确认，见 §5。）

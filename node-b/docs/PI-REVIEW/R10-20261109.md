### 3.3 C 板接法（沿用 R5 的 CFG-U，不再讨论）
USB_UART 全程插着（电源+串口）；板上开关是上电闸门；J-Link 只接 SWD+GND，不接 3.3V/VTref/5V；J5 不接。**断电口径：** 开关 OFF 且电源灯灭。**禁止**带电插拔线、同时用 USB 与 J5 供电、用会拉 DTR/RTS 的终端打开 COM15。

### 3.4 单个窗口的标准流程（Codex 自治）
1. **准备**：Broker 与观察端就绪；热点开启（沿用 sector3 现配置，**不写 sector3**）；C 上电并读回身份，安装该窗口镜像（五板节点此时**不上电**，沿用“仅 C 上电安装”的做法），读回核对。
2. **上电五板**：A/B/D/E 上电，等待节点就绪。
3. **新启动与绑定**：COM15 已打开（`dtr=rts=False`）后，用 **J-Link 纯复位**得到新启动，收到 `FIELD01 DISARMED…` 横幅后，在 45 s 内发**一次** `FIELD01 START`。（由于 COM15 在开关 OFF 时不存在、ON 后才出现，直接上电会丢横幅；复位绑定是 R5 已验证的做法。**若控制器需要为此修改，属于工具修理，不重置授权计数，须有 Host 测试，PI 事后复核。**）
4. **窗口**：T0 → 150 s → `FIELD01 STOP`/硬停 210 s；全程采集 `B5 DIAG`（含 DWT、`svc_max_cyc`、`can_rx_*`）、Broker 逐流到达。
5. **收尾**：F-N115 正常停止后，C 保持工具可读状态；F-P230 硬停后按**冷启动**处理（开关 OFF 再 ON，再安装下一镜像）。
6. W1 完成后直接做 W2，两窗之间 Broker 与热点保持。

### 3.5 停止条件
沿用 R3 §5.4，另加：CAN bus-off 或持续错误计数上升、五板任一节点异常发热/异味/复位、`FIELD01` 固件自身的 STOP 锁存（`TIMER/CAN/LINK/DMA/SOURCE`）、START 在 T0 之前**连续两次**失败（先停下，交 PI）。停止后保存原件，不自动再上电。

### 3.6 回执（一次性）
台账（条目数与 SHA）；每窗的串口原件 SHA；每流逐秒到达表（交付、间隔、迟到）；**DWT 汇总**：`svc_cyc/svc_n`（均值）、`svc_max_cyc`、`tx_cyc/tx_b`、`await_cyc/await_b`、`rxstep_cyc/rxstep_b`、`irq_cyc/irq_n`、`can_rx_a/b`；QoS1 槽位占用与 PUBACK 分布；UART/CAN 错误；断电口径。**Host/Windows 构建 PASS 与实板结果分栏；估算与实测分栏。**

## 4. PI 预先约定的判读（不得事后改）

| 观测 | 含义 / 下一步 |
|---|---|
| W1 复现缺口（队列顶满、丢弃/顶替明显）且 `svc` 均值 ≥ ~30 µs | **N-14 成立**：问题在 C 的业务服务开销。下一步：降低 `service()` 单次开销→DMA 发送→（必要时）168 MHz |
| W1 复现缺口但 `svc` 均值很小（≈台架水平） | N-14 **不成立**；缺口来自别处（输入比下界高、CAN 抢占的间歇峰值、发送路径的其它开销）。PI 重新规划，**不再押任何优化** |
| W1 不复现缺口（跟得上） | 现场缺口与这版代码/条件不符（历史构建、热点、输入强度）。PI 先核对输入速率与历史构建差异，再重定位 |
| W2 零丢弃、队列稳定、无 UART/CAN 错误 | 透传 230400 是候选；仍须 WP-AA 的 230400 恢复在**硬件**上验证（H-JUNK 实板确认）后才能进入生产 |
| W2 出现非法帧/`PASS_UNKNOWN`/不能恢复 | 记录原因，停止透传路线的生产化；回到“降低服务开销”路线 |
| 任一窗口有 `uart_err>0` 或 CAN 溢出 | 单独列为缺陷，**不与容量结论混写** |

**注意**：FIELD01 窗口是 150 s。即使 W2 全绿，也**不能**签“五板 300 s 完整性”或“容量 PASS”；那需要同镜像更长窗口的后续批次（PI 届时再起草）。

## 5. 简化后的流程（以后沿用）

1. **一份文档=PI 放行+授权卡**（本文）。范围内 Codex 自治，**不再逐步请示**，只在 §3.5 的停止条件触发时停下，一次性汇报。
2. **镜像按 SHA 冻结**：范围内镜像无需再放行；范围外镜像需要 PI 书面放行。
3. **PI 只做三件事**：①事前冻结 SHA 与判读表；②事后复核回执与证据；③起草下一份授权卡。
4. **工具修理**（控制器、观察器、脚本）不重置授权计数，但必须有 Host 测试，PI 事后复核。
5. **负责人的现场动作只有三项**：开关电源、开热点与五板电源、确认断电。其余由 Codex 提示。

## 6. 负责人现场清单
1. 热点开启（2.4 GHz、SSID 不隐藏、关闭自动关闭），靠近 C。
2. 五板各自电源按此前窗口接好，**非人体输入**接好；CAN 接线保持不变。
3. C 只用 USB_UART 供电；J-Link 只接 SWD+GND；J5 不接。
4. 现场有人值守；任何异味、发热、异常声响，先断电再说。
5. Codex 提示时，拨开关上电/断电，并确认电源灯状态。

窗口结束后 C 保持当前镜像并报告；**原五板应用的回退由负责人在批后决定**（PI 的建议：W1/W2 判读完成、需要恢复原应用演示时再回退并验证启动）。

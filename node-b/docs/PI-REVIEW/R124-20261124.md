## 3. 标准之外的三个固件问题（§5 和 §10 都出现）
### 3.1 波形上传丢点增加到约 3 倍（R1 计算阻塞主循环）
| 录制 | 固件 | ECG 丢失 | 缺口间隔正好 2.00 s 的比例 |
|---|---|---|---|
| r123sim 20/12 段 | R1 | 15.5% | 40.3%（中位间隔 2.00 s） |
| r123sim ECG 段 | R1 | 18.1% | 38.1% |
| r116 | C2 | 4.2% | 0.4% |
| r119 | C2 | 6.5% | 1.4% |
| r108 | C2 | 2.0% | 1.2% |
| r106sim | C2 | 2.7% | 0.0% |

- **原因**：R1 每 2 s 做一次谱计算，B 的主循环因此停顿超过 100 ms。等待 CAN 上传的点超过 100 ms 就被丢弃（`b_canopen_app.c`）。
- **影响范围**：
  - 板上 HR 和 RR 不受影响：它们在上传前算好，模拟器下 HR、RR 都是 100% 有效，也没有断段。
  - 受影响的是云端波形显示，以及用 MQTT 原件做的离线分析。
- **修法**：把 R1 的计算拆成小段，分散到多次主循环调用里。输出值不变，可以用主机重放证明。

### 3.2 R1 由有效转无效时，会多发一帧“RR = 0、VALID”
- **出现频率**：r123human 中 RR 由有效转无效 8 次，其中 7 次在转换前紧挨着一帧“VALID、0.0”；r123sim 中也有 1 次（16:07:04，切档瞬间）。C2 时期 R108–R119 四份录制中一次也没有。
- **风险**：云端如果把这一帧当作真实呼吸率，可能误报“呼吸过缓”。
- **推测的原因**：B 用两个 CAN 报文分别发数值（x2120，无效时为 0）和有效标志（x2130，变化时才发）。主循环停顿后 CAN 发送积压，标志报文晚于数值报文到达网关，网关就把新的 0 和旧的“有效”拼在了一起。3.1 的停顿让这种情况从罕见变成了必然。**尚未核实**，需要查 C 网关的拼帧逻辑。

### 3.3 ECG 模式下出现一帧“RR = 9、VALID”（低频边缘误报）
- 时间是 16:01:54，ECG 模式，没有呼吸信号。
- 用 MQTT 补齐缺口后重放：窗末为 16:01:50、:52、:54 的三个窗都估出 8.8–8.9 次/分，并通过了全部门槛。
- 原因：接夹子后的基线长尾，加上之后的缓慢漂移，在略高于 8 次/分（R1 下限）的频率上形成了谱峰。R102 的阴性数据中没有这类情况。

### 4.4 次要分析（非预注册，只作参考，不改变 4.3 的判定）
- 用现场抽样计数（7、8、8、8、7，平均 15.2 次/分）作真值时：
  - 板上 R1 覆盖率 44%（≥40%），±2 以内 54/63（86%），**未达到 90%**。
  - 不达标的 9 帧中，3 帧是 3.2 节的“有效 0”，6 帧是 13（与 15.2 相差 2.2）。
  - 如果去掉“有效 0”，±2 以内为 54/60（90%），**正好在门槛上**。
- 真值本身不确定。抽样计数的范围是 14–16 次/分；若取 14，±2 以内为 95%。
- 结论：板上 R1 的数值落在 13–15，与频谱主峰（14.1）一致；覆盖率刚过 40%。在 3.2 修好、计数改为连续累计之前，不宜宣称 PASS。

### 4.5 负责人观察：RR 的有效时间比 HR 长
- T0+10 s 到屏气前：RR 有效 117/631（19%），HR 有效 52/631（8%）。节拍段内：RR 44%，HR 约 4%。
- **原因**：两者的瓶颈不同。HR 受 5–25 Hz 胸壁肌电噪声限制，丙的这一噪声在历次志愿者中最大。RR 用的是阻抗通道的低频起伏，不受这一频带噪声影响，只要呼吸节律规整就能出值。
- 自然呼吸段 RR 基本无效：频谱主峰在 6–8 次/分附近游走，不规整，这符合 R1 偏保守的设计。

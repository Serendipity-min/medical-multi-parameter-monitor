# R21 WP-AR 离线回执

WP-AR 使用独立的 `--production-diag` 构建选项，只能与生产 115200 透传的 `--pass-lifecycle` 同用。S1b/S1b-2 实板使用 R20 冻结镜像。本候选尚未上板。 [R21 批次卡](https://github.com/Serendipity-min/medical-multi-parameter-monitor/blob/797e8d9/node-b/docs/PI-REVIEW/R21-20261110.md)

## 计数口径

- 复用现有约 5 秒空闲诊断时隙，每次先冻结同一组计数再输出。`B5 PROD` 总数、三组 `B5 PROD_FLOW`、`B5 PROD_ACK` 和 `B5 PROD_SLOTS` 用同一个 MCU `tick` 关联。输出不进入启动等待、串口逐字节收发或中断。
- `enqueued` 统计进入 Router 的批，包括随后被顶替或丢弃的批。`published` 统计本地 MQTT 发布成功返回的非 replay 批，`acked` 统计相应 QoS1 PUBACK。QoS0 只加发布数。replay 发布和确认分别计数，按 `gateway/data_model/model.h` 的流枚举输出。`B5 PROD_FLOW` 的每流五项依次为入队、发布、确认、replay 发布、replay 确认。总数和每流计数均为自启动累计，跨会话重连保留。
- `slot_used` 为当前占用，`slot_peak` 为本次启动峰值，`slot_mean_milli` 为启动以来按占用时间加权的均值（千分之一槽）。`slot_full_ms` 与 `B5 PROD_SLOTS` 输出每档累计毫秒数的低 32 位，可用无符号差分计算窗口平均占用及满槽时长。槽位从分配到回收计时，会话失败清槽，累计值保留。
- `B5 PROD_ACK` 输出累计 p50、p95、p99 桶上界、最大值和 12 个桶计数。窗口分位可用前后快照差分计算，溢出桶仅能判断超过 2,516 ms。窗口实收/入队由同窗 Broker 新消息除以固件入队差分，replay 单列。固件发布和 PUBACK 计数供交叉核对。

保持发布策略、入队策略、槽数和复位恢复流程。附加日志使用同一控制台，实板需测输出耗时及队列影响。

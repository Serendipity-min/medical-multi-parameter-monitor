# PI 审查 R24：断网保留需求定案（方案 A）与离线工作包

**日期** 2026-11-10　**审查人** Claude（PI）　**承接** [R23](R23-20261110.md)

## 1. 需求（负责人 2026-11-10 决定）
**方案 A：标量与节点状态在约 3 分钟断网内无损；波形尽力而为；标量优先。**
- 标量：SpO₂、PR、HR、RR、温度；状态：节点 A/B/D/E 与网关状态。
- 波形（ECG、RESP、PPG）：断网后保留尽可能多的最近数据，超出部分允许缺口；**溢出时先丢波形，后丢标量。**
- 不放宽 Flash 边界（仅 C sector0/4，不得用 sector3/Options）；不改云端主题与载荷结构（需改动先报 PI）。

## 2. 离线工作包（Codex，Host 测试，不刷写、不上板、不动 B/A 节点固件）
先完成 R23 §6.1 的三项追查（第二次掉线原因、RESP 前导零、SNTP 161.8 s 时间线）；它们不依赖本需求，可并行。

### WP-AS：时间锚保持（C 侧）
- 断网后 UTC 锚用本地单调钟外推保持，保持期上限 ≥10 min（覆盖 3 min 目标并留余量）；重连后新鲜 SNTP 校正，校正不得使已存批的时间戳回退或乱序。
- 超过保持期仍无锚：恢复现行拒绝行为，并计数。
- 先核对谁产生 CANopen TIME；若 C 产生，在保持期内继续发 TIME，使 B 不再丢弃波形（B 固件不改）。若不是，列出需要改 B 的条件，**不实现**，报 PI。
- 给出外推漂移上限和失效后行为。

### WP-AT：标量/状态保留（Router）
- 标量和状态独立于波形历史环，至少保留 **240 s**（目标 180 s 加余量）；波形环满时只覆盖波形，不挤占标量。
- 回放顺序：标量与状态先于波形；回放速率不得拖慢实时 QoS1（实时优先，回放用剩余槽位）。
- 给出 RAM 预算：每批字节数、标量 240 s 的总字节、C 空闲 RAM 前后对比。若放不下，先报 PI，不自行降级。
- 回放耗时估算：QoS1 实时约 5.8 条/s，4 槽理论上限约 12 条/s，回放可用约 6 条/s；约 1,100 条需约 3 分钟。可行则不改载荷；若要合批，先出载荷变更提案，**不得直接改云端结构**。

### 验收（Host，无上板）
1. 模拟 180 s 断网后恢复：标量与状态零丢失、零重复、保序；波形丢弃先于标量。
2. 240 s 边界：超出才允许标量缺口，并计数。
3. 保持期内 `unstamped` 增量为 0；超过保持期行为与现状一致。
4. 重连校正不使时间戳回退。
5. 稳态路径不变：生产 115200 透传、入队、发布与 S1b-2/WP-AR 一致；`--production-diag` 计数保留并新增标量保留与回放计数。
6. 新 SHA；VPS 位级复核由我做；冻结镜像不变。

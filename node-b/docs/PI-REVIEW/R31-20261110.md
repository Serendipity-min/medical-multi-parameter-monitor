## 2. 收尾协议错误：不是断电造成的，很可能与断电提示后的某个物理动作有关
**时间线（回执 R30-S2C，MCU/对时估算）：**
- 断电提示后 3.592 s：Broker 记录 C 的遗嘱，原生行 `disconnected due to protocol error`（晚 0.720 ms）。
- 遗嘱后约 **3 s**：仍收到 A、B、D、E 四节点的运行态快照，心跳年龄 <0.5 s；C 本身继续运行、UART 继续输出。
- 遗嘱后 6.675 s：C 开始退出透传（与 S2/S2-b 的 5–6.5 s 检测期一致）。
- 遗嘱后约 12.5 s：COM15 消失，即板子真正断电。

**推论：**
1. **协议错误先于断电。** 断电（C 掉电）至少发生在遗嘱后 3–12.5 s，所以不是"掉电造成"。五块板和 C 在遗嘱后仍然在运行。
2. **同一指纹。** Broker 原因行、遗嘱先于 C 退出 6.7 s，都与 S2/S2-b 的 6 次非人工断链相同。
3. **STM32 侧仍然干净。** 遗嘱前后两个周期行覆盖 5.029 s，增加 19,384 B / 29 个事务，`short/txe_to/reentry` 增量 0，最大间隔未变，最后一次 `req/wr`=727/727。
4. **TLS 之后才出现错误的位置约束：** Broker 报的是"协议错误/畸形报文"，不是 TLS 解密失败或 socket 错误。TLS 记录有完整性校验，传输过程中的字节损坏会触发 TLS 错误而不是 MQTT 协议错误。因此**字节是在 ESP 的 TLS 加密之前被破坏的**，也就是 C→ESP 串口线、ESP 的接收缓冲或 ESP 的透传打包。这排除了"Wi-Fi/网络层损坏字节"这一支（H2 的字节损坏形式）。

**与"取下模拟器探头"的关系（证据强度：时间巧合，机理未知）：**
- **碰运气的概率很低。** S2-c 全程 1,209 s 没有断链，若自然发生率按合并估计 6/1,415 s，一个 3.6 s 窗口内碰巧出现的概率约 1.5%；按 S2-c 本窗实测估计更低（约 0.3%）。时间点紧接在断电提示之后，**最合理的解释是该时段内的某个物理动作触发了它**。
- **但我不能确认是探头。** 回执写明"现场实际拨动时刻没有独立记录"；提示后 3.6 s 内你可能做了不止一个动作（取探头、碰线、移动工装、靠近板子等）。
- **探头本身不是 C→ESP 数据路径的一部分。** 探头接在 A/B 节点（模拟器输入）。能影响 C 到 ESP 字节流的途径只有电气：**共用电源/地的瞬态**（插拔造成的电流或电位变化）、**ESD 或电磁耦合进 ESP 模块或其 UART 线**，或**ESP8266 的 3.3 V 供电瞬时跌落**（ESP8266 发射时有数百 mA 峰值电流，供电或去耦不足时，常见现象就是 UART 乱码或丢字节）。
- **这与"断链率随会话变化"相容：** 若根因是供电或电气噪声，不同会话的现场摆放、供电和手部动作不同，发生率自然不同。
- **反方向的约束：** S2/S2-b 的断链发生在稳态运行中，**没有记录到相同的物理动作**；所以"取探头"最多是触发因素之一，不是唯一原因。

**新假设 H5：ESP8266 的 3.3 V 供电或其 UART 线对电气扰动敏感，导致发送字节在进入 TLS 之前被丢失/破坏。** 支持：§2 推论 3、4；"紧随物理动作"；断链率随会话波动；这是 ESP8266 模块的常见弱点。不支持/缺口：没有任何电压波形；S2/S2-b 没有可疑的物理动作。**这是假设，不是结论。**

## 4. 下一步
### 4.1 S3 窗口：3 分钟标量无损（沿用 S2-c 镜像，不刷写；需负责人放行）
S2-c 的发送侧诊断已经就位，当前也没有新的 C 侧缺陷证据，不再等断链问题完全解决才做 3 分钟窗口——短断链本身已经在用保留环。
- 镜像：C 当前的 S2-c（code `8a790e5dea80b5c24abd2c76754d83f1984b0cd0bbe158a420708b2869c62f80`），**不刷写**。额度：上电 ≤2、热点切换 ≤4、隔离 Broker 1（开连接日志）。无 J-Link 复位、无 START、无血压泵。
- 流程：冷启动 → 稳态 ≥5 min → 热点关 **180–220 s**（≤230 s）→ 开 → 恢复 + 排空 + 稳态 ≥10 min（含排空完成后至少 5 min）。**窗口期间不触碰探头、线缆、工装。**
- 判据与预测：沿用 R26 §2 的预登记（标量按采集时间戳完整度 ≥99%、零重复、保序；断网期 `unstamped`=0；`anchor_valid=1`；标量排空 ≤6.5 min；排空期间队列 ≤16/24；`console_max` ≤40 ms；TXCHK 增量记录）。
- **窗内如发生非人工断链：** 不当作失败，继续窗口；记录断链时刻、原因行、TXCHK 增量；在账目里区分"计划断网"与"意外断链"两部分。LINK 停止仍是终止条件。
- **收尾探头试验（窗口数据采集结束之后、断电之前，用于检验触发假设）：** 在链路正常时，**记下时刻**后取下 A（或 B）的模拟器探头，等待 15 s，记录 Broker 有无协议错误/遗嘱；然后断电。预测：若探头触发，则 5 s 内出现协议错误/畸形报文（我给约 40%）；不出现则说明上次触发的是别的动作。**务必分别记录每个物理动作的时刻和顺序。** 该试验在所有数据采集结束后执行，不污染窗口判据。

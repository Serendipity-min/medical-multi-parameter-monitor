# R70 · C 启动只读诊断卡（GT-246-4 接法下）

2026-11-14，PI 签发，由 Codex 执行，负责人在现场操作。负责人已授权（原话：“授权签发 R70 诊断卡”）。依据为 R69 §3–§5。

## 0. 目的与边界
- **目的**：在 R68 接线不变的情况下，确定 C 上电后停在哪一步，区分以下三种情况：
  - ESP AT 握手失败，C 没有打开 CAN；
  - C 已打开 CAN，但与 GT 之间仍有总线错误；
  - C 本身没有运行。
- **结论口径**：只给出定位证据，不判定 GT 接入 PASS。即使本轮五板全部上线，也只记为“诊断通过”，正式冒烟另行安排。
- **授权范围**：按顺序给 GT 和五板上电；**被动**录制 C 的控制台串口（USART1，以往为 COM15，只接 RX 或以只读方式打开端口）；观察指示灯；用 GCAN Box **只读**查看通道状态；断电。可选的直连对照见 §2 S5。
- **不在范围**：任何烧录；调试器连接、Reset、Go；向 C 或 ESP 发送任何串口字节（包括回车）；改 GT 配置；改云端配置、ACL 或服务；拔线做故障注入；改热点设置。

## 1. 判读依据（WP-AZ `2c97094`）
C 上电后的控制台顺序如下（`gateway/b5/network_main.c:795–830`，`gateway/mqtt/src/platform.c:846`）：
1. `GW PASS_BOOT_ESCAPE` → `GW PASS_ESCAPE_SENT` → `GW PASS_AT_OK` → `GW PASS_BOOT_AT_OK`：MCU 与 ESP 的 UART AT 握手成功。**这一步不需要 Wi-Fi。**
2. `FIVE AUTO …`，然后 `UNI UART baseline=… total=…`：两个 CAN 控制器已打开。从这一刻起，C 应答 GT，CAN1/CAN3 应不再报错。
3. 之后才开始入网（Wi-Fi、TLS、MQTT），成功后云端网关 ONLINE。

失败标记：
- `GW PASS_BOOT_RESET_LOCKED`、`GW PASS_BOOT_UART_STORM`、`GW PASS_PRE_GUARD_FAIL`、`GW PASS_AT_UNCONFIRMED`、`GW PASS_BOOT_AT_UNCONFIRMED`、`GW FAIL LINK`：C 停在 CAN 打开之前。
- 有 `PASS_BOOT_AT_OK`，但没有 `UNI UART baseline`：CAN 初始化本身卡住（`b4_hw_init` 失败后进入死循环）。

## 2. 执行步骤
**S0 准备（全部断电）。**
- 拍照记录 R68 现状接线和 GT 拨码，**包括 AP 的实际位置**。
- 记录热点状态：已开启、2.4 GHz、热点名与 C 预置的一致（只写“一致/不一致”，不写名称和密码）。
- 主机准备好 C 控制台串口的被动录制，参数与 R40 相同，原始字节写入文件，并带主机时间戳。

**S1 GT 和从板上电。** 先给 GT 上电，等 SYS 闪烁；再给 A/B/D/E 上电。等 60 s，记录 CAN1–CAN4 指示灯。预期：CAN2/CAN4 绿闪或无红灯；CAN1/CAN3 此时可能已经变红（C 未上电，没有应答方）。这一现象**本身不触发停止**，只记录变红的时刻。若 GCAN Box 能只读显示各通道的错误计数、TEC/REC 或 BUS_OFF，截图一次。

**S2 C 上电，录 3 分钟。**
- 先启动串口录制，再给 C 上电。记录 **C 上电的北京时间，精确到秒**，并立即告知负责人转给 PI（PI 会从 VPS 同步录制 WSS）。
- 记录 C 电源灯、ESP 指示灯（若有）的状态。
- 记录 CAN1/CAN3 红灯是否熄灭，以及熄灭时刻（与控制台的 `UNI UART baseline` 行对照）。
- 3 分钟后再截一次 GCAN Box 通道状态（若可用）。

**S3 判读后的处置。**
- 情况 A：控制台出现 `UNI UART baseline`，CAN1/CAN3 转为绿闪。继续观察到 10 分钟，记录四节点上线时刻和网关 ONLINE 时刻（或一直 OFFLINE）。如果网关仍为 OFFLINE，说明问题只在入网，记录控制台中入网阶段的原文即可。
- 情况 B：控制台出现 §1 的任一失败标记，或者 C 上电 60 s 后仍没有 `UNI UART baseline`。保存原文，进入 S4，不重试。
- 情况 C：出现 `UNI UART baseline`，但 CAN1/CAN3 仍红灯常亮。保存原文和截图，进入 S4，不重试。PI 届时再处理位定时和收发器问题。
- 情况 D：控制台完全没有输出。按 STOP_TARGET 处理，检查并记录 C 的供电指示，进入 S4。

**S4 断电。** 先断 C，再断其余板和 GT。停止串口录制并计算 SHA-256。

**S5 可选对照（仅在情况 B 或 D 时，且负责人同意）。** 把接线恢复为 R68 之前的直连接法（不接 GT，每段三板），断电量两段阻值（预期约 40 Ω），然后按以往顺序上电，重复 S2 的串口录制 3 分钟。
- 直连下 C 正常：问题与 GT 接入有关（例如上电时序或供电）。
- 直连下 C 仍然失败：问题出在 C 或 ESP 本身，与 GT 无关。

对照完成后断电，接线保持对照状态，并在回执中写明。

## 3. 停止条件（STOP_TARGET）
以下情况立即断电，保存现场，不复位，不重刷：
- 任一板发热、冒烟或出现异味；
- C 反复复位（控制台反复出现启动行）；
- 出现 HALT/ROM 迹象；
- GT 的 SYS 不闪烁。

## 4. 回执要求（`R70-…-RECEIPT-…md`）
- 接线照片和拨码（含 AP）；热点状态（一致/不一致）。
- S1 指示灯和 GCAN Box 截图。
- C 上电的精确北京时间；控制台原文：完整列出首 3 分钟的每一行，并附带主机相对时间；串口原件 SHA-256。
- §1 中各标记出现与否，以及判读为 A/B/C/D 中的哪一种。
- CAN1/CAN3 红灯熄灭时刻（如有）；四节点和网关 ONLINE 时刻（如有）。
- S5 是否执行及其结果。
- 每项按 PASS / FAIL / NOT_RUN / UNKNOWN 填写。凭据、热点名称和 UID 不写入回执。

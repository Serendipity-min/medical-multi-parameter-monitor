# R15 WP-AI 透传生命周期

软件退出、确认、重试和重连已实现。现有 C 板的 ESP 硬复位绑定为 **BLOCKED**。历史硬件记录指出 STM32 没有连接或配置 ESP 的 GPIO RST，当前源码中的 `esp_mqtt_reset()` 只清理 STM32 本地 UART 接收状态。板级复位接口已由 Host 验证，ARM 默认实现返回不可用，进入锁存。需要核实实物 RST/EN 控制后才能完成自动硬复位。 [P5 网关硬件记录](../../../doc/P/04_第四阶段_P5_coreMQTT裸机迁移/技术讲解与复盘/01_P5_coreMQTT_网关运行机制与源码调用链_v2.0.md)

## W3 收尾原件

核对受限串口 JSONL，SHA-256 `815950801e8cd0c968dc10577ede44d433dcd7a07f8cb5a259e4a4ab370355b9`。以下相对时间为主机单调时钟。 [W3 实测回执](R12-W3-FIELD-RECEIPT-20261109.md)

| T0 后 | 记录 | 说明 |
| --- | --- | --- |
| 142.140 s | `FIELD01 WORK_CUT`，MCU 142,117 ms | 停止接纳新发布，继续排空。 |
| 150.015 s | `B5 STOPPED NO_AUTOREARM` | 定时 STOP 已锁存。 |
| 150.031 s | `B5 STOP_STATE tick=169124 reason=10 phase=0 required=884 written=884 unsynced=0 pending=0` | 最后记录的发布字节数相等，STOP 快照没有失步。 |
| 150.172 s | `GW PASS_MODE_UNKNOWN` | 调用旧 `platform_passthrough_leave()` 失败。 |
| 150.187–150.219 s | 四条 `B5 AT_EVENT` 的 MCU tick 为 161095、161116、161136、161240 | 均早于 STOP，属于最后两次透传发送的阶段转换。 |

旧 `gateway_network_close()` 先关闭 MQTT 本地状态，再调用 `platform_passthrough_leave()`。该函数要求剩余业务预算至少 5,800 ms。定时 STOP 后剩余为零，所以在 guard 和写 `+++` 前便返回失败。即使绕开预算，旧 guard 也拒绝在 STOP 后继续。W3 这次失败可以定位到未发送转义。旧路径另外只在发送前等待 25 ms，发送后等 1,001 ms，再查 `AT+CIPMODE?`，这些步骤在 W3 收尾均未执行。实际模块若收到转义是否接受、是否回复仍为 UNKNOWN。

旧 `pass_send` 遇 UART 错误或部分写入可锁存 UNKNOWN，`pass_recv` 将非法 MQTT 应答或链路文本转为 FAULT。旧 close 只尝试一次，UNKNOWN 直接拒绝后续退出或 AT。FIELD01 两个冻结镜像保留这条路径。

## 新路径

1. 先停发并锁住业务入口。等 USART TC，保持发送静默 1,001 ms，写三字节 `+++`（不带 CRLF），等 TC 后再静默 1,001 ms。静默期丢弃下行残留。只接受新发 `AT` 后的完整 `OK`，转义本身无回执也可通过。
2. 一次失败后最多重复一遍。第二次探测先结束可能留在命令缓冲区的转义前缀。仅退出流程的定长串口写入与清理可越过业务 STOP 门控。AT 探测期限 500 ms。确认命令态后先关闭套接字，再切回普通模式。关闭收到 ERROR 时，须以 `AT+CIPSTATUS` 确认没有套接字才能继续。
3. 转义、确认或关链无法完成时调用一次板级硬复位接口。接口实际触发复位后须在 3 秒内收到 `ready`，再以新 `AT` 确认。硬复位成功则销毁旧会话并回到完整启动。接口不可用、启动无回复或同步未确认时锁存，普通 AT、MQTT 发送及后续 close 重试均不得写入。
4. MQTT 或传输失败时将未确认票据及待发帧交现有 Router 失败路径，然后重新走配置、TLS、透传与 MQTT 建链。每次 STM32 启动最多三次重入，退避 2、4、8 秒，成功后计数继续保留以约束反复掉线。上限或不可恢复失步走 LINK 停止。业务 STOP 可完成有界清理，之后不重入。
5. 115200 保持不变。继续拒绝业务数据跨发送边界的三连加号，下行保留 CONNACK、PUBACK、PINGRESP 三种类型。 [Espressif ESP-AT 透传说明](https://docs.espressif.com/projects/esp-at/en/release-v2.2.0.0_esp8266/AT_Command_Set/TCP-IP_AT_Commands.html#cmd-send)

步骤码均以 `GW PASS_` 开头。保护和同步用 `PRE_GUARD_FAIL`、`ESCAPE_WRITE_FAIL`、`ESCAPE_SENT`、`POST_GUARD_FAIL`、`AT_UNCONFIRMED`、`AT_OK`、`ESCAPE_RETRY`。关链用 `CLOSE_UNCONFIRMED`、`SOCKET_ABSENT`、`SOCKET_UNCONFIRMED`、`NORMAL_UNCONFIRMED`。复位用 `HARD_RESET`、`HARD_RESET_UNAVAILABLE`、`HARD_RESET_UNCONFIRMED`、`HARD_RESET_OK`。重入用 `REENTRY_BACKOFF`、`REENTRY_ATTEMPT`、`REENTRY_OK`、`REENTRY_LIMIT`。

## Host 验证

`python -X utf8 gateway/microphone/test_unified.py` 的生产透传组使用真实 AT 状态机、网关与 coreMQTT，ESP/TLS/SNTP 由合成对端响应。Host 22 组通过，生产透传场景逐项断言如下。

1. 转义无独立回执，AT 确认后正常关闭。
2. 第一次 AT 无回复，静默期伪 OK 被丢弃，第二次确认成功。
3. 两次 AT 无回复，硬复位不可用并锁存，后续调用不重复复位。
4. 硬复位后缺少 `ready`，保持命令禁入。
5. 硬复位后缺少 AT 回复，保持命令禁入。
6. 合成复位、`ready` 和 AT 均成功，重走启动。
7. `CLOSED` 后重新走 TLS/MQTT，并执行三次重入上限。
8. STOP 发生在保护间隔且剩余业务预算归零，清理成功，拒绝重入。
9. 模块已回命令态，重试清理转义残留并确认。
10. 前保护 TX 未完成，转义未写出并触发复位降级。
11. 转义写入部分完成，按有界重试恢复。
12. 后保护 TX 未完成，按有界重试恢复。
13. 关闭套接字超时后命令锁存。
14. 关闭返回 ERROR，状态确认没有套接字，允许归一。
15. 关闭返回 ERROR，状态仍有套接字，命令锁存。
16. 归一到普通模式超时后命令锁存。

## 待实板问题

- 核对 C 板是否可由 STM32 独立控制 ESP 的 RST/EN，确认脚位、电气、脉宽以及对 STM32/CAN 的影响。J-Link 纯复位的既有证据只覆盖 STM32。
- 核对实际 ESP 在套接字断开、STOP 与 UART 错误下的转义行为，以及硬复位后从 `ready` 到 TLS/MQTT 重建的时间。
- 对照实际 STOP、服务和 UART 时序，核实退出时两侧静默、串口残留丢弃与重入次数。

全部实板项为 **NOT_RUN**。

## 4. 已知限制与设计取舍（ACCEPTED，不是缺陷）

- **断网无损只覆盖标量和状态**：波形尽力而为。全波形 3 min 约需 126–190 KB，超出 192 KB SRAM 的可用量（R23§3.1、R24）。
- **云端不补传历史状态**：断网期间的节点状态只保留在 C 的 736 项状态环里（R25§3）。
- **体温只播报"体表温度约 X °C"**：探头放置 60 s 后才播，不判断正常或异常（R44§3）。
- **RR 不作判据**：工装模拟器只输出 ECG，RR 的 VALID 比例为 0（R37、R43）。
- **状态帧仍标 MOCK**：正式档的 FAULT 和状态帧仍带 MOCK 标记，播报门禁只用生理 LIVE（R46 O1）。
- **sector3 主写入路径时间不够**：按现在的读速，擦除加写入在 180 s 内做不完，再写 sector3 需要另行设计（R51 O1）。
- **播报规则的两个行为**：同一参数 5 min 的重播间隔在离线时不清零，所以复电后 TEMP 约 92 s 才播；重启后端会补播一条（R65 §3）。
- **TTS 状态是写死的**：`tts_enable(power_good=true, protocol_confirmed=true)` 由固件直接设定，模块断电时固件察觉不到（R63）。
- **gateway-c 写 ACL 仍是通配**：收窄要在 C 在线时验证，是待做的加固项（R64）。
- **不引入 FreeRTOS**：瓶颈是逐字节开销，sector4 也放不下内核（R6、R9）。
- **测试一律用开关断电**：没有续接记录的软复位会锁定生产镜像（R17）。

## 6. 答辩可讲的技术难点（精选）
1. **出口容量从猜测到量化**：用 DWT 周期计数器把每字节开销拆到 svc、tx、rx 各环节，否定了"提高波特率"和"引入 RTOS"两条路，最终改用透传，速率从 8.08 提到 10.46 批/s。
2. **断网无损的需求拆分**：先对账找出三层缺口，再按 SRAM 预算证明全波形无损做不到，与负责人商定"标量无损、波形尽力"，实测 203 s 断网标量 0 缺失。
3. **断链定性与排除法**：没有 UART 抓取器，靠 Broker 原生日志、TLS 完整性和发送侧计数，把问题定位到"字节在 TLS 之前被破坏、STM32 发送侧干净"，再把处置从"停机"改成"自愈"。
4. **冷启动两个缺陷叠加（WP-AX）**：从现场锁停追到源码，用 Host 复现，最小修复，实板复测通过。
5. **Flash 安全**：只写 sector0/4；sector3 写前判定时间预算；只补写 1 个提交字完成恢复；每次写入都整片双读，前后比对。
6. **位级可复现构建**：每个候选镜像，PI 都在独立环境重编并逐位比对，关闭新功能后应回到上一个已验证镜像。
7. **云端到板载喇叭的播报链路**：规则只用 LIVE 数据；MPB1 帧以单调时间戳防重放、带 TTL；C 端队列有界、每轮工作量有上限，不拖慢透传主循环。
8. **B 板算法**：BIO_V2 每个无效状态都带原因位，单路故障只清本路，ECG 和 RR 多档名义速率通过。
9. **用上界代替缺失的测量**：拨开关时刻没记下来时，从系统约束推出可证明的上界（R65）。

## 7. 流程与协作教训
1. **证据分层，不跨层升级**：Host PASS 不等于实板 PASS；SEND OK 不等于服务器收到；页面生成不等于喇叭发声；150 s 工作段不等于容量 PASS。
2. **预测先登记，失败如实记**：811 ms、161.8 s、676 s、断链概率约 70 %、探头触发约 55 % 等预测都没达到，全部保留，不事后改线。
3. **PI 的错误要登记**：R1 过采样、R3 的 flow=0、R11 选错指标、R12 漏读 `allow_new`、R16 判"无硬复位"、R17 的停机设计、R22 的覆盖率算法、R34 的措辞、R35 漏核硬复位交互、R47 漏核时间预算、R63 把喇叭规格误读为 1 Ω。
4. **授权要精确到对象、上限和有效期**：一次性授权不复用，现场额度以台账为准。负责人替 PI 放行时，必须事后复核并记下原话。
5. **时间基准要统一**：Codex 本机比服务器慢约 8–9 s。播报复核一律用服务器时钟；现场必须记下真实开关时刻，否则只能推出上界（R52 → R65）。
6. **先修观察工具，再判被观察对象**：活动 RAM 读取、观察器遇首个错误即停、主机把人工等待算进计时等工具问题，都曾被误当成固件问题。
7. **硬件未验证的路径要排期**：PF6 硬复位一直列为"未验证"，到窗口 3 才被现场撞到。
8. **窗口前置条件单独准入**：Wi-Fi 配置、串口、供电、云服务驻留余量要事前检查，避免浪费唯一的 START 或窗口。
9. **安全纪律**：真人窗口不接市电、J-Link 拔下、双人分工、泄压手段事先确认；真人数据只存受限归档。
10. **凭据纪律**：令牌和账号不进仓库、回执和对话，PI 不读取凭据内容。
11. **文档格式**：R43 冻结包里有表格被空行打断，留待仓库整理时修正（R44）。

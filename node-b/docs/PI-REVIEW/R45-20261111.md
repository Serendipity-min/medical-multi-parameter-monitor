# PI 审查 R45：C 板上电直连正式云端的方案（WP-AY0）

**日期** 2026-11-11　**审查人** Claude（PI）　**承接** [R44](R44-20261111.md)　**背景** 新版监护页面已上线（`web-20261111-04`，分支 `claude/cloud-ui-v2`）；负责人反馈：输入令牌后页面一直显示"等待设备上电 / 采集网关离线"，C 上电也看不到数据。

## 1. 现象与根因（源码与服务器只读核对）
冻结镜像 WP-AX（`b057a65`，code `0fa2e774…`）是为隔离 Broker 窗口设计的，与正式云端在四处不匹配，所以 C 上电后数据到不了正式页面：

| 项 | WP-AX 冻结镜像 | 正式云端（H3，线上） | 依据 |
|---|---|---|---|
| MQTT 端口 | 编译期固定 28895 | 只有 8883 在监听；28895 的隔离 Broker 已停 | `gateway/dual_can/build_arm.py:48,75`；服务器 `ss` |
| 网关 ID / 主题 | `GW-B5-001`（`mpm/v1/GW-B5-001/…`） | 后端只订阅、只授权 `GW-C-001` | `build_arm.py`（`--b5`）；`cloud/backend/app/main.py:42`；`cloud/broker/acl` |
| MQTT 身份 | 只接受 `b5-c-isolated` / `b5-gateway`，否则判配置无效、不联网 | ACL 只允许 `gateway-c` 写 `mpm/v1/GW-C-001/#` | `gateway/b5/b5_policy.c:3–4`；`cloud/broker/acl` |
| 节点编号 | 五节点：TEMP→NODE-D，NIBP→NODE-E | 线上后端（`5da742f`）只接受 NODE-A/NODE-B/GATEWAY | `gateway/data_model/roles.h`；`5da742f:cloud/backend/app/models.py:28` |

另：WP-AX 把所有数据强制标为 `MOCK/synthetic`（`b4_gateway.c:165`），页面会显示"MOCK 标记"。

**结论**：这不是页面或令牌的问题，只改服务器或只改 C 的 Flash 配置都不够，**至少要出一个面向正式云端的新镜像**。H3 时期 C 能上正式云，用的是另一套构建（`gateway/physical_can/build.py`，8883、`GW-C-001`，见 `doc/H3/H3-AC-CLOSEOUT-FINAL-HANDOFF.md` §12），不是现在的五板镜像。

## 2. 令牌
负责人提供的令牌与服务器上的只读令牌是**同一个**（指纹一致）。它已经出现在聊天记录中，视为泄露，需由管理员更换：生成新令牌 → 更新 H3 后端环境中的 `MONITOR_VIEW_TOKEN` → 重启 `medical-monitor-h3-webbackend` → 新令牌只交给负责人，并更新 VPS 上的 `~/.config/mmpm/monitor-view-token`（权限 600）。演示模式不需要令牌；令牌只用于查看服务器上的真实数据。

## 3. 方案 WP-AY0（需负责人放行；放行前不生效）
**目标**：C 板上电 → 约 1 分钟内自动出现在正式页面上（记住了令牌的大屏无需任何操作）。

**F 固件（Codex，离线）**，基线 `b057a65`，新增构建开关 `--formal-cloud`，关闭时与 WP-AX 逐位一致：
1. 网关 ID 改为 `GW-C-001`，TLS 端口 8883；只在 `--formal-cloud` 下放开 `build_arm.py` 对 28895 的限制。
2. `b5_identity_allowed()` 在 `--formal-cloud` 下改为只接受正式发布账号（`gateway-c` 及其 client_id），隔离身份不再放行。
3. 数据来源标记改为 `LIVE`（`synthetic=false`）。这是真实采集数据，属于正确标记；后端已支持 `LIVE`。网关自身状态帧保持原语义。
4. 其余（透传、断网保留、WP-AW/AX 链路恢复）不改。交付 boot/code/HEX、SHA、余量、Host 回归，并证明关闭开关时与 WP-AX 逐位一致。我用 `/mmpm-rebuild-verify` 复核。

**S 服务器（管理员协助；动正式云端需当次授权）**：
1. 后端升级为 `field01` 分支的后端（已支持 `MPM_NODE_PROFILE=five`，接受 NODE-D/E），设置 `MPM_NODE_PROFILE=five`、`MONITOR_GATEWAY_IDS=GW-C-001`，保留旧运行时用于回滚。
2. Broker：确认或重设 `gateway-c` 口令；ACL 不用改（`gateway-c` 已能写 `GW-C-001/#`，`backend-reader` 已能读）。

**B 板端（现场窗口，需单独放行：Flash 写入为独立授权对象）**：
1. 写 sector3：host 为正式域名、Wi-Fi、`gateway-c` 用户名/口令、client_id（沿用 `b5_sector3_package.py` / `b5_sector3_write.py` 的流程，凭据不入库）。
2. 安装新镜像 sector0/4（`unified_install.py --phase install --cold-boot`），读回核对。回退：WP-AX（`0fa2e774…`）+ 原 sector3 备份。
3. 验收：五板冷启动 → 正式页面在 ≤90 s 内出现实时数据，来源为 LIVE；断电 → 页面回到"等待设备上电"；再上电自动恢复。不涉及真人。

**与 AI（WP-AY）的关系**：WP-AY0 是 AI 真实云端实测的前提。AI 下行播报另起合同，在 WP-AY0 验收后进行。

## 5. 负责人决定（2026-11-11）：放行 WP-AY0
按 §3 顺序执行，每一步完成并经 PI 复核后才进入下一步：F（固件，离线）→ S（服务器，管理员协助）→ B（现场窗口，另出批次卡）。

**Codex 任务卡 F（离线；不上电、不刷写、不动服务器；基线 `b057a65`）**
1. `gateway/dual_can/build_arm.py` 新增 `--formal-cloud`：网关 ID `GW-C-001`、TLS 端口 8883；只在该开关下放开 28895 限制。
2. `gateway/b5/b5_policy.c`：`--formal-cloud` 下 `b5_identity_allowed()` 只接受正式账号（用户名 `gateway-c`，client_id 由编译常量给出，与 sector3 一致），隔离身份不再放行；未开启时行为不变。
3. 数据来源：`--formal-cloud` 下遥测 `synthetic=false`、`source=LIVE`（`b4_gateway.c:163–165`、`b5_prepare_publish`）；未开启时仍为 MOCK。
4. Host 回归：正式身份通过、隔离身份拒绝、主题前缀 `mpm/v1/GW-C-001/`、LIVE 标记；现有 30 组与定向 pytest 全过。
5. 交付：源码提交、带开关构建的 boot/code/HEX 与 SHA、Flash/RAM 余量；**不带开关构建必须与 WP-AX（`0fa2e774…`）逐位一致**。sector3 打包工具（`b5_sector3_package.py`）如需支持正式身份，一并修改并给出离线测试，凭据不入库。

## 6. 令牌与"两套演示"（负责人提问，2026-11-11）
- 令牌不是演示用的：它是查看服务器数据的只读访问凭据。以前输入它能看到模拟数据，是因为服务器上一直运行着模拟发布服务（`medical-monitor-mock`，网关 `GW-DEV-001`），旧页面可以切过去。新页面不再连接 `GW-DEV-001`，所以现在输入令牌只看到"等待设备上电"。
- WP-AY0 上线后，令牌保护的是 C 上报的**真实数据**，必须保留；它已在聊天中泄露，在 S 步骤里由管理员更换，届时一并生效即可。
- 服务器端的模拟数据与页面本地演示模式确实重复。建议保留页面本地演示，在 S 步骤中停用服务器模拟（`medical-monitor-mock`、旧的 phase-1 后端 `medical-monitor` 及 `GW-DEV-001` 授权），停用前保留配置备份。

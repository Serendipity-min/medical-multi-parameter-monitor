# R27 非人工断链离线追查

原件为 R22 WP-AR 和 R26 S2 的 UART、Broker 订阅记录。两次原件的 SHA-256 均与既有回执一致。五次断链以 Broker 遗嘱时刻为基准，另核对 C 开始退出透传前的区间。 [R27](https://github.com/Serendipity-min/medical-multi-parameter-monitor/blob/3c32b22/node-b/docs/PI-REVIEW/R27-20261110.md) · [R22 回执](R22-AR-FIELD-20261110.md) · [S2 回执](R26-S2-FIELD-20261110.md)

## Broker 日志

原隔离服务为 Mosquitto 2.0.18。配置只启用了 `error`、`warning`。对 R22 一次、S2 四次分别查询从 C 退出前 20 s 到退出后 5 s 的同服务 journal，均为 0 行，因而五次断链原因均为 UNKNOWN。相同方法能查到 S2 启动准备期的一条已知 TLS 诊断，证明 journal 查询能命中该服务已记录的行。

已核对该版本支持 `connection_messages true`、`log_dest stderr` 和 `notice`、`information` 等级，安装二进制包含协议错误、畸形报文、对端关闭及超时的原因模板。S2-b 使用独立临时配置副本，保留原 ACL、端点和 TLS 策略。实测隔离 TLS 预检的两次连接和两次断开均进入此次服务的 journal，日志门槛通过。

## 畸形载荷拼接检验

下表只列解析失败点前后各 40 字节的结构，`dN` 表示 N 位十进制数字。两条原件均为 ASCII，偏移从 0 开始。

| 原件 | 失败点之前 | 失败点之后 | 后缀与比对 |
| --- | --- | --- | --- |
| R22 RESP，第 8,963 条，683 B，偏移 574 | 六位小数数组连续四段，末尾是负号和一位整数 | 直接接六位数字，随后继续出现小数与逗号 | 全部 109 B 后缀只有数字、符号和分隔符，无新 JSON 字段。共 52 个逗号分隔片段，尾部残缺。与相邻 ±10 s 的合法载荷无长度 ≥15 的连续匹配，拼接来源 UNKNOWN。 |
| S2 PPG，第 918 条，631 B，偏移 378 | 六位小数的采样值，最后一个采样值后是逗号 | 数组内部突变为 `source` 键的残片，接 `synthetic`、`unit` 键 | 完整 253 B 后缀与 87 ms 前第 913 条合法 RESP 的字节偏移 92 起逐字节相同，后续还包含 `value`、`sample_rate`、`samples`。另有更早的 RESP 记录出现同样片段，因此内容吻合，具体来源帧无法唯一确定。 |

S2 PPG 确认包含另一类 JSON 载荷的中段，单纯尾部截短无法形成这种结构。R22 RESP 的内部小数异常和超出 50 点的片段数也不能用单纯尾部截短完整解释，但缺乏可识别的拼接证据。两条畸形各在其附近遗嘱前约 41 ms。载荷混入加强了 H1，原订阅记录仍无法独立确认混入位置是在 C→ESP、ESP 内部还是观察链。另三次 S2 断链前未观察到畸形载荷。

## 五次断链前的 UART

| 断链 | 遗嘱前 10 s 的 UART | 遗嘱之后、C 退出之前 |
| --- | --- | --- |
| R22 | 84 行，无 `GW` 行。两个快照的槽位 2→1，实时队列 0→5，PUBACK 增 31。 | 槽位曾满，实时队列升至 23；相邻快照间仅新增 4 次 ACK，均落在 1,501–2,516 ms 桶。 |
| S2 第 1 次 | 85 行，无 `GW` 行。槽位 1→2、实时队列 0，PUBACK 增 29。 | 实时队列升至 14，出现 4 次顶替，累计 ACK 最大从 641 升至 1,536 ms。 |
| S2 第 2 次 | 86 行，无 `GW` 行。槽位保持 2、实时队列 0，PUBACK 增 30。 | 记录到本地重入计数清零，实时队列升至 7，累计 ACK 最大升至 1,986 ms。 |
| S2 第 3 次 | 85 行，含上一轮的 SNTP 重试与重连；本会话只存在约 2.343 s。没有足够的同会话快照判定断链前趋势。 | 槽位采到 4，实时队列 4，两个快照间增加 13 次 ACK。 |
| S2 第 4 次 | 86 行，无 `GW` 行。槽位 2→3、实时队列 0，PUBACK 增 38。 | 槽位 4、实时队列 8，累计 ACK 最大升至 2,496 ms。 |

五个窗口的 UART 基线后错误增量和 CAN 溢出均为 0。除连接仅 2.343 s 的事件外，遗嘱前仍能看到 ACK 持续推进，没有共同的断链前满槽或实时队列积压。较长 ACK 与积压主要见于遗嘱后至 C 检测退出的几秒内。这里的槽位是约 5 s 采样，峰值与先后顺序只按记录分辨率判读。

## TX 对账边界

- `B5 IO tx_calls` 是 MCU 发起发送的次数，`tx_ms` 是最近一次发送耗时。透传的 `pass_send()` 记录 `required`、`written`，能反映 MCU 本地写入。现用生产候选周期诊断没有总 TX 字节；`B5 TX_CONTEXT` 与 `B5 AT_EVENT` 是停止上下文快照。两份原件没有可逐包对账的上下文。
- `B5 IO tx_ok`（`tx_confirmed`）和 `tx_bytes_total` 由普通 AT 的 SEND OK 路径累加，透传不会为每个发送分片更新它们。带传输剖析的 FIELD01 可输出 MCU 侧 `tx_b`，S2 未启用。
- 透传正常只解析 CONNACK、PUBACK、PINGRESP。五个会话的断链前未记录到属于该会话的 ESP `busy` 或 `ERROR`；第 3 次之前的 SNTP 错误属于上一次恢复。退出后的 AT 确认只验证重新进入命令态。MCU 写入次数、Broker 发布计数和 QoS1 确认都无法提供 ESP 实收 UART 字节数。 [串口发送与透传接收](../../../gateway/mqtt/src/platform.c) · [诊断输出](../../../gateway/b5/network_main.c)

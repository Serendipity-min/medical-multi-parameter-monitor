## 2. 225 次错误的来源：PI 的假设（未证实）
**假设：ESP8266 上电时 ROM 以 74880 baud 打印启动日志（`ets Jan 8 2013,rst cause…` 等约一两百字节），STM32 的 USART3 以 115200 接收，全部成帧/噪声错误。** 依据：
- ESP8266 的 ROM 启动串口速率为 74880，之后 AT 固件才切到配置速率；
- 此前所有五板/FIELD01 窗口都用 **J-Link 复位 STM32**（ESP 一直带电运行，不重启），所以从未遇到；S1 是**第一次开关冷上电**，C 与 ESP 同时上电；
- 225 与一段 ROM 日志的字节数同量级。

**可证伪的预测（请用原件核对）：**
1. `uart_err` 的增长**只在上电后约 0.1–1 s 内**，之后恒定；
2. 锁存时间点在 `ready` 之前或附近；
3. 若错误在 ESP 启动完成后仍持续增长，或 ESP 未装/保持复位时也有错误，则本假设不成立，需另查（USART3 引脚初始化毛刺、RX 环溢出 `uart_overflow_total`、硬件噪声）。

## 3. 修复规格（WP-AQ，离线）
1. **启动期错误基线：**冷启动先清空 RX，等待 ESP 启动完成（`ready` 行，或 RX 静默 ≥200 ms 且上限约 3 s），**然后一次性**把 `uart_error_baseline` 重设为当前总数，再做转义与 `AT`。DIAG 复述 `boot_uart_err0=<n>`，保持可见。
2. **不屏蔽真故障：**基线只在启动期设一次；其后任何增长仍按原规则停止。启动期错误设**风暴上限**（如 >1,024 视为异常，停止并报码），避免把线路故障当作开机噪声。
3. 不改 J-Link 无记录复位的锁存策略；不改 FIELD01 冻结镜像（证明 F-P115/F-P230 重编 SHA 不变）。
4. **Host 用例：**对端上电先发 74880 乱码再发 `ready`；乱码后无错误→放行；放行后再出一个错误→停止；乱码超上限→停止；ESP 不回 `ready`→走既有未确认路径；无乱码的暖启动不受影响。
5. 修复后给新候选 SHA；我位级复核，重新冻结 S1。

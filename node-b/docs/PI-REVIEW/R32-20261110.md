# PI 审查 R32：负责人回忆的收尾动作顺序与新增离线检验

**日期** 2026-11-10　**审查人** Claude（PI）　**承接** [R31](R31-20261110.md)

## 1. 负责人回忆（2026-11-10）
断电提示后：**先取下 SpO₂ 模拟探头，再关闭 C 电源（COFF）；另外 4 板（A、B、D、E）电源没有关。** 各动作的精确时刻未记录。

## 2. 对"先关 C 电源、其他 4 板还在发消息"的判断：不成立
- 遗嘱后约 3 s，A、B、D、E 的快照仍到达，C 也仍在运行；COM15 在遗嘱后约 12.5 s 才消失。**C 掉电发生在协议错误之后**，所以协议错误不可能是"关 C 造成的"。
- C 掉电以后，ESP 也断电，不再有任何字节送到 Broker；其他 4 板继续向没有接收方的 CAN 总线发帧，只会让它们自己看到无应答/总线错误，**不会产生 Broker 的 MQTT 协议错误**。
- 4 板没断电本身不是这次事件的原因；但完整收尾应当把它们也断电，避免它们长时间在无接收方的总线上空转。

## 3. 动作顺序与时间线的吻合
提示 →（约 3.6 s）协议错误 →（约 3 s 后节点仍在线）→（遗嘱后约 12.5 s）C 掉电。若"取探头"发生在提示后几秒，"关 COFF"在其后约 9 s，则两者与时间线吻合，**取探头成为首要嫌疑**（仍是时间相关，未证明因果）。

新增一条**软件侧**路径（H6，假设）：取下 SpO₂ 探头使 A 的输出变为无效/短批（R22 离线分析已显示 A 的质量门控空档后第一批是 1 点 INVALID），C 的报文种类和长度在那一刻发生变化。S2 那条畸形载荷恰好是 PPG；是否存在"某类数据变化→C/ESP 路径异常"，需要用数据检验，不能只用电气解释。

## 4. 对 R28 解读的修正
R28 把畸形 PPG 载荷解读为"连续丢字节"。**同样的观测也符合"插入了 253 字节旧数据"**：Broker 按声明长度 L 读取，PPG 载荷后部被一段与 87 ms 前 RESP 完全相同的 253 B 填满，其余真实字节被推迟到下一条报文位置，下一条报文头被错读，随后协议错误。两种解读都意味着"字节流在 TLS 之前被破坏"，区别在于"丢"还是"重复旧数据"。**重复旧数据更像环形缓冲指针问题（读到上一圈的残留），而不像单纯的串口丢字节。** 我也核对过简单的"STM32 发送缓冲区残留"：RESP 偏移 92 的字节在缓冲区中的位置与 PPG 偏移 378 不同，同一发送缓冲区的陈旧残留不能解释这个偏移。

## 5. 新增离线检验（Codex，不需新授权）
1. **探头动作时刻：** R31 §3 的三项检查保持。S2-c 里 A 的 SpO₂/探头位在哪个 5 s 快照翻转，相对遗嘱（MCU tick 1,236,670，±309 ms）先后如何。
2. **A 数据变化与断链的统计关系：** 对 R22 一次、S2 四次、S2-b 两次、S2-c 一次的断链，各查断链前 10 s 内是否有 A 的 PPG INVALID/空档事件。A 的空档平均每 40 s 左右出现一次，**随机基线约 25%**；只有显著高于该基线才有意义。
3. **字节距离检验（新）：** 对 S2 的畸形 PPG（第 918 条，偏移 378）和与其相同的 253 B 源（第 913 条 RESP，偏移 92）：按订阅原件和 MQTT 头开销，计算源字节与目的字节在**发送流**中的距离（含中间所有报文，包括被丢弃/重放的）。若距离接近 **1,024 或 2,048 的整数倍或某个固定缓冲区大小**，指向环形缓冲指针追上一圈（ESP 接收环或类似结构）；若无规律，则弱化该方向。
4. **R22 的 RESP 畸形（683 B）：** 用同一方法在更大范围（±60 s）搜索 ≥15 B 的重复片段，而不是 ±10 s。

## 6. S3 窗口的收尾探头试验（修订 R31 §4.1）
保持 R31 §4.1 的窗口流程，**修改收尾试验为**：数据采集结束后、断电之前，
1. 链路正常，记录时刻后**只取下 SpO₂（A）模拟探头**，其余不动；等待 15 s，观察 Broker 有无协议错误；
2. 无论结果，**重新插回，等 30 s 链路稳定**，再取一次，再等 15 s（共 2 次）；
3. 然后按"取下探头 → 关 C → 关其余 4 板"的完整顺序断电，**记录每个动作的时刻**。
预测：探头触发的概率由我上调到约 **55%**（时间线吻合）。2 次试验用来看可重复性，不增加上电额度。

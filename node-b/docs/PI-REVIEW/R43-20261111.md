## 4. 新增已知限制，及其对后续工作的影响
1. **SpO₂ 数值合理性**：静坐志愿者约 15–23% 的 VALID 读数不在 94–100%。**后续云端 AI 不能把单次 SpO₂ 读数直接播报为"偏低"**，至少要做持续时间或中位数判断，并说明读数仅供参考。
2. **体温**：GY641 读的是体表红外温度（约 31 °C），不能按正常成年人体温 36–37.3 °C 判断，否则 AI 会误报"体温偏低"。AI 播报前要么改为"体表温度"并不做正常/异常判断，要么先做标定或补偿（需要新的工作包）。
3. **`source=MOCK`**：要让云端 UI 和 AI 识别真人数据，需要一个出 `LIVE` 标记的构建变体，会产生新镜像。可与 AI 播报所需的下行通道合并为同一个工作包。
4. 实时顶替：一窗出现 4 次（无丢失），一窗为 0，原因 UNKNOWN。
5. PPG 缺口为源端限制；RR 在本工装下无效；硬复位重设路径只有 Host 证据。

**可选（零硬件）**：请 Codex 从现有受限原件补一份 SpO₂ 范围外读数的脱敏统计（低于 94 的分档、最低值、是否集中在某段时间、与 PR/质量标志的关系），以及原批次 4 次顶替前后的队列和 PUBACK 间隔。这些数据可以直接用于 AI 播报规则的设计。是否需要由负责人决定。

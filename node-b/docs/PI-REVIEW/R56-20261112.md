## 3. 朗读 NOT_PASS：原因分析
- WP-AY 的朗读是**浏览器朗读**（页面调用 `speechSynthesis`），**不是开发板发声**。正式 C 镜像构建时 `audio_enabled=false`（R45、R54 §0），所以开发板喇叭无论供电是否够 5 V 都不会响，这不是本轮的原因。开发板 TTS 能否发声，属于"设备音频下行"，一直是 NOT_RUN。
- **AI 令牌**只用于"AI 助手"问答页，播报和朗读都不需要它，也不是原因。
- 可能的原因（按可能性排序）：
  ① 点"朗读播报"的那个页面不在出声的那台电脑或浏览器上（例如点在 Codex 打开的自动化浏览器里，那里通常不输出声音）；
  ② Windows 系统缺少中文语音包，Chrome 遇到 `zh-CN` 时静默不读；
  ③ 标签页被静音，或音频输出设备不对；
  ④ Chrome 在调用 `cancel()` 后立即 `speak()` 时会丢掉确认语（页面代码的问题）。
  判断方法：开启时如果连"播报朗读已开启"这句确认语都没听到，原因就在①–④中。
- **页面改进（已提交，未发布）**：`claude/cloud-ui-v2@1945c9c`。系统中有中文语音时明确选用它；开启时不再先调用 `cancel()`；软键上直接显示"朗读：开 / 朗读中… / 无中文语音 / 朗读失败"，现场一眼就能看出原因。测试 28 项通过，构建通过。生产页面仍为 `web-20261112-02`。

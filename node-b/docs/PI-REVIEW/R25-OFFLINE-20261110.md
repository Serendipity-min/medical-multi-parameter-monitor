## 授时与回放

| `B5 RETENTION` 字段 | 含义 |
| --- | --- |
| `sync_ms` | 最近一次实际新鲜 SNTP 建链所产生的带符号 UTC 修正量，单位毫秒。每 10 秒的本地锚更新不会覆盖此值。首次建立 UTC 或过期后向前重建时，若无需渐进校正则为 0。 |
| `anchor_age_ms` | 从最近一次 UTC 锚更新到同组快照的单调毫秒差。首次建立锚前为 0。 |
| `anchor_valid` | 快照时 UTC 是否可用，0 或 1。 |
| `anchor_expirations` | 本次启动中锚超过 610 秒并失效的累计次数。同一次失效只计一次。 |

锚无效时暂停新发布，继续处理已经在途的 PUBACK。锚有效但队首晚于当前 UTC 时，历史批留在原位，等时间达到原采集时刻再取出。延后的历史发布在再次提交前也检查时间。实时优先、标量先于波形以及四个 QoS1 槽的既有规则仍适用。

控制台仍每组追加一条 `B5 RETENTION`。按保守的 328 字节上界和 115200 8N1 估算，单行线时约 28.5 ms。实板 `console_max` 和时基漂移均为 UNKNOWN。修正量包含授时样本误差，需要结合锚年龄解读。

## 验证

- Host **27 组通过**。实际 UTC 校正路径施加 −1,500 ms 修正后仍非递减。coreMQTT 夹具另注入回放时钟落后队首 1,501 ms、锚失效以及距队首时间 1 ms 的情况，均未提前取出。UTC 到达后从原队首继续。再次失效时仍回收已发批次的 PUBACK，下一批等到锚恢复。
- 采集时间早于发送时间约 179 秒的 NIBP 批通过 QoS1 确认，保留原时间戳和两个值，走 `NODE-E/replay/nibp`，载荷为 `source=REPLAY`，实时 NIBP 计数不增。
- 115200 透传的 110 秒 Host 稳态对照输出逐字节一致。Python 回归 **85 项及 12 个子例通过**。

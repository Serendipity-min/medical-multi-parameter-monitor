## WP-AI 透传生命周期（生产必需）

问题：FIELD01 以冷停收尾，W2/W3 STOP 后均为 `PASS_MODE_UNKNOWN`；生产不能冷停。
1. **盘点现状**：`platform_passthrough_enter/leave/normal`、`pass_send/pass_recv`、STOP 与错误锁存各自的退出尝试；回答"STOP 后为什么没确认退出"——是没发 `+++`、保护时间不足、还是 ESP 无应答？依据 W3 串口原件（受限档）逐行说明，不能确定处写 UNKNOWN。
2. **设计并实现**（最小改动，生产镜像与 FIELD01 共用）：
   - 正常退出：停发 → ≥1 s 静默 → `+++`（不带 CRLF）→ ≥1 s → `AT` 同步确认回到命令态；
   - 退出未确认的降级：有界重试一次，仍失败则**硬复位 ESP**（既有复位路径）后重走启动，不原地假设状态；
   - 掉线/重连：链路或 MQTT 断开、`CLOSED`、超时后的退出 → 重新 TLS/透传建链；重入次数与退避有上限，超限进入既有 `LINK` 失败路径；
   - 保持：UART 波特率恒为 115200（不涉及 UART_CUR 改动）、`pass_send` 三连加号拒绝、下行仅 0x20/0x40/0xD0。
3. **Host 测试**：正常退出；退出无应答；退出后 `AT` 无应答；重试成功/失败；掉线重连成功；重连上限；STOP 与退出同周期；退出中收到数据；任一失败后命令禁入。
4. 每个降级分支必须有可 grep 的 `GW PASS_*` 步骤码，便于实板判读。

**验收**：Host C 全组通过；新增用例逐条列出；Windows/VPS 位级一致（F-P115 之外的新镜像另给 SHA）。

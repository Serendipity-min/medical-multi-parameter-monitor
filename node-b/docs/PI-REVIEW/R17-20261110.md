## 3. PI 发现的问题
1. **（P1）重连上限把"Wi-Fi 断网"也算成了永久故障。** `network_main.c` 里 `gateway_network_open` 失败与 MQTT 失败都走 `pass_reconnect`，每次消耗一次重入额度（`gateway_passthrough_retry`，上限 3，退避 2/4/8 s）。热点/路由器重启超过约 1–2 分钟，额度耗尽，设备进入 `LINK` 停止，直到整机重启。旧生产路径是无限退避重连。**这是相对旧路径的回退。** 要求：额度只限制"已建立的会话短时间内反复掉线/退出失败"；入网不可达（Wi-Fi/SNTP/TLS 开不起来）按**有上限的无限退避**（如 2 s 倍增到 30 s）继续重试，不消耗额度。
2. **J-Link 复位会锁死候选。** 无有效续接记录的软件复位（含 J-Link 的 SYSRESETREQ）进入 `PASS_BOOT_RESET_LOCKED`。生产策略可以接受，但**测试流程必须用开关断电**，不能再用 R5 的"J-Link 纯复位取新启动"。而开关断电会丢启动横幅（COM15 在开关 ON 后才出现），因此要求：把本次启动的恢复摘要（转义结果、AT 确认、复位原因、重入计数）在启动后 60 s 内**周期性复述**到现有 `B5 DIAG`，便于判读。
3. **PF6 复位前必须核对 GPIO0。** 图纸上 ESP 脚 3（GPIO0）接 `GBC_LED`。ESP8266 复位释放时 GPIO0 为低会进入下载模式。需查明 `GBC_LED` 对应哪个 MCU 引脚、固件上电后的默认电平与板上上下拉，复位前后不得为低。
4. **PPG 短批无上限。** 60.5 批/s 的独立压力档（PPG 每点一批）在 115200/230400 都丢 9,222/3,543 批，三槽四槽相同——**与链路无关，要在源头限速**。生产里 PPG 间断、来源切换会触发短批。需要设计（不改外部语义）：短批合并或最小间隔，并说明对时间戳和有效性的影响。
5. 启动转义在命令态发 `+++`（无 CRLF）会让下一条 `AT` 变成 `+++AT`：Host 对端已建模为一次 ERROR 后恢复，**真实模块行为 UNKNOWN**（与 H-JUNK 同类风险），实板要看。

# R61 · W-AY run4 简卡：HR 120 bpm 复测（不调节模拟器）

**2026-11-12 · PI。** 负责人要求在结项前复测 120 bpm，并把开发板 TTS 和喇叭播报纳入范围（另立工作包 WP-AZ，方案另出）。R60 中"WP-AY PASS"的结论保持不变；本卡专门处理 120 bpm 这个遗留项。

## 0. 目的
run2（R58）中，120 bpm 段 HR 频繁 INVALID（连续无效最长 47 s），当时操作者调节过模拟器。本轮把设定**一次设好、全程不碰**，用来区分两种可能：
- (a) 当时的调节动作造成了无效；
- (b) B 板在 120 bpm 下 HR 有效性本身不稳。

## 1. S7 后端开关（Codex 执行；负责人要求做 run4，视为已放行）
做法同 R59 §1：在 env 中只加一行 `MONITOR_BROADCAST_HR=1`，只重启 webbackend，其余三个服务的 PID 不变。run4 结束后立即移除这一行，并核对 env 与 S4 备份逐字节一致。

## 2. 窗口（约 15 min，不需要志愿者）
- 条件同 R59 §2：C 用正式镜像；B 板只接模拟器；D 板测室温；E 板不启动；不刷写、不发串口命令。开窗前通知 PI 开始记录，普通 Chrome 开着朗读。
- 步骤：
  1. 75 bpm 保持 ≥2 min（基线）。
  2. 改为 **120 bpm**。改之前先确认屏幕上显示的设定值，记下切换时刻，**之后不要再碰模拟器**，保持 ≥6 min。
  3. 改回 75 bpm → 断电 → S7 收尾。
- 此外请记录：模拟器型号，以及 120 bpm 档的波形类型（如正常窦性 / 导联 / 幅度设置）。如果 B 板屏幕上有 HR 或信号质量提示，拍照记下。

## 3. 判定
- **PASS**：120 bpm 段以 VALID 为主，首个 VALID 120 后 120–200 s 内恰好出现 1 条"请静坐后复测心率。"，并能听到朗读；75 bpm 段 0 条。
- **NOT_PASS（B 板）**：设定不动的情况下 HR 仍频繁 INVALID，播报无法触发。此时定性为"B 板高心率下 HR 有效性不稳"，写入问题总结。是否修 B 板固件由负责人另行决定（涉及 B 板刷写，须单独授权）。
- PI 按分钟统计 VALID 比例，并找出最长连续 VALID 段，与 run2、run3 对比。

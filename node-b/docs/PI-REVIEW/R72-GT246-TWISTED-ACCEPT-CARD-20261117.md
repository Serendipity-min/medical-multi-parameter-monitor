# R72 · GCAN-GT-246-4 双绞线正式验收卡

2026-11-17，PI 签发，由 Codex 执行，负责人在现场操作。负责人原话：“当前一进两出端口完成配置，双绞线也完成链接……你来给codex签订合同”。依据为 R68（接法和配置）、R70（上电与录制方法）、R71 §4–§5（附带条件和前置要求）。

## 0. 目的与边界
- **目的**：在双绞线接法下完成 GT-246-4 拆段的正式验收：
  - 断电检查四个子段的阻值、线序、参考地和隔离；
  - 上电后五板连续在线 30 分钟，GT 四路不报错；
  - 补齐 R70 缺失的 C 启动原文、逐点灯态、GCAN Box 错误计数和启动溢出计数。
- **结论口径**：本卡只判定“GT-246-4 双绞线接入验收 PASS/FAIL”。不包括 CAN 裕量、断线或故障注入、长时间老化、真人数据，也不能用来回答 R68 失败根因。负载口径同 R68 §1：拆段降低的是电气负载（40 Ω → 60 Ω），总线占用率不变。
- **授权范围**（本卡一次有效）：
  - 断电检查（S1）；
  - 一轮上电，顺序为 GT → A/B/D/E → C，稳态观察 30 分钟；
  - 用 GCAN Box **只读**查看通道状态和计数；
  - **被动**录制 C 的控制台（USART1，只收不发）；
  - 断电后复测阻值。
  - S1 不合格时不得上电。上电中途停止后，**不再进行第二次上电**，等 PI 复核。
- **不在范围**：
  - 任何烧录（含 sector0/3/4、options、ESP 固件）；
  - 调试器连接、Reset、Go；
  - 向 C 或 ESP 发送任何串口字节（包括回车）；
  - 写入或保存 GT 配置（GCAN Box 只允许读取/上传到电脑，不允许下载到设备）；
  - 改云端配置、ACL 或服务；改热点；
  - 拔线、短接等故障注入；
  - 直连对照；
  - 真人测量。C 保持 WP-AZ `2c97094`，GT 保持配置 SHA-256 `2fbb39b1…`。

## 1. 接法（与 R68 相同，只把杜邦线换成双绞线）
C 固件中 C.CAN1 一侧的远端节点是 A(1)/E(5)，C.CAN2 一侧是 B(2)/D(4)（`gateway/dual_can/b4_gateway.c:11-13`）。GT 只转发 CAN1↔CAN2 和 CAN3↔CAN4。因此必须满足两条：**A·E 接在 GT CAN2，C.CAN1 接在 GT CAN1**；**B·D 接在 GT CAN4，C.CAN2 接在 GT CAN3**。
- 只核对“A·E 在 CAN2、B·D 在 CAN4”还不够，C 的两个口也要接对。若 C 的两个口对调，控制台会出现 `wrong_bus` 递增，节点也无法上线。

| 子段 | GT 通道 / 拨码 | 两端 | 拓扑 | 预期 H–L |
|---|---|---|---|---|
| S1 | CAN1 / R1 ON | GT CAN1 ↔ C.CAN1 | 点对点 | ≈60 Ω |
| S2 | CAN2 / R2 OFF | A.CAN1 ↔ E.CAN1，GT CAN2 在中间分出 | 一进两出 | ≈60 Ω |
| S3 | CAN3 / R3 ON | GT CAN3 ↔ C.CAN2 | 点对点 | ≈60 Ω |
| S4 | CAN4 / R4 OFF | B.CAN1 ↔ D.CAN1，GT CAN4 在中间分出 | 一进两出 | ≈60 Ω |

**一进两出的要求**：
- 两端必须是两块板（A 和 E、B 和 D），它们的板载 120 Ω 就是这一子段仅有的两只终端；
- 分线点放在 GT 端子上或紧挨端子，GT 的支线尽量短（不超过 30 cm）；
- 不要从分线点再拖出第三条长线。

**线序**：
- GT 的 CAN2–CAN4 在顶部，从左到右为 `CANH | CANL | GND`；CAN1 在底部，顺序**相反**，为 `GND | CANL | CANH`。
- 板上两针插座：插座 2 为 CANH，插座 1 为 CANL（`06-CAN-Wiring-and-M1-Contract.md` §一）。
- AP 保持 OFF。旧杜邦线须全部拆除，不允许新旧线同时留在同一子段。

## 2. 执行步骤
**S0 准备（全部断电）。**
- 拍照：四个子段的全景、GT 端子特写（能看清线序）、拨码特写（含 AP），以及每块板的 CAN 插座。
- 记录每个子段的线长和分线点位置（估计值即可）。
- 记录热点状态：已开启、2.4 GHz、热点名与 C 预置的一致（只写“一致/不一致”）。
- **C 的供电**：只用一条明确的供电路径，回执写明是哪一条。J-Link **物理拔除**。C 断电时在设备管理器中确认 COM15 不存在。
- **控制台适配器**（R71 §5）：
  - 用独立的 USB-TTL 适配器，电平设为 3.3 V；
  - 只接两根线：适配器 RX ← C 的 USART1 TX（PA9），适配器 GND ↔ C 的 GND；
  - 适配器的 TX 和 VCC 两根不接；
  - 插上主机后确认 C 的电源灯仍然不亮，即适配器没有反向给 C 供电；
  - 参数 115200 8N1，DTR/RTS 设为 false，原始字节写入文件，带主机时间戳。
  - 没有适配器时，改用 COM15，但要用每 100 ms 重试一次的打开循环，并在回执中写明。

**S1 断电检查（GT 和五板全部断电，所有 USB 已拔，电阻档）。** 逐项记录读数，不能只写“正常”。

| 编号 | 测量 | 合格范围 |
|---|---|---|
| S1.1 | 每个子段 H–L，在**每个端点**各量一次：S1 在 GT CAN1 和 C.CAN1；S2 在 GT CAN2、A.CAN1、E.CAN1；S3 在 GT CAN3 和 C.CAN2；S4 在 GT CAN4、B.CAN1、D.CAN1。共 10 个读数 | 55–65 Ω，同一子段各点相差 ≤2 Ω |
| S1.2 | 线序：GT 端 CANH 到各板插座 2，以及 GT 端 CANL 到各板插座 1（同名线），共 12 个读数 | ≤2 Ω |
| S1.3 | 线序反证：GT 端 CANH 到各板插座 1（异名线），每个板端一个读数，共 6 个 | ≈60 Ω（与 S1.1 相同）；若读到 ≤2 Ω，说明 H/L 接反 |
| S1.4 | 参考地：GT `CANx_GND` 到该子段每块板的 GND，共 6 个读数 | ≤2 Ω |
| S1.5 | 对地绝缘：每个子段在 GT 端量 H–GND 和 L–GND，共 8 个读数 | ≥1 kΩ |
| S1.6 | 跨子段隔离：在 GT 端子上，任意两个子段之间的 H–H 和 L–L（6 对，共 12 个读数） | ≥1 kΩ |
| S1.7 | 拨码 R1 ON、R2 OFF、R3 ON、R4 OFF、AP OFF；GT 电源端子从左到右为 `PE \| 0V \| 24V`，极性正确 | 与照片一致 |

读数的含义：约 120 Ω 表示某一端断线或缺少终端；约 40 Ω 表示多了一只终端（拨码错误或多接了板）；接近 0 Ω 表示短路。

**S1 任一项不合格时停止**，不上电，回报读数和照片。

**S2 GT 和从板上电。**
- 先给 GT 上电，等 SYS 闪烁；再给 A/B/D/E 上电。B 接 ECG 模拟器并打开，让 S3/S4 一直有连续的高频报文。A 的血氧和 E 的血压不要求，也**不接真人**。
- 等 60 s，记录 CAN1–CAN4 指示灯。此时 C 还没上电，CAN1/CAN3 红灯是预期现象（R70 S1），不触发停止。
- 用 GCAN Box 只读截取一次四路的状态和错误计数，作为“C 上电前”的基准。

**S3 C 上电。**
- 先开始控制台录制，确认适配器已在接收（空闲无字节属正常）。
- 提前至少 5 分钟通知负责人转告 PI 预计的上电时刻，PI 会在 VPS 上开始 WSS 录制。
- 给 C 上电，记录**北京时间，精确到秒**。
- 记录 CAN1/CAN3 由红转绿的时刻，与控制台中 `UNI UART baseline=…` 一行对照。

**S4 稳态 30 分钟。** 从网关和四个节点首次全部 ONLINE 起算。在 T+0、5、10、15、20、25、30 分钟各记录一次：
- GT 指示灯：SYS 和 CAN1–CAN4 的红/绿状态；
- GCAN Box 的通道状态和错误计数（截图）；
- 控制台中最近一条 `ABC A_CAN`/`B5 DIAG` 的 `txfail`、`esr`、`overflow`，以及最近一条 `FIVE STATE` 的 `resets`、`wrong_bus`、`malformed`；
- 云端网关和 A/B/D/E 的状态。
- 期间不读 MCU 内存，不接 J-Link，不做任何串口写入。

**S5 断电。**
- 先断 C，再断其余板，最后断 GT。记录每一步的时刻。
- 停止控制台录制，计算 SHA-256。
- 全部断电后重复 S1.1 的 10 个读数。
- 接线保持原样。

**S6 离线补查（R71 §4.2，可与 S0–S5 分开做）。** 在受限 EFS 中查找以往直连现场（W-AZ、R65 等）`FIVE STATE` 或 `ABC A_CAN` 的首个 `overflow` 值，只回报数值和来源文件 SHA-256，不回报原文。

## 3. 判定
**PASS 需要同时满足：**
1. S1 全部合格。
2. C 上电后 60 s 内，控制台显示四个节点心跳计数为正且 `nmt=5`；`UNI CAN mask=3`。
3. 网关和四个节点在 C 上电后 120 s 内全部 ONLINE，并连续 ONLINE 满 30 分钟，期间没有节点进入 OFFLINE。单个标量短暂 STALE 只记录不判失败，以 W-AZ 直连基线为参照。
4. 在 30 分钟内：
   - GT 任一通道都没有出现红灯；
   - 控制台的 `txfail`、`esr` 保持 0；`overflow` 在启动首个样本之后不再增加；`resets`、`wrong_bus`、`malformed` 均保持 0；
   - GCAN Box 错误计数在 7 个采样点之间不增加。
5. 断电后复测的阻值仍在 55–65 Ω 之内，且与上电前同一测点相差 ≤1 Ω。

**其他口径：**
- 启动原文（`GW PASS_BOOT_AT_OK`、`UNI UART baseline`）没有录到时，这一项记为 UNKNOWN，不判失败，但回执中要写明原因。
- GCAN Box 读不出计数时，这一项记为 UNKNOWN，判定改为依据第 4 条中的指示灯和控制台计数。
- 首个 `overflow` 值只记录，不作为判定依据；与 S6 的基线对照由 PI 复核。

## 4. 停止条件（STOP_TARGET）
出现以下任一情况，按现场状态保存证据，不复位，不重刷，不再上电：
- S1 任一项不合格（不上电）；
- 任一板发热、冒烟或出现异味；GT 的 SYS 不闪烁；
- C 反复复位（控制台反复出现启动行），或出现 HALT/ROM 迹象；
- C 上电后 60 s，CAN1/CAN3 仍红灯常亮，或者控制台没有看到四个节点：**继续被动录制满 3 分钟**（R70 方法，用于定位），然后进入 S5；
- 稳态期间任一通道转为红灯常亮，或任一节点 OFFLINE 超过 10 s：截图并记录时刻，进入 S5。

## 5. 回执要求（分支 `codex/r72-gt246-accept`，文件 `R72-GT246-TWISTED-ACCEPT-RECEIPT-20261117.md`）
- 本卡的提交 SHA 和文件 SHA-256。
- S0：照片清单、线长和分线点位置、C 的供电路径、适配器型号和接法、热点状态（一致/不一致）。
- S1：全部读数表，上电前和断电后两次。
- 时刻：C 上电（精确到秒）、CAN1/CAN3 转绿、首次全部 ONLINE、30 分钟窗口的起止、各板断电。
- 控制台：启动标记是否出现及其主机时间，首个 `overflow` 值，7 个采样点的计数表；原件和逐行索引的 SHA-256。原件只放在受限 EFS。
- 7 个采样点的指示灯表和 GCAN Box 截图。
- 本机 WSS 录制的帧数、起止时刻和 SHA-256。
- S6 的数值（如果做了）。
- 是否触发停止条件。
- §3 各条按 PASS / FAIL / NOT_RUN / UNKNOWN 逐条填写，最后给出总判定。真人数据为 NOT_RUN。凭据、热点名称和 UID 不写入回执。

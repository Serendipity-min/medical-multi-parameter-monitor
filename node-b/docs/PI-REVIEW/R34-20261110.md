## 2. WP-AW（Codex，Host，新 SHA，不刷写）
基线：S2-c/WP-AU 候选（code `8a790e5d…`）。新增编译选项 `--link-resilience`，默认关闭；关闭时 boot/code/HEX 必须与 `8a790e5d…` 候选逐位一致。

### 2.1 重入策略
- 已建立会话的断链**不再因为"同一恢复周期内第三次"而永久停止**。改为长退避继续重试：2/4/8/16/30 s，之后每 30 s 一次（沿用获取失败的退避），并随连续失败次数封顶在 60 s。
- **LINK 停止只保留给本地不可恢复的情形**：UART 错误风暴、冷启动基线异常、身份/配置错误、既有的 STOP 请求。网络造成的事件（协议错误、遗嘱、Wi-Fi 丢失、SNTP 失败、握手失败）一律不停止。
- 既有的 300 s 稳定清零计数、`PASS_REENTRY_*` 步骤码和 DIAG 字段保留，另增 `consecutive_drops`、`total_drops`。
- 既有的 PF6/STM32 软复位升级梯度保持现状，不因本包扩大；若重入重复失败，能否升级到 ESP 硬复位取决于 WP-AP 的硬件验证，**本包不改这条梯度**。

### 2.2 停滞感知的 QoS0 波形节流（缓解试验）
- **停滞判据：** 有 QoS1 在途，且距上一次收到 PUBACK 的时间超过阈值 T。
- **动作：** 暂停**新的 QoS0 波形报文写出**，QoS1（标量、状态）和 CAN 接收、入队照常；波形留在 Router 队列，队列满时按既有规则覆盖最旧波形。收到 PUBACK 立即恢复。
- **保护：** 暂停不得超过现有 5 s 事务期限；到期走既有断开路径，不另设计时器。
- **T 的选取必须用数据校准，不得拍脑袋：** 用 S2-c、S3、S1b-2、WP-AR 的 `B5 TXACK` 与 PUBACK 记录，统计"QoS1 在途期间自上次 PUBACK 起的等待时间"的分布。已知正常稳态的相邻 PUBACK 间隔约 ≤450 ms，单次最大约 750–1,170 ms。要求：**在这些正常稳态窗口回放中节流触发率≈0**（给出 T、触发次数、被暂停的字节数），并给出 T 的敏感性（T 取 600、800、1,000 ms 的触发情况）。
- **目的：** 在 TCP 停顿时，ESP 缓冲不再被持续写入的波形灌满。这是缓解试验，不证明 H7。

### 2.3 诊断
`B5 LINKRES`（5 s 时隙，≤30 ms 线时）：节流触发次数、累计暂停毫秒、被暂停的报文数和字节数、连续/累计断链次数。不删除既有诊断；SRAM 余量、sector4 余量必须随新 SHA 报告（当前约 16,120 B / 8,288 B），超过余量先报 PI。

### 2.4 验收（Host）
1. 连续 20 次人工模拟的断链（遗嘱/协议错误/Wi-Fi 丢失/SNTP 失败/握手失败）**不停止**，退避与封顶符合 §2.1，STABLE_RESET 语义不变。
2. UART 风暴、冷启动基线异常、STOP 请求仍然停止。
3. 模拟 PUBACK 停滞 ≥T：停滞期间 QoS0 写出字节有界（≤1 KB 量级，给出实测值）；PUBACK 恢复后立刻恢复，波形无重复；标量零丢失。
4. 正常稳态回放：节流触发 0 次，速率、队列与 S2-c 对照一致。
5. 关闭选项重编与 `8a790e5d…` 逐位一致；`test_unified.py`、pytest 全过。

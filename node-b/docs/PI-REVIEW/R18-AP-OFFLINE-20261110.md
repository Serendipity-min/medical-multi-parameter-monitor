# R18 WP-AP PF6 诊断镜像

## S2 候选

使用既有 ESP 查询工程的独立构建入口。

```text
python -X utf8 gateway/esp_at_probe/build.py --pf6-diag
python -X utf8 gateway/microphone/test_unified.py
```

Windows Arm GNU 14.2.1 / SPL V1.4.0。诊断镜像 Flash 装载段都在 sector0，起点 `0x08000000`。镜像包含 SysTick、两个 115200 UART 和与生产候选共用的 PF6/PC0 GPIO 序列。未链接 CAN、MQTT 或生产网络启动代码。ESP 侧唯一主动命令是 `AT`，只有在本次复位后确认完整 `ready` 行才发送。

| 制品 | 字节 | SHA-256 |
| --- | ---: | --- |
| `esp_pf6_diag.bin` | 4,884 | `37cdfe82829e480719ddc558c3d4d764671dbec803c2462da57fcc6dc42995ed` |
| `esp_pf6_diag.hex` | 13,807 | `7e3d46c72d1323d6ffa181d827c451412c85056fdb34271b0a0c23f229188118` |

主机控制台只接受独立的 `PF6` 一行，支持 LF 或 CRLF。每次启动最多消费一次，包含门控拒绝和失败。记录脉冲前、结束时 PC0 电平、脉冲状态、释放到完整 `ready` 的时间和 AT 确认。脉冲状态 `0` 为门控拒绝、`-1` 为保持复位、`1` 为已释放。 `ready=0` 时 `ready_ms` 不适用。等待 `ready` 上限 3 秒，AT 事务上限 500 ms，控制台只输出这些字段。

Host C 24 组通过。共用 GPIO 替身覆盖 PC0 低电平、开漏、脉冲时间和保持复位。新组覆盖完整命令、单次消费、分片、非法输入、UART 错误后的行边界及 `ready` / `OK` 精确匹配。S2 为 **NOT_RUN**，本批只交构建和摘要。S2 的现场隔离与硬件动作由后续批次放行。

## S1 准入核对

本机 Windows COM15 已枚举，未打开串口或调用 J-Link。冻结 S1 的 boot、code、HEX 本机摘要与 R18 一致，完整 code SHA 为 `163d1bffcd9267686c14e68ffb6857f379bfbd7edc3be38be997230d625062ac`。负责人 SHA 放行和现场运行待定。 [R18 批次卡](https://github.com/Serendipity-min/medical-multi-parameter-monitor/blob/d02ea2f/node-b/docs/PI-REVIEW/R18-20261110.md)

| R18 观测项 | 冻结镜像的输出边界 |
| --- | --- |
| 启动摘要、恢复步骤、队列、CAN/UART、PUBACK | 启动与恢复摘要、队列统计和 UART/CAN 计数有输出。PUBACK 有累计分桶上界和最大值，单独的稳态窗口分布无法由累计分位数反推。 |
| DWT、QoS1 槽位占用 | 冻结构建没有 `--transport-profile`。四槽是配置值，运行占用和高水位没有计数输出。 |
| 稳态 Broker 实收 / C 入队 ≥99% | `B5 FLOW` 只列 7 个流，缺 PPG、SpO₂、PR、NIBP 和事件的入队计数，无法直接得到全流分母。原阈值保留，这项应列 **UNKNOWN**。 |

若按原 SHA 进行 S1，可记录启动、恢复、队列和 Broker 实收到达。需要完整容量判据时，由 PI 先补齐观测并另行冻结相应镜像。

## 2. 离线统计判读
**SpO₂**
- 两批中位数都是 95%，P5 约 89%，最低 56% / 79%。对静坐的健康志愿者，95% 的中位数偏低，整体分布向下偏。
- 越界读数分散在整个 300 s 内（每 30 s 都有，2–13 条），最长连续段只有 8 条和 5 条。这不像单次动作造成的一段干扰，更像持续存在的测量偏差加零散的离群值。
- 越界帧及其前后帧的 SpO₂、PR、PPG 有效标志几乎全是 VALID。**模块自带的 VALID 标志挡不住这些读数**，下游不能只靠它来过滤。
- 越界帧附近 PR 的中位数（86–87 bpm）与范围内读数（84–89 bpm）接近，但最大值到 139–148 bpm，说明 PR 也有零散的尖峰。
- 成因（佩戴、灌注、模块算法）仍是 UNKNOWN；没有参照血氧仪，无法判断准确度。

**体表温度**
- 原批次 31.0–31.8 °C，平稳缓升；复测开头 26.08 °C，第 1 s 内跳升 2.30 °C，之后约 5 分钟才升到 31 °C 左右。这和探头刚放上、贴近皮肤后需要时间趋稳的现象一致（推断）。
- 读数是体表红外温度，比体温低约 5–6 °C，而且放置后至少前 30 s 不稳定。

**原批次 4 次顶替**
- 集中在 +270–280 s，当时队列占用升到 6–9/24，之后很快回到 0–1；没有断链、UART/CAN 错误、控制台超时或节流触发。PUBACK 累计间隔上界 981 ms。
- 判读：一次短暂的出口拥塞，让两路最旧的实时帧转入回放，数据没有丢失。逐条成因 UNKNOWN。记为已知限制即可，不需要工作包。

## 3. AI 播报规则建议（用于后续工作包，现在不实施）
总原则：只做一般性信息，不做诊断；每条播报都附带"仅供参考，不构成医疗建议，如有不适请咨询医生"；**只对 `source=LIVE` 的数据播报**（当前载荷全为 MOCK，见 §4）。

| 参数 | 建议规则 | 依据 |
|---|---|---|
| 血压（NIBP） | **最适合播报**。只播报 90 s 内的新结果（与现有 `<90s 播报` 规则一致）。按一般成年人参考：收缩压 <90 或舒张压 <60 → "偏低"；120–139 / 80–89 → "正常高值"；≥140 或 ≥90 → "偏高"。单次结果都提示"建议静坐 5 分钟后复测"。 | 单次测量有结果帧和模块有效标志，真人 1 次已通过 |
| SpO₂ | **不播报单次读数**。用 VALID 读数的 60 s 滚动中位数；只有中位数持续 ≥2 分钟低于 90% 时，才提示"请检查指夹佩戴后复测"，不说"缺氧"或"偏低"。 | 健康志愿者中位数 95%、P5 89%、VALID 标志挡不住离群值；用 60 s 中位数可吸收零散越界 |
| 脉率 / 心率 | 用 60 s 中位数，静息参考 60–100 bpm；超出时同样只提示"复测"，不做诊断。真人 ECG 心率尚未实测（本窗为模拟器），上线前需补一次真人验证。 | PR 有零散尖峰（最高 148 bpm） |
| 体温 | **不判断正常或异常**。最多播报"当前体表温度约 X °C（体表温度低于体温，不作判断）"，且只在探头放置 ≥60 s 后播报。要判断体温需要另开标定工作包。 | 读数约 26–32 °C，放置初期跳变 |
| RR | 不播报。 | 两窗 VALID 均为 0 |
| 频率 | 同一参数至少间隔 5 分钟才再次播报；血压每出一次新结果播报一次。 | 避免频繁打扰 |

## 4. 后续工作包的前置条件
1. **`LIVE` 标记**：`gateway/dual_can/b4_gateway.c:163–165` 在 `MP_B5_CLOUD_CANDIDATE` 下强制 `synthetic = true`，这是有意的设计（B5 阶段只允许合成来源），所以所有载荷都显示 MOCK。要让云端 UI 和 AI 区分真人数据，需要一个出 `LIVE` 标记的构建变体，这会产生新镜像，后端的来源和 ACL 规则也要相应调整。
2. **下行播报通道**：透传构建强制 `--no-audio`（R40 §8）。AI 播报需要 C 能订阅下行主题并驱动 TTS 和喇叭。下行内容建议是**短文本或播报码**，由 C 端本地合成，不传音频，以免挤占约 10.5 条/s 的上行。新镜像的 sector4 余量只有 7,056 B，需要先评估 TTS 驱动的体积。
3. 以上两项建议合并为一个工作包（暂名 WP-AY），在云端 UI 重设计的部署环境就绪后统一设计；合同和实板窗口届时另行放行。

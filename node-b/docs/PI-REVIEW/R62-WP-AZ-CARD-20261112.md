# R62 · WP-AZ 方案卡：云端播报 → 开发板 TTS 喇叭

**2026-11-12 · PI。** 负责人要求：正式样机现场没有电脑，最终用**板上喇叭**播报 WP-AY 生成的云端播报，完成后再结项。
**本卡分阶段，每一阶段都须负责人逐项放行。AZ-0 和 AZ-1 不碰正式环境，也不刷写 C。**

## 0. 现状（PI 调研并抽查，证据为 `codex/field01-preflight` 上的源码）
- **板端 TTS 驱动已有**：`gateway/voice/tts_frame.c` / `tts_queue.c` / `tts_uart_port.c`。帧格式为 `0xFD + 长度(2B) + 0x01 0x04 + UTF-8 文本`，最长 240 B；状态机为 SENDING→ACCEPTED→PLAYING→DONE，两条之间最少间隔 5 s；走 **USART2（PA2 TX / PA3 RX），9600 波特**，中断优先级 15，低于 CAN 和 ESP。已有 Host 测试：`gateway/voice/tests/`。
- **实板发过声**：2025-11-02 在独立 C 语音台架上（不带 CAN），云端回复由 C 板 TTS 播出，ACK=1、DONE=1，负责人确认喇叭说出了原句（`node-b/docs/CODEX-C-INMP441-20261102/VOICE-RESULTS.md`）。**正式透传镜像从未发过声。**
- **正式镜像为什么不发声**：`build_arm.py:69` 在透传模式下强制 `no_audio`，定义了 `MP_AUDIO_DISABLED`，构建时还断言镜像中不存在 `USART2_IRQHandler` 和 `mpm/mic/v1/`。下行订阅（`network_main.c:938`）也被编译掉了。现有回复路径 `unified_audio_reply` 要求先有一次麦克风录音会话，**不能直接用于主动播报**。
- 当初关闭音频的原因（R40 §8、R44 §4）：sector4 余量只有约 7 KB，而且 TTS 对上行速率和 PUBACK 时序的影响没有评估过。
- **UNKNOWN**：TTS 模块确切型号和协议版本；5 V 供电与功放规格；PA2/PA3 是否和某块串口屏共用；broker 对 `gateway-c` 的订阅 ACL；新代码能否放进 Flash 和 RAM。

## 1. 方案（最小改动，不复用麦克风问答链路）
**云端 → C 的播报下行**
- 后端 WP-AY 引擎每生成一条播报，同时向 `mpm/v1/GW-C-001/voice/broadcast` 发布一条消息：QoS1，不保留，有效期 15 s。
- 消息格式为固定头加 UTF-8 文本：魔数、版本、`id`（u32，单调递增）、生成时间、有效期、文本长度和文本，**整帧 ≤240 B**。
- 后端为喇叭另生成 **`speech` 文本**，把符号改成汉字读法：`°C`→"摄氏度"，`108/71 mmHg`→"收缩压108，舒张压71，毫米汞柱"，并附免责声明。页面上显示的文本不变。
- 新开关 `MONITOR_BROADCAST_DEVICE=1`，默认关闭。

**C 端新构建档 `--tts-broadcast`**
- 在透传构建基础上，**只加入 TTS**：链接 `tts_*`，订阅上面这一个主题，收到后校验网关、长度、有效期和 id 是否单调，然后送入 `tts_submit`。
- 不加入麦克风、DMA1_Stream0 和 `mpm/mic/v1/`，构建断言照旧保留。
- Flash 写入范围仍然**只限 sector0/4，sector3 和 Options 不动**。

## 3. 主要风险
- 新镜像改动了已冻结的 WP-AY0，**透传时序要重新回归**：TTS 中断虽然优先级最低，但主循环增加了工作量。
- sector4 余量可能不够，以 AZ-1 的 size 报告为准；不够时就精简，不扩大写入区域。
- 加了 5 V 功放后，可能对 ESP 串口形成电气干扰（R31 曾记录 ESP 对扰动敏感），需要独立供电、共地，并在 AZ-3 中观察。
- 喇叭播报对现场所有人可听见，措辞沿用 WP-AY 已审核过的文本。

## 5. 负责人决定（2026-11-12）与 AZ-1 接口约定
- **AZ-0、AZ-1 已放行**；AZ-2、AZ-3 待放行。
- C 板 PA2/PA3 现在**接的是 TTS 模块**，不存在与串口屏冲突的问题。TTS 模块的型号和协议由 Codex 在 AZ-0 中总结后报告 PI。
- **喇叭播报全部播报内容**。样机阶段**只播数据，不读免责声明**，商用时再考虑。页面上的播报条仍然显示免责声明，不做改动。
- **AZ-1 接口约定**（PI 定）
  - 后端为每条播报另生成 `speech` 文本：只读数据和提示，不含免责声明，符号改成汉字读法，UTF-8 编码 ≤200 B。快照中可以带上这个字段，页面会忽略它。示例：
    - TEMP："体表温度约31.3摄氏度"
    - NIBP："血压，收缩压108，舒张压71，毫米汞柱，在一般参考范围内，建议静坐5分钟后复测"
    - SpO₂："请检查指夹佩戴后复测血氧"
    - PR/HR："请静坐后复测脉率/心率"
  - 下发主题为 `mpm/v1/GW-C-001/voice/broadcast`，QoS1，不保留。只在 `MONITOR_BROADCAST_DEVICE=1` 时发布，默认关闭。发布失败只记日志，不能影响 ingest 和快照。
  - 消息为二进制：魔数 `MPB1`、版本、`issued_ms`（u64，epoch 毫秒）、`ttl_ms`（15000）、文本长度、UTF-8 文本。
    - **去重和防重放以 `issued_ms` 严格递增为准**。后端的 `id` 在重启后会从 1 重新编号，不能用来去重。
    - C 的时钟未同步时拒收；`issued_ms + ttl_ms` 已过期时丢弃。
  - C 端增加小队列（≥3 条），播放前再丢弃已过期的条目，遵守 TTS 两条之间至少 5 s 的间隔。TTS 每次推进的工作量要有上限，不能拖慢透传主循环。

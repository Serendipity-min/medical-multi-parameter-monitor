# W2 新鲜 SNTP 失败与离线修复

同镜像追加复测使用 F-P230 `bb560b89`。A 板三项准入通过，C 接受 START。粗授时第 7 次查询成功，耗时 12.011 s。随后 `GW SNTP_REJECT reason=2 received=0 rtt_ms=1000 server_index=1`。48 B UDP 请求已由 ESP 传输接口接受，固件在 1 s 内收到 0 B，随后锁存 `LINK`（reason 13）。锁存快照为 `ESP_AT_CLOSED`，无 T0、TLS/MQTT 或对端遥测。日志不能区分请求或回复在哪个网络环节丢失。

旧 FIELD01 在网络启动失败时直接锁存，未使用普通 B5 已有的安全轮换资格。修复沿用该资格，仅在完整请求、零回复、UDP 已关闭、AT 同步且未停止时，允许同一次 START 换到下一个既有授时端点一次。只有至少两个端点且剩余时间能覆盖 UDP 的 5 s 打开、1 s 取样、2 s 关闭和 8 s 后续启动预算时才尝试。两次请求使用各自 nonce。收到短包、错误 nonce 或其他无效样本、关闭失败、失步、STOP 或余量不足时维持失败路径。 [W2 原判读标准](https://github.com/Serendipity-min/medical-multi-parameter-monitor/blob/b9f633a/node-b/docs/PI-REVIEW/R11-20261109.md)

Host 19 组通过，新增用例覆盖首次零回复后第二端点成功、两次零回复、单端点、预算边界、STOP 以及部分发送、部分回复、错误 nonce、关闭失败和失步。Windows Arm GNU 14.2.1 构建通过。原五板非 FIELD01 的 boot、code、HEX 与 R9 基线逐位一致。该修复针对 T0 前启动，R11 完整 150 秒判读和窗口排空行为沿用既有规则。

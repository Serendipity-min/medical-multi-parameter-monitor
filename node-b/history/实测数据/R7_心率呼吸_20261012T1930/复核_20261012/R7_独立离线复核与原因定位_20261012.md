# R7 独立离线复核与原因定位

日期：2026-10-12（Asia/Shanghai）。对象：用户提供的 R7 人体来源既有数据及配套历史快照。本轮没有连接串口/J-Link、复位、烧录或再次采集，没有修改生产源码。原始数据、原报告及脚本全部保留；多数一致重建是独立派生记录。

## 1. 核心结论

**已经找到确定的数据导出和软件处理问题，但不能把全部问题归结为传感器损坏。** 本次原因分为：

| 层次 | 已确认的问题 | 证据强度 |
|---|---|---|
| 外部导出 | 运行中读取环形槽发生跨代混字，原 CSV 中部分尖峰是导出伪像 | 高：39 个冲突序号；31 个少数版本含相邻 ±128 代槽的数据字 |
| 心电显示/滤波状态 | 超时重新学习清零 FIR，在有直流偏置的输入下制造启动瞬态；显示没有避开学习期 | 高：源码、恒定输入对照、R7 重置时刻后的回放波形 |
| 心电判拍 | 有短暂检出但不能持续形成可靠 RR；末段噪声闸门拒绝全部局部候选峰 | 高：固件快照与实际 C 回放一致；不是本轮全程首拍锁死 |
| 呼吸算法 | 零初始 DC 造成巨大启动过渡；漂移/小波纹干扰局部峰与周期锚点 | 高：实际 C 回放及已知 15 次/分合成对照 |
| 输入成分的来源 | 50 Hz周期成分、约7.6–8 Hz成分和低频变化的具体来源/性质 | 尚未确定：缺少参考输入、接线/电压测量及受控对照 |

R5 首拍恢复代码已在 R7 镜像中运行，不能继续用 R4 的“始终没有首拍”解释 R7 全程。也不能将短暂输出的数字视为受测者准确心率；本批没有独立参考 ECG 或呼吸参考。

## 2. 身份与原始采集检查

R7 保存的烧录前 1 MiB Flash SHA-256 为：

```text
6d44275aac8edec2ab2892d543a1658032fdd515421ca6a6de961bdb9f1c343e
```

与 R5 普通修复固件结束 Flash 相同；应用 BIN 为 `9f58a8902da3ba35c30c2d736f416c75a68e578a69835a2ed94ded9d1ad58281`。R6 的普通镜像、符号与当前三个相关生产源文件一致，Pan-Tompkins 源码 SHA 为 `faee8e201d8d7ff02ee4cb428ba321b3b154ce86febac1ee2735c4d7aafab364`。

R7 原采集脚本有复位/运行及末端 halt 操作，不能把原试验称为完全只读；本轮复核自身是纯离线。

导出主数据共 26588 点，seq=1→26588，首末 ms=1367→107818，固件时戳跨度 106.451 s。全部相邻序号加 1，flags=0；IRQ 周期换算约 4002.71～4004.77 μs，名义 168 MHz 下推算约 249.757 SPS。这里只核验固件时钟，没有外部仪器认证物理时钟。

末端保存 RAM 中，IRQ/captured/delivered=26591/26591/26591，SPI/bad_status/队列溢出/初始化/长间隔错误均为 0，queue_peak=12，miss_cnt=0，ready=1。最后一次槽读取之后又处理了 3 帧；主 CSV 不是整个停机终点的全部帧，末端 RAM 的最新采样时戳为 107830 ms。

这些记录支持采集驱动、PG15 START 及队列在本轮没有出现先前调度丢帧故障；**序号完整不能保证外部读取的每帧内容正确**。

## 3. 确定的导出问题：跨环形槽代混字

逐一审计 800 份 `slot_*.bin` 中对同一序号的全部观察：

- 39 个序号出现两个不一致版本，无投票平局。
- 其中 20 个原导出首选版本不等于重复快照的多数一致版本。
- 冲突涉及 CH1 13 个序号、CH2 12 个序号、STATUS 13 个序号，另有周期/时戳/对齐空间差异；这些分类相互重叠，不相加当作总帧数。
- 31 个冲突少数版本中，变化的原始数据字或时基字恰好来自 `seq−128` 或 `seq+128` 的另一代槽。
- 1576 个被跳过的无效槽全部为全零启动空槽，不能作为 ADC 产生 1576 个坏帧的证据。
- 有 35 个序号只观察一次，其原子性无法由重叠观察独立确认。

示例：seq=673 的导出含来自 seq=545 的原始数据字；seq=3959 的冲突少数版本含 seq=4087 的 IRQ 周期和时戳。槽容量 128，这些相邻代匹配直接支持“读取过程跨过 ISR 更新”的机制。

seq=2463 原 CH1=654624，多数一致版为 589088，差 65536。原报告的 CH1 最大值因此被伪像抬高；多数一致版的 CH1 范围为 **581348～625411**，不是原件的 581348～654624。

生产者在 IRQ 中写入 24 B，外部 SWD 读取并未遵守生产队列的发布/消费同步；`frames.setdefault(seq, slot)` 只保留首选，也不检查同序号冲突。正确的 STATUS 头不能认证这 24 B 来自同一次写入。

多数版另存于本机私有目录，没有覆盖原始 CSV/BIN。它提升可复核性，但仍不称为绝对真值。后续导出应采用录制完成后读取固定缓冲，或稳定版本校验/冲突拒绝，而非只检查序号无缺口。

## 4. 心率：并非全程无输出，后半段被当时门限拒绝

原状态表的 `bpm_a` 实际是算法侧，`bpm_b` 是 UI 侧，原 README 标签写反。80 个快照中：算法 valid=1 有 6 个，UI valid=1 有 7 个。

| 固件采样时刻 | 算法值/有效性 | UI 值/有效性 |
|---|---|---|
| 27020、28369、29719 ms | 44 / 有效 | 44 / 有效 |
| 31068 ms | 无有效值 | 44 / 有效，尚未刷新撤销 |
| 71547、72888、74246 ms | 130 / 有效 | 130 / 有效 |

这些是固件自身输出，不是本报告对人体心率的认证。98%“质量”由 `QualityTick()` 的帧通过率和覆盖率计算，不评价 QRS、工频或生理可信度。

独立 Host 重放实际生产 C、实际中值/伪迹函数及 FIR 系数，得到 19 次算法受理事件、2243 个有效心率点，随后多次超时重新学习。Host FIR 使用 float32 数学实现，不冒充 ARM CMSIS 优化执行；实际快照是更高层的实机证据。

多数版回放在相同采样时刻与固件快照比较，SPKI、学习峰值和累计窗口峰值最大绝对差均小于约 5×10⁻¹⁶；NPKI 仍有约 1.43×10⁻¹⁰ 的最大差异。运行中读取状态并非原子，不能把整个快照称为逐字段位精确匹配。

最后一次重新学习起点为 74974 ms。学习完成后至数据结束，**1008 个局部候选峰全部未越过其发生时的门限**，最大 `峰值/当时门限=0.939`。这直接解释末段没有有效心率。

原报告拿历史最大积分峰 `6.237e−7` 与末端快照 `8×noise=6.202e−7` 比较“只差0.6%”，两者不是同一时刻，不能解释一次实际判峰是否应该接受。当前问题是带内背景及候选峰/RR不稳定，不是简单把一个门限减 0.6% 就能闭合。

## 5. 滤波重启制造显示伪峰

`PanTompkins_ProcessAt()` 在无新拍/有效 RR 超时后调用 `InvalidateAt()`，后者清零 FIR 和判拍历史。`FrameFeed()` 继续给屏幕发送滤波波形，不以学习期结束或有效心率为显示前提。

R7 回放中有 8 次超时重新初始化。例：8278 ms 重置后 600 ms 内带通输出最大绝对值约 0.009992，重置前 500 ms 内约 0.001741。

独立恒定输入数学对照：ADC 始终为 100000 码，没有任何峰；用真实 129 抽头系数和全零 FIR 初态，按当前 `×1e6` 标度产生启动输出约 **−5787～5965**，稳态约 177。输出的大瞬态不是输入电极发生的心拍。

因此，R7 中部分大带通尖峰不能作为“传感器原始输出乱跳”的依据。至少存在“超时→清零 FIR→启动显示瞬态”的软件机制。**这不证明学习期内这些瞬态被受理为真实心拍**，两秒学习期会阻止期间的普通判拍。

后续应区分判拍状态撤销与连续滤波状态维护，或明确屏蔽/标记滤波重启的显示过渡；不能只调整显示增益使尖峰更显眼。

## 6. 呼吸：启动基线、波纹和时间锚点共同导致失效

### 6.1 R7 原输出为什么无效

实际生产 C 回放原件和多数版均得到 37 次呼吸候选事件：

- 第一事件为启动阶段事件，没有前一周期。
- 后续 36 个间隔中，32 个小于 1500 ms，3 个大于 10000 ms。
- 仅 1 个有效间隔：68985 ms 处的 2343 ms，保存的 rate0=25。
- 至少需要 2 个有效间隔才输出，因此全段呼吸 valid=0。

大量候选间隔约 240～300 ms，受 240 ms 不应期约束。代码即使判定该间隔过短、不存入速率窗口，仍更新 `s_last_peak_ms`。密集波纹因此不断移动锚点，后面的周期继续与最近伪峰比较，无法稳定得到呼吸周期。

只在 Host 反事实中阻止过短事件移动锚点，会得到未经验证的 **39 次/分** 输出。它可能只是将密集候选按最小间隔重新组合，不能作为直接应用的修复或准确呼吸率。这一改动未应用于生产。

### 6.2 独立已知输入证明处理逻辑存在不足

用实际生产呼吸 C 代码、固定 250 SPS 虚拟时戳作三个非人体输入对照：

| 已知输入 | 观测 |
|---|---|
| 恒定 615000 ADC 码，无呼吸 | 零 DC 初态产生约 0.05124 的低通启动峰，712 ms 时产生一候选；无有效速率 |
| 615000 DC + 幅值1000、0.25 Hz正弦（设定15次/分） | 61112 ms 才首次有效，最后输出15 |
| 同上再加幅值1000、8 Hz小波纹 | 首次有效约60692 ms，最后错误输出19；设定仍为15 |

这直接证明：从零开始估计一个大直流基线，会形成显著人工启动过渡并抬高峰/噪声包络；现有单级低通和局部峰判据不足以稳定抵御叠加波纹。不能把所有失败都交给传感器接线解释。

### 6.3 R7 中的低频成分

多数版 CH1 去线性趋势及 50/100 Hz拟合后，按分带边界插值积分，0.03～40 Hz分析功率中约 **66.3% 在0.03～0.05 Hz，89.5%在0.03～0.1 Hz**；0.15～0.5 Hz约2.82%。这些很低频的变化支配基线/包络，不能把每个慢波峰直接视为一次呼吸。

旧脚本没有直接积分该区间；各窄带独立mask再积分会漏掉相邻带边界之间的面积，不能由剩余量直接认定“<0.05 Hz约83%”。本次统一插值分带口径的结果如上，低频占比较大这一观察仍然成立。

后续应优先验证首样本/稳定期 DC 初始化、基线与呼吸带隔离、周期锚点及真实波峰显著性；保留噪声拒绝与参考输入验证，不能通过强制拼周期获得一个数字。

## 7. 干扰来源和原分析中的误判

1. **约7.6 Hz不能归因于SWD。** 轮询均值约7.412 Hz，中位间隔140.14 ms；7.59 Hz附近网格的心电–轮询相干性约0.0044、呼吸–轮询约0.0337，目前不支持该因果关系。事件时刻来自轮询末端序号，只是近似，仍需受控台架对照。两通道在该频点相干性约0.126，也不足以称为同一个确定电气源。
2. **原“26.8%工频占比”含趋势。** 原代码计算整个拟合（线性趋势加周期项）的方差比例。多数版仅50/100 Hz周期项占原始方差约13.27%，去线性趋势后约15.35%；包含趋势则约26.77%。不同口径不能直接比较，更不能据此证明“接RL就解决”。R6/R7输入条件也不完全相同。
3. **高于Nyquist的谐波不可直接认证。** 当前采样率约249.757 SPS，150/200 Hz拟合会涉及混叠，不能把这些基函数拟合幅值独立当作真实高频干扰测量。
4. **约1秒自相关结果是边界。** 原呼吸代码在1～15 s范围直接找全局最大值，结果恰好在最短搜索滞后，不是检出的局部周期峰，因此不能称为1 Hz心电串扰证据。独立SOS滤波、去掉两端10 s后，在1.5～10 s内找到约8.216 s的探索性局部峰；没有呼吸参考，仍不能认证真实呼吸率。

本批不足以唯一判定电极接触、RL/RLD、供电、呼吸调制路径或外部干扰源，也不证明芯片损坏。后续电气对照应在已知信号台架进行，避免把未知人体输入直接当标定源。

## 8. 状态导出和回放口径修正

- 最后完整主数据为107818 ms，最后周期状态快照为106617 ms，相差 **1201 ms**。原 Python 回放全数据后与更早快照比较，不能把差异统称为浮点重放失败。
- 正确按同一采样时刻比较，78 个有采样的快照中，呼吸整数周期状态均一致。浮点仍非全部位精确，涉及实时状态非原子读取、不同数学实现及导出错误，不宣称完全精确。
- 状态解析将 signed `s_filtered` 用 u32读取，再以数值接近猜测心电/呼吸变量；**29 个呼吸滤波状态值不等于真实带符号呼吸变量**。这不会改变板上算法，但会误导离线绘图。
- 原报告的“最后无有效值”不能代替整段时间线；算法与UI变量的归属也需按符号来源明确。

## 9. 建议执行顺序与本轮边界

1. **先修导出及状态解析。** 稳定记录协议、重复版本验证、signed解析、同一时刻比较，保留原件与派生标记。
2. **修软件启动/恢复处理。** 呼吸DC启动、滤波连续性/过渡显示、周期锚点和峰显著性；用上述已知15次/分及噪声夹具回归，不只降低全局门限。
3. **在已知信号台架分离模拟前端问题。** 用同口径输入比较干扰、参考端和观察方式，核实正常QRS/呼吸周期；自然人体且无参考不能作为准确度准出。

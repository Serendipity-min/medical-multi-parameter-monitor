# 双通道独立削顶最小修复与脱机验证

日期：2026-10-13。范围：新算法_v2 实验工程的普通 Host 验证、ARM 构建及既有数据回放。本轮未连接设备、烧录或进行新的采集，未执行安全扫描、Git 提交或推送。

## 1. 问题与修复结论

旧 `BioV2_Process()` 在任一路达到削顶阈值时重置两路状态并提前返回。因此，CH1 呼吸持续顶轨会清除 CH2 ECG 的滤波和心率周期历史，连源序号、末帧时间及原始码也不更新。

已将削顶保护改为逐通道执行。呼吸顶轨时，呼吸率无效、呼吸滤波停止接收顶轨码；ECG 继续独立处理和判定。ECG 顶轨时对称处理。两路共同削顶时两路仍无效。源帧缺口、源 flags、采集时间缺口及无输入超时属于公共链路故障，仍使两路失效。

这项修复消除了软件共同失效原因，但没有消除实际输入顶轨或工频干扰，也没有证明人体心率/呼吸率准确度。

## 2. 最小改动及恢复边界

| 文件 | 改动 |
| --- | --- |
| `实验固件/HARDWARE/bio_v2.c` | 独立削顶标志、独立预热起点；只有未削顶通道进入滤波与周期判定；两路原始码及公共帧证据继续留存 |
| `实验固件/HARDWARE/bio_v2.h` | 说明诊断计数及逐通道失效语义，公开结构字段与布局不变 |
| `tests/run_channel_isolation.py` | 新增旧版本对照、独立保护/恢复、边界和既有实测回放测试 |

首次削顶只清空本路滤波状态与周期资格。持续削顶保持本路 `CLIPPED` 位，不向滤波器输入顶轨码；getter、Tick 发布不能抹除该位。恢复到未削顶输入后，该路从新输入重新预热（ECG 5 秒、呼吸 10 秒），再积累至少三个满足原稳定性规则的新鲜间隔；旧率值不会直接恢复。

削顶阈值保持原来的包含边界 `raw >= 8304721 || raw <= -8304721`。滤波系数、幅度、峰宽、周期稳定性、噪声和工频资格阈值均未修改。

公共源时间/序号继续逐帧更新，避免呼吸削顶被误认作 ECG 采集缺口。健康通道不因另一路削顶或恢复而重置。

### 诊断字段解释

- `BioV2Diag` 仍为 120 B，ABI version 仍为 2，API 与字段偏移不变。
- `samples` 现在是接收到的输入帧数，包含削顶帧；不能当作有效信号帧数。旧版本在提前返回时不计数。
- `clipped_samples` 是任一路削顶的输入帧数，两路同时削顶也只计一次；不是每通道单独累计值。
- `segment` 表示公共源连续性分段，单路削顶不再产生共同分段。
- 无效通道波形输出为 0，但原始 ADC 码保留；必须结合有效位/原因码判断，不能把输出 0 解释为正常零信号。

UI/CAN 调用只读核查：心率与呼吸率分别获取和导出有效位，没有要求两路同时有效；无需修改调用方。本轮未修改 ADC 寄存器/RLD、SPI、采集环形缓存、UI、CAN 或固件链接布局。

## 3. 普通测试结果

| 验证 | 结果 | 核心证据 |
| --- | --- | --- |
| 原算法普通 Host 回归 | 27/27 PASS | 心率/呼吸夹具、DC、噪声、工频、时间回绕、超时与缺口回归 |
| 新增通道隔离专项 | 29/29 PASS | GCC C99，`-O2 -Wall -Wextra -Werror -ffp-contract=off` |
| 普通 ARM 构建 | 退出码 0，0 errors，0 warnings | Keil/ARMCC 实际构建日志与 ELF/BIN |

专项测试先复现旧缺陷：正常合成 ECG 60 bpm 配合持续顶轨呼吸，旧算法心率有效帧为 0。新算法心率保持 60 bpm；对应健康通道的波形、RMS、工频指标、候选/接受周期、率值及有效位逐帧与无故障参考一致。

反向测试使用持续顶轨 ECG 与合成呼吸 15 次/分，呼吸保持独立有效。正/负顶轨、两路同时顶轨、从正常到单路故障再恢复、阈值内外边界、公共 flags/序号/时间缺口、输入超时、uint32 时间回绕均通过。无削顶的双路输出逐帧与旧算法一致。健康通道为 DC 时仍判无有效率值，未为获得 PASS 强行制造正常数字。

这些输入是工程合成夹具，不是人体准确度验证。

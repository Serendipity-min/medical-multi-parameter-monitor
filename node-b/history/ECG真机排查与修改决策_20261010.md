## 1. 直接回答：是不是人体电极导致？

**不能把异常归因于人体电极。** 在芯片内部输入短接模式，完整任务仍记录到 +2718719、−3932160 的异常采样；这些异常不需要人体信号作为输入。

将主循环缩减为最小采集后，同样的内部短接模式在本次保存的 2048 点中没有出现同类大尖峰，范围为 −1395～−1319，标准差约 11.21 码。同时驱动记录的积压丢样计数由非零变为零。

这支持 **完整任务负担、延迟读取与采集异常有关**，并且与静态审查找到的“DRDY 只计次数、UI 阻塞发送、无历史样本缓存”一致。不过，最小采集仍存在 16/17 ms 的处理间隔，内部测试波形也未达到预期周期；不能把所有问题都解释为屏幕阻塞，更不能宣告只改 UI 就已经解决。

本轮采用内部测试、内部短接及正常输入配置的真实硬件数据，不是合成字节流；**没有合格的人体 ECG 验证数据，不能据此评价人体信号采集质量或设备接触人体的安全性。**

## 4. 实际执行的对照

先运行未经诊断修改的原版，再使用隔离诊断副本进行下列六组短采集。每组复位后运行约 11.5 秒，由 SWD 在末端停机读取 RAM，读完恢复运行；缓冲只保留前 2048 次读取，后续记录数量单独计数，不覆盖既有样本。

| 名称 | 输入配置 | 主循环 | SPI 读帧实现 |
| --- | --- | --- | --- |
| mode0 | 正常输入，CH2SET=0x40 | 原版完整任务 | 原实现 |
| mode1 | 内部测试，CONFIG2=0xE3、CH2SET=0x45 | 原版完整任务 | 原实现 |
| mode2 | 内部短接，CH2SET=0x41 | 原版完整任务 | 原实现 |
| minimal1 | 与 mode1 相同 | 仅原驱动读取，移除 UI/判拍/CAN 任务 | 原实现 |
| minimal2 | 与 mode2 相同 | 同上 | 原实现 |
| guarded1 | 与 minimal1 相同 | 最小采集 | 只增加数据末端 10 μs CS 低电平保持 |

诊断副本增加了：

- 启动阶段的寄存器实际回读，附带自身需要的片选高间隔。
- 固定 RAM 记录：处理时间、DRDY 积压数量、原始 STATUS、signed24 CH1/CH2、帧头合法性。
- 每组独立快照、源码差异和准确固件身份。

完整诊断版新增 RAM 为 49216 B，原版 RW+ZI 为 9184 B，完整诊断版为 58400 B，低于本 MCU 的 128 KiB SRAM。缓冲只由主循环写、SWD 停机后读；满后不覆盖，不打印逐样本日志。诊断记录会产生一定额外执行开销，本轮没有测量其精确开销，不能把诊断版当成未经扰动的原版性能测量。

所有时间戳都是 **MCU 读取/处理时间**，不是 ADC 采样或 DRDY 边沿时间。图中没有插值补点或假定等间隔。

## 6. 六组原始采集结果

每组保存 2048 次原始读取，包括非法 STATUS，未只保存通过帧。驱动累计计数取自后续约 11.5 秒快照，窗口不同，不能和前 2048 点统计混为一谈。

| 组别 | 保留窗口非法 STATUS | 保留窗口积压丢样计数 | CH2 最小值 | CH2 最大值 | 末端驱动 miss 累计 |
| --- | ---: | ---: | ---: | ---: | ---: |
| mode0 | 0 | 53 | 1359 | 183181 | 64 |
| mode1 | 0 | 57 | −15380 | 99328 | 66 |
| mode2 | 1 | 53 | −3932160 | 2718719 | 63 |
| minimal1 | 0 | 0 | −15406 | 12673 | 0 |
| minimal2 | 0 | 0 | −1395 | −1319 | 0 |
| guarded1 | 0 | 0 | −15381 | 12696 | 0 |

“保留窗口积压丢样计数”按每次读取的 `max(pending−1,0)` 累加，是驱动可见事件的计数，不保证统计到所有物理 DRDY 边沿；EXTI 事件合并或未收到边沿也不会被它发现。

缓冲满之后没有归档的记录数量为：mode0=299、mode1=271、mode2=296、minimal1=312、minimal2=360、guarded1=378。这是诊断保存容量限制，**不是额外 ADC 丢帧数量**。

### 6.1 内部短接：异常与积压相关

mode2 的两次大尖峰：

| 处理时间（自启动，ms） | CH2 原始值 | 同次读取 pending |
| ---: | ---: | ---: |
| 5412 | 2718719 | 5 |
| 9412 | −3932160 | 5 |

内部短接后，原始值通常在约 −1340 码附近，这个非零均值是偏置表现，不应直接判为芯片失败。两次数百万码的孤立跳变与附近常态差异极大，且同时存在积压。

最小采集 minimal2 的范围只有 −1395～−1319，标准差约 11.21 码，保存窗口没有同类大尖峰，pending 全部为 1。

**确认的事实：** 同一芯片、相同内部短接配置，在完整任务和最小采集下表现明显不同。主循环负担相关的延迟读取是已经有证据的故障方向。

**尚属推断：** 延迟读帧跨越 ADC 更新区造成数据撕裂，或者延迟路径放大 SPI 时序/传输错误。目前没有同时捕获的 DRDY/SCLK/CS/DOUT 电气波形，不能把某一种机制直接写为已证实。

该对照移除了多个任务，不能仅凭它区分是屏幕发送、算法执行、CAN 处理还是它们组合造成全部影响；但屏幕连续发送超过 4 ms 的代码证据仍然成立。

### 6.2 内部测试：有幅度响应，但周期验证未通过

配置请求内部 1 Hz 测试输入，原始正、负平台大约在 +12650 与 −15360，说明输入复用切换确实产生了不同于正常外部输入的结果。不能因此直接宣告内部测试全部通过。

minimal1 保存窗口只有三段负平台，符号变化处理时间为：

```text
3010, 3206, 7022, 7146, 9333, 9605 ms
```

guarded1 为：

```text
4880, 4900, 6574, 6638, 7759, 8163, 8660, 8908 ms
```

这些数据没有呈现稳定的预期测试周期。增加数据末端 CS 保持后，周期异常仍然存在。因此本轮不能把它判为仅缺少这一个 CS 等待，也不能把差异随机波动称为修复成功。

测试选择及内部波形预期来自 [TI ADS1292R 数据手册，CONFIG2/CH2SET 及内部测试输入](https://www.ti.com/lit/ds/symlink/ads1292r.pdf)。本轮未独立测量内部时钟、测试源或参考电压，也未在采集结束重新读取全部 ADS 配置；启动回读只能证明启动时的配置，不证明配置或电气条件始终未变化。

### 6.3 最小采集仍有长间隔，miss=0 不等于等间隔采样正常

| 组别 | 16 ms 间隔数 | 17 ms 间隔数 |

多数处理间隔为 4 ms，但上述长间隔并未伴随多个 pending。它们不能全部解释为完整 UI 任务积压，因为最小采集也存在；可能与实际 DRDY、引脚争用、时钟/转换、SPI、较高优先级中断或边沿遗漏有关，尚不能逐一排除。

**必须保留的阻塞项：** 用独立信号观测确认实际 DRDY 周期与 MCU 是否漏边沿，并核对 CLKSEL、CLK、PA2/PA3 外围连接。仅用当前软件处理时间不足以判定芯片转换频率。

## 7. 修改决策

### 优先修改方向：先保证采集连续性与错误可见性

已具备证据支持的方向：

1. 到达 DRDY 时及时读取并保存真实样本，算法和显示消费缓存。不能只扩大事件计数，也不能等 UI 完成后重读历史样本。
2. 将屏幕发送改为有界、非阻塞或每次限量处理，避免连续多个命令占用采样窗口。具体 ISR/DMA/UART 队列方案需要明确资源及并发边界，不直接照搬最小采集循环到生产代码。
3. 保留独立计数：积压丢样、非法 STATUS、SPI 超时/错误、采样间隔异常和削顶；初始化要明确报告实际配置及失败。
4. 明确保障 CS 和读帧时序；保留有界错误退出。CS 保持是应修的时序保证，但本轮没有证据证明它能单独解决所有现象。

### 必须继续定位的前置问题

- 内部测试源周期异常、最小采集仍有 16/17 ms 间隔，尚未闭合。
- 需要模块正反面、CLKSEL/CLK 接法、PA2/PA3 周围跳线及实际信号时序资料；“已经接好”不能替代这部分证据。
- 应先检查开发板是否有其它电平驱动接到 PA2/PA3，再选择安全的信号观测点。当前没有照片，不能宣称 SP3232/CH340 跳线冲突已经发生。
- 不直接大改时钟、增益或呼吸配置来获得好看的波形；每次只改变一个有明确假设的条件，并保留原结果。

### 后续处理层修改

原始采集问题闭合后，再处理静态报告中的 gain=4 与阈值口径、抑制器五点语义和显示单位问题，用同一份可靠原始记录回放对比。

当前不决定“改回 gain=2 就能解决”、不决定“模块坏了需要换”，也不把任何软件波形改善当作人体连接安全的证明。

**本轮实际实施的只是隔离诊断改动和诊断对照，未修改原工程生产代码。** 修改方案按上述证据排序，尚不提交一份声称问题全部解决的新生产固件。

### 12.3 与约 16 ms 间隔的关系：可检验的假设

TI 数据手册在当前 250 SPS 条件下给出转换启动建立时间为 2052 tMOD。按标准 fMOD=128 kHz 计算约为 **16.03125 ms**，与本轮最小采集中的 16/17 ms 长间隔数量级相符。[TI ADS1292R 数据手册，§8.5.1.9–8.5.1.10、表 13](https://www.ti.com/lit/ds/symlink/ads1292r.pdf)

因此“START 线上出现非预期变化，使转换重新启动/建立”应列为优先验证的假设，PA1 的板载共用连接给出了具体检查位置。但是处理间隔不是 DRDY 时戳，数值相符也不是因果证明；不能据此声称已测到 START 毛刺或 LAN8720 输出。

下一次应在人体断开、实物连接确认后，同时观测 ADS START/PWDN、DRDY 和 SPI，而不是只看滤波后的屏幕波形。若需隔离板载外设或迁移引脚，应先核对新引脚所有连接，再做有记录的单变量对照，不直接改成另一组“看似空闲”的引脚。

### 12.4 更新后的修改顺序

1. **先确保采集引脚可使用：** 核对开发板版本/装配、P3、PHY 状态以及模块供电、共地和 J3。接线方向正确不代表共用网络没有争用。
2. **再修采集连续性：**及时读帧并保存真实数据、降低主循环阻塞、保障 SPI 时序及独立错误统计。已有实测支持这一代码整改方向，但不能代替第一项电气核验。
3. **最后处理滤波和显示：**基于已通过的原始采样验证增益口径、抑制器语义和显示尺度。

# 标准采集本轮数据离线复核

日期：2026-10-13。仅离线分析，不连接设备、不修改固件、不覆盖采集原件及原报告。

## 1. 结论

**完成轮的采集连续性和稳定导出已通过本轮复核，但波形和算法输出仍有明确问题，不能据此判定心率/呼吸功能正常。**

主要问题：

1. 两通道都有很强的约50 Hz成分，ECG尤其明显。预热后，49～51 Hz占本报告统计频段功率的 **96.28%（ECG）/49.77%（呼吸）**。
2. 心率有效输出零散；105份状态快照中，算法BPM仅13份有效，末端BPM无效。
3. 呼吸代码存在**过期速率被无效新候选重新激活**的问题：没有产生新的合法呼吸间隔，仍将旧23次/分标记为有效。本轮回放复现并有实机状态对应。
4. 模拟器型号、输出幅值、心率及呼吸率参考值缺失。因此现有数值不能作准确度验收。

建议继续使用标准取数工具。下一步针对输入/模拟前端的50 Hz成分做已知输入对照，并定点修复呼吸有效性与历史新鲜度；目前没有依据重写整个采集链。

## 4. 波形：约50 Hz成分占主导

分析采用第30 s以后记录；按名义DWT时钟还原时间，以约249.802 SPS计算Welch频谱，段长8192、逐段线性去趋势。分带在边界插值后各自积分；分母为0.03 Hz～Nyquist。**下表不包括原始直流，不能解释为全部原始能量或临床SNR。**

| 频带 | ECG CH2功率占比 | 呼吸CH1功率占比 |
|---|---:|---:|
| 49～51 Hz | 96.28% | 49.77% |
| 99～101 Hz | 1.97% | 1.50% |
| 0.03～0.1 Hz | 0.38% | 26.62% |
| 0.1～0.67 Hz | 0.31% | 7.53% |
| 5～40 Hz | 0.53% | 6.95% |

两路约50 Hz峰位置约49.979 Hz，频谱分辨率约0.03049 Hz。ECG在四个稳态子窗口内的49～51 Hz占比仍约95.7%～96.8%，不是仅启动时出现。两通道在该频率附近的相干性约0.9984，支持共享很强的周期成分，不能单独证明其电气来源。

ECG原始值全轮约125514～249384，呼吸约640552～649575，均非全零或ADC顶轨；但“有数值、未顶轨”不能认证心电/呼吸信号正常。呼吸还存在明显的慢漂移/阶跃，尤其约85～110 s附近。

目前无法区分：模拟器本身输出此周期成分、输入连接/参考端未形成预期回路、模拟前端/供电/连接拾取周期干扰。模拟器也可能设置了干扰模式，因型号/设定缺失不能排除。不能据文件直接判定ADS1292R损坏、某根线接反，或把约50 Hz主成分判成心跳。

## 5. 心率：存在检测，但未形成持续有效输出

105份状态快照中：

- 算法BPM valid=1共13份，值为61、66、73；这是快照计数，不是连续有效时长。
- 最终实机算法与UI均BPM=0、valid=0。0表示无有效输出，不是模拟器真实心率为零。
- UI“质量”末端98来自帧通过率/覆盖率平滑，**不是QRS质量或ECG准确度98%**，代码见 [QualityTick](心率+呼吸/HARDWARE/hr_page.c:623)。

用与冻结源码对应的独立C副本做普通Host回放，编译和运行退出码均0；仅增加观察量，不修改生产算法。Host接受事件44次，BPM有效状态4714/37129个输入点，约12.70%。这些是算法行为，不是44次真实心跳的认证。

回放观察到10次心率算法重新初始化/学习。连续采样和flags均正常，其触发路径与“失拍/RR记录过期”等软件失效策略一致；不是10次MCU重启。9次可直接看到距上一接受拍约4003～4004 ms；另一次距上一拍3931 ms，代码还独立检查最近有效RR过期，不能把所有重学习都粗略称为同一个失拍条件。入口见 [PanTompkins_ProcessAt](心率+呼吸/HARDWARE/pan_tompkins.c:240)。

最后一次重学习时刻141618 ms之后，278个已学习阶段局部候选峰中，最大的“峰/当时门限”约0.847，仍未越过门限，解释了末端BPM无效。重新初始化也会把FIR历史清零，在非零直流输入下产生大启动过渡；Host图可见，不应把这些滤波过渡当作ADC原始尖峰。

不能仅凭本轮数据通过降低门限强求BPM输出。当前先需要确认已知输入与强周期成分，再评价算法参数。

## 6. 呼吸：发现实际发生的陈旧速率重新有效问题

实机UI呼吸率valid=1共26份快照，值包括23、16、28，末端显示28。没有参考值时，数值落在算法量程内不代表正确。

Host回放得到62个呼吸候选事件；其中52个间隔过短、2个过长，仅7个间隔满足代码的1.5～10 s范围。这里是代码接受范围，不是人体诊断标准。

### 可复现的具体事件

| 项目 | 回放观察 |
|---|---|
| 旧候选峰时刻 | 89280 ms |
| 后续长期无候选、Getter因12 s超时无效 | 已发生 |
| 新候选峰时刻 | 132323 ms |
| 本次间隔 | 43043 ms，超过10 s上界 |
| 是否录入新合法间隔 | 否，interval_accepted=0 |
| 保留的历史速率窗 | 23、8、37，rr_count=3 |
| Getter结果 | valid从0变1，返回历史23 |

原因有代码依据：

- [resp_rate.c:195](心率+呼吸/HARDWARE/resp_rate.c:195) 在间隔被拒绝后仍更新s_last_peak_ms。
- [RespRate_Get](心率+呼吸/HARDWARE/resp_rate.c:205) 超时只返回0，没有撤销历史速率窗；后续仅检查历史数量和最近候选时刻。
- 因此，一个没有产生新有效RR的候选峰，能让旧速率重新有效。实机后段再次出现23，与回放行为一致。

104份能按样本ms对齐的内存快照，其心率last_beat/rr_count及呼吸last_peak/rr_count四项整数状态均与Host回放吻合。这支持复现对应实际代码行为；live浮点字段可能跨更新，不能据此宣称Host与ARM逐位一致。

这是应该定点修复的软件有效性问题。修复验收应覆盖“正常输出→超时→只有非法候选不能重新有效→足够新合法间隔后恢复”。短候选刷新锚点也需受控验证；不能简单改成每隔若干噪声峰接受一次，否则会组合出看似正常的错误呼吸率。

算法图保存在本地忽略目录：[离线回放与滤波示例](OBJ/标准采集数据复核_20261013T133641/algorithm_review.png)。离线带通仅用于观察，不作为设备输出或真实QRS认证。

## 7. 下一步顺序

1. 保留这一轮为**链路完整、强周期成分、参考缺失、呼吸新鲜度缺陷**的定位样本，不将原PASS改写为生理准确度通过。
2. 用确切型号/设定的主动输入做对照，记录ECG幅值及定义、心率、是否输出呼吸阻抗/呼吸率、是否启用了噪声模式。先弄清输入与前端的50 Hz成分。
3. 对呼吸历史窗与有效性做小范围修复，并通过上述负向/恢复用例；不需要重写SPI/缓存或整个工程。
4. 用同一份标准原始输入做算法A/B回放；有已知真值后再决定滤波或门限的改动是否改善正确率。

本轮完成数据分析和归档，没有修改采样工具、生产源码或执行新的硬件动作。

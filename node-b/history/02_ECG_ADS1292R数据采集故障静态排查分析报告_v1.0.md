## 1. 摘要与总体结论

针对用户反馈的 **“ECG 模块无法正常采集数据，采集的数据有问题”** 现象，依据 TI ADS1292R 官方数据手册（SBAS502）、STM32F407 参考手册（RM0090）及本项目实际工程源码，进行了全链路的代码审查与硬件设计交叉比对。

### 核心结论
本次“数据异常”并非单一原因引起，而是**软件存在多处破坏采样连续性、波形形态与显示幅度的实质性缺陷**，同时**硬件层面存在引脚版本冲突与共模工作点高危隐患**：

1. **软件层面具有明确的责任**：
   - **架构阻塞与丢样**：DRDY 中断仅进行事件计数而未设计硬件/软件采样队列。主循环中向串口屏发送指令采用单字节死等 `USART_FLAG_TC` 阻塞机制，500ms 控件扫描单次阻塞达 5.73 ms（超过 250 SPS 的 4 ms 采样周期），导致实时数据流严重丢样与时间轴失真；
   - **SPI 读帧时序越界隐患**：`ADS1292_ReadFrame()` 读完 9 字节数据后未检测 `SPI_I2S_FLAG_BSY` 且缺乏尾部 CS 保持延时（违反 TI 手册要求的至少 3 ~ 4 个 `t_CLK` 保持时间），存在末字节截断或移位寄存器复位风险；
   - **算法参数与增益口径严重脱节**：心电通道实际配置为增益 4（满量程 ±605 mV，约 13865 码/mV），但接触伪迹抑制门限 `HP_SPIKE_STEP = 5000` 仍按增益 2 设定，相当于仅 0.36 mV 的跳变即触发抑制，导致正常陡峭的 QRS 波群被削平长达 100 ms 以上；
   - **显示标度单位不匹配**：送显波形经归一化并乘以 100000 放大，实际 1 mV 输入对应数值仅约 165，而送显自动增益跟踪下限被硬编码为 1024（初始 4096），造成正常心电波形在屏幕上被压缩至中线上下数个像素的极小抖动，直观呈现为“没信号”或“死线”；
   - **初始化静默失败**：未对 ID 寄存器进行握手校验，`CONFIG2` 内部基准寄存器未回读，重写失败未返回错误状态，导致硬件离线时程序仍伪装正常运行。
2. **硬件/物理层面不可忽视的外部诱因**：
   - **工程引脚与硬件手册存在重大版本分歧**：技术手册中规定为 PB3~PB5 / PD0~PD1 / PE8~PE9，而当前运行源码全量改为了 PA0~PA7，若物理连线按手册连接则硬件彻底不通；
   - **PA2/PA3 开发板外设复用风险**：PA2/PA3 常作为板载 USART2 连接至 SP3232 芯片，跳线帽未拔除将导致电平箝位与 EXTI3 中断失效；
   - **右腿驱动（RLD）与电极直流偏置**：人体浮空未接 RL 电极或电极接触不良时，工频干扰会导致输入超出共模范围并饱和削顶（±8388607），触发代码内的自动作废复位逻辑。

## 2. 采集与处理全数据链路拓扑

整个心电（ECG）信号从电极拾取到最终屏幕呈现的实际数据通路如下：

```text
[人体三导联电极 (RA/LA/RL)]
       │ (差分信号注入 IN2P/IN2N，RL 反馈抑制共模)
       ▼
[TI ADS1292R 模拟前端] (PGA=4, 内部 2.42V 基准, 250 SPS 连续转换)
       │
       │ 每 4 ms 产生一次下降沿
       ▼
[STM32F407 PA3 (EXTI3)] ──> EXTI3_IRQHandler: 仅执行 s_drdy_cnt++ (无数据缓冲)
       │
       │ 主循环轮询 HrPage_Task() -> FrameFeed()
       ▼
[ADS1292_ReadFrame()] ──> SPI1 (PA5/6/7) 读取 9 字节 (STATUS + CH1 + CH2)
       │                  (若 s_drdy_cnt > 1，仅读 1 帧，多余事件记入 s_miss_cnt 丢弃)
       ▼
[STATUS 字合法性校验] ──> (检查前 4 位是否为 1100b 及 13 位保留零位)
       │
       ▼
[ADS1292_S24ToS32(&f[6])] ──> 提取 CH2 (心电)，24 位补码符号位扩展为 int32
       │
       ├─ [削顶判定] ──> 若幅值 >= 8304721 (99%满量程)，执行 ecg_reset()
       │
       ├─ [5 点中值滤波] ──> ecg_median(): 滤除 1~2 点窄脉冲
       │
       ├─ [接触伪迹抑制] ──> EcgDespike(): 步进超 5000 码时按 1/8 速率追踪
       │
       └─ [Pan-Tompkins 算法] ──> 归一化 (/2^23) -> 129 抽头 FIR 带通 -> 微分 -> 平方 -> 积分 -> 判拍算心率
              │
              ▼
[显示抽点与尺度缩放] ──> 每 4 点取 1 点 -> FIR 输出 * 100000 -> WaveScale() (峰值归一到 0~255)
       │
       ▼
[串口屏推点] ──> GraphChannelDataAdd() -> USART1 (阻塞发送，每点 15 字节)
```

## 3. 软件代码缺陷详细排查与证据

### 3.1 【缺陷 1】读数据帧末尾缺失 CS 保持时序与 SPI 忙状态检查

- **源码位置**：`HARDWARE\ads1292.c` 第 303–307 行
  ```c
  ADS_CS_LOW();
  // RDATAC 连续读：连续发 9 个 0xFF 产生 SCLK，依次移出 STATUS/CH1/CH2 各 3 字节
  for (i = 0; i < 9; i++)
      f[i] = SPI1_TxRx(0xFF);
  ADS_CS_HIGH();
  ```
- **时序机理对比**：
  在同文件的 `ADS1292_Cmd()` 与 `ADS1292_WriteReg()` 中，作者显式加入了：
  ```c
  gap_us(ADS_CMD_GAP_CS_US); // ★ tSCCS：第 8 个 SCLK 下降到 CS 高要 ≥3 tCLK，10us
  ```
  并在文件头注释中强调：“第 8 个 SCLK 下降到 CS 高需要 3 tCLK（≈1.46us），否则命令会被掐断”。
  然而在数据吞吐量最高、最关键的 `ADS1292_ReadFrame()` 中，**9 字节接收一完成，代码立即拉高 CS**。
- **违规分析**：
  1. `SPI1_TxRx()` 的实现为：
     ```c
     while (SPI_I2S_GetFlagStatus(SPI1, SPI_I2S_FLAG_TXE) == RESET);
     SPI_I2S_SendData(SPI1, data);
     while (SPI_I2S_GetFlagStatus(SPI1, SPI_I2S_FLAG_RXNE) == RESET);
     return (uint8_t)SPI_I2S_ReceiveData(SPI1);
     ```
     当第 9 个字节触发 `RXNE` 并被读走时，STM32 内部移位寄存器的最后边沿可能尚未完全平息，且代码未等待 `SPI_I2S_FLAG_BSY == RESET`；
  2. 紧接着拉高 `ADS_CS_HIGH()`，完全没有保证 TI ADS1292R 数据手册 §6.6（时序要求表）中规定的 `t_SCCS ≥ 3 t_CLK`（末位 SCLK 下降沿到 CS 上升沿至少保留 3 个时钟周期，在内部 512kHz 时钟下为 5.86 μs，正文要求 `≥ 4 t_CLK` 约 7.81 μs）；
  3. **后果**：CS 过早抬高会导致 ADS1292R 内部移位寄存器被强制复位，极易引起最后一字节（CH2 心电最低字节 LSB）传输截断，导致采集数据尾字节出现随机波动或数据帧错位。

### 3.2 【缺陷 2】事件计数代替样本缓存，主循环阻塞导致等间隔采样彻底崩塌

- **源码位置**：
  - `HARDWARE\ads1292.c` 第 176–182 行（中断服务）、第 287–298 行（读帧消费）
  - `SCREEN\hmi_user_uart.c` 第 82–87 行（串口驱动）
  - `HARDWARE\hr_page.c` 第 846–854 行（控件扫描）
- **代码事实**：
  ```c
  // 中断函数中：
  void EXTI3_IRQHandler(void) {
      if (EXTI_GetITStatus(EXTI_Line3) != RESET) {
          s_drdy_cnt++; // 仅累加计数
          EXTI_ClearITPendingBit(EXTI_Line3);
      }
  }

  // 读帧函数中：
  irqState = __get_PRIMASK();
  __disable_irq();
  pending = s_drdy_cnt;
  s_drdy_cnt = 0;
  __set_PRIMASK(irqState);
  if (pending == 0) return 0;
  if (pending > 1) s_miss_cnt += (pending - 1); // 积压帧直接作废
  ```
- **机理剖析与量化测算**：
  1. ADS1292R 内部**没有多帧 FIFO 硬件缓存**，每个采样周期（250 SPS 下为 4.0 ms）结束时，新数据会自动刷新覆盖输出移位寄存器；
  2. STM32 固件在 `EXTI3_IRQHandler` 中仅执行计数，**没有使用 DMA 或中断读取并压入环形缓冲区**；
  3. 主循环中，串口屏底层发送函数 `SendChar()` 采用全阻塞轮询：
     ```c
     void SendChar(uchar t) {
         while (USART_GetFlagStatus(USART1, USART_FLAG_TXE) == RESET);
         USART_SendData(USART1, (uint8_t)t);
         while (USART_GetFlagStatus(USART1, USART_FLAG_TC) == RESET); // 死等移位寄存器发完
     }
     ```
     在 115200 波特率下，传输 1 字节严格耗时：10 / 115200 ≈ 86.8 μs；
  4. `hr_page.c` 中的 `ScanControls()` 每 500 ms 执行一次，连续下发 6 条控件读取指令，共计 66 字节，纯串口阻塞时间即达 **5.73 ms**；
  5. 此外，每次推心电波形需 15 字节（1.30 ms），推呼吸波形需 15 字节（1.30 ms），每秒文本刷新及报警记录下发数百字节；
  6. **直接后果**：
     - 单次串口阻塞时间（5.73 ms）明显长于采样周期（4.0 ms），导致 DRDY 必然发生积压（`pending ≥ 2`）；
     - `ADS1292_ReadFrame` 只能读出当前最新的 1 帧，中间被覆盖的帧全部永久丢失（计入 `s_miss_cnt`）；
     - 脱机测试验证：积压 5 次 DRDY 时，仅能读取 1 帧，其余 4 帧彻底丢失；
     - 采样流的等间隔性被彻底破坏，实测等效采样率远低于 250 Hz 且抖动巨大；
     - 后续 Pan-Tompkins 算法的 129 抽头 FIR 带通滤波器完全建立在严格 250 Hz 均匀采样的数学假设之上，时序抖动导致滤波频响畸变，微分斜率失真，算法频繁进入 100ms 输入超时作废分支（`PanTompkins_Invalidate()`），导致心率输出长期显示 `---`。

### 3.3 【缺陷 3】CH2 实际增益（Gain 4）与算法伪迹抑制门限口径严重脱节

- **源码位置**：
  - `HARDWARE\ads1292.c` 第 72–75 行：
    ```c
    // CH2SET (05h) = 0x20 —— 通道2 = 心电，增益 2（满量程 ±1210mV）
    { ADS_REG_CH2SET, 0x40, "CH2SET " },
    ```
  - `HARDWARE\hr_page.c` 第 63–66 行：
    ```c
    #define HP_SPIKE_STEP 5000
    /* 上面的门限是增益 2（CH2SET=0x20，≈6932 码/mV）下的码值，改增益必须同比缩放。 */
    ```
- **参数失配分析**：
  1. ADS1292R 的通道增益寄存器编码中，`0x40` 对应 GAIN=4（`100b`），满量程为 ±V_REF / 4 = ±2.42V / 4 = ±605 mV；
  2. 在 24 位 ADC 下，增益 4 对应的转换分辨率为：
     - 分辨率 LSB = 605 mV / (2^23) ≈ 0.07212 μV/LSB
     - 对应刻度换算：约 13865.5 码/mV
  3. 代码中的门限 `HP_SPIKE_STEP = 5000` 是原先在增益 2（6932 码/mV）下按 0.72 mV 设计的；但在实际增益 4 下，5000 码仅对应：
     - 输入电压跳变 ΔV = 5000 / 13865.5 ≈ 0.3606 mV
  4. 正常人体胸壁心电信号的 R 波尖峰幅度通常在 1.0 ~ 1.5 mV 左右，在 250 SPS 采样率下，QRS 上升支的单步微分差值极易超过 0.36 mV；
  5. 审查 `EcgDespike()` 函数逻辑：
     ```c
     if (d > HP_SPIKE_STEP) {
         if (s_sp_n < HP_SPIKE_MAX) { s_sp_n++; }
     }
     if (s_sp_n > 0) {
         s_sp_p += (v - s_sp_p) / 8; // 强行按 1/8 速率平滑，极度压制快速跳变
         if (d <= HP_SPIKE_STEP) { s_sp_n--; }
     }
     ```
  6. **实测表现**：经抽取函数执行阶跃测试，一旦跳变超限，抑制状态将连续维持 27 个样本点（长达 108 ms，足以覆盖整个 QRS 间期）。原本正常的 R 波陡峭尖峰被强制当成伪迹衰减削平，破坏了波形形态，并使得微分能量无法达到判拍阈值。

### 3.4 【缺陷 4】波形送显映射的标度单位严重失配（屏幕波形被极度压缩）

- **源码位置**：
  - `HARDWARE\hr_page.c` 第 138 行、第 222–234 行 (`WaveScale`)
  - `HARDWARE\pan_tompkins.c` 第 278 行 (`s_filtered` 计算)
- **数值断层分析**：
  1. 信号处理链中，输入 ADC 码先除以 2^23（`8388608.0f`）归一化至 [-1.0, +1.0]；
  2. 经过 129 抽头带通滤波后，在 `pan_tompkins.c` 中放大送显：
     ```c
     s_filtered = (int32_t)(input * 100000.0f);
     ```
     对于 1 mV 的输入信号，在增益 4、参考电压 2.42V 下，经过通带增益为 1 的 FIR 滤波后，`s_filtered` 的理论峰值约为：
     - 归一化输入值：(1 mV × 4) / 2420 mV ≈ 0.0016528
     - 送显放大值：0.0016528 × 100000 ≈ 165
  3. 但是在 `hr_page.c` 中，自动增益跟踪峰值 `s_ecg_peak` 初始化为 **4096**（注释写着“ADC 码”，实际上接收的是上述只有 165 的数值），并且代码对峰值下限进行了死区钳位：
     ```c
     if (*peak < 1024) { *peak = 1024; }
     ```
  4. 随后执行归一化映射：
     ```c
     y = 128 + (v * 110) / *peak;
     ```
     当输入峰值 v = 165 时：
     - 若处于开机阶段（`*peak = 4096`）：y = 128 + (165 × 110) / 4096 = 128 + 4 = 132；
     - 若已收敛到最低峰值下限（`*peak = 1024`）：y = 128 + (165 × 110) / 1024 = 128 + 17 = 145；
  5. **直观呈现**：大彩串口屏曲线通道纵坐标范围为 0 ~ 255，基线位于 128。正常 1 mV 的心电信号在屏幕上偏转仅有 ±4 ~ ±17 个阶梯，波形幅度极度低平微弱，用户用肉眼观察极为类似“没有采集到有效波形”或“采集数据严重错误”。

### 3.5 【缺陷 5】初始化缺乏有效握手与 ID 回读校验（静默失效）

- **源码位置**：`HARDWARE\ads1292.c` 第 226–268 行 (`ADS1292_Init`)
- **逻辑缺陷**：
  1. **未校验 ID 寄存器**：TI ADS1292R 芯片地址 `0x00` 处内置只读 ID 寄存器，ADS1292R 的标准身份标识必须等于 `0x73`。代码在初始化中完全未读取或核验 ID；
  2. **关键基准寄存器未回读**：
     ```c
     ADS1292_WriteReg(ADS_REG_CONFIG2, 0xE0);
     Delay_ms(20);
     ```
     `CONFIG2` 负责启动内部 2.42V 基准电压缓冲器（`PDB_REFBUF=1`）。代码直接跳过回读，若电源或 SPI 线路接触不良导致该寄存器写入失败，基准源未建立，后级 ADC 将无法进行正确的差分转换；
  3. **重写失败缺乏二次判定**：在循环写入其余寄存器时，代码只在第一次读取不符时补写一次，之后**未再次回读确认重写是否生效**；
  4. **函数无错误返回值**：`ADS1292_Init()` 返回类型为 `void`，即使整个 SPI 总线未插线、读回全为 0x00 或 0xFF，函数依然盲目执行 `ADS1292_Cmd(ADS_RDATAC)` 并拉高 `START`，系统对外表现为“初始化成功并进入采集”，导致通信断开等硬件故障被严重掩盖。

### 3.6 【缺陷 6】显示波形为窄带判拍信号而非临床诊断级心电

- **源码位置**：`HARDWARE\ecg_filter.c` 第 17–44 行
- **频响特性分析**：
  经对源码中 129 抽头 FIR 系数进行离散傅里叶变换（DFT）理论频响计算：
  - **0 Hz（直流）**：增益 0.01488（-36.55 dB）；
  - **0.5 Hz**：增益 0.02861（-30.87 dB）；
  - **1.0 Hz**：增益 0.07037（-23.05 dB）；
  - **4.0 Hz**：增益 0.75731（-2.41 dB）；
  - **10.0 ~ 25.0 Hz**：增益约 0.998（-0.01 dB，通带中心）；
  - **29.0 Hz**：增益 0.75673（-2.42 dB）；
  - **35.0 Hz 以上**：增益 < 0.00079（-62.03 dB）。
- **说明**：
  该滤波器是专门针对 QRS 波群能量集中区设计的带通滤波器，其 -3dB 通带约为 3.8 ~ 29.2 Hz。
  该频响会把心电信号中极其重要的低频分量（P 波、T 波、ST 段）大幅衰减（衰减超过 20 ~ 30 dB），且引入了约 256 ms 的固定群延迟。
  如果用户或测试人员期待在屏幕上看到的是临床标准（0.05 ~ 100 Hz）的完整心电形态，而代码直接将判拍用的滤波波形输出至屏幕，观察者必然会判定波形形态失真畸变。

## 4. 硬件、引脚与电气环境层面的潜在根因排查

在确认上述代码缺陷的同时，根据项目硬件资料，以下硬件电气因素亦是导致“数据采集不正常”的常见根因：

### 4.1 引脚定义存在历史版本重大冲突（致命排查项）

对照项目技术档案，发现了两套截然不同的引脚分配方案：

| 信号名称 | 实际代码配置 (`main.c` / `ads1292.h` / `spi.c`) | 技术手册规定 (`01_ECG_RESP_ADS1292R原理图与驱动技术手册.md`) | 硬件复用及冲突风险 |
| :--- | :--- | :--- | :--- |
| **PWDN / RESET** | `PA0` | `PE8` | 手册强调 PE8 避免占用 PD2（血压）；代码实际使用 PA0 |
| **START** | `PA1` | `PD1` | 手册规定 PD1；代码实际使用 PA1 |
| **CS (片选)** | `PA2` | `PD0` | **高危**：开发板上 PA2 默认连接 USART2_TX（P3 跳线） |
| **DRDY (数据就绪)** | `PA3` (EXTI3) | `PE9` (EXTI9) | **高危**：开发板上 PA3 默认连接 USART2_RX（P3 跳线） |
| **SCLK** | `PA5` (SPI1) | `PB3` (SPI1) | PB3 处于 JTAG/SWD 调试引脚复用区，代码切为 PA5 |

- **排查建议**：
  必须立即使用万用表或肉眼核对杜邦线实际插接引脚！
  如果硬件连线是按照旧版《技术手册》插在 PB3/PB4/PB5、PD0/PD1、PE8/PE9，而当前编译烧录的固件运行在 PA0~PA7，**单片机与 ADS1292R 之间根本没有任何电气连接**，SPI 读回全 0xFF 或全 0x00，DRDY 永远不触发！

### 4.2 开发板 PA2 / PA3 硬件跳线帽冲突

- STM32F407 开发板通常板载 SP3232 或 CH340 芯片连接 `PA2 (USART2_TX)` 和 `PA3 (USART2_RX)`，并通过开发板上的 **P3 排针跳线帽** 切换。
- 当前代码将 `PA2` 用作 ADS1292 的软件 CS 片选输出，`PA3` 用作 DRDY 外部中断输入。
- **排查重点**：
  若开发板上的 P3 跳线帽短接了 1-3 或 2-4，板载电平转换芯片将强行驱动 PA2/PA3，导致 CS 无法被拉低或 DRDY 下降沿被箝位在 3.3V，使单片机无法捕获中断或无法建立 SPI 片选通信。

### 4.3 人体电极共模电压与 RLD（右腿驱动）饱和

- 代码中 `RLD_SENS` 配置为 `0xEC`（`1110 1100b`），其中 Bit 5 (`PDB_RLD`) = 1 使能了内部 RLD 缓冲器，Bit 3 (`RLD2N`) = 1、Bit 2 (`RLD2P`) = 1 选择通道 2 提取共模电压；
- **生理测量特性**：
  心电信号为微弱差分信号（0.5 ~ 2 mV），叠加在高达数伏的人体 50Hz 工频共模电压之上。
  - 若测试时仅连接了正负电极（RA、LA）而**未接第三根 RL（右腿驱动）参考电极**；
  - 或者电极片干燥、接触不良导致阻抗过大；
  - 人体共模电平将脱离 ADS1292R 的允许共模输入范围（AVSS + 0.2V ~ AVDD - 0.2V），导致内部仪表放大器（PGA）深度饱和；
  - 一旦饱和，ADC 转换输出将长期锁死在正满量程 `+8388607`（`0x7FFFFF`）或负满量程 `-8388608`（`0x800000`）；
  - `hr_page.c` 检测到幅值超过 `HP_ADC_CLIP`（8304721），会无条件调用 `ecg_reset()` 并清除所有数据，导致界面无法绘图、心率显示为无效。

### 4.4 模块 CLKSEL 时钟选择引脚悬空

- ADS1292R 的 1 脚为 `CLKSEL`：
  - 当接高电平（DVDD）时，选用内部 512 kHz 振荡器；
  - 当接低电平（DGND）时，必须由外部 CLK 引脚提供方波时钟。
- 若模块上的 J3 跳线脱落或 CLKSEL 悬空，芯片内部调制器无法获得时钟，DRDY 将永远保持高电平，停止一切转换。

## 6. 静态排查结论与后续软硬件修复建议

### 6.1 结论定性

1. **“数据有问题、采集不正常”在软件层面完全能够复现**：
   - 即使硬件电气连接 100% 正常，当前代码也会因为**串口屏阻塞导致等间隔采样严重破坏**、**伪迹抑制门限口径错误将 R 波削平**、以及**显示映射下限过高将波形压缩成死线**，最终在界面上呈现出“波形错误、心率不出”的故障假象；
2. **硬件排查必须优先于算法调优**：
   - 在调整软件前，必须先核查硬件引脚与跳线，排除 PA2/PA3 冲突和连线版本冲突。

### 6.2 建议修复步骤（按优先级排列）

#### 阶段一：硬件与接线核验（无需改动代码）
1. **实物接线核对**：确认模块是否连接在 `PA0 (PWDN)`、`PA1 (START)`、`PA2 (CS)`、`PA3 (DRDY)`、`PA5 (SCK)`、`PA6 (MISO)`、`PA7 (MOSI)`；
2. **跳线排查**：确认开发板 P3 跳线帽已拔下，断开 PA2/PA3 与板载串口电平转换芯片的连接；
3. **电极接入**：测试时必须连接全部 3 根导联线（RA/LA/RL），RL 必须良好接地/人体以建立共模基准，避免 PGA 饱和。

#### 阶段二：软件关键缺陷修复（代码层面）
1. **重构数据读取机制（消除丢样）**：
   - 将 DRDY 改为直接在中断中触发 SPI DMA 读取，或者在 `EXTI3_IRQHandler` 中有界读取 9 字节存入环形队列（Ring Buffer），彻底解除主循环阻塞对采样的破坏；
   - 将串口屏发送从死等 `USART_FLAG_TC` 改为非阻塞环形缓冲或中断/DMA 发送；
2. **修正 CS 时序保护**：
   - 在 `ADS1292_ReadFrame()` 中，读完 9 字节后增加等待 `SPI_I2S_FLAG_BSY == RESET`，并追加 `Delay_us(10)` 的 `t_SCCS` 保护时间再拉高 CS；
3. **校准算法参数与显示标度**：
   - 将 `hr_page.c` 中的 `HP_SPIKE_STEP` 调整为与增益 4 匹配的合理门限（如 10000 码以上），或直接以真实心电形态评估抑制器必要性；
   - 调整 `WaveScale()` 的峰值初始化和下限，将 `*peak` 范围由 1024~4096 改为与送显幅值匹配的区间（如 150~300），使正常心电波形在屏幕上占有 ±60 ~ ±80 像素的清晰偏转；
4. **完善初始化自检闭环**：
   - 在 `ADS1292_Init()` 中增加读 ID 寄存器（`0x00`）并校验 `0x73`，回读 `CONFIG2` 确认基准开启，提供初始化布尔返回值，失败时明确上报硬件故障。

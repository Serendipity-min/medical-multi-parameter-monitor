# 通用多样本采集工具与数据协议设计 v1.0

日期：2026-10-13。状态：**设计稿，尚未实施或联板验收**。

适用范围：本项目心率/呼吸采集，以及今后通过独立适配器接入的其它采集通道。本文规定数据交付与比较口径，提出工具和传输接口设计；不修改现有固件、不自动授权硬件操作，不改变 Gateway 的 MQTT/Router 协议。

## 1. 对当前方案的判断

修完《采集工具问题清单与重新采集要求_20261012.md》后，可以得到**针对当前镜像的可靠性更高、可复核的采集方式**，但仍不能直接称为通用采集工具，原因如下：

| 当前约束 | 多样本使用时的影响 | 本方案的处理 |
|---|---|---|
| 固定 BIN、RAM 地址及 128×24 B 槽布局 | 换镜像就可能读错字段 | 经过核对的适配配置绑定镜像和符号 SHA |
| SWD 运行中取数不是原子读取 | 连续序号不证明记录内容完整 | 原件保留，严格稳定重建，逐记录标明证据强度 |
| 没有统一样本、轮次、启动段身份 | 复位后的相同 seq 或多轮文件容易混用 | 使用独立 run_id、boot_id、segment_id |
| 原始、滤波、算法和 UI 数据容易混淆 | 无法明确异常发生在哪一层 | 分开保存，按真实样本时刻关联 |
| 输入设定与参考值不完整 | 波形可以画，准确度无法验收 | 参考输入及同步条件是独立必填项；未知值不补造 |
| 目前原型输出及负向处理未完成 | 无法作为统一生产入口 | 先完成文件规范及离线验收，再验证适配器 |

**建议后续统一的是本文件规定的“采集包与分析口径”，不要求所有版本都使用同一种取数接口。** 当前 SWD 方式作为过渡适配器；具备条件后采用专用连续数据接口。不同适配器输出相同文件协议，因此历史数据和新数据能进入同一个批量分析入口。

这是一份项目工程规范，不声明符合任何行业采集标准或医疗设备认证。采集文件完整性、信号准确度和人体连接安全性是三个不同结论。

## 2. 成功标准与最小工具结构

目标是：换一轮、换一个样本、换一版算法后，不用重新猜地址、单位、输入类型或时间关系；任意结论都能追溯到原始文件与分析版本。

```text
当前 SWD / 今后专用串口 / 历史文件
              ↓ 各自适配器
不可覆盖的原件 + 身份与操作回执
              ↓ 离线校验、解码、时间分段
统一采集包：样本、状态、事件、参考、质量
              ↓ 固定版本的分析程序
单轮报告 + 多轮分组对比报告
```

工具建议名称为 `acq`，先用现有 Python 环境实现命令行，不先开发 GUI。命令名是**拟定接口，当前不能直接执行**：

| 命令 | 功能 | 允许的副作用 |
|---|---|---|
| `acq init` | 新建轮次与元数据模板 | 只新建本地目录 |
| `acq precheck` | 核对配置、文件身份及采集条件 | 默认纯脱机；板卡核验须显式使用已获授权的硬件模式 |
| `acq capture` | 根据已批准操作清单采集 | 硬件行为由适配器与清单明确列出，禁止隐式烧录/复位 |
| `acq import` | 导入 R7 等旧文件 | 新建派生目录，不改旧目录 |
| `acq validate` | 验证包结构、身份、序号、时间、冲突 | 纯脱机 |
| `acq analyze` | 解码、回放、生成图与指标 | 纯脱机，绑定分析配置 |
| `acq compare` | 按数据集清单批量对比 | 纯脱机，检查可比条件后再统计 |

适配器只负责取数和解释设备格式；通用校验与分析不能依赖 COM 编号、某个固定盘符、某个工程目录或个人用户名。中文项目路径保持可用；工具所需短路径映射由单次任务管理，不能撤销其它任务的映射。

## 3. 身份与版本规则

| 字段 | 规则 |
|---|---|
| `dataset_id` | 多样本实验集合；例如同一输入下的固件 A/B 对照 |
| `sample_id` | 输入对象的匿名编号；不是 seq，也不能使用姓名 |
| `condition_id` | 明确的实验条件编号，关联不可变条件配置 |
| `run_id` | 每轮唯一，推荐“含时区的时间标识 + 随机后缀”；失败重跑必须新建 |
| `boot_id` | 每次已确认启动分配一个标识；复位后不能延用旧标识 |
| `segment_id` | 时间连续且语义不变的数据段；断连、时间无法解卷绕等需新段 |
| `protocol_version` | 本文件数据格式版本，初始为 `1.0` |
| `adapter_id/version` | 设备格式适配器及其版本，不与数据协议版本混用 |
| `analysis_id` | 每次分析唯一，绑定代码、配置和所有输入 SHA |

固件记录 BIN/ELF SHA-256、源码身份、构建工具版本和采集相关配置。源码树有未提交修改时记录相关文件清单及 Diff SHA，不能只写 Git HEAD。适配配置保存符号文件 SHA、源模块、字段地址/偏移、类型、长度、字节序及校验规则；当前固件的地址表不得当作通用默认值。

采集启动前核对设备身份与允许的镜像。旧文件导入时，无法从原始证据确认的身份使用 `null` 和原因，不能把当前电脑上的镜像身份回填成历史身份。读取设备身份、镜像和停止状态的范围受实际硬件授权约束。

## 4. 标准采集包

```text
数据集/
  dataset_index.csv
  conditions/条件编号.json
  runs/唯一run_id/
    session.json                  输入声明、身份、计划、工具版本
    channels.json                 通道、原始类型、单位及校准信息
    adapter_profile.json          经核对的本轮取数配置
    raw/                          原始字节、槽块、状态、调试日志、指令
    acquisition_receipt.json      实际操作、退出码、停止和恢复状态
    raw_manifest.json             原件大小与 SHA-256，封存时生成
    derived/唯一analysis_id/
      samples.csv                 经校验的原始码，逐采样点、逐通道
      firmware_state.csv          实机状态，保留一致性与时刻边界
      events.jsonl                缺口、冲突、配置变更等
      observations.csv            原始观察与稳定样本之间的映射
      reference.csv               有参考输入才提供，未提供时不能伪造
      quality.json                分层校验结果及不能判断的项目
      analysis_receipt.json       分析身份、输入及参数、退出码
      report.md / plots/          分析报告与图
      manifest.json               本次派生产物大小与 SHA-256
```

先采集到唯一临时目录，失败也封存；采集回执与解析回执分开。原件封存后不覆盖或删除。修解析器后新增 analysis_id，原错误解析与失败记录继续保留。`raw_manifest.json` 不收录自身，派生清单同样不收录自身；上层索引可另记录清单 SHA，避免自引用。

文件内路径使用采集包内相对路径，移动整个数据集后仍可解析；本机绝对工作路径仅放本地操作回执。大体积原件可保存在本地证据根目录，用带 SHA 的明确关联记录管理，不得仅依赖临时盘符。可能含个人信息的数据保持本地，不自动上传公开仓库。

文本采用 UTF-8；JSON 不使用 NaN/Infinity、不允许重复键，未知值使用 `null`。这是本项目基于 [JSON RFC 8259](https://www.rfc-editor.org/rfc/rfc8259) 选定的格式约束。CSV 使用逗号、表头、CRLF 和双引号转义，遵循 [CSV RFC 4180](https://www.rfc-editor.org/rfc/rfc4180) 的通用格式；空字段表示未知，不等于 0。严格分析入口按声明类型读取，避免表格软件把长序号、SHA 或时间戳自动变换。JSON 中可能超出 2^53−1 的整数使用十进制字符串。

## 5. 数据协议：统一样本与状态字段

### 5.1 `channels.json`

每个通道必须有：`channel_id`、`physical_source`、`role`、原始有符号类型、有效位数、原始单位、采样率设定、增益、量程/参考电压、数据来源、转换与校准说明。

当前初始通道映射：`resp`＝ADS1292R CH1，`ecg`＝CH2。原始码是 signed 24-bit，统一 CSV 解码为有符号整数；不得拿滤波值、像素、BPM 或 unsigned 整数代替。保留 ADC STATUS、真实 flags 和原始字节。

物理量转换采用显式、版本化的公式：`physical = (raw_code - offset_code) × scale`。scale、单位和适用条件未经核实则保持未知，不能默认为 mV。呼吸阻抗原始码不能仅凭 ADC 电压比例直接称为欧姆或呼吸率。gain/reference 变化后新建条件或数据段。

### 5.2 `samples.csv`：逐采样点、逐通道的长表

```csv
run_id,boot_id,segment_id,source_seq,device_tick_raw,device_time_us,irq_cycles_raw,channel_id,raw_code,adc_status_raw,source_flags_raw,integrity,provenance,observation_count,source_ref
```

| 字段 | 类型与语义 |
|---|---|
| `source_seq` | 设备采集事件序号，不是接收包序号；当前适配器是 DRDY IRQ 序号，不能称为 ADC 独立计数 |
| `device_tick_raw` | 原始设备时间计数；单位/位宽/起点由适配配置声明 |
| `device_time_us` | 在已证实段内按 tick 频率解卷绕后的整数微秒；无法确定则为空，不按名义采样率补造 |
| `irq_cycles_raw` | 原始 DWT 计数；无此字段则为空 |
| `raw_code` | 声明通道的有符号原始码 |
| `adc_status_raw`、`source_flags_raw` | 保留原始整数与字典，不按需要清除位；未知位也保留 |
| `integrity` | `CONSISTENT_RECONSTRUCTION`、`PUBLISHED_SNAPSHOT`、`CRC_VERIFIED_FRAME` 或 `UNVERIFIED`；含义见第 8 节 |
| `provenance` | 来源与选择方式；不能把重复重建改名成原子读取 |
| `observation_count` | 独立原始观察次数，不含解析器重复运行的次数 |
| `source_ref` | 原始文件及字节区间/观察编号；多来源通过 observations 表展开 |

唯一键为 `(run_id, boot_id, segment_id, source_seq, channel_id)`。同一采样事件的两通道共用 source_seq 与设备时刻；完整性检查按通道要求判断，不能把双通道两行算成两次采样。另一采集设备使用自己的源序号/时钟，不能假装与 ECG 同步。

默认 `samples.csv` 只接收满足对应适配器一致性规则的样本；未认证记录写入 observations/events，保留原件。探索性导出未认证数据必须另命名并明确标注，不能混入默认批量准确度分析。

### 5.3 状态、离线结果和 UI 分开

`firmware_state.csv` 使用长表：

```csv
run_id,boot_id,segment_id,observation_id,module,field,value,value_type,unit,valid,sample_seq,sample_tick_raw,read_start_host_ns,read_end_host_ns,coherence,source_ref
```

`module` 必须区分 `ecg_algorithm`、`resp_algorithm`、`ui`、`adc_driver`。`valid` 为空表示没有取得有效性证据，0 表示实机声明无效，1 表示实机声明有效；算法 valid=1 不自动证明准确。

`coherence` 可为 `LIVE_UNCOORDINATED`、`HALTED_MEMORY_POINT`、`FRAME_ASSOCIATED`。只有经过设备发布协议确认并关联处理样本，才使用 FRAME_ASSOCIATED。冻结内存不保证停在完整算法更新边界；live 块内字段也不能仅凭一个 ms 强行配对。

滤波回放、离线 QRS、频谱等写到独立分析产物，显式标记 `offline`、滤波配置及初始状态。禁止和实机状态混表后伪称设备输出。UI 旧值需要保留其 valid 与最后更新时刻，不能当作当前算法结果。

## 6. 时间、启动段与事件

每次 IO 记录主机 UTC（带时区）和单调计时的请求/完成区间。主机计时频率/原点在回执中声明；不能跨主机或主机重启直接相减。文件创建时间、sleep 参数都不能当作实际采样时间。

设备计数保留原始值。u32 差采用模运算；只有结合采集间隔上界、其它时钟及启动证据能唯一解卷绕时才输出解卷绕时间。DWT 168 MHz 下约 25.565 s 回绕一次，超过可判定间隔、调试暂停期间时钟行为未知或复位时，重新分段并记录限制。不能把 IRQ 的名义时钟频率当作经过标定的绝对时基。

事件采用 `events.jsonl`，每行一个 JSON 对象：`event_id, run_id, boot_id, segment_id, type, device_seq_start/end, host_request_ns, host_confirmation_ns, details, source_ref`。常见 type：

- `SOURCE_GAP`、`TX_GAP`、`HOST_IO_ERROR`、`CRC_ERROR`、`CONFLICT`、`PENDING`。
- `BOOT_DETECTED`、`TIME_AMBIGUOUS`、`CONFIG_CHANGED`、`INPUT_CHANGED`。
- `HALT_REQUEST`、`HALT_CONFIRMED`、`RUN_REQUEST`、`RUN_CONFIRMED`。

SWD HALT 请求与确认形成停止时刻的观测边界，确认时刻不写成实际停止瞬间；没有确认就记录目标状态未知。分段不自动证明复位原因，原因不足写 unknown。

平均采样率以同一连续段**不同 source_seq 的采样事件**计算 `(N−1)/(t_last−t_first)`；跨缺口时另列源序号推进速度与间隔分布，不能只用一个平均值宣布无丢样。至少报告实际样本数、预期通道覆盖、缺失范围、重复、冲突、时间异常和已知驱动错误。头尾未观测范围未知时，只声明观测跨度内的结果。

## 7. 输入与参考协议

输入类型必须显式选择：`ACTIVE_HARDWARE_SIMULATOR`、`INTERNAL_TEST_SIGNAL`、`SOFTWARE_FIXTURE`、`PASSIVE_PHANTOM`、`HUMAN_DECLARED` 或 `UNKNOWN`。声明与证据核实分开；不能把“模拟真实人体信号”自行翻译成硬件模拟器。

采集前记录实际设备型号/编号、是否主动输出 ECG/阻抗信号、输出方式、接线、信号幅值及其定义、心率、呼吸率、变化计划、温度/运动/噪声等相关条件。未提供的数值为 null。被动假体不自动产生已知 ECG。

参考文件表头：

```csv
run_id,reference_id,reference_time_us,device_time_us,sync_uncertainty_us,channel_id,metric,value,unit,reference_kind,source_ref
```

`reference_kind` 区分 `PROGRAMMED_SETPOINT` 与 `INDEPENDENT_MEASUREMENT`。设定值不是对实际输出的独立测量。同步方法及误差必须记录；设备时间无法对齐时留空，不凭主机开始按钮认为同步。缺乏可靠同步时可做稳态窗口级对照，不能计算逐拍延时。

无参考时只做信号表征、链路与算法行为分析，心率/呼吸率准确度标为 `NOT_EVALUATED`。本文件不授予人体操作权限，也不以“电池供电”或元数据勾选替代患者保护核验。

## 8. 当前 SWD 过渡适配器规范

适配器建议编号 `ads1292r_swd_ring24/v1`，只对经核对的镜像与 ABI 生效。不能给新固件自动套用旧地址。

1. 每个运行槽块必须精确 3072 B，记录真实 IO 顺序与区间。
2. 同一 boot/segment 内保存完整 24 B 的所有版本；A 出现至少两次且其它版本均只出现一次时可选择 A，仍保留冲突。
3. **若两个不同版本均出现至少两次，停止该序号的一致性认证，不按票数大小选取。** 单次版本标 pending；全零槽、非零非法槽分开记录。
4. 暂停尾段只读取同一份 RAM 的 head/slots，并采用已发布最后 127 槽规则；疑似活动写入槽排除。head 与 IRQ 序号分别解释。
5. 已认证版本与暂停版不一致时停止完整认证；不得覆盖历史版本。观察区间可能跨复位且无法确定归属时，不按 seq 合并。
6. 输出 samples、状态表、observations、conflicts/pending 事件、原件及两个阶段的回执。恢复运行的请求和确认单列，不能依赖 J-Link 总退出码宣称已恢复。

当前约 250 SPS 的 128 槽历史窗口只有约 512 ms。为重复观察提供机会，必须依据实际 IO 间隔、最坏耗时和槽覆盖统计判断轮询是否足够；两次观察之间槽未被覆盖是必要条件。即使平均轮询频率足够，偶发长延迟也会留下 pending/缺口，不能用 nominal sleep 值代替验证。

`CONSISTENT_RECONSTRUCTION` 仅表示符合重复观察一致性规则；`PUBLISHED_SNAPSHOT` 表示来自保守发布槽边界。两者都不是物理 ADC 边沿无丢失、逐样本 CRC 或模拟信号真值证明。

当前 `stable_slot_export.py` 仍采用“唯一最高票”选择，尚未满足第 3 条；入口仍缺完整导出与恢复状态核验。**本轮没有修改这些程序，因此过渡工具尚未准入统一采集。**

## 9. 今后连续接口的候选传输协议

本节是下一阶段可选设计，不要求立即改固件。先确认独立数据接口可用：当前 USART1 接 HMI，COM18 不能仅凭枚举就当作原始采集端口。不能把二进制样本直接混入 HMI 指令流。

候选帧采用显式序列化，不发送 C 结构体内存。多字节字段小端，定长头 32 B：

| 字节偏移 | 类型 | 字段 |
|---:|---|---|
| 0 | 4 bytes | magic：ASCII `ECAP` |
| 4 | u8 | wire_version，初始 1 |
| 5 | u8 | message_type |
| 6 | u16 | header_len，必须 32 |
| 8 | u32 | payload_len，绝对上限 1024 |
| 12 | u64 | stream_token |
| 20 | u32 | packet_seq |
| 24 | u32 | profile_id，本轮协商编号，完整 SHA 在元数据中 |
| 28 | u16 | record_count |
| 30 | u16 | reserved，初始必须 0 |
| 32 | bytes | payload |
| 32+payload_len | u32 | CRC-32 |

CRC 覆盖完整头与 payload；采用与 `binascii.crc32(data, 0) & 0xffffffff` 一致的 CRC-32，结果小端。测试向量 ASCII `123456789` 应得 `0xCBF43926`。算法实现可参照 [Python 官方 binascii 文档](https://docs.python.org/3/library/binascii.html#binascii.crc32)。CRC 只用于传输错误检验，不是身份认证，也不证明 ADC 数据正确。

message_type：0x01 METADATA、0x02 SAMPLES、0x03 STATE、0x04 COUNTERS。除 SAMPLES 外，payload 是有界 UTF-8 JSON、record_count=0；元数据超长则拒绝或另行设计版本，不能无界分配。未知版本不解码为 v1；未知 type 保存原件并标覆盖限制。

SAMPLES 初始固定为双通道 ADS1292R profile：每记录 28 B，最多 16 条，payload_len 必须等于 record_count×28，record_count 必须 1～16：

```text
0:u32 source_seq   4:u32 sample_ms   8:u32 irq_cycles
12:u32 adc_status  16:i32 ch1_raw    20:i32 ch2_raw   24:u32 source_flags
```

STATUS 高 8 位必须为 0；通道须已符号扩展且在 signed 24-bit 范围内。flags 映射在 profile 中固定；不能重新解释旧固件标志位。其它设备使用新 profile 和明确记录布局，不能沿用上述双通道格式。

stream_token 由主机在开始新数据流前分配、通过显式绑定交互确认。新实现复位后必须清除绑定并暂停数据流，重新交换镜像/配置元数据；没有重新绑定不能沿用旧 token。绑定是新增控制接口，具体命令及故障行为须实施前单独审查，不是假设当前固件已有能力。

source_seq 在采集事件处分配，采集失败/源队列丢失保留序号缺口及原因；packet_seq 在封包尝试时分配，发送队列丢包保留缺口及独立计数。两者及主机 IO 丢失分别报告。序号回绕与复位规则必须在 profile 声明，无法消除歧义则分段。

采用有界队列、非阻塞发送和明确丢弃策略，不能为“无丢包”阻塞 ADC ISR。主机完整保存原始流，限定长度与超时，坏 CRC/非法长度逐字节寻找下一合法帧并记录被跳过区间；不能触发设备复位或把半包当完整数据。

名义 250 SPS、10 记录/帧时样本流约 `250×28 + 25×36 = 7900 B/s`。按 8N1 计算，115200 baud 容量为 11520 B/s，单样本流约占 68.6%；230400 baud 名义占 34.3%。还需状态/统计、调度和抖动余量。设计目标为正常总流量不超过名义容量 60%，实际接口、波特率及队列资源必须单独验证，不能据计算声称当前接口已可用。先保留现有 SWD 过渡方案，不为实施串口协议重写整个采集链。

## 10. 多样本采集与可比性规则

每轮一个 run；同一输入重复采集也新建 run。用 `dataset_index.csv` 组织，不靠目录名字猜实验条件。建议首个已知输入验收集合：

| 组别 | 输入 | 重复与目的 |
|---|---|---|
| 链路组 | 内部测试信号或已知稳定输入 | 至少 3 轮，核验完整性及重复性；不能当呼吸准确度真值 |
| 功能组 | 可主动输出 ECG/阻抗的已知模拟器 | 已知心率、幅值、呼吸率条件各至少 3 轮 |
| 边界组 | 零输入、超量程、断段等可控台架数据 | 先用脱机夹具验证无效值/丢样处理，硬件动作另行明确 |
| 对照组 | 相同输入下旧/新固件或算法 | 单次只改变一个变量，按条件配对；记录顺序和环境变化 |

这些是工程起步建议，不是统计学充分样本量。建议基础轮次为显式预热 30 s、分析 120 s；已有短记录只分析实际覆盖。慢呼吸场景需覆盖足够周期，否则延长计划或标证据不足。预热数据同样保存，仅在分析配置里排除，不能删除或改写时戳。

上述时长是新工具的计划参数，不是当前脚本能力的声明。当前原型限制 100～800 次轮询、180 s 进程超时，且轮询次数不等于设备采样点数；实施时必须按实际耗时校核计划与限额，不能直接复用原型参数宣称完成 150 s 数据窗口。

允许对比的条件分层检查：

- **链路比较**：序号语义、时间测量方式、目标速率和观察跨度可解释。
- **波形比较**：通道含义、增益、校准、采样率、输入幅值及噪声条件一致；不同单位须有经核对的转换。
- **算法比较**：使用同一份经过校验的原始输入做 A/B 回放，固定滤波初态、预热、缺口策略与分析版本，避免把两次不同输入当算法差异。
- **真机结果比较**：同输入条件也可能有模拟器/模拟链波动；参考不充分时明确限制，不能等同于同输入离线 A/B。

变化未经记录、参考不存在、时钟/幅值校准未知、关键样本未认证时，不进入相应的正式比较。重采失败不能从索引中删除；使用 disposition 标记保留、排除原因及用途。

配置 SHA 用于证据身份，不单独决定可比性。比较程序应检查与目标指标相关的配置字段；不能因为 JSON 排版变化就断言物理条件变化，也不能因为相同配置文件 SHA 就忽视实际输入变化。

## 11. 批量分析输出与分项结论

每轮及集合报告都应分开给出：

| 维度 | 输出 | 缺条件时的结论 |
|---|---|---|
| 身份/导出完整性 | SHA、覆盖跨度、缺口、冲突、pending、IO/设备计数 | `FAIL` 或 `INCOMPLETE`，不按图看起来平滑放行 |
| 时间与同步 | 间隔分布、计数回绕、读数区间、参考同步误差 | `LIMITED` / `NOT_EVALUATED` |
| 波形表征 | 原始范围、饱和比例、漂移、明确频段的噪声指标、通道关系 | `OBSERVATIONAL`；不能独自判传感器损坏 |
| 算法行为 | 首次有效时刻、有效覆盖率、重置/超时、UI 旧值、回放差异 | 无参考仍可做行为分析 |
| 心率/呼吸准确度 | 有参考时给误差、无效率及匹配方法 | `NOT_EVALUATED_WITHOUT_REFERENCE` |

图必须标单位、原始/实机/离线来源、缺口与排除窗口。插值只能生成另列的可视化数据，不能填回原始样本或用于声称无损。

频谱按连续有效段计算，声明去趋势、窗口、带宽与滤波版本。50 Hz 谐波不可重复累计，积分不能跨不连续频带；ACF 应报告局部峰及边界命中，不能把搜索区间边界最大值直接解释为呼吸/心率。没有可靠真值时，不输出“人体测试通过”。

集合报告列每轮真实值、失败和限制，再按条件汇总中位数/范围及有效轮数；不把同一轮几万个采样点当作几万个独立实验样本。不把不同条件混成一个总体 PASS。

## 12. 实施顺序与准入测试

### 第一阶段：统一文件，先不改固件

落实 session/channels/索引模板，完成通用离线校验；把 R7 原件作为导入夹具。导入到新目录，保留旧错误输出和全部冲突。补齐 SWD 严格重复冲突判定、类型明确的 CSV、状态/来源表、计时和失败回执。

### 第二阶段：验证当前适配器

在单独获准的台架窗口验证当前固定镜像：身份、稳定导出、尾段、实际 IO 与恢复确认。通过后将其列为该镜像的可用适配器，不能推广为所有固件已通过。

### 第三阶段：有需要再做连续接口

先确认 HMI 外的可用接口及预算，再实施第 9 节的接口。需要修改固件时单独建立最小改动及 Host/ARM/台架验证清单；不改变既有业务协议，不为采集需求引入 RTOS 或全面重写算法。

最低普通验收用例：

| 用例 | 预期 |
|---|---|
| 两个版本各重复 ≥2 次；多数不平票 | 仍停止一致性认证，不靠多数覆盖 |
| 全零、非法非零、单次记录、短块 | 分类保留；默认稳定样本不收录未认证记录 |
| 负 raw/filtered、24 位极值 | 解码有符号类型正确，不猜字段归属 |
| 复位 seq 重用、DWT 回绕、多次回绕无法确定 | 启动段隔离；有证据才解卷绕，否则限制时间结论 |
| 状态落后、UI stale、halt 无确认 | 保留状态边界，不配成同帧，不宣称停止或恢复成功 |
| 原件 SHA 漂移、重复 run_id、失败目录再利用 | 拒绝并保存失败回执，不覆盖旧证据 |
| 改增益/时基/profile 后混合比较 | 拒绝相关比较或要求明确转换，不能暗用旧配置 |
| 参考缺失、被动假体、同步不明 | 不评心率/呼吸准确度，不伪造参考 |
| 将来串口半包、连包、垃圾前缀、坏 CRC、超长/未知版本 | 有界解析、记录损坏、恢复到合法帧；不越界或复位设备 |
| 同一原件、同一分析版本重复运行 | 数值/选择结果一致；不同 analysis_id 均可追溯 |

只有实现上述规则、通过相关普通离线测试和对应适配器的台架验证后，才能把工具标为“可用于标准采集”。本轮交付为方案及填写模板，没有联板采集，没有新增协议的固件实现，也没有改变历史采集结论。

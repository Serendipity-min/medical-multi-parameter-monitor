## 1. 结论与当前状态

本轮证据支持两个需要同时处理的原因：

1. **PA1 不适合作为这块开发板上的独占 START 控制脚。** 将其置低的对照中，MCU 在约 32.595 μs 内记录到 64 次引脚边沿，观测中断触发上限后关闭；此时没有 DRDY/采样。将模块 START 改接 PG15 并释放 PA1 输出后，DRDY 间隔恢复约 4.004 ms，原先的 16/17 ms 长间隔消失，内部测试恢复稳定周期。模块移离后，旧 PA1 网络仍有高速边沿，支持干扰来自板上共用网络。
2. **旧代码没有保存连续样本，主循环阻塞会造成迟读与丢样。** 已改为 DRDY 中断及时读帧、128 帧固定队列、主循环按原始采集顺序及时间戳消费。不能只改一个事件计数变量来重建旧样本。

板上现在运行的是 **PG15 START、正常电极输入配置** 的修复版，不是内部测试或短接固件。原始工程内已整合经验证的改动；原版源文件、失败数据、测试前 Flash 和对照固件均留存。

最终普通启动检查：**3406 帧捕获、3406 帧交付；初始化错误、SPI 错误、非法帧、队列溢出及长间隔计数均为 0。** 这些结论只覆盖本轮约 15 秒启动观察，不作为人体接触安全、真实 ECG 算法或长期运行的验收。

## 3. START 网络的根因证据

### 3.1 为什么不能把 PA1 当作普通独占 GPIO

用户提供的开发板 STM32F407_原理图.pdf（原报告本地资料链接，原件未随本包公开） 第 4、6 页显示 PA1/RMII_REF_CLK 与 LAN8720A 的 nINT/REFCLKO 共用。PA1 的 GPIO 输出配置并不能解除板上的电气连接。

在正常高电平 START 模式，初期没有记录到 PA1 数字边沿，不能据此证明电气上完全稳定。之后低电平命令启动对照出现以下真实失败：

| 项目 | 结果 |
| --- | --- |
| 请求 START 电平 | 低 |
| PA1 观察计数 | 64，到上限停用 |
| 首末观察跨度 | 约 32.595 μs |
| 记录到的 GPIO 数字电平 | 包含 0 和 1 |
| PWDN 观察边沿 | 0 |
| DRDY / 原始帧 | 0 / 0 |

这不是正常软件 START 高低切换：此段代码没有反复写 PA1。发现后停止该对照，将 MCU PA1 输出释放为输入，保留 RAM 原件，没有继续尝试在该网络上长期强拉低电平。

图纸连接、异常边沿和换脚后的功能恢复共同支持 **板载共用网络干扰 START 控制** 是主要根因。**尚未使用示波器直接测量该信号频率或逐段追到 PHY 输出，因此不把“测到了 50 MHz LAN8720 时钟”写成实测结论。** 50 MHz 是相关 PHY 功能说明，不是这些 IRQ 记录给出的频率。[Microchip LAN8720A 数据手册](https://ww1.microchip.com/downloads/en/DeviceDoc/00002165B.pdf)

### 3.2 单变量换脚对照

同样的内部测试配置、完整 UI/CAN 任务和 ISR/FIFO，比较模块 START 接 PA1 与 PG15：

| 项目 | PA1 / FIFO | PG15 / FIFO |
| --- | ---: | ---: |
| 保存原始帧 | 2048 | 2048 |
| DRDY IRQ 入口间隔中位数 | 4004.107 μs | 4003.964 μs |
| 最大 IRQ 间隔 | 16114.286 μs | 4004.810 μs |
| 15–18 ms 间隔数 | 29 | **0** |
| SPI 错误 / 非法 STATUS | 0 / 0 | 0 / 0 |
| 队列溢出 | 0 | 0 |
| 内部测试形态 | 负平台出现不规则 | 正负平台稳定交替 |

PG15 实际 START 观察边沿为 0；原 PA1 已改为输入且不再连接模块，仍记录到 64 个边沿并封顶。这一对照把模块输入与旧网络的活动分开了。

内部测试实测半周期约 **512.5 ms**，约 **0.976 Hz**，记录实际数值，不写成精确 1.000 Hz。数据用于证明周期稳定性与输入复用响应，不作为外部时基校准。

### 3.3 受控暂停/恢复，确认 PG15 确实控制模块

在独立对照固件中只执行一次低电平暂停并恢复：

- 实际低电平保持：**20.0028 ms**。
- PG15 观察到两次控制边沿，没有触发封顶。
- DRDY 出现一次 **33.5906 ms** 的有意间隔，随后恢复稳定采集。
- 总捕获/交付：2524/2524，SPI 错误、非法帧及队列溢出均为 0。

该有意间隔与控制时刻对应，不作为未知故障或偷偷删除。它表明新线不是仅把模块 START 随意固定接到高电平，PG15 的控制能够影响采集状态。受控 START 原始回执（原报告本地资料链接，原件未随本包公开）

所有时间来自 MCU DWT/IRQ 记录，IRQ 入口不等于外部引脚边沿的精确时刻；中断抢占、有限数字带宽和封顶均是观察局限。

## 4. 采集调度与缓存修复

### 4.1 旧路径及迟读证据

旧 DRDY 中断只累计次数，主循环读取当前数据，一次积压不能重建多份历史帧。屏幕发送仍为阻塞式，6 条控件扫描的名义串口时间约 5.73 ms，超过 250 SPS 的 4 ms 周期。

本轮原路径短接对照读取 2347 帧、观察 2376 次 DRDY，存在 29 次事件积压差额；保留窗口的最大 IRQ→读帧启动延迟约 **3995.55 μs**，记录到一次读帧过程中 IRQ 序号变化。前轮已保存的数百万码异常尖峰和 STATUS 失败没有删除。

本轮原路径短接对照没有再次出现数百万码尖峰，这是本次结果，不写成“每次都能复现尖峰”。已复现的迟读/积压，以及历史尖峰证据分别保留，不混为同一观察。

### 4.2 新路径

```text
DRDY IRQ
  → 保存入口序号、DWT 周期和毫秒采集时戳
  → 10μs更新区等待 → SPI读取9字节 → 有界BSY等待 → 10μs末端保持
  → 独立SPI状态及STATUS校验
  → 固定128帧队列，满则拒绝新帧并计数
主循环
  → 只消费已保存帧
  → 按采集时戳与序号处理，不把积压样本伪造成当前同一时刻
  → 滤波/判拍、显示与CAN沿原任务运行
```

每帧 24 B、128 槽，队列占 3072 B。生产者只有 DRDY ISR，消费者只有主循环，使用 DMB 发布/释放槽位；初始化前才可 Reset。不是多生产者或多核通用队列。

SPI 等待每段使用 DWT 有界计时，采样字节 `0xFF` 与错误返回分离。ISR 不做 FIR、显示、CAN 或逐点串口打印。配置阶段与运行阶段的 SPI 所有权分开：当前应用只在初始化访问命令/寄存器；未实现采集期间的热配置，主循环不能直接与 ISR 并发访问 SPI。

记录真实序号断段、超过 6 ms 的 IRQ 间隔标志及溢出；**不根据间隔猜测并补造物理丢帧数量**。上层遇到断段重新初始化历史，不把旧、新片段拼接。

### 4.3 时间接口迁移

仅添加 `ProcessAt/InitAt/InvalidateAt` 时间接口，原接口保留兼容；心率/呼吸输入使用采集时戳。FIR 系数、增益、抑制阈值、判峰数学和显示尺度没有调参。

队列只是保存数据；如果继续用消费时间计算 RR，批量处理仍会压缩样本间隔，因此时戳迁移是此次队列整改所需的部分。现有 5 点中值、抑制器和屏幕自动增益问题保留给下一阶段。

# 标准采样工具使用说明 v1.0

日期：2026-10-13。程序：`acq/1.0.1`。对应《通用多样本采集工具与数据协议设计_v1.0_20261013.md》。

**当前是完成普通脱机验证、待首次联板验收的 SWD 版本。** 27 项普通测试通过；R7 原始文件完整导入验证通过。本轮没有连接、复位或烧录开发板。

## 1. 能做什么

- 每轮唯一目录，样本/条件编号，固件、ELF、符号与工具 SHA 绑定。
- 当前 ADS1292R 固件的 J-Link 采集；Flash 只读，不烧录、不改寄存器配置。
- 全部原始槽块、状态、IO 时间区间、命令和日志保留；失败也封存。
- 严格重复版本验证及发布尾段，输出双通道 signed 原始码、实机状态、冲突/pending 事件。
- 清单校验、历史导入、新版本重新分析、原始波形 SVG、基础统计、数据集索引和分组对比。
- 可保存用户提供的模拟器心率/呼吸率设定；不补造参考或同步，不自动宣称准确。

首版只实现已有 SWD 适配器。设计中的 ECAP 串口协议尚无对应板端实现，不能直接选择 COM18 接收原始 ECG。无需为使用本工具重写生产固件。

## 2. 使用条件

需要 Python 3.11+、PowerShell 7、已安装的 J-Link Commander。无需安装 pip 依赖。保留整个 `工具/` 目录及相邻模板、工程身份文件，不要只复制 acq.py 一个文件。

首版硬件模式仅用于非人体台架：主动模拟器、被动假体或实际已经存在的内部测试输入**。** 本工具不核验患者保护条件，不提供以声明代替核验的人体 SWD 入口。离线导入/分析可以处理已经保存的数据，不访问设备。

## 3. 最方便的入口：PowerShell 启动脚本

先在 PowerShell 7 执行以下**纯脱机预览**。请用真实样本、条件和模拟器型号替换示例文字：

```powershell
& '<LOCAL_PROJECT>\doc\B\心率+呼吸\工具\开始标准采样.ps1' `
  -SampleId 'sim-001' -ConditionId 'known-input-a' `
  -Fixture '实际主动模拟器型号及设置' -InputKind ACTIVE_HARDWARE_SIMULATOR `
  -Duration 10 -Warmup 0
```

输出新的轮次目录和离线身份核验。未加 `-Execute` 时不会连接 J-Link。查看该轮 `session.json`，补齐输入设定、接线、操作者、参考与条件信息；未知项保持 null。实际操作许可由运行者判断，PREPARED 文件不是安全证明。

在确认非人体台架条件成立后，对刚创建的轮次启动短采集：

```powershell
$acqTool = '<LOCAL_PROJECT>\doc\B\心率+呼吸\工具\acq.py'
$acqRun = '替换为上一步输出的完整轮次路径'
python -X utf8 $acqTool capture --run $acqRun --execute --confirm-no-human
```

也可以通过启动脚本一次创建并采集：增加 `-Execute -NoHumanElectrodesConfirmed`。每次运行脚本都新建轮次。不要把一次失败的旧目录重复采集。

首次先用 10 s / 预热 0 s 检验工具身份、取数、尾段与恢复，不据短记录判断心率/呼吸准确度。通过首次台架复核后，多样本常规轮次可用 `-Duration 150 -Warmup 30`；主机 150 s 不保证设备有足够 150 s，报告会如实记录启动延迟和实际窗口不足。

默认数据集在项目 `doc/B/心率+呼吸/OBJ/标准采集数据` 下，该 OBJ 目录受现有 Git 忽略规则保护。用 `-DatasetRoot` 可选择其它本地数据盘；不同数据集分开存储，不自动上传。

## 4. 实际硬件动作

运行 `capture` 不加 --execute 只显示计划。实际启用后的动作固定如下：

1. 读取 DHCSR、UID、器件 ID；全片 Flash 双读并校验身份。初始若暂停，不在身份核验前恢复。
2. 身份匹配后，**一次 reset + go**，开始本轮采集。此动作会重新启动当前程序。
3. 运行中读取 3072 B 槽块，间隔目标 100 ms；每 10 轮读取一次 2048 B 状态。记录每次请求/确认边界。
4. 到计划时长后，**一次 halt** 并核对 S_HALT，记录寄存器，读取 128 KiB RAM 尾段。
5. go 后两次检查运行状态，再退出 Commander。回执只称“断开前运行已确认”，不称持续运行或硬件恢复验收完成。

不打开 COM18，不发 HMI 数据，不写 Flash，不切换 START/ADC 配置，不执行安全扫描。只有 hardware identity 全部符合才执行 reset。

本版时长 1～300 s，轮询上限 4000。实际 IO 延迟超过历史窗口会使数据不完整，不能由软件凭空补回。首轮须用真实日志核查 Commander V5.12 的交互确认及吞吐；模拟进程通过不等于实际 J-Link 已验证。

## 5. 停止和失败处理

按 Ctrl+C，或在轮次目录创建名为 `STOP` 的文件。收到停止后不追加 reset/halt/go；若中断在最终 halt 之后，目标可能仍暂停，回执会标未知状态。工具不会对未知身份/状态自动“抢救”。先读回执再处理设备。

身份不匹配、命令错误、长度错误、超时、意外复位/暂停、无法确认恢复时停止。所有已读文件、日志与失败回执继续保留。新尝试须创建新轮次。

硬件失败后的原始文件仍可执行 `analyze` 做限定观察；采集未完成时不会报完整 PASS。发生启动归属歧义时，当前适配器停止稳定导出，不猜测启动边界拼接样本。

## 6. 采集后看哪些文件

```text
轮次/
  session.json / channels.json / adapter_profile.json
  acquisition_receipt.json     实际动作与目标结束状态
  raw_manifest.json           原始文件完整清单
  raw/                        原件、commands.jlink、jlink.log、io.jsonl
  derived/analysis-唯一编号/
    samples.csv               每采样事件两行：resp(CH1)、ecg(CH2)
    stable_frames.bin         进入样本表的完整24 B记录，便于原C工具回放
    firmware_state.csv        ADC、ECG、呼吸、UI分模块，有符号类型正确
    observations.csv          含无效、空槽、冲突、未选择观察
    events.jsonl              缺口、冲突、pending及HALT/GO请求/确认
    segments.json             连续段及名义时基
    reference.csv             仅有声明的模拟器设定时生成
    quality.json              分项结论
    summary.json / report.md / waveforms.svg
    analysis_receipt.json / manifest.json
```

先看 acquisition_receipt，再看 quality。`integrity=PASS` 只表示观测跨度内符合适配器选择规则，不是“ADC 物理边沿完全无丢失”或“生理准确度通过”。状态块也可能读在算法更新中间，不能当作逐帧原子结果。

`device_time_us` 是**每连续段首样本为零**的相对时间，根据名义 ms 时基换算，未做时钟校准；DWT 另保留原计数并检验回绕/一致性。段之间不补造时间。多段 SVG 的时轴各自归零，可能重叠，应按 segments/CSV 分段读取。

源码未提供准确度真值时，不输出心率/呼吸误差。当前分析功能为基础原始表征、实机状态与证据导出，尚未实现独立参考对齐和心率/呼吸准确度自动验收；给出模拟器设定也不改变这个限制。

## 7. 单命令与历史导入

以第 3 节的 `$acqTool` / `$acqRun` 为例：

```powershell
python -X utf8 $acqTool precheck --run $acqRun
python -X utf8 $acqTool validate --run $acqRun
python -X utf8 $acqTool analyze --run $acqRun
```

`precheck` 永远纯脱机；`validate` 校验文件及数据包，不当作硬件/准确度准出；`analyze` 创建新的 analysis_id，保留上一份报告。工具更新后，新硬件采集应重新 init；历史分析允许用新工具版本，并单独绑定新分析代码 SHA。

CLI 创建轮次还可记录模拟器设定：

```powershell
python -X utf8 $acqTool init --dataset 'E:\本地采集数据\ecg-set-a' `
  --sample sim-001 --condition hr60-resp15 --input-kind ACTIVE_HARDWARE_SIMULATOR `
  --fixture '实际型号' --hr-setpoint 60 --resp-setpoint 15 --duration 150 --warmup 30
```

将历史 slot/state 原件导入另一个新轮次：

```powershell
python -X utf8 $acqTool import --run $acqRun --source '实际历史原始块目录' `
  --paused-ram '已保存的128KiB暂停RAM文件' --paused-snapshot-confirmed
```

没有暂停证据则省略最后两个参数，末端 pending 会保留。导入只复制原始文件，不运行历史脚本；设备身份默认 UNKNOWN，不能用当前板卡或磁盘 BIN 回填历史身份。暂停声明会注明来源，不冒充本工具的 DHCSR 实测。

退出码：0＝命令完成（仍需看分项限制）；1＝门禁/IO/配置错误；2＝导出不完整；130＝用户中断。`LIMITED` 不自动变成整体通过。

## 8. 多样本采集与对比

同一条件至少从 3 轮工程重复开始；同一样本可复用 sample_id，每轮 run_id 不同。固定输入、增益、速率和预热，单次只改变一个变量；不把同一轮的采样点当独立实验次数。失败轮次留在索引。

```powershell
python -X utf8 $acqTool compare --dataset '实际数据集目录' `
  --output '新的比较输出目录' --purpose integrity
```

输出 comparison.csv/json，逐轮保留失败和限制。`--purpose waveform` 加强输入/增益检查；未知身份、未知输入核验、未完整导出等会排除相应正式比较，但仍列出单轮统计。配置按实际内容分组，不依赖 JSON 排版。不同分析代码 SHA 不混为同一分析口径。

当前不会把 UNKNOWN 自动改为 VERIFIED，也不会将假体/未知输入视为有真实心率。对比基础指标更容易，不等于自动完成算法准确度验收。

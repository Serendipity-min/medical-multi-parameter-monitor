日期：2026-10-12。目的：说明 R7 取数工具的问题，为下一轮采集提供可检查的要求。本文件聚焦采集与导出，不要求重写生产固件，不将采集完整性等同于心率/呼吸准确度。

重采步骤适用于非人体台架或已知模拟信号。本文件不确认人体连接的隔离与患者保护条件。无主动信号输出的被动假体，只能用于连接/环境噪声观察，不能用于心率和呼吸准确度验收。

## 3. 正确解释24 B记录

`EcgQueuedFrame`不是9 B MQTT/串口包，而是RAM中的24 B结构：

| 偏移 | 长度 | 类型/含义 |
|---:|---:|---|
| 0 | 3 | ADS1292R STATUS，大端拼接 |
| 3 | 3 | CH1，24位有符号大端原始码 |
| 6 | 3 | CH2，24位有符号大端原始码 |
| 9 | 1 | flags，保留真实断段标志 |
| 10 | 2 | 结构对齐空间，不解释为采样内容 |
| 12 | 4 | IRQ序号，uint32小端 |
| 16 | 4 | IRQ入口DWT周期计数，uint32小端 |
| 20 | 4 | 采样时戳ms，uint32小端 |

STATUS校验`(status & 0xF01FFF) == 0xC00000`仅检查固定格式，**不能认证其余字段来自同一次写入**。全零空槽、非零无效槽、版本冲突、真实flags必须分别统计。

DWT在名义168 MHz下约每25.565秒回绕。周期差必须按`(next-prev) % 2**32`计算，不得把回绕当时间倒退，也不得仅用浮点相减。IRQ时刻是软件观测时刻，不是外部仪器测得的ADC物理边沿。

## 4. 建议的稳定重建规则

### 4.1 运行中快照

1. 保留每份原始槽块及采集顺序，先检查长度必须为3072 B。
2. 对每个序号保存所有完整24 B版本及观察次数，不用首读覆盖后读。
3. 一份仅观察一次的记录，列为未认证，不写成稳定PASS。
4. 至少两次逐字节相同，且没有另一个同样重复的版本，才选为稳定版本。
5. 若两个不同版本均重复出现、平票或出现疑似复位重用序号，停止完整认证，保留全部证据；不能靠“票多一点”隐去持续冲突。
6. 重建后检查序号、ms、DWT、STATUS、flags及驱动统计。禁止插值补点、清零错误或删除真实断段以获得PASS。

重复观察提高可信度，不是端到端CRC或独立模拟输入真值证明。更强方案是在片内完成记录、停止写入后再读取，或增加经过验证的发布/版本协议。

### 4.2 尾段封存

停下CPU后，使用**同一份RAM快照**里的`head`和`slots`封存尾段。`head`是成功Push的发布位置，不得无条件等同于IRQ序号。

即使CPU暂停，若停在Push中途，`head % 128`对应的最老槽也可能已被下一次写入部分覆盖。保守使用最后127个已发布位置：

```text
published positions = [max(0, head-127), head)
physical slot        = position & 127
```

不要将可能正在写入的槽混入尾段。暂停后仍有冲突或未认证记录，应报告不完整，不能静默删掉。尾段最终版与已稳定版本不一致时也必须停止并调查。

R7离线验证中，该规则识别39个冲突，封存35个单次尾段记录及最后新增的3帧，得到1～26591共26591条稳定重建记录。前26588条与独立多数重建逐字节一致。**这是旧数据离线验证，不是新一轮联板测试。**

## 5. 状态字段、符号和时间对齐

当前普通固件BIN绑定：

```text
9f58a8902da3ba35c30c2d736f416c75a68e578a69835a2ed94ded9d1ad58281
```

下表仅对该已核对镜像有效。不是通用地址，新构建不得直接复制：

| 字段 | 当前地址 | 类型/归属 |
|---|---|---|
| slots | 0x20002038 | 128×24 B |
| head / tail | 0x200001C4 / 0x200001C8 | uint32发布/消费位置 |
| ADS1292Stats | 0x2000020C | 12×uint32，注意与CAN同名统计区分 |
| g_lastSampleMs | 0x20000088 | 最近心电处理的采样时戳 |
| s_filtered（心电） | 0x20000098 | int32，Pan-Tompkins |
| s_filtered（呼吸） | 0x200000BC | int32，RespRate |
| BPM / valid（算法） | 0x20000092 / 0x20000094 | uint16 / uint8 |
| BPM / valid（UI） | 0x20000102 / 0x20000106 | uint16 / uint8 |

原R7导出`bpm_a`是算法，`bpm_b`是UI，原README说明写反。不能依靠同名符号数组顺序或浮点值“比较接近”自动判断归属；应固定经过核对的源模块、地址和类型表。

状态表至少记录原始文件、样本ms、主机取数时间、是否暂停和读取区间。运行中读取的2048 B块可能跨越多次更新；一个样本ms字段不保证其它字段都处于同一逻辑更新阶段。

暂停RAM是某个内存时点，也可能停在算法处理半帧中；保存PC/XPSR、消费进度等信息，不强称其为完整帧处理结果。逐帧精确状态需要适当的帧关联/版本协议。

R7主数据末端107818 ms，最后周期状态106617 ms，相差1201 ms；最终暂停RAM的最新处理时戳是107830 ms。必须先对齐，再分析浮点差异、门限或RR状态，不能拿历史最大峰和最后时刻门限判断某次候选应否受理。

## 6. 重新采集执行清单

### 开始前

- 记录非人体输入的实际类型、是否主动输出、型号、ECG心率/幅值、呼吸率及噪声设定。无参考值就标记“仅表征”。
- 核对板卡UID/型号、BIN、ELF、地址表和Flash身份。身份不符即停，不偷偷升级或覆盖镜像。
- 本轮优先保持上述固件基线，先验证取数工具；不要同时改算法参数，使前后难以比较。
- 创建唯一轮次目录，绑定所有输出路径。已有盘符映射不能擅自撤销别的任务映射。
- 写清复位、运行、暂停操作。包含`r/h/g`就不是完全只读，即使没有烧录。

### 采集期间

- 保存所有槽块、状态原件、J-Link指令与日志、命令退出码、实际块长度、主机单调耗时。
- 轮询周期需明显短于128点历史的覆盖时间；当前约512 ms。使用实际测得周期，不把`sleep 100`当作精确10 Hz。
- 记录计划规模/时长、实际耗时、固件样本跨度，三者分开。
- 若序号重启、身份异常、持续冲突或IO失败，保留本轮为不完整；新一轮另建目录。

### 结束后

- 保存暂停尾段及发布位置，记录恢复运行是否确实完成；停止或超时后的状态未知要如实说明，不能写“已恢复”。
- 稳定重建、尾段封存、错误/flags分类、时序检查全部通过后，才标记“导出跨度内稳定序号完整”。
- 质量通过不等于ADC物理边沿无丢失，也不等于生理准确度通过。

```text

firmware_state_timeline.csv         模块明确、类型正确、时间可对齐的状态
conflicts.csv / pending.csv         所有冲突和未认证记录
```

`raw_samples.csv`建议字段：`seq, sample_ms, irq_cycles, flags, status, resp_raw, ecg_raw, observation_count, provenance`。`provenance`区分重复稳定、暂停发布尾段和未认证记录；未认证记录不混入稳定文件。状态表中的滤波值必须明确是实机读取还是离线计算。

保留原始采集回执，解析阶段另写回执。实际人体原始数据保持本地保存，不自动提交公开仓库。

## 9. 最小验收用例

| 用例 | 应有结果 |
|---|---|
| 同序号A重复3次，B一次混字 | 保留原件和冲突，选A，记录选择依据 |
| 同序号A/B各重复2次或更多 | 停止认证，不能任意选多数或首读 |
| 一个序号仅读到一次 | pending，不能报稳定完整 |
| 暂停时下一次Push正覆盖最老槽 | 排除该槽，只取最后127个已发布位置 |
| 原始块少于3072 B | IO失败；不能读取旧同名文件顶替 |
| signed滤波值−12345 | 解析仍为−12345，不得变成4B以上的正整数 |
| DWT跨2³² | 模运算间隔正常，不伪造异常长停顿 |
| 真实flags、SPI错误或序号缺口 | 如实保留，不清零/补点获得PASS |
| 数据末端与状态快照相差1秒以上 | 按各自采样时刻对齐，不能直接比较终态 |

重新采集的成功标准是获得身份明确、版本稳定、来源和时序可追溯的数据。心率/呼吸是否准确，另用已知输入或独立参考判断。

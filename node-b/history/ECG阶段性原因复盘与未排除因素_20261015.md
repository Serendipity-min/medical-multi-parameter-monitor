# ECG阶段性原因复盘与未排除因素

日期：2026-10-15，Asia/Shanghai。将用户所称“GEC”理解为 ECG（心电）。

范围：核对现存源码、历次报告及既有证据；本轮没有连接设备、采集、烧录、修改算法、执行安全扫描或提交 Git。工程样本分析采用 OpenClaw Medical Skills 的来源和结论边界要求；未向外部服务上传采集数据。

## 1. 当前最准确的结论

**连续采到原始帧的问题已经在限定测试中解决；持续得到可信心率的问题仍未解决。**

历史上有多个确定的软件/接线问题：PA1板载共用网络影响START、主循环迟读且缺样本缓存、运行中SWD导出混字、旧算法滤波重启瞬态，以及呼吸削顶使ECG共同失效。不能说原来完全没有代码问题。

但是，最新算法解除双路共同削顶后，既有数据中的ECG仍因自身强周期干扰和缺少合格周期而无效。此前外部输入记录也只有短暂有效输出，没有可核验输入真值。**现在可确认拒绝有效值的程序路径，却不能把干扰的电气来源唯一归因于电源、接线或模块损坏。**

特别注意：最新8,412帧真机数据是在外部接口拔下时采得，只用于验证配置与连续性，不是有效ECG源测试。其心率无效不能单独证明模块不能采正常ECG。

| SPI寄存器时序风险 | 当前分频128，名义656.25kHz；初始化真实回读与期望一致 | 没有外部测量SCLK/CLK及信号完整性；旧工程和示例不自动继承此修改 |

## 4. 当前代码为什么会不给有效心率

### 4.1 输入到显示的实际调用链

`ads1292.c:175` DRDY ISR读9字节并保存时戳/序号 → `ecg_frame_queue.c`发布完整帧 → `ads1292.c:303`主循环取帧 → `hr_page.c:289`拆CH1呼吸/CH2 ECG并按原时戳调用 `BioV2_Process()` → `bio_v2.c`独立滤波/质量/周期判定 → `hr_page.c:403`分别读取心率和呼吸有效位。

`samples`表示接收处理帧数，包含削顶帧；不代表心拍检出数或信号合格数。驱动帧连续、屏幕有曲线和心率valid=1是三个不同的条件。

### 4.2 ECG强干扰会直接清空周期资格

关键位置：bio_v2.c:213（原报告本地资料链接，原件未随本包公开）。

当前条件为 `raw_power > 10000` 且 `line_power > raw_power * 0.95`。成立时执行 `forget_periods(..., BIO_V2_MAINS)`，清掉候选率、周期窗口和锚点，同时关闭当前峰状态，不进入普通心拍判定。`publish()`又检查质量并只在全部原因清除时发布valid。

这解释了为什么陷波后看见起伏仍然不给心率：代码保留滤波波形，但强干扰输入不能仅凭视觉平滑取得周期资格。干扰消退后也需要新周期重建，原因码不会单靠功率下降立即归零。

`line_power`来自 `(去DC输入 - 陷波输出)^2` 的指数平均，并非严格正交的49–51Hz频带积分。它含滤波相位/过渡响应等影响；“MAINS”是工程判据名称，不能直接当作已经测定USB电源为噪声源，也不能把在线指标0.974解释为精确97.4%的原始频谱功率。

### 4.3 峰及周期资格仍需逐项满足

| 条件 | 当前代码 | 不满足的结果 |
| --- | --- | --- |
| 本路削顶 | `accept_input():64`；包含边界±8304721 | 本路停止滤波、清历史、CLIPPED；另一通道可继续 |
| ECG预热 | `heartbeat():157`；至少5秒 | 尚不建立心率周期资格 |
| 候选幅度 | `heartbeat():146`；max(30码，2.5×带内RMS)，峰值还需达到门限1.05倍 | 无足够显著的候选 |
| 候选宽度 | `heartbeat():156`；12～160ms | 不进入周期受理；是本算法滞回宽度，不是独立标注的生理QRS宽度 |
| 合法周期 | `accept_cycle():99`；273～2000ms | 过短不更新锚点；过长清资格 |
| 足够新历史 | `accept_cycle():114`；至少3个合法间隔 | NO_CYCLES；至少涉及4个周期锚定峰 |
| 稳定性 | `accept_cycle():124`；窗口所有间隔偏离中位数不超过20% | UNSTABLE |
| 新鲜度 | `expire():93`；last_good超过4秒，或已有锚点超过2秒上限 | 清资格；不能仅说必须等4秒才失效 |
| 公共源完整性 | `Process():202`、`Tick():233`；flags/序号异常、输入间隔或年龄超过100ms | 两路共同失效；驱动另有>6ms IRQ异常flags |

因此强干扰反复清历史、弱/宽/不规则峰没有过门限、或不能积累稳定新间隔，都能造成“偶尔有数字，但不能稳定”。工程范围内偶发率值不是精度认证。

66=`MAINS(64)+NO_CYCLES(2)`。最后一帧原因码解释最后状态，不代表全程每帧的唯一原因；前两轮有效率是旧冻结BIO_V2的历史回放统计，本轮没有重算它们。通道独立修复的无削顶合成对照通过，不能冒充外部数据新版本实机验证。

### 4.5 界面提示容易混淆采集与接触

hr_page.c:368（原报告本地资料链接，原件未随本包公开） 的“探头接入”取决于近期有帧且至少一路测量有效。因此，两路率值无效时，即使帧持续到达，也可能显示未接入。

当前 `LOFF_SENS=00`，导联检测相关通道未开启；不能把STATUS形式正确或导联位为零作为电極接触合格的证明。RLD感测选择和RLD缓冲使能也是两个独立配置条件；寄存器回读正确不等于外部RLD导线/反馈闭环正确。[TI ADS1292R数据手册，§8.6.7–8.6.9](https://www.ti.com/lit/ds/symlink/ads1292r.pdf)

这是状态展示语义的限制，不是本轮新发现的ECG停止采样证据。本轮未改界面。

## 5. RLD改善了什么，没有改善什么

内部短接、RLD缓冲关闭的限定单变量测试中，只取消CH2正/负感测选择（CC→C0），ECG工频带RMS从1.572码升到60.888码，约38.73倍。返回基线的认证片段回到1.558码；B3整轮仍因冲突为REVIEW_REQUIRED。

这支持“感测选择影响内部短接工频底噪”。但是正常采集源码与真实回读原本就是 **EC**，已经开启缓冲并选择CH2两端，最近正常轮没有把RLD改成另一个数值。**尚无正常外部输入RLD修复前后改善的证据。**

RLD缓冲、呼吸调制和解调在内部短接时只观察到约1.50～1.70码的工频RMS小幅变化，不能推广为外部电极、实际RLD负载和阻抗输入下完全无影响。

| 优先级 | 因素 | 为什么仍未排除 | 能区分它的后续证据 |

| P0 | 最新通道隔离修复的实际运行身份 | 最新候选未在历史记录中烧录复测；本地源码不能证明今天板上运行状态 | 核对实际镜像SHA，再做限定非人体对照 |

| P2/暂缓 | 供电、电脑公共地、USB与J-Link耦合 | 用户要求暂时跳过；没有独立供电和连接路径分离对照 | 独立数据留存后进行同固件单变量连接/电源对照；USB烧录本身不能排除 |
| P2 | 外部时基/SPI电气质量和长期/高负载 | 现有IRQ稳定与寄存器回读支持当前链路；没有独立引脚时序或长期极端负载证据 | 需要时用外部时序测量与对应负载记录，不能把小速率误差当百万码干扰的已证根因 |

## 7. 修代码还是再重写

目前不支持立即再重写整套算法。BIO_V2已能在已知合成输入下稳定给出心率/呼吸率，且通道独立修复针对了确定的共同失效缺陷。继续重写不会自动修复外部源、共模条件或前端干扰。

建议下轮顺序：

1. 核对要测试的实际固件SHA与PG15接线，先确认通道隔离候选已正确运行，不能拿旧固件结果评价新补丁。
2. 用已知非人体ECG输入验证CH2，记录参考心率/幅值以及原始、过滤后、原因码、候选/受理数和新鲜间隔。CH1缺有效负载时允许其独立无效，不作为ECG试验失败。
3. 若原始输入仍被50/100Hz或约25Hz主导，先定位外部源/RLD/前端/负载条件，暂不通过放宽门限制造数值。
4. 若参考输入清晰，而算法仍漏检，使用同一记录冻结回放，再针对峰宽/幅度、漂移恢复、滤波和周期资格做最小可测修改。若需验证不规则周期适应性，单独给出相应输入和成功标准，不能用稳定工程夹具代表所有形态。
5. ECG受控验证通过后，再引入已知呼吸阻抗源及正常调制条件，确认两路各自有效、无相互失效。

本轮只制定区分原因的顺序，未启动硬件操作或追加改造。

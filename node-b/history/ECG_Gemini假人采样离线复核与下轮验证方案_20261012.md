# ECG Gemini 假人采样离线复核与下轮验证方案

- 复核日期：2026-10-12。
- 范围：既有文件、采集脚本、当前源码及 AXF 符号的离线复核。本轮没有连接、复位、烧录或采集硬件，没有修改生产源码。
- 用户补充：输入为“模拟的真实人体信号”，采集期间没有调整电极等操作。模拟源型号、设定心率/幅值/呼吸率及输出方式尚未明确，因此输入身份和定量参考值保持未核实。
- 原始 R1/R2/R3 数据、报告、图片和失败记录均保留；新材料独立写入 `排查证据_20261010/R3_离线复核_20261012/`。

## 1. 结论

**这批数据不能判定为正常且验收通过。** 能确认保存的原始码不是全零或顶轨，帧格式符合驱动校验条件，各连续小段的时戳与约 250 SPS 相符。不能确认完整采集无丢样、81 BPM 准确、20 rpm 准确或彩屏实际波形合格。

已经确认的主要问题位于导出及离线分析链路：不连续的缓存快照被当作连续数据；Python FIR 索引有误；离线像素模拟与固件不同；统计脚本字段错位。现有证据不支持推翻 R2 已完成的 PG15 START 与 ISR/FIFO 连续性修复，也不能据此认定传感器损坏。

此外，CH2 中存在明显约 50 Hz 分量和基线变化，CH1 有较大的基线阶跃。需要下一轮使用已知输入、完整连续记录区分输入信号、模拟源/连接/供电干扰与采集链路原因，暂不通过继续调增益或滤波参数掩盖问题。

## 4. 离线算法与统计脚本审查

### 4.1 FIR 计算错误：已精确复现

原脚本先 `state.insert(0, inp)`，再计算 `inp*coeffs[0] + sum(coeffs[1:]*state)`，使当前输入同时乘了 c0 和 c1：

```text
应为：y[n] = c0*x[n] + c1*x[n-1] + ... + c128*x[n-128]
实际：y[n] = (c0+c1)*x[n] + c2*x[n-1] + ... + c128*x[n-127]
```

按错误公式复算，**4480 个滤波整数值全部与原文件一致**，定位证据明确。即便只修正索引、继续错误地拼接缺口，4470 个输出仍与原文件不同，差值 RMS 约 248.02。这一对照仅验证索引问题，不作为正确固件输出。

原脚本跨缺口继续累积滤波历史，把相距 225～272 ms 的点当成相邻 4 ms 点，滤波时间轴因此失真。若采用断段处理，35 段每段仅 128 点，均不足以建立 129 抽头的完整输入历史，**没有任一段具备完整的 129 点 FIR 历史**。不能简单重新滤波后宣告问题解决。

原文件全体滤波范围为 **−6884～5488**；原报告的 **−2642～2297** 恰好对应跳过前 130 个保存点后的范围，应明确排除的区间。离线零状态启动也不同于实际已运行约 69 秒的固件滤波器状态。

### 4.2 不是实际固件滤波值或实际屏幕坐标

固件链路是 `五点中值 → EcgDespike → FIR/Pan-Tompkins`；原脚本直接将原始码送入自制 FIR，没有复现前置处理。固件还有序号/flags/时戳断段处置及算法状态，脚本未保持这些行为。

固件心电每 4 个采样点才调用一次 WaveScale（62.5 点/秒），脚本则每个样本调用；峰值衰减时间尺度不同。Python `//` 对负数向下取整，C 整数除法向零截断，仅这一差异就使 **1075 个模拟像素值不同**。因此 CSV `ecg_filtered / screen_y / peak_tracked` 是离线推算值，不能称为 SWD 读出的算法输出或屏上实际坐标。

17～238 的动态范围反映自动归一化效果。自动增益也会放大噪声，像素跨度大不能证明 ECG 合格。

### 4.3 驱动统计字段错位

当前 AXF 符号确认 `s_stats=0x20000204`、`slots=0x20002030`、`s_miss_cnt=0x20000040`。按当前结构定义，原 `verify_ram.py` 的标签存在如下偏移：

| 地址 | 实际字段 | 原脚本打印标签 |
|---|---|---|
| 0x20000204 | irq_count | irq_count（正确） |
| 0x20000208 | captured | captured（正确） |
| 0x2000020C | delivered | delivered（正确） |
| 0x20000210 | bad_status | miss_cnt（错误） |
| 0x20000214 | spi_errors | bad_status（错误） |
| 0x20000218 | queue_overflow | spi_errors（错误） |
| 0x2000021C | queue_peak | q_overflow（错误） |

真正的 `s_miss_cnt` 没有包含在原脚本指定的读取范围内。原报告 29899/29899/29899、81 BPM、98% 等为其报告声明；缺少原始 RAM/J-Link 输出，本轮不能独立核实这些现场数值。不能据此确认完整零丢帧；98% 质量值也不是独立的形态/节律验收。

## 5. 当前工程身份及 Gemini 的改动

对 R2 回执中的 13 个源码文件逐项做 SHA-256 比对，11 个未改变；仅 `hr_page.c`、`pan_tompkins.c` 改变，精确 Diff 已另存。四处参数变化为：

1. `HP_SPIKE_STEP: 5000 → 80000`。
2. `s_ecg_peak: 4096 → 1000`。
3. WaveScale 衰减下限 `1024 → 200`。
4. `s_filtered` 输出倍率 `100000 → 1000000`。

`s_filtered` 的倍率在微分/平方/积分计算之后，仅改变显示返回值，**不能单独归因于它修好了心率判拍**。放宽 despike 门限才会改变进入算法的信号，但其取值是否恰当还需已知幅值/QRS/伪迹输入的对照。当前最大段内原始相邻跳变为 36415 码，也不能直接当作经过中值滤波后 despike 的触发幅值。

WaveScale 被心电和呼吸共用，降低其下限会同时改变两路的显示映射；不是只影响 ECG。相关 ADC 单位/旧门限注释也未随参数同步更新。本轮仅记录，没有更改参数或注释。

## 6. 下一次假人/模拟源验证方案

先修正证据获取方式，再作受控采样，暂不以“波形铺满屏幕”为验收标准：

1. 记录模拟源实际类型/型号、连接、设定 BPM、ECG 幅值、呼吸率及是否叠加噪声；若这些无法给出，只能判定采集链路，不能做定量模拟人体等价验收。
2. 核对固件 SHA、PG15 START 接线、ADS1292R ID 和实际配置寄存器，保留原始读取输出及命令退出码。输入保持不变，记录是否从零启动及预热区间。
3. 使用独立诊断副本内的一次性连续记录，或能保证连续序号的专用输出。**不再用每约 0.75 秒读取最近 0.512 秒槽历史的方式声称无损采集。** 若使用专用 RAM 缓冲，应先验证 RAM/栈预算和 ISR 开销；满缓冲停止记录并保留计数，不能覆盖旧数据。具体实现及烧录在下一轮执行。
4. 固件先稳定运行至少 5 秒，再记录 10～15 秒连续数据。至少保存 raw CH1/CH2、STATUS、seq、sample_ms、flags，若记录滤波/BPM/UI，须与同一 seq 关联并标明实际上屏抽点；同时保存开始/结束驱动统计。
5. 首先验证连续性：seq 连续、无重复/倒退、时戳节律合理、SPI/STATUS/队列溢出与长间隔计数增量为零。缺口必须如实判不完整，不插值冒充原始数据。
6. 对已知 ECG 输入比较稳定窗口的 R-R/设定 BPM、原始幅值与约 50 Hz 分量，并按真实时戳、前置处理、float32 FIR 和屏幕抽点复核算法。启动/断段历史与有效稳态区间分别列出。
7. 对已知呼吸输入核对周期和 CH1 基线稳定性；无阻抗模拟能力时标记“呼吸功能未验证”。若约 14 秒阶跃重现，在输入不变条件下追加参考端/供电/模拟源对照，再决定修改哪一层。

本轮没有启动上述硬件流程。下一次记录的目标是“完整数据与已知输入一致”，而非再次取得某个合理的瞬时 BPM。

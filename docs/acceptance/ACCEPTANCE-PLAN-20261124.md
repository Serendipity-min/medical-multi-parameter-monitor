# 项目验收阶段规划

2026-11-24，北京时间。PI 起草，负责人原话：“我们进入项目验收阶段，不再无限期优化算法……验收视频日志材料等需要完备，以及最终就是项目书和 Github 仓库整理”。

本文件是计划，不是放行。凡涉及刷写、真人、断网故障注入、长测、合并 PR、删分支、改仓库可见性或许可证的动作，仍须按 `AGENTS.md` 由负责人当次写明放行。

## 0. 验收阶段的规则

1. **功能冻结**
   - R125 是最后一张算法卡。R126 出结果后，B 的算法和五板镜像一律冻结，不论 PASS 还是 FAIL。
   - 冻结后只允许两类改动：修正导致崩溃、复位或数据错误的缺陷；修正文档。不再调整门限，也不再新开算法研究。
2. **每项补测只有一次机会，外加至多一次复测**
   - 复测只用于现场流程出错，例如计数方式不对或报时缺失，不能为了把 FAIL 变成 PASS 而复测。
   - 复测结果与原结果并列保存，原结果不删。
3. **未达标的项目照实写**
   - 写“NOT_PASS，已接受”，并写明限制，口径同 `docs/closeout/01-ISSUES-AND-ENGINEERING-REVIEW.md` §1.3。
   - 不改验收口径，不把模拟器结果写成真人结果。
4. **每项补测都要同时交付三样东西**：
   - 预注册的判据（采集前提交）；
   - 原件（日志和视频）及其 SHA-256；
   - 判读结果。

   缺任何一样，只能判 NOT_EVALUATED。

## 3. 判据要点（正式卡片据此展开，采集前提交）

### 3.1 V1 演示

- **上线**：上电后，每块板 ≤90 s 在网页上线。
- **数值一致**：各参数在屏上、C 端和网页上的数值相同。
  - 每个参数至少核对 3 个时刻；
  - 以视频画面里的同框为准。
- **ECG 段**：网页 HR 为 60 ± 2；RESP 段：RR 为 20 ± 1。复用 R124 §5 口径。
- **NIBP**：一次测量在屏、网页、播报中一致。
- **TTS**：录像中听得到播报。

### 3.2 V2 故障演示

| 场景 | 判据 |
|---|---|
| ① 拔 CAN | 网页按既有时效转为 STALE/OFFLINE；插回后 ≤60 s 恢复 LIVE |
| ② 断网 60 s | 期间的标量补传后无缺失、无重复（复用 S3 的对账脚本）；恢复耗时照实记录，不设门限（已知 NOT_PASS，已接受） |
| ③ B 断电 | 不出现旧值重播；复电后 HR/RR 重新判有效 |

### 3.3 L1 长测

- **无异常复位**：各板运行时间计数连续。
- **断链记录**：记录 C 的断链次数和每次的自恢复耗时。
- **完整性**：标量完整率 ≥99%，波形覆盖率只记录。
- **资源**：内存和队列高水位不持续上升。
- **网页**：断开后能重新连接。
- **结论表述**：2 h 结论只能写“2 h”，不能写成 24 h。

### 3.4 安全

- 长测和故障演示全程不接触人体。
- 有人体接触的环节：全部电池供电，拔掉 J-Link，接触时间 ≤30 min。复用 R74 卡的条款。
- L1 无人值守过夜前，须负责人确认供电与防火条件。

## 4. 证据材料规范（视频、日志、照片）

### 4.1 视频

- **拍摄要求**：
  - 每项一个**不剪辑的连续主镜头**；
  - 画面里要能看到时钟（手机秒表或电脑时钟）；
  - 一次入镜各屏、网页和喇叭，必要时加第二机位；
  - 开始时口播编号和时刻，例如“V1，14:03:00 开始”。
- **隐私**：
  - 不拍志愿者面部；
  - 网页地址栏、热点名、IP 不入镜（遵守 `AGENTS.md` 的端点规定）；
  - 只用代号称呼志愿者。
- **文件命名**：`<编号>-<YYYYMMDDTHHMMSS>-<机位>.mp4`。
- **入库与存放**：交付后计算 SHA-256，写入清单；原文件存受限存储，**不进 Git**。
- **剪辑版**：可另做 3–5 min 剪辑版，用于答辩或项目书，注明“剪辑版，非原件”。

### 4.2 日志与原件

每项补测都要有：
- MQTT 录制（jsonl）；
- WSS 录制；
- C 的串口诊断；
- 现场记录 JSON（时刻和读数）；
- 判读脚本的输出。

另外，涉及刷写的补测还要有刷写和读回回执。所有原件记 SHA-256 和行数，同 R124 表头的格式。

### 4.3 照片

需要以下照片：
- 接线全景；
- 两段 CAN 端接；
- GT-246-4；
- 供电方式；
- 各板丝印与版本标签。

这能补上 R73 §4 记录的“照片缺口”。

### 4.4 证据总清单

- 新建 `docs/acceptance/EVIDENCE-MANIFEST.json`，逐项登记：编号、文件名、类型、SHA-256、时长或行数、存放位置（受限存储的路径代号）、对应判据。
- 同时更新 `DEFENSE-EVIDENCE-INDEX.md`。现有版本停在 2026-11-06。
